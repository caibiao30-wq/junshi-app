# 内容级阶段验收与会话级动态阶段

> 定位：interview 技能组共享规范 · 服务 `interview-workflow`（阶段验收）与 `interview-reporter`/`interview-qc`（报告与质检对阶段结构的落点）
> 状态：方案待采纳 · 依据《interview 技能组优化升级报告》§8《内容级阶段验收与动态阶段计划》
> 生效范围：本规范只约束"阶段怎么定义、怎么算完成、怎么写进报告"，不作为访谈的固定六阶段模板

## 1. 目的

六个固定 Phase 只查"文件存在、字段勾选"，不查"访谈对象/用户/问题/约束/目标/证据/决定是否真的清楚"。本规范把阶段验收从**工件级**提升到**内容级**：验收看的是内容是否收敛、前提是否满足、缺口是否显式化，而非产物文件与否。

## 2. 会话级动态阶段（不套固定六阶段）

- 默认阶段只是**骨架**，不构成强制顺序；每个会话根据实际问题树的生成与收敛情况，形成自己的**阶段计划**。
- 阶段允许**增加、合并、跳过或回退**。任何阶段调整都必须有明确理由、状态和验收依据，并在 02 记录（或独立状态记录）中留痕；不允许无理由跳阶段、跨阶段、一次性灌输全部问题。
- 阶段推进**逐层闭环**：当前阶段全部前沿节点完成提问、信息核实完毕、无残留待确认前置问题、逻辑自洽无矛盾后，方可解锁下一阶段；未闭环、存疑点、信息缺失的节点不得带入下一阶段。

## 3. 每个阶段必须定义七项

每个被写入阶段计划的阶段，都必须显式登记以下七项；缺项即视为阶段定义不完整，未补齐前不进行该阶段的进程判定。

| 字段 | 必须包含的内容 | 未满足时的处理 |
|---|---|---|
| **目标** | 本阶段要回答的核心问题、要达成的产出、服务的最终目标 | 无目标不开阶段 |
| **当前 frontier** | 当前前沿节点集合（根节点派生的、满足前置条件的可确认节点） | 无前沿不提问 |
| **问题集合** | 本阶段要提问/核实的问题及其依赖关系、所属分支与问题类型 | 问题须能回溯到节点与依赖链 |
| **完成证据** | 内容级判据：哪些事实/判断/决定已被核实，证据指向 02 记录或来源 | 无证据不算完成 |
| **用户确认方式** | 用户以何种方式确认（复述、纠正代理、明确拍板、沿用默许与补问）；什么不算确认 | 确认方式不成立不算确认采纳 |
| **未决清单** | 仍未闭环的待确认/待验证项、负责人、所需证据、下一步 | 未决项不以摘要掩盖、不静默带入下阶段 |
| **下一阶段解锁条件** | 满足哪些条件才放行下一阶段；条件未满足则停在本阶段 | 不满足不解锁 |

## 4. 内容级完成判据

阶段验收先过内容而非过文件。以下判据为"内容是否收敛"的最低检查，任何一条不满足即阶段未完成：

- **对象/用户/问题/约束/目标/证据/决定** 各自是否真的清楚，而非仅有字段值；
- 当前前沿节点是否全部完成提问，是否有未核实、未确认、逻辑冲突或信息缺口仍残留为待确认项；
- 每个关键判断是否具备来源、状态和缺口；没有来源支撑的表述不得写成结论；
- 阶段内逻辑是否自洽，有无隐藏的依赖未解锁、下游决策未落地；
- 未使用"文件存在""测试通过""模板就位"等工件级信号代替内容级验收。

## 5. 阶段验收示例（按阶段性质给出内容判据）

阶段不套固定名称，按实际性质套用对应判据；下列为通用示例，会话可根据实际问题增补：

- **目标范围阶段**：用户能用自己的话复述对象/使用者/问题/约束/预期改变，并能纠正代理复述；纠正前后差异已留痕。
- **证据阶段**：每个关键判断有来源、状态和缺口；来源可回溯到路径/URL/版本/获取时间，不可访问来源记为失败不静默跳过。
- **决策阶段**：每个关键决定有前提、取舍、风险、下游影响和完成证据；`[专业建议·代拟]` 与用户原话分离，未确认不写成结论。
- **收尾阶段**：未决项都有负责人、所需证据和下一步，不以摘要或阶段小结掩盖；已确认/专业暂定/待确认/待验证四类状态齐全。

## 6. 报告映射（动态阶段、无空章）

阶段的定义与完成情况最终落到 02 记录，报告据此生成：

- 报告**按实际阶段与问题节点生成，不生成空章**；本会话未发生的阶段不写入报告正文，不保留固定六章空骨架。
- 第一章对应本会话第一个实际阶段，章名 = 实际阶段名，不是"阶段 0/1/2…"的固定序号（会话若沿用默认阶段骨架则仍按名称标注）。
- 每章可带阶段头部，概述该阶段的目标/前沿/问题集合/完成证据/确认方式/未决/解锁条件，均取自 02 记录，不得在报告侧补造。

## 7. 与其他工件的关系

- 阶段七项定义与验收可在 `02_访谈记录.md` 或独立阶段状态记录中登记；`interview-reporter` 依据本规范决定报告章节结构与是否写空章。
- 本规范是阶段层面规范；节点生命周期（`candidate/ready/active/blocked/done/stale/superseded`）与取证/确认状态判据见 `decision-tree-contract.md`、`state-rubric.md`，本文不重复定义。
