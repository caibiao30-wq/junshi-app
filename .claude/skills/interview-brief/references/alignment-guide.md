# 约定引导（Alignment Guide）

本文件用于引导一次访谈约定对话。逐维度提问、逐项收敛，把受访者确认的结论写进 `00_访谈约定.md`。

**方法学入口**：涉及长论证的提问、复述或整理时，只读取主技能的 [`reasoning-methodology.md`](../../interview-workflow/references/reasoning-methodology.md) 对应小节；本文件不复制方法学。该方法学约束论证质量，不产生产品结论，也不改变本技能“只做约定”的职责。

**保真边界**：约定阶段可整理表达，但不得把受访者的前提、条件、限定、反例、证据等级、修正链和未决项压成孤立结论；代拟必须单独标注，且在确认前不得升级状态。无法确认的内容留为未决，不进入门控放行。

## 维度一：对象与权限

- 你在这个项目里是什么角色？哪些事你能最终决定？
- 哪些事你明确还缺能力、经验或资源？
- 采访者以什么身份进行？（可提：本人、产品访谈、正式方案起草前的沟通）

## 维度二：目标与产出

- 这次访谈你最想谈透的一两件事是什么？
- 谈完的产物给谁用？读者看完应能做什么？
- 用什么算"这次访谈谈成了"？

## 维度三：方法与阶段

- 接受分阶段推进，还是希望自由展开？
- 各阶段是否设置收敛门槛（该阶段关键问题有回应、状态已标注、记录授权已获得）？
- 追问偏好：喜欢被层层反例和边界追问，还是点到为止？

## 维度四：方向与范围内外

- 优先讨论哪些方向？（背景 / 现状 / 本质 / 角色边界 / 机制 / 实现）
- 明确不谈什么？（不进入的领域、不代你下结论的边界、暂时不聊的技术细节）

## 维度五：记录与保密

- 达成共识的内容是否默认写入访谈记录？
- 哪些内容要标注保密或不记录？
- 原始底稿位置是否确定？

## 维度六：代拟授权

- 当你不想答或不确定时，是否允许采访者按你既有立场代拟专业答案？
- 强调：代拟只是草稿，不等于你的确认；确认后才写入。

## 收敛方式

每个维度先听受访者立场 → 复述已达成 → 识别未决点 → 只有确有分歧才追问 → 判定是否收敛。复述与落稿前后，快速核对长论证的前提、限定、反例、证据等级、修正和未决项仍在；把已确认项逐条写入门控，未确认项显式留为未决。未达一致的维度不进入下一维度。
