# 示例访谈约定

> 以下内容为虚构示例，非真实产品决策。
> 状态：已确认

## 访谈对象与权限
- 受访者：示例项目发起人（无编程背景）
- 决策权与角色：负责项目方向与最终取舍
- 采访者：访谈工作流主技能 Phase 1

## 目标与产出
- 本次访谈要谈清：项目为何存在、服务谁、如何验证
- 产物使用者：项目决策者与后续执行代理
- 读者读完应能：区分已确认判断、候选方案与待验证问题

## 对象—用户—问题—约束—目标
- 对象：一个面向非专业用户的学习陪伴产品构想
- 用户：即将升学、需要决策指引的学生
- 问题：用户说不清要什么，需先厘清真实场景与具体例子
- 约束：无编程背景、时间窗口 3 个月、只能先做轻量验证
- 目标：把模糊想法收敛为可验证的需求与下一步

## 六大前置要素
- 核心目标：厘清产品核心问题与交付成果
- 边界范围：动机、用户、价值、边界、机制、验证；需记录共识项，禁止记录无关闲聊
- 执行方法：树形节点 + 前沿迭代；批判过滤与前置过滤为刚性约束
- 实施阶段：前置摸底 → 逐层核实 → 闭环校验 → 成果固化
- 核心方向：每个节点覆盖决策内容、前置依赖、事实与取舍、下游解锁、完成证据
- 验收标准：节点完成、前提满足、矛盾显式处理、用户确认依据可定位

## 范围与方法
- 访谈范围：动机、用户、价值、边界、机制、验证
- 阶段顺序：背景 → 现状 → 本质 → 角色边界 → 机制 → 实现
- 追问方法：开放问题、因果追问、反例、边界、实例
- 阶段收敛标准：当前阶段关键问题有回应、状态已标注、记录授权已获得

## 明确不谈什么
- 不进入与本次主题无关的领域
- 不在五元组收敛前进入具体技术选型
- 采访者不代受访者作最终决定

## 调查授权与来源范围
- 调查目标与核心问题：验证用户需求与竞品现状
- 产出给谁、用于什么决定：给决策者，用于是否立项
- 时间窗口：未来 7 天
- 仓库分支/提交点/文档版本：main @ 2026-09-11
- 允许的来源类型与平台：公开网页、GitHub、论文；不访问 X
- 是否允许联网：仅限来源登记表中列出的平台
- 明确排除范围：不调研私有竞品内部资料
- 失败来源处理方式：记入待核验清单，不静默跳过
- 调查结束验收条件：关键判断均有来源与状态
