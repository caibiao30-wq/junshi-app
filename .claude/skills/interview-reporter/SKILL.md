# Interview Reporter（访谈报告撰写·辅技能）

## 本技能是什么

一次访谈的**专业报告撰写角色**。它只在访谈全部完成、`02_访谈记录.md` 已存在且被主技能认可为证据源后出现：把记录整理成更正式、更专业、结构更清晰的 `03_访谈报告.md`。

它只做一件事：**以记录为唯一证据，做正式化整理**——不发明内容、不替用户下结论、不留尾巴。

## 它与主技能的关系

- 由 `interview-workflow` 在 Phase 4 派子代理加载本技能（首选路径）；主代理直接调用为降级路径，降级时在产出中如实标注"由主技能代执行、未走辅技能子代理"。
- 主技能负责集成、统一口径、去重与最终验收（或派 `interview-qc`）。本技能产出报告稿并保留待确认/待验证项，不代做定稿判定。
- **证据源边界**：`02_访谈记录.md` 是唯一内容证据源。报告不得用报告自身证明报告（拒绝自证），也不得回到原始未删减底稿自行创造记录中不存在的内容。

## 输入 → 输出契约

| 项 | 内容 |
|---|---|
| 证据源（必读） | `02_访谈记录.md`（唯一内容证据） |
| 可选参考 | 原始底稿仅作查证与定位回溯，不据此新增内容 |
| 产物 | `03_访谈报告.md` |
| 证据方向 | `03 → 02 → 原始底稿`（三态可回溯） |

**无 `02_访谈记录.md` 则不能开工。** 记录缺失、状态冲突或证据不足以支撑某条结论时，停下并回报主技能，不臆造补齐。

## 正式化边界（这条决定报告该长什么样）

报告比记录**更正式、更专业、结构更清晰**，但只做这几类改动：

**允许改**
- 整理总目录、章/节导航、问题标题与结构层级；
- 正式化措辞、统一术语、清理明显错别字/标点/断句/格式；
- 为独立阅读补最小标题、连接语与来源标签；
- 合并完全相同、无新信息且不变更顺序或状态的机械重复。

**禁止改（保真底线，与记录同等生效）**
- 不得压缩/压榨用户的长论述、推理、事实、例证、限定、反例与自我修正；
- 不得改变观点顺序、因果或确认状态；
- 不得把采访者代拟写成用户原话；
- 不得把"可能/我认为/暂待验证/尚存争议"等限定词升级为确定事实；
- 不得删去被修正的早期内容或抹掉自我修正轨迹。

详见 `references/reporting-rules.md`。

## 报告结构

产出必须包含（与 `interview-workflow/references/artifact-schemas.md` 中 03 的契约一致），结构顺序如下：

1. **标题与文档状态**
2. **总目录**（列全部章、节与文末区块）
3. **阅读说明**（报告与记录关系、状态标记说明、长篇回应处理说明）
4. **结论总览**（正文前，四类状态概要）
5. **第一章 ~ 第六章正文**：章 = 阶段（第一章=阶段 0 … 第六章=阶段 5），节 = 问题（节号 `章号.问题序号`，标题保留原始问题编号，例 `3.1 问题 2-1：<主题>`）；每节含 **标准化问题 → 回应与论证 → 节内确认状态 → 记录定位**
6. **结论边界**（已确认 / 专业暂定 / 待确认 / 待验证）
7. **待确认清单**
8. **待验证清单**
9. **回溯索引**（报告章/节 → 记录位置 → 原始底稿位置）
10. **附录**（状态与代拟说明）

**双层状态**：每节内保留具体确认状态；文末以"结论边界 + 待确认/待验证清单"做全报告汇总。

模板见 `assets/templates/03_访谈报告.md`。

## 长论证方法学接入与保真规则

起草每个问题单元前后，按需读取主技能 `interview-workflow/references/reasoning-methodology.md` 的「保真底线」「灵活形式选择器」「报告」相关小节；本技能只**引用**该方法学，不复制其正文，也不在产物中显性挂名。`reporting-rules.md` 是落地规则，二者都不能替代 `02_访谈记录.md` 作为内容证据。

对每条长回应，先按记录顺序保留完整论述，再做最小正式化。每条长论证必须能分别核对并保留：**前提、条件与限定、反例/例外、证据等级、修正链、未决项**。这些零件可用小标题、段落或列表呈现，但不能用摘要、结论总览或表格替代长论述本身；记录未提供某项时写明「记录未提供」，不得补造。摘要只是导航，绝不当作长论证。

- 长答案只最小改写，不压缩、不压榨；不改变观点顺序、因果、适用边界、限定词或确认状态；早期被修正的表述保留并标 `[已被修正]`。
- 证据等级不混写：事实、来源判断、推断与待验证分别标明；产品机制、推理推断不能作为自证证据。
- 每个问题单元都带**确认状态**与**记录定位**，可回溯到记录。
- 采访者代拟必须保留并标注 `[专业建议·代拟]`，除非用户已明确确认；代拟不能伪装成用户事实。
- `[待确认]`、`[待验证]` 必须进入对应清单并保留，报告不能把未确认/未验证项升级为用户事实。
- 状态不确定时取更保守状态，并记录缺少的证据。

判定统一走共享状态判据（六态），本技能只按证据填写、不得自行升级；方法学只影响论证组织方式，不充当结论依据。

## 拒绝自证与来源缺失处理

- 报告每个问题单元都以 `记录定位` 指向 `02_访谈记录.md`，报告自身不作为证据。
- **停机关**：若 `02_访谈记录.md` 不存在、同名问题的记录回应缺失、或记录状态彼此冲突，**停下并回报主技能**——不自行回到底稿创造记录，不静默跳过。
- 记录存在但不足以支撑报告某条正式表述时，按所在问题状态标注为 `[待确认]` 或 `[待验证]`，而非补写成事实。

## 配套结构导航（渐进披露）

- **scripts/**：`python3 scripts/report_gate.py <03报告.md> [02记录.md]` —— 确定性结构校验。定稿前运行，作为行为门槛；不能替代人工语义核验。
- **references/**：`reporting-rules.md` —— 记录到报告的正式化规则：什么能改、什么不能改、长答案保真、状态与代拟表达、问题结构与回溯索引、记录缺失如何停机。写报告时按需读；同时只读主技能 `interview-workflow/references/reasoning-methodology.md` 的相关小节，获取长论证零件、形式选择与证据边界，不复制其正文。
- **assets/templates/**：`03_访谈报告.md` —— 报告产物脚手架。
- **examples/**：`03_访谈报告.example.md` —— 从一条记录生成正式报告的虚构示例，对照"长成什么样算对"。
- 状态判据与保真契约见 `interview-workflow/references/state-rubric.md` 与 `fidelity-contract.md`（只读共享契约）。

## 完成后自检

- 是否以 `02_访谈记录.md` 为唯一内容证据源生成？
- 每个问题单元是否有确认状态与记录定位、可回溯到记录？
- 长答案是否未压缩、未压榨，前提/限定/反例/证据等级/修正链/未决项是否齐全、论述顺序与确认状态是否保留？
- 摘要是否只作导航、未取代任何长论证？
- 代拟是否标注、未上升为用户事实？待确认/待验证是否进入清单？
- 是否出现任何用报告自证、或回到底稿自行创造记录的情况？
- 是否已运行 `report_gate.py` 并通过？未被该脚本覆盖的语义保真仍须人工核验。
