# Interview Reporter（访谈报告撰写·辅技能）

## 本技能是什么

这是一次访谈的**正式文档级全文写作角色**，采用"正式文档表达 + 最大保真最小改写"。访谈记录是最原始的构思草稿与现场层；访谈报告是可直接投入正式使用的成文稿。报告必须采用连续、完整的叙述性表达，不得用誊抄、摘要或提纲替代正文。"最大保真"指不改变原意的语义保真，而非逐字誊抄：允许做专业性、正式性、文档级改写，可压缩冗余、合并重复、调整段落与衔接、适度减少篇幅；但不得把完整论证压成摘要或提纲，且关键事实、确认内容、逻辑依据、限定、反例、修正链与未决边界必须保留。

具体做法：把现场口语正式叙述化为书面语，优化句式、段落、标题与衔接，使原论述成为可直接投入正式使用的成文稿。改写以语义保真为前提：事实、确认状态、逻辑依据、限定、条件、反例、修正链与未决边界必须保留；允许删除纯口头赘词、机械重复和不增加信息的表达，允许在不改变原意与论证关系的前提下重组句子/段落并适度压缩。可重排章节或合并同义重复内容，前提是不改变原意且可回溯到 02，优先最小改动。不得把完整内容压成摘要、提纲或字段串，不得删除任何关键事实、确认内容、逻辑依据或未决边界，不得新增未经证据支持的推断。报告不得增加未经证据支持的事实，不得把专业代拟或待确认升级为用户结论。

## 与访谈工作流的关系及证据链

- 由 `interview-workflow` 在 Phase 4 派子代理加载；主代理直接调用是降级路径，降级时在产出中如实标注。
- 证据链固定为：`01 调查取证 → 专业过滤/代拟 → 02 访谈记录（内容证据层）→ 03 正式报告`。
- `02_访谈记录.md` 是报告唯一内容证据。报告可以脱离记录独立阅读，但不得绕过 02 新增内容；报告自身不能证明报告。
- `00_访谈约定.md`、`01_调查取证.md`、原始底稿及其他材料只能帮助理解范围或回溯定位，不能成为报告新增事实的依据。
- 无 `02_访谈记录.md`、回应缺失、原始定位为空或状态冲突无法解释时，停止并回报主技能，不回到底稿自行补写、不静默跳过。

## 输入 → 输出契约

| 项 | 内容 |
|---|---|
| 必读证据源 | `02_访谈记录.md`（唯一内容证据） |
| 可选定位材料 | 原始底稿（只用于核对和回溯，不新增内容） |
| 产物 | `03_访谈报告.md` |
| 回溯方向 | `03 → 02 → 原始底稿` |

## 正式文档级重写边界（最小改写 · 最大保真）

### 可以做（以最小改动达成正式表达）

- 将现场口语改为正式书面语，补足连接语，统一术语，修正错别字、标点、断句和 Markdown；
- 优化标题与句式，使标题准确概括记录已有范围、句子衔接更通顺；
- 将同一回应组织成连续段落；必要处可用小标题或列表呈现论证零件，但不替代长论述；
- 删除不增加信息的口头赘词与机械重复；在不改变原意和论证关系的前提下重组句子/段落、合理压缩；重排章节或合并同义重复内容，前提是不改变原意且可回溯（优先最小改动）。

### 不可以做

- 把完整论述压成摘要、提纲、结论或字段标签串；
- 删除或缩减任何理由、事实、例证、限定、反例、失败路径、犹豫、自我修正或关键逻辑依据；
- 重组到损失原内容、改变事实含义、因果关系、观点适用范围、确认状态或证据等级；
- 把采访者的专业代拟写成用户原话或用户决定；
- 把“可能”“我认为”“暂待验证”“尚存争议”等限定升级为确定事实；
- 删除被后续内容修正的早期表述；须保留并标 `[已被修正]`；
- 生成记录中不存在的产品能力、用户事实、工程实现或因果解释。

## 报告结构与编号

目录必须与正文一致，并列出全部有真实内容的章、节及文末区块。采用正式标题格式：

- 章：`第 1 章：实际阶段名`
- 节：`1-1 正式问题标题`

章 = `02_访谈记录.md` 中实际发生且有内容的阶段；节 = 有回应的问题。动态阶段可增加、合并、跳过或回退，只影响实际章名，不取消正式编号格式。不得生成空章或空节。

正式报告依次包含：

1. 标题与文档状态；
2. 与正文一致的总目录、章/节索引和文末区块索引；
3. 阅读说明（证据边界、状态、正文与附属信息的分层）；
4. 结论总览（仅导航）；
5. 正文（按章、节展开；标题下直接接连续完整叙述）；
6. 结论边界；
7. 待确认清单；
8. 待验证清单；
9. 回溯索引；
10. 附录（状态与代拟说明）。

每一节都应写出标准化问题、完整回应与论证、节内确认状态和记录定位。正文可在必要处使用小标题，但不能退化为“前提=……；反例=……”等行内清单。状态、来源注记、记录定位和回溯索引应放在节尾注记或文末，不打断正文叙述。

若 02 提供阶段目标、当前 frontier、问题集合、完成证据、用户确认方式、未决清单和下一阶段解锁条件，按原有内容保留；记录未提供则写明“记录未提供”，不从报告侧推断补齐。

## 状态与长论证

沿用共享七态判据，按证据填写，不自行升级：`[用户明确判断]`、`[确认采纳]`、`[专业建议·代拟]`、`[已被修正]`、`[待确认]`、`[待验证]`及其他共享判据要求的状态。确认只覆盖用户明确指向的内容；“请为我作答”只授权代拟，沉默不等于确认。

每条长回应必须以完整正文保留并分别可核对：前提、条件与限定、反例/例外、证据等级、修正链、未决项。记录未提供某项时写“记录未提供”。这些零件可以通过段落、小标题或列表组织，但不能替代长论述。早期被修正内容保留并标 `[已被修正]`。

- 已确认项写结论与依据；
- `[专业建议·代拟]` 明确不是用户观点；
- `[待确认]` 必须写未确认原因、影响范围、后续处理要求，并回溯到具体记录；
- `[待验证]` 必须写需运行、样本、反馈或长期实践验证的事项、影响范围和处理要求；
- 四类状态均在正文后的结论边界中汇总，待确认和待验证另列清单。

## 配套结构导航

- `references/reporting-rules.md`：写作前后按需读取，执行证据、重写、长论证、状态、章节和回溯规则。
- `assets/templates/03_访谈报告.md`：按实际阶段和问题填充，不把占位符带入成品。
- `examples/03_访谈报告.example.md`：学习正式标题、连续叙述、状态分层和回溯方式。
- 共享的 `interview-workflow/references/state-rubric.md`、`fidelity-contract.md`、`stage-acceptance.md` 和 `reasoning-methodology.md` 只读引用；它们不能替代 02 作为内容证据。
- `scripts/report_gate.py` 如项目流程要求可由主技能运行；其结构检查不能证明语义保真。本任务交付时只做 Markdown 静态检查，不运行测试、eval、runner 或 gate。

## 完成前自检

- 是否只以 02 为内容证据，且保留 `01 → 代拟 → 02 → 03` 三态链？
- 目录、正式编号、正文章节和文末区块是否一致，且无空章？
- 标题下是否为连续完整正文，而非摘要、提纲或字段串？
- 长论证的关键零件、修正链、限定、反例和未决边界是否保留？
- 已确认、代拟、待确认、待验证是否分层，且待确认包含原因、影响和后续处理？
- 每节是否有可回溯到 02 的记录定位，报告是否拒绝自证？
