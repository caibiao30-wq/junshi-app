# 学业军师 · 团队编排执行方案（Team + Ralph 产品版）— 交付计划

## Context（为什么做这件事）

这是学业军师工程开发前置准备的**最后一步交付**。用户要求把此前 deep-interview（三份访谈权威锚 + 商业战略定调）与 ralplan 共识（过程机制）的成果，固化为一份**团队编排执行方案**，作为下一轮 Claude agent teams 用 `/team ralph` 可靠交付「工程开发总文件 + 派生专业文件 + 可回溯交付总表 + 产品自持硬边界与门禁」的执行宪章。

**关键约束（来自访谈与用户定调，不得违反）：**
- 学业军师是**裁缝产品**（0.5→1 拼接缝合复用成熟开源部件）；用户是**商人**，追求利益与效率，唯一目标是「把设想打通、跑通、达成目的」；信任 **AI 与 GitHub** 的力量。
- **首版把一切「不可替换」部分构建完毕**（学业规划最高责任、判断引擎、客观证据模型、唯一状态源与生命周期、权限与确定性强制、证据审计链、业务回滚语义、全学段/全学科统一结构、学生主体边界），可替换部分 0.5-1 复用并随开发优化/升级/替换。
- **权威锚**：前端=第二次访谈报告；产品本体/其余=第三次终局访谈定案；工程方法=开发指导文件；候选组件=暂定逐案核验。
- **流程准入**：严格符合 OMC `/team ralph` 真实管线（team-plan→team-prd→team-exec→team-verify→team-fix，外层套 Ralph 持久循环），且用户确认在 **team-prd 与 team-exec 之间插入「高层会议门」**（模拟公司内部对产品的高层决策会，全部无异议通过才放行）。

**明确不做**：本轮不直接起草交付层/承载层文件、不替下一轮裁决访谈冲突、不决定首版学段/回滚/CRDT/候选组件采纳。

## 交付物（本计划要产出的）

一份可交给 `/team ralph` 执行的《团队编排执行方案》，核心内容如下。

## 流程准入（team+ralph 标准管线 + 高层会议门）

```
Ralph 外层持续循环（iteration 1..N）
 └─ Team 管线：
    team-plan → team-prd →【高层会议门】→ team-exec → team-verify
        │                                        └─通过→ Ralph architect 验证
        │                                        │          └─通过→ 完成/取消
        │                                        └─失败→ team-fix → 回 team-exec→team-verify
        └─ fix 超 max_fix_loops → Ralph 递增 iteration 重跑整条管线
        └─ Ralph 超 max_iterations → 终态 failed
取消任一模式 → 双双取消（取消耦合）
```

**终止条件**：team-fix 受 `max_fix_loops`（默认 3）限制；Ralph 受 `max_iterations` 限制；均避免无限循环。

## 高层会议门（team-prd 与 team-exec 之间 · 强治理闸门）

模拟公司内部对产品的高层决策会，**执行前最后一道闸门，全部无异议通过才放行**。

- **参与者**（真实 OMC 代理）：`architect`（产品语义辩论人）+ `code-reviewer`（工程机制辩论人）+ `security-reviewer` + `tracer`（证据合规辩论人）+ 主控总协调。
- **程序**：各视角独立批判 → 往返互驳 → 收敛；每项争议记录【结论—状态—依据—影响—升级对象】；引用不替代记录，不用「大家同意」代替逐条记录。
- **审查对象**：team-prd 产出的范围 + 验收标准 + 计划。重点查：是否违反访谈权威锚、是否静默合并冲突、是否把待确认写成已定、候选组件是否被误当已采纳、产品自持硬边界是否外化。
- **通过条件**：全部讨论无异议通过（每项争议关闭或显式升级到用户门）。
- **未通过**：回 team-prd/team-plan 修订，再开会（≤3 次）；超限仍未通过 → 升级用户门，**不得带病进 team-exec**。

## 证据冲突处理（不得静默合并）

下一轮团队开工前建立「来源—状态—冲突」矩阵，以下须为用户裁决门或待确认/待验证：
- 首版学段/年龄/学科/典型任务（终局阶段 2 明确待确认）。
- 回滚单元/版本语义/错误补偿（G1）。
- CRDT/同步（终局：暂不引入，待验证）。

## 候选组件暂定机制

候选组件仅作 0.5-1 暂定输入，逐案核验【许可证/依赖/范围/本地运行/迁移/替换】，**不得写成已采纳**；处理建议限 复用/改造/受控整合/隔离/暂缓/放弃/自建，由下一轮团队逐案取证 + 用户准入门裁决。

## 一致性协议（起草期闭环，防跨文件漂移）

1. 冻结基线：总编签发 `baseline_id`。
2. 继承声明：每派生文件头 `inherits_from: baseline_id`。
3. 变更传播：上游变更签新 baseline_id，标记受影响派生 `STALE/PENDING`。
4. 单一写权：每主题独立责任人/写入者/冲突裁决者。
5. 冲突裁决：只回上游总文件或用户决策簇，禁总编静默择一。
6. 向上修订路径：派生发现缺口→变更请求→总编判定骨架（重冻结+STALE）或待决（挂用户门）。
7. 放行核对：终版前「基线版本—派生引用—差异/例外」三表核对。
8. 继承边界：组件 HOW/编排方案标 `indep`，不伪造继承来源。

**成本护栏**：总代理≤10=任一时刻并发实例数；口径=专题子任务+ralph 循环，不含总编/verifier/组件准入独立通道；重试计一次；ralph 单循环 ≤3×≤2。

## 验收标准（S1–S8，含测量口径）

- **S1 状态标签覆盖率**：分母=全部结论条目；判定=100%（原始用户判断/代拟/确认/待确认/待验证/已被修正）；证据=统计报告。
- **S2 关键结论定位覆盖率**：判定=100% 含 `文件:页码/行号`；证据=定位清单。
- **S3 字段完备率**：每份文件具 目的/范围/输入/输出/责任/完成定义/验收标准/实际证据/未验证边界；缺失=0。
- **S4 边界无越界**：grep 为筛查非判定，逐命中语义分类（允许引用/历史/越界）；越界撤回清零。
- **S5 最小闭环可读通**：模板固定 输入→步骤→预期输出→记录；L1 机制 + L2 故障注入验收入口，作者不自审。
- **S6 规范一致性**：从冻结总文件生成规范条目 ID 集，每派生逐条映射 `covered/N-A/例外`；状态/权限/回滚/审计/范围高风险字段全量对照；差异未清零终版硬停。
- **S7 链接/只读质检**：Markdown/链接/交叉引用/表格扫描，错误=0。
- **S8 审计轨迹**：门通过/硬停重开/争议关闭依据/用户确认/未决清单齐全。

## 门控、重试、取消、幂等恢复

- **门控**：team-verify 通过才进 Ralph architect；任一阶段失败按管线回退。
- **重试**：team-fix 受 `max_fix_loops`（默认 3）；超限 Ralph 递增 `iteration` 重跑；Ralph 超 `max_iterations` 终态 `failed`。
- **取消**：取消 Ralph 先优雅关 Team 再清 Ralph 态；取消 Team 则标记 Ralph 迭代取消停循环；二者互为取消。
- **幂等恢复**：主控崩溃时读 `state_read(mode="team")` + `state_read(mode="ralph")` 恢复 slug/phase/iteration；用 OMC handoffs + task 列表定位进度；恢复监控模式而非重复 spawn；自上次记录阶段继续。
