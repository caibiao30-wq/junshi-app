# Context

`mate/` 已完成旧五编到新六编的目录迁移，但当前仍存在三类结构问题：部分章节混合多个核心问题；Ⅲ、Ⅴ等编的职责承诺尚未由正文闭合；状态、记忆、模型/回退、核壳术语存在跨编冲突。与此同时，后续 Agent 缺少目录级工作入口和高效检索路由。

本计划的目标是：在**不撤销六编、不物理建立三层目录**的前提下，规划“内容三层视图 + 六编物理目录”，将混合章节精细化为“一章一个核心问题”，并建立 `mate/CLAUDE.md` 与 `mate/AGENT-检索导航图.md`。本阶段只形成执行计划，不修改仓库文件。

## 已确认约束

- 三层保留为最高内容架构视图；在此之上，六编不再视为不可拆分的最终编制，而是按职责**进一步逻辑分化为更多编**，将拆分后的单主题章节按需归入分化后的编（2026-09-02 用户确认）。
- 分编采用**四项成立标准**：独立内容域；至少两个关联但不可合并的正式章节（或明确长期扩展责任）；唯一主责、输入、输出、边界与验证入口；能融入三层并与其他编有明确接口，且不为凑数而拆。
- **先逻辑分编，暂不物理迁移目录**：在计划中建立“三层 → 目标多编 → 章节”的目标树、职责矩阵与迁移映射；现有六编目录保留，待结构确认后再执行物理调整。
- 执行代理**按目标分编责任组织**，而不是按现有六编粗分；计划代理仅设计"需要哪些代理"，不替用户决定最终分编——最终分编须用户确认。
- 每章一个核心问题；允许包含必要的前提、边界、接口和验证，但不得堆叠多个独立决策。
- `00-横切工程责任总纲与接口矩阵.md` 负责产品跨编责任、接口、断言状态、冲突暂停和派生闸门。
- `README.md` 负责全书导航；`mate/CLAUDE.md` 负责 Agent 如何工作；`mate/AGENT-检索导航图.md` 负责 Agent 去哪里检索；二者不替代 00，也不成为产品法源。
- `mate/CLAUDE.md` 必须使用 `claude-md-management:claude-md-improver`；导航图必须使用已启用的 `mermaid` skill。
- 用户确认采用 9 个逻辑任务、3 个 Explore 并行后 1 个 Plan 整合；Explore 与 Plan 已完成，本计划由主代理审查。
- 既有文件名前缀是排序键、正文 H1 保留历史真实章号；**是否正式重排 H1/新编号仍须用户单独确认**，执行前不得默认重排。

# 目标内容架构

三层为最高内容架构视图：
- **产品本体层**：产品为何存在、目标、对象、范围、非目标、阶段承诺与成功标准；
- **运行机制层**：学习如何运行、Agent 如何判断/行动/记忆、证据与状态如何演化、用户如何交互与核壳组合；
- **治理闸门层**：如何验证、评估、发布、回滚、运维、合规并派生到工程。

在上述三层之内，将现有六编按职责进一步**逻辑分化为目标多编**。初始候选分编方向（**均为候选**，须经四项成立标准逐编判定并由用户确认，不直接落盘）：

- Ⅰ 产品本体与目标 → 可考虑细化为「产品本体与价值」「服务对象与适用范围」等候选编；
- Ⅱ 学业规划与教育机制 → 可考虑细化为「学业规划」「学习机制与反馈」「复盘与元认知」等候选编；
- Ⅲ Agent 核心架构与判断机制 → 可考虑细化为「判断与推理」「Agent 核与 harness」「记忆与上下文」「策略与能力编排」等候选编；
- Ⅳ 证据、状态与学业资产 → 可考虑细化为「证据与学业资产」「对象状态」「版本/谱系」等候选编；
- Ⅴ 产品交互与核壳组合 → 可考虑细化为「角色与交互」「Agent 交互」等候选编；
- Ⅵ 工程治理、验证与派生实施 → 可考虑细化为「选型与架构」「验证与发布」「AI 安全与数据治理」等候选编。

分编成立通用判定（四项标准，均须满足）：
1. 有独立内容域问题；
2. ≥2 个关联但不可合并的正式章节，或有明确长期扩展责任；
3. 有唯一主责、输入、输出、边界和验证入口；
4. 能融入三层、与其他编有明确接口，且不是为凑章数而拆。

划定目标多编后，将拆分后的单主题章节按职责归入对应目标编，再决定执行代理数量（按目标编组织）。

# 9 个逻辑任务与依赖

1. **建立结构基线**：盘点 mate 文件树、标题、文件排序号/H1历史章号、链接、旧 `book/` 映射、陈旧编名和悬空链接。产出不可静默改写项清单。无依赖。
2. **设计“三层→目标多编→章节”逻辑架构**：依据四项分编成立标准，逐一判断现有六编是否需要拆分、每个候选新编的独立问题、正式章节数/长期责任、唯一主责、输入输出、边界和验证入口；形成候选分编树、三层映射和用户确认清单。只做逻辑分编，不移动目录。依赖任务1。
3. **处置产品本体与教育机制域**：在任务2候选分编边界内处理Ⅰ—Ⅱ，将产品本体/目标/对象/规划/闭环/反馈/复盘/学习方法拆为单主题章节；状态、记忆和资产只登记接口与冲突。依赖任务2。
4. **处置 Agent 运行域**：按目标分编规划判断、Agent 核/harness、loop/工具、记忆/上下文、策略/模型语义章节；登记 03/05 状态冲突和记忆、模型归属分叉。依赖任务2、3。
5. **处置证据与资产域**：按目标分编规划证据/资产概念、生命周期、对象状态、版本/谱系、持久化/权利等章节；区分产品语义与工程语义。依赖任务2、3、4。
6. **处置交互与核壳域**：按目标分编规划角色、平板/可达性、Agent 交互、核壳适配章节；登记角色、法域、壳术语阻断。依赖任务2、3、4、5。
7. **处置工程治理与附编域**：按目标分编规划评估发布门、SLO、AI安全、数据治理及附编同步；区分当前结构、历史记录和预留项。依赖任务2、5、6。
8. **设计 Agent 工作入口与检索导航**：使用 `claude-md-management:claude-md-improver` 规划 `mate/CLAUDE.md`，使用 `mermaid` 规划 `AGENT-检索导航图.md`；建立三层—目标多编—章节图、问题→首读文件→接口→验证路径、概念主责/协同/待确认索引。依赖任务2—7的边界初步稳定。
9. **集成、验证与执行顺序**：合并候选分编树、文件处置矩阵、章节树、跨编冲突、同步策略、暂停条件、回滚点、代理编制和验收命令；由主代理统一审查，并将目标多编提交用户确认。依赖任务1—8。

# 技能与工具

- `skill-first`：记录实际 skill/agent/tool、输入输出、阻塞和验证。
- `md-writing`：所有 Markdown 章节、README、入口文件、导航和附编的结构、单主题、链接和状态表达。

- `Plan`：把已确认结论转成实施计划（本轮已调用）。

## 按需技能

- `documentation-audit`：执行后限定审计 mate 内 Markdown 链接、导航和内容漂移。
- `code-review`：仅当实际触及代码/配置时启用；本计划不默认使用。
- `graphify`、`dataviz`：不使用；本任务是静态文档架构图，不是知识图谱或数据图表。

## 工具边界

- 只读勘察：`Read`、`mcp__filesystem__directory_tree`、`mcp__filesystem__search_files`、只读 `Bash`、Explore/Plan 代理。
- 执行阶段：`Read`、`Edit`、`Write`、`Agent`、`TaskCreate/TaskUpdate`；两个指定技能按其职责调用。
- 验证：路径与链接目标、标题/编号映射、旧引用分类、状态标签、三层映射、主责索引和 Mermaid 语法检查。
