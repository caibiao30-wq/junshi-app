# Skill-First 统一执行协议

本命令是全仓库唯一的命令级入口，对仓库内所有目录、文件类型和任务一律适用，不限定特定工作区或领域。它把“识别任务 → 选择能力 → 实际调用 → 记录证据 → 验证收束”串成一条可复核链；不增加工具，也不能从 Markdown 层强制运行时调用。

## 何时使用

阶段开始前，只要满足以下任一条件就使用本协议，且不受工作目录或文件位置限制：

- 任务跨多个阶段、文件、工具或轮次，或需要保存中间状态。
- 任务涉及外部研究、配置/安全审查、文档处理、代码编写/审查/测试、Orca 协作或任何本仓库目录的实质工作。
- 用户明确要求使用 skill、agent、MCP、编排或本命令。
- 存在适用或专用 skill，即使任务表面上可以直接用基础工具完成。

单步、直接且一眼可验证的任务可以跳过；跳过时仍在任务记录中写明：`无适用 skill：<具体理由>`。本命令被调用后，不再寻找或依赖其他命令级入口。

## 执行顺序

1. **界定任务**：写明目标、任务类型（如 `draft`、研究、审查、写入、文档、代码、编排）和成功标准。
2. **发现能力**：分层检查并分别记录：①仓库 `.claude/skills/*/SKILL.md` 中的项目 skill；②仓库 `.claude/agents/*.md` 中的项目 agent；③当前会话 `available_skills`/Skill 工具清单中的实际可调用 skill；④当前会话已连接且确实可用的 MCP/工具。`~/.claude/skills`、插件 marketplace/cache 及 `skills-disabled/` 只能作为磁盘发现或来源线索：前两者不自动等于当前会话可调用，后者不算活跃能力。文件、入口和当前会话可用性都能核验，才可标为“可用”；仅有文档、历史记录、系统提示或目录存在不算。
3. **选择最小集合**：按职责匹配一个首选 skill；只有存在独立且不可替代的前置/后置职责时才增加能力。说明选择理由，避免重复加载或把协议当成业务 skill。**凡涉及任意 Markdown（`.md`）文件的撰写、从零创建、改写、优化、重构、审查、导航设计、文档集维护或内容迁移，必须选择并实际调用 `md-writing`；不得用基础工具直接代替。**
4. **先调用后执行**：通过 Skill 工具、agent 入口或当前环境提供的 MCP/工具实际调用所选能力。Read、Grep、Bash 等基础工具只能补充执行，不能冒充专用 skill 的调用证据；对 Markdown 任务，先调用 `md-writing` 再读取、分析或写入目标文件。
5. **确认边界**：写入、删除、联网、安装依赖、发布或其他不可逆/外部可见动作，先核对授权、范围和安全影响；能力不可用时记录阻塞，并说明经授权的降级路径。
6. **记录证据**：在当前任务报告、过程日志或交付文件中追加“记录模板”；记录实际返回的结果，不只写计划或 skill 名称。
7. **验证收束**：按成功标准运行最小匹配验证，区分已验证、未执行、阻塞和需人工确认；缺少调用或验证证据时，不标记为完成。

## 全仓库路由提示

本节覆盖当前会话 Skill 工具清单中的每个可调用 skill；它是路由索引，不替代第 2 步的实时核验。项目 skill 当前为 `graphify`；用户目录 skill 为 `deep-product-interview`、`md-writing`；带命名空间的条目来自已启用插件。路由时必须以当前会话可调用清单为准，不能把磁盘文件、缓存目录、历史名称或未加载插件当作能力。一个任务可同时命中多个 skill，但只有职责独立且确实需要时才叠加。

```markdown
## Skill 使用记录

- 阶段：<阶段名称>
- 任务类型：<类型>
- 目标与成功标准：<可观察结果>
- 能力发现：<来源分层：仓库 skill/仓库 agent/全局 skill/插件 skill/MCP；可用性核验依据——磁盘存在还是当前会话可调用；不得把磁盘存在写成本会话可调用>
- 选择理由：<为何选择最小适用集合>
- 实际调用：`<skill/agent/入口>`；结果：<返回摘要>
- 协作 agent/工具/MCP：<实际使用；没有则写“无”>
- 输入：<文件、路径、URL、参数或范围>
- 输出：<文件、路径或结论摘要>
- Markdown 专项：若任务涉及 `.md` 文件，必须记录是否实际调用 `md-writing` 及其影响；未调用须写明理由。
- 阻塞/降级：<原因、授权路径；没有则写“无”>
- 未调用项及理由：<候选能力与具体理由；没有则写“无”>
- 验证：<命令/检查、结果、未执行项>
- 下一步：<下一动作和门槛>
```

## 证据与边界

- 写出 skill 名称不等于调用；必须有实际入口和返回结果。
- 来源分层标记：仓库 skill、仓库 agent、全局 skill、插件 skill、MCP 分开记录；当前会话可调用才记为能力，磁盘存在、插件 market 或系统提示提及只能作为来源线索。
- 该协议不能阻止裸读、裸写、网络访问、安装、删除或发布；权限由宿主设置、hook、Orca 生命周期和人工确认负责。
- 不把基础工具调用、目录存在、候选研究或原型结果升级为专用能力已执行、产品决策或工程已实现。
- 外部材料与本仓库事实、用户决策、开发者判断和模型推断分开记录；缺少来源或状态时标记阻塞，不凭记忆补齐。

## 完成标准

一次阶段交付只有同时满足以下条件才算完成：

1. 任务类型、目标和选择理由清楚。
2. 能力确实可用，实际调用入口和返回结果可复核。
3. 输入、输出和影响范围有路径、URL、参数或简短摘要。
4. 授权、阻塞、降级及未调用候选没有被隐去。
5. 最小匹配验证已执行并报告结果；人工确认项仍明确标为待确认。
6. 下一步或结束理由清楚，且没有把未验证内容写成通过。
