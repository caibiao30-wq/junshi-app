# 深度产品访谈 · 可复用方法保留

> 目标：把"那次和产品负责人聊透的提问方法"从一次性对话中抽出来，沉淀成**下次还能再跑一遍**的方法骨架。本文交付的是**方法本身（how to ask）**，不是某场访谈的复述稿。

---

## 1. 这份材料的用途与契约

- **它是什么**：一套"深度产品访谈"的可复用方法 + 填空式问法库 + 输入/输出契约。谁拿了这份材料，就能在没有原访谈者/原记录的情况下，重新发起并走完一次同等深度的访谈。
- **它不是什么**：不是某场访谈的文字记录，不是观点清单。它刻意去掉了领域内容，只留下"怎么问"的可迁移结构。
- **复用边界**：
  - 可用：任何要"把一个产品构想/决策谈透、再落到正式方案"的场合。
  - 不可用：用于现场评分、用于单方面的信息收集（这套方法本质是**双向确认**，受访者中途必须参与修正，默认需要一位愿意被追问的受访者）。
- **成功标准**（核验本文是否可用）：只读本文，能否独立**发起一次**访谈并产出可落地的结论稿。能，则方法保留成功；不能，则某层抽象仍有缺失，需补。

---

## 2. 一次访谈的完整跑法（30 秒看全貌）

```
准备(P0) → 打开愿景(P1) → 收敛边界(P2) → 拆解机制(P3) → 代拟确认(P4) → 收束沉淀(P5)
   ↓          ↓              ↓               ↓              ↓              ↓
  定题       问"你要做成   逼出"不是什么"   让模糊变具体     把受访者口头     生成可复用
  找受访者   什么"          卡边界            追问到机制      判断落成文字     的产品知识 + 方法
```

**铁律一条**：每一阶段"问到底"再进下一阶段，不要提前跳到结论。深度 = 每一层都追问到"受访者自己说出第一条他自己都没写下来的判断"为止。

---

## 3. 阶段与方法：到底怎么问

### P0 · 准备（10 分钟）
- 定"要谈透的一件事"，一句话。它必须是一个**产品判断/决策**，不是一个人。
- 选出受访者：能做产品判断、且愿意被追问至少 60 分钟的负责人。
- **产出物**：一句话题目 + 预期时长 + 已提前写下的"已知假设"草稿（用于对照受访者后来所说）。

### P1 · 打开愿景（问"往哪去"）
问题模板：
- "如果你要在 3 个月内让它成功，它为用户解决的那个**最根本**的问题是什么？"
- "想象用户已经在用，他**再也不会回到旧方式**——旧方式是什么？"
- "如果只能传达一句话定位，这句话是什么？"

技法：**第一性追问**。听到一个愿景词（如"效率""陪伴"），立刻问"这里的效率，具体是替用户省了哪一步？"——直到落到一个能画出来的行为，而不是一个形容词。

### P2 · 收敛边界（问"不是什么"）
问题模板：
- "这个产品**明确不做**的是什么？为什么现在不做？"
- "谁是**一定不是**你的目标用户？"
- "什么情况下你会**砍掉**现在的核心功能？"

技法：**反例与边界卡**。边界的唯一判据是"可证伪"。受访者给出"我们服务年轻人"，追问"你接受它**不服务**35 岁以上吗？若接受，那你的边界就是年龄；不接受，说明这句定位是空的"。（用问题定语测试真伪，而非让受访者自证。）

### P3 · 拆解机制（问"怎么运作")
问题模板：
- "当第一次使用发生时，第一步动作是？第二步？用户看到反馈后才继续往下，这条**反馈闭环**在哪？"
- "用户为什么会在第 3 天回来，而不是第 1 天？留住他的那个机制是什么？"
- "这个机制换成一个最笨但能跑的初版，最笨的形态是什么？"

技法：**具象化 + 机制下钻**。每得到一个名词，替它装一个"动词"：
- 有"内容" → 问"内容从哪来、谁来生产、什么时候更新"；
- 有"社区" → 问"人为什么聚、为什么留、冲突了谁裁决"；
- 有"推荐" → 问"推荐依据哪几个字段、字段从哪收集"。
目标是让受访者逐条点头确认**机制的五要素**：触发 → 动作 → 反馈 → 回报 → 退出。

### P4 · 代拟确认（把口头变文字）
核心动作：**你自己代拟一段"我理解你是这么定：……"，让受访者修改**。
问题模板：
- "我复述一遍，你看哪句不对：『这样产品要先……，最核心的用户是……，第一步是做……』——哪句需要改？"
- "如果我把你刚才的边界写成『P2 不做……』，可以吗？"
- "按我们聊的，第一个里程碑的定义是『……』，对吗？"

技法：**代拟确认（proposed-draft confirmation）**。不要问"你同意吗"（默认点头），要**给出具体到可挑错的一句话/一条边界/一个里程碑定义**，把纠错成本压到最低，逼出真正的修正。受访者改掉的那个字，就是整场访谈最重要的产出。

### P5 · 收束沉淀（让产出可以被复用）
产出三件套，写到同一处：
1. **一句话判断**（愿景）
2. **边界清单**（明确的不做）
3. **首个里程碑定义**（可验收的第一步，含"最笨形态"）
- 给本次访谈打"可复用性标签"：哪些问题最锐利、受访者哪类追问反应最好，记回第 3 节问法库，供下次复用。

## 4. 可迁移的提问技法（脱离任何领域都成立）

| 技法 | 一句话描述 | 何时用 |
|---|---|---|
| 第一性下钻 | 把形容词逼成可画出的行为 | P1 听到愿景词时 |
| 反例/边界卡 | 用"不做/不是谁"测试定位真伪 | P2 |
| 机制五要素下钻 | 触发→动作→反馈→回报→退出逐条确认 | P3 |
| 给名词装动词 | 每个抽象名词追问它的动作来源 | P3 |
| 代拟确认 | 给出具体到可挑错的话让人改 | P4，访谈核心 |
| 最笨形态还原 | 问"最笨但能跑的初版" | P3/P5，防过度设计 |

## 5. 填空式问法库（下次直接照抄重跑）

> 使用时：把方括号替换为本次主题，逐条推进，受访者每确认一条，勾掉一条。**不要跳阶段。**

```
P0 题目：________________（一句话要谈透的产品判断）
P0 受访者：____________ / 预计长度：___ min
P0 已知假设：[预先写下的我猜他会怎么说]

P1 最根本解决的问题是：______
P1 用户不再回到的旧方式是：______
P1 一句话定位是：______
P2 明确不做的是：______；为什么：______
P2 一定不是的用户是：______
P2 什么情况会砍核心功能：______
P3 首次使用第一步→第二步：______ / ______
P3 用户第3天回来的机制：______
P3 这个机制的最笨可跑形态：______
P4 代拟①"产品要先__，核心用户__，第一步__"→受访者改：______
P4 代拟②边界"P2不做__"→受访者改：______
P4 代拟③里程碑"验收=__"→受访者改：______
P5 一句话判断：______
P5 边界清单：______
P5 首个里程碑（最笨形态）：______
P5 本次最锐利的问题（记回第4节）：______
```

## 6. 最小示例（看一张跑完的表长什么样）

```
P4 代拟①：我说"产品要先做知识库，核心用户是学生，第一步是导入资料"
受访者改：'不是导入资料，核心用户不是"学生"而是"备考再来的人"——
          第一步是让他告诉系统他缺哪块，而不是导入。'
→ 整场判断由此翻转：从"工具型"改为"诊断型"。改掉的那个词就是最大产出。
```

## 7. 本方法自身的可复用性快评（诚实自评）

- **已验证**：问法库可直接照抄重跑；阶段顺序不依赖具体领域（P1-P5 的动词链可迁移到课程、文档、调研等同构场景）。
- **未验证**：未在真实第二场访谈中跑通过（无受访者）。"P4 代拟确认是否必然逼出修正"这一课在外人=受访者时假设成立，尚未实证。
- **已知缺失**：没有"受访者抗拒/沉默时如何继续"的兜底话术——若被考察的复用场景双方都很健谈，此缺失可接受，否则需补一节。
