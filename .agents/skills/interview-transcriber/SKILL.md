# Interview Transcriber（访谈现场记录）

## 角色与边界

本技能服务 `interview-workflow` Phase 3，是现场记录岗位，不是采访主持、调查、报告撰写或质检岗位。

长论证的通用定义、证据层级和推理边界以主技能方法学为准：
`../interview-workflow/references/reasoning-methodology.md`。
本技能只引用并执行与现场转写有关的部分，不复制或替代主技能方法学；该引用文件缺失、版本不明或与主技能指令冲突时，暂停相关写入并回报主技能。

负责：

- 将主技能提供的、已经达成共识且获准写入的原问答写入 `02_访谈记录.md`；
- 以问题推进顺序组织记录，保留可见的事实、观点、理由、例证、限定、反例、犹豫、自我修正和状态变化；长论证不得丢失“主张 → 依据/理由 → 推理链 → 结论”的可见链条；
- 为每个问题单元补齐确认状态、原始定位与记录授权；
- 按主技能已判定的六态填写状态，不自行升级状态。

不负责：

- 不重新采访、不追问、不替受访者作最终决定；
- 不修改原始未删减底稿；
- 不把待确认、待验证或采访者代拟写成用户结论；
- 不把长论述压缩成摘要、要点或新的产品判断；
- 不越过主技能的记录授权门控，不擅自写入尚未获准的内容。

记录是“已获准写入的现场证据层”，不是原始底稿的替代品，也不是最终报告。报告只能以记录为内容证据源。

## 全量先于局部：每次增量写入前的硬门控

凡是新增记录、修正既有记录，或处理任何记录增量，第一步都必须读取并核对**整份** `02_访谈记录.md`；不得只读主技能点名的问题单元。目标文件不存在时，先核对将要采用的完整模板，再进入首个写入批次。

全量核对至少覆盖：

- 所有问题单元是否完整，`## 阶段` → `### 问题` 层级和问题推进顺序是否清楚；
- 原有论证结构是否仍可见，长论证是否被压缩、拆散或横向扁平化；
- 前提、条件/限定、反例、证据等级、修正链和未决项是否保留；
- 六态、记录授权、原始定位、记录变更和三态回溯字段是否齐全；
- 重复、冲突、版本边界，以及早期表述被后续修正时的可见性。

先输出核对结论，再处理局部请求。问题按“结构缺失 / 保真疑点 / 状态问题 / 授权问题 / 定位问题 / 重复或冲突 / 版本边界”分类，并区分**阻塞**与**可安全修正**。可安全修正的内容只能在本次授权范围内做最小定点修复；会扩大授权、改变用户含义或无法确认来源的内容不得猜测、覆盖或顺手整理，须先回报主技能。局部请求不得成为跳过全量核对的理由。

确定性结构检查可使用 `scripts/record_gate.py --full <02访谈记录.md>`；它只能辅助发现结构、字段、重复定位和版本边界问题，不能替代对长论证、授权和三态回溯的人工语义核对。

## 调用输入与输出

主技能派遣本技能时，应提供：

- 访谈目录及目标 `02_访谈记录.md` 路径；
- 本次待写入的阶段、问题单元和现场原问答缓冲；
- 主技能已判定的确认状态；
- 每个单元的原始定位（消息编号、段落锚点、相对路径或链接）；
- 用户允许写入的范围、保密/不记录标记和本次增量版本；
- 若存在争议，争议点、冲突来源和停止条件。

输出为目标 `02_访谈记录.md` 的最小增量，至少包含每个问题的：

```markdown
### 问题 N-M：<主题>
**问题**：<最小必要整理，保留语境与回答要求>
**回应**：<可见原问答的完整论述；代拟另行显式标注>
**确认状态**：[六态之一]
**原始定位**：<可回溯定位>
**记录授权**：<谁在何时/哪轮允许写入，以及范围>
```

如果输入缺少授权、回应、状态或定位，先返回阻塞/待补字段，不用猜测补齐，也不应伪造记录。

## 写入流程

1. **全量先行**：按“全量先于局部”完成整份记录的健康核对并回报分类结果；存在未能安全处理的全局阻塞时，暂停相关写入。
2. **确认范围**：读取共享契约；确认目标文件、阶段、增量版本与本次授权范围。目标不存在时沿用主技能模板，不另造 schema。
3. **分离材料**：区分受访者原答、采访者复述、采访者代拟、后续修正和未决内容；不把不同来源拼成无标签的“用户回应”。
3. **选择转写粒度**：完整的一问一答整体转写；同一问题的多轮回答只有在主题连续且顺序、状态和定位仍可见时才合并。
4. **保真转写**：只做明显错别字、标点、断句、格式和最小连接语修正；保留原论述顺序、限定词和状态变化。
5. **写入门控字段**：为每个单元填写问题、回应、确认状态、原始定位、记录授权；回应中显式保留推理链、限定、反例和修正链，待确认/待验证另列清单。
6. **冲突处理**：发现定位冲突、授权范围冲突、同一问题状态冲突或后续修正时，保留可见的早期表述并标 `[已被修正]`，将后续表述单列；无法判断时停止写入该单元并回报主技能。
7. **增量收束**：只追加或定点更新本次授权范围，更新“记录变更”；不重排既有阶段，不静默覆盖用户已确认记录。
8. **交回门控**：回报新增单元、未写入项、冲突及验证结果，由主技能向用户展示增量并取得阶段确认。

## 转写规则

### 单轮完整问答

一次问答已经完整、语义无缺且获准记录时，可作为一个问题单元全量转写。问题只做最小整理，回应保留全部可见论述，不把它改造成摘要或结论。原答中的“可能”“我认为”“暂时”“但前提是”等限定词必须保留。

### 多轮同题合并

同一问题经过多轮长问答时，可以合并成一个连贯单元，但只在以下条件同时满足时进行：

- 每轮确实围绕同一问题，合并不会改变问题边界；
- 原始顺序仍能读出，必要时使用“第一轮回应”“随后补充”“后续修正”等小标签；
- 理由、事实、例证、限定、反例、犹豫、自我修正和状态变化全部保留；
- 每轮或每个可辨识段落仍有可回溯定位；
- 记录授权覆盖全部被合并内容。

不能因为重复、篇幅长或结论相似而删除长论述。若合并会掩盖观点演进，应拆成多个问题单元或在同一单元内分轮保留。

### 推理链、限定与未决项

长论证按原有顺序保留至少以下可辨识内容：主张、依据或理由、从依据到结论的推理链、限定条件、反例或失败路径，以及未决项。原文未明确某一环时，写“原答未说明”，不得由记录者补造；这些字段是保真边界，不是要求受访者现场补答。

观点发生变化时，保留“早期表述 → 触发的补充/反例 → 后续修正 → 当前状态”的修正链；不得只保留最终句。未决项必须同时说明其状态（`[待确认]` 或 `[待验证]`）、缺口和影响，不能藏在总结性措辞中。

### 代拟与状态

采访者代拟必须显式写出“采访者代拟”或“按受访者既有立场拟的草稿”，并标 `[专业建议·代拟]`；“请为我作答”只代表允许代拟，不代表用户确认。用户明确确认代拟内容后，才可按主技能证据改标 `[确认采纳]`，并记录确认定位。六态仅限：

- `[用户明确判断]`
- `[确认采纳]`
- `[专业建议·代拟]`
- `[已被修正]`
- `[待确认]`
- `[待验证]`

同一单元可在正文中保留多个阶段状态，但单元的当前状态必须清楚；早期被修正内容不得删除或伪装成从未出现。

### 定位与授权

原始定位使用稳定、可复核的最小地址，例如 `原始底稿.md#消息-051`、`消息 051-053`、相对路径加段落锚点。不能用“见上文”“本轮”这类不可复核表述替代定位。

记录授权写明授权者、授权时点/轮次、覆盖范围，以及保密或不记录边界。标记为保密、不记录、超出本次授权或无法确认授权的内容不进入记录；在回报中指出未写入原因即可。

## 配套结构导航（渐进披露）

- `references/recording-rules.md`：开始转写前读取；查阅全量转写、多轮合并、授权、定位、版本和冲突细则。
- `assets/templates/02_访谈记录.md`：目标文件不存在或需要新阶段脚手架时使用；字段与主技能 `artifact-schemas.md` 对齐。
- `examples/02_访谈记录.example.md`：不确定代拟、修正或多轮保真写法时对照；内容全部虚构，不作为产品事实。
- `examples/02_全量核对示意.example.md`：演示“局部请求先触发全量核对、分类修正或阻塞”的流程；内容虚构。
- `scripts/record_gate.py`：做确定性结构/健康门禁（`--full` 全量扫描：单元与字段完整、六态、重复定位/冲突、版本边界、待确认/待验证段落），写入前后均可运行；它不替代主技能对保真、授权和语义状态的人工核验。

只在需要时读取配套文件，避免把模板或示例中的虚构内容当成当前访谈材料。

## 增量与冲突记录格式

每次写入都在文末“记录变更”中说明：

- 版本或增量编号；
- 新增/修订的问题单元及原始范围；
- 本次记录授权及未写入内容；
- 用户确认状态；
- 冲突、待补定位或待补授权。

全量核对发现的问题还须在交回主技能时按以下分类报告：

- **结构缺失**：问题单元、阶段层级或必填字段不完整；
- **保真疑点**：论证可能被压缩、拆散，或限定/反例/修正链不可见；
- **状态问题**：六态缺失、错标或有升级迹象；
- **授权问题**：写入范围、保密边界或授权依据不足；
- **定位问题**：原始定位为空、不稳定或覆盖不全；
- **重复或冲突**：重复问题、重复定位、来源/状态/授权互相冲突；
- **版本边界**：记录变更无法说明增量、覆盖关系或修正关系。

每类注明“可安全修正 / 阻塞待裁决”。安全修正仅限本次授权的定点字段，不得借机重排全文件、删除早期表述或扩大写入范围；阻塞项保留原文、停止受影响单元并交主技能裁决。

不能用整文件重写掩盖增量差异。若同一问题的新回应改变旧判断，旧回应保留并标 `[已被修正]`，新回应按证据填写当前状态；若谁的表述具有更高权威无法确定，暂停该单元并交主技能裁决。

## 完成自检

交回主技能前逐项检查：

- [ ] 本次写入前已对整份记录做全量健康核对，并回报了分类结论。
- [ ] 每个独立问题都有问题、回应、确认状态、原始定位和记录授权。
- [ ] 每个回应均在授权范围内；保密/不记录内容未写入。
- [ ] 六态拼写准确，未把沉默、代拟、可能或待验证升级为确认。
- [ ] 单轮问答未压缩；多轮合并未删去推理、例证、限定、反例或修正；全量核对发现的压缩/扁平化问题已按边界处理。
- [ ] 被修正的早期表述仍可见，观点演进和顺序可读。
- [ ] 代拟明确标注，不冒充用户原话或用户结论。
- [ ] 每个单元能回到原始消息、段落或路径；没有空定位。
- [ ] “待确认与待验证”和“记录变更”已更新。
- [ ] 已运行 `python3 scripts/record_gate.py --full <02_访谈记录.md>`；脚本结果与人工语义核验分别报告。

本技能不运行完整 skill eval；本目录的脚本自检仅验证结构，不代表访谈内容已经被用户确认或产品已经验证。
