# 取证细则（Due Diligence Guide）

本文件承载取证专业化的操作细节。本技能核心是**只读、可复核、分层**：不把材料当结论，不把推断当事实，不把历史当现状。

**方法学引用**：凡涉及调查推理、长论证编排或交接，先读主技能 [`../../interview-workflow/references/reasoning-methodology.md`](../../interview-workflow/references/reasoning-methodology.md)。本细则只承接其在“只读取证”下的落地映射，不复制全文。

## 一、分区与并行

- 大范围按**来源类型**（仓库/文档/外部/代码）或**材料区间**（版本、目录、阶段）切分区。
- 每个分区只由一个子代理负责；每个子代理记录自己读了哪些路径、哪些没读及原因。
- 汇总时若两个分区结论冲突，先核对各自来源再报告，不擅自仲裁。

## 二、来源定位与状态

每条观察必须能定位：`路径/URL + 章节/行号/消息号 + 时间/版本 + 权限`。无法定位的内容不得写成证据。材料状态分：

| 状态 | 含义 | 能不能写成当前事实 |
|---|---|---|
| 现状材料 | 有依据反映当前，但仍未获用户确认 | 不能直接升级 |
| 历史材料 | 过去阶段记录 | 不能代表现在 |
| 候选/研究 | 可能方案或外部研究 | 不能成为决定 |
| 待核验 | 来源不足/冲突/须确认 | 必须留清单 |
| 来源事实 | 可直接从来源定位到 | 可引用，但不等同“现实已证明” |

## 三、事实/判断/推断分层

- **来源事实**：可直接定位到来源的文字、代码、状态。
- **来源观点**：材料作者的主张，需标明作者，不转成用户立场。
- **调查推断**：调查者基于证据的推理，必须写依据，用“推断”语气。
- **缺口/冲突**：来源缺失、互相矛盾或时间线断裂，单独列出。

证据等级与主方法学一致（事实/来源判断/推断/待验证 各归各位）；本技能把“待验证”落到“待核验”并另行标注材料状态，二者互补不冲突。

原则：宁可写“未获来源支持”，也不把推断补成结论；宁可保留空白，也不用外部臆测填洞。

## 四、外部资料与联网边界

- 只有主技能明确授权联网/读外部资料才使用；未授权则标为待核验。
- 外部信息必须记录来源 URL 和获取时间；临时网页、不可复现内容降级为弱证据。
- 外部研究与候选方案一律标为 `[候选/研究]`，不并入产品决定。

### 取证场景 → 专技绑定（承接主技能 §14 绑定表）

按取证来源与任务类型固定绑定专项技能；**未获外部来源授权（主技能 00 调查授权权限项）时不发任何外部取证、也不调用下列外部专技**，仅限仓库内只读取证场景不绑定：

| 取证场景 | 固定绑定 | 能力定位 |
|---|---|---|
| 全域搜索、背景摸排、多平台/多渠道、海量筛查 | `agent-reach` | 广度、无死角 |
| 核心事实核实、专业考据、逻辑溯源、深度论证 | `research` | 精度、核实、可信 |
| 网页/在线文档/列表/可视化内容的实时结构化采集 | `playwright-cli` | 结构化、完整、可复现、可溯源 |

绑定专技在取证前按场景确定；其输出同样纳入来源 schema 登记（来源 ID/类型/版本/获取时间/权限/访问状态/证据等级）与待核验清单。缺口项 → 报告阻塞，不越权自行外部取证。

## 五、问题候选的纪律

- 问题必须来自**证据缺口、冲突或待核验项**，不把“标准答案”塞进问题。
- 区分“材料写了什么”与“现实是什么”，两者不一致时是最高价值的访谈切入点。

## 六、收尾检查

1. 每条结论可定位？状态标了？
2. 推断是否带依据、未冒充事实？
3. 历史/候选是否被误升级？
4. 冲突与缺口是否全部进入待核验清单？
5. 是否未修改来源、未越过主技能推进正式访谈？

### 长论证保真（引用主方法学）

来源含长论述/推理时，按主方法学保真底线执行：保留前提、条件与限定、反例/例外、依据、修正链和未决项；不做最小改写之外的压缩，不补模型隐藏推理，不把“可能/我认为/待验证”升级为事实。详见主方法学相应小节。
