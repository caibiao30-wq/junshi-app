# 记录到报告的正式化规则

本规则服务 `interview-workflow` Phase 4。访谈记录是最原始的构思草稿与现场层；访谈报告是可直接投入正式使用的成文稿。写作原则是**正式文档表达 + 最大保真最小改写**：报告必须采用完整、连续的叙述，不得以摘要、提纲或誊抄替代正文。

## 1. 输入、证据链与停机

- 唯一内容证据是同一访谈目录下的 `02_访谈记录.md`；报告文件头必须明确写出该文件名或路径。
- 证据链为：`01 调查取证 → 专业过滤/代拟 → 02 访谈记录（内容证据层）→ 03 正式报告`。报告不绕过 02 新增内容。
- `00_访谈约定.md`、`01_调查取证.md`、原始底稿和其他材料只能帮助理解范围或定位，不能作为新增事实依据；报告自身不能自证。
- `02_访谈记录.md` 缺失、回应缺失、原始定位为空，或状态冲突无法解释时，停止写作并回报主技能；不得回到底稿补写，也不得静默跳过。
- 记录不足以支撑正式表述时，不猜测，保留原有信息并标为 `[待确认]` 或 `[待验证]`，同时进入对应清单。

## 2. 正式表达与最小改写

改写以实现语义保真为准，而非逐字誊抄。允许做专业性、正式性、文档级改写：将口语正式叙述化，优化句式、段落、标题和衔接，修正错别字、标点、断句与 Markdown，统一术语，并为独立阅读补足不改变含义的连接语；允许删除纯口头赘词、机械重复和不增加信息的表达，允许在不改变原意与论证关系的前提下重组句子/段落、适度压缩。可调整章节层级或合并同义重复内容，前提是不改变原意且可逐项回溯。

不得把“正式化”理解为压缩、摘要或自由改写。不得删除、缩减或重组到损失任何事实、理由、例证、限定、反例、失败路径、犹豫、自我修正、关键逻辑依据、确认内容或未决项。不得新增推断、产品能力、用户事实、工程实现或因果解释。

## 3. 长论证的完整保留

每条长回应先完整把握原始含义和论证关系，再做正式书面化。可删除纯口头赘词、机械重复和不增加信息的表达，可合并同义内容、重组句子或段落、适度压缩，但正文必须仍然是连续、完整的论述。逐项核对并保留关键事实、确认内容、逻辑依据、前提、条件与限定、反例与例外、证据等级、修正链和未决项。事实、来源判断、推断和待验证各自标明；推断及产品机制不能自证。早期表述及后续修正均保留，早期内容标 `[已被修正]`。记录未提供某项时写“记录未提供”，不补造。摘要、总览、结论或表格不能替代长论述本身；正文不能退化为字段串。

## 4. 状态、确认与代拟

使用共享七态判据，按证据填写，不自行升级：`[用户明确判断]`、`[确认采纳]`、`[专业建议·代拟]`、`[已被修正]`、`[待确认]`、`[待验证]`及共享判据规定的其他状态。

- 已确认项写结论及依据，并保留原有限定。
- `[专业建议·代拟]` 明确不是用户观点；“请为我作答”只授权代拟。
- `[待确认]` 强制写明未确认原因、影响范围、后续处理要求，并回溯到具体记录。
- `[待验证]` 写明需要何种运行、样本、反馈或长期实践、影响范围及处理要求。
- 用户沉默不等于确认；确认只覆盖用户明确指向的内容；状态不确定时取更保守状态。

## 5. 章节、目录与正文

章 = 02 中实际发生且有真实内容的阶段，节 = 有回应的问题。采用正式格式：`第 1 章：实际阶段名`、`1-1 正式问题标题`。阶段可增加、合并、跳过或回退；只影响实际章名，不取消编号格式。不得生成空章或空节。

总目录必须与正文一致，列出所有真实章、节和文末区块。每节包含标准化问题、完整回应与论证、节内确认状态、记录定位；标题下直接接正文。状态、来源注记、记录定位和回溯索引放在节尾或文末，避免打断文章。阶段字段若记录提供则完整保留，未提供则写“记录未提供”，不补齐。

## 6. 结论边界与回溯

结论总览只负责导航，不能替正文。正文之后分别汇总已确认、专业暂定、待确认、待验证；待确认和待验证另列清单。每个问题单元形成：`报告位置 → 02_访谈记录.md 中的问题/段落 → 原始底稿消息、路径或锚点`。记录未提供原始定位时，明确写“记录未提供原始底稿定位”，不补造。

## 7. 交付核对

逐段核对内容、顺序、事实、确认、逻辑、限定、反例、修正链和未决项。Markdown 静态检查只能验证格式，不能证明语义保真；报告稿交由主技能或 `interview-qc` 做最终集成与定稿判定。
