# Interview QC（访谈质检·辅技能）

## 本技能是什么

访谈工作流的**质检与集成专业岗位**，服务 Phase 4 定稿前后。它不亲自写访谈记录或报告，而是作为独立质检岗核对四个工件（00/01/02/03）之间的结构、状态、证据源、保真与可回溯关系，输出带严重度、证据定位和修复建议的质检报告。

一句话定位：**质检输出是"通过 / 阻塞 / 需人工复核 + 证据定位 + 修复建议"，不是一份新的访谈报告。**

## 调用方式（与主技能的关系）

- **主路径**：由 `interview-workflow` 主技能派子代理优先加载本技能完成后，回传质检结论。
- **降级路径**：主代理直接调用本技能、由主技能亲自逐条核对 02→03 证据链（此时产出一致，只是载体不同）。

本节技能即使未被打包为主技能的子代理，也可独立针对一个访谈目录或 02/03 文件运行校验。

## 质检输入

| 输入 | 说明 |
|---|---|
| 访谈目录 | 含 `00_访谈约定.md` `01_调查取证.md` `02_访谈记录.md` `03_访谈报告.md` 的目录路径 |
| 或 02/03 文件路径 | 只校验记录↔报告的证据与保真，不校验 00/01 |
| 集成后上下文 | 主技能传"由谁改了什么、是否存在代拟/待确认/待验证加持"等背景 |

当拿到目录路径时，也调用 `scripts/qc_run.py` 做确定性启发式核查，再人工逐条核验；拿到 02/03 单路径时，直接核验证据源与保真。

## 质检层级（六层，逐层核对）

**长论证方法学是本技能的外部依据**：逐项质检前读取
`../interview-workflow/references/reasoning-methodology.md`。本技能只引用其保真零件与边界，不复制整套方法学；若该文件尚未存在，记录为阻塞/待补依据，不凭本技能旧文案替代。

1. **结构**：00/01/02/03 是否存在且目录完整（无则阻塞）；报告为正式章/节结构——章=阶段（第一章←阶段0至第六章←阶段5）、节=问题（节号 `章号.问题序`，节标题保留原始问题编号），含总目录、结论总览、结论边界、待确认/待验证清单、回溯索引与附录。
2. **证据**：报告的证据源是否为记录，拒绝自证（报告不以自身或以底稿为证据源，只以 02 为源）。
3. **状态**：待确认/待验证是否被明显升级、被抹除或混入结论。
4. **保真**：长答案是否被压缩、被偷偷总结、或被报告概括替换。
5. **定位**：记录的"原始定位"是否为空；报告能否回溯到记录；三态闭环是否断裂。
6. **长论证保真零件**：前提、条件/限定、反例/例外、证据等级、修正链、未决项是否逐段保留；报告是否把摘要冒充完整论证。
7. **权限/集成**：是否越权改写用户结论；是否静默补齐待确认项；报告是否单列待确认/待验证清单；集成前后口径是否一致。

## 严重度与停止条件

| 严重度 | 含义 | 处置 |
|---|---|---|
| **阻塞** | 结构缺失、证据源断裂、长答案被明显压缩、原始定位为空 | 定稿必须停止，回主技能修复 |
| **严重** | 状态被升级、报告无待确认/待验证清单、记录无原始定位标记 | 修复后再定稿 |
| **一般** | 弱信号、建议、（目录模式下的）00/01 存在性骨架提示 | 参考与提示 |
| **需人工复核** | 超出脚本能力（原文重组顺序、代拟冒充原话、语义保真） | 交主技能/用户做最终语义核验 |

**停止条件**：出现任一阻塞项即停止放行，不再进入后续集成/定稿；严重项与需人工复核项列出后交主技能合并处理。

## 输出格式（质检报告，不是产品报告）

```markdown
## 质检结论
结论：通过 / 阻塞 / 需人工复核    定稿是否可放行：是 / 否 / 待确认

## 分项汇总
- 通过项：<每项 + 一句依据>
- 阻塞项：<每项 + 结构/证据/保真定位>
- 严重项：<每项 + 状态/定位/权限定位>
- 需人工复核项：<每项 + 交由谁、核什么>

## 每项格式
[严重度 · 层级] <文件/定位>
    <发现 + 最小修复建议>
```

**约定**：只给出问题定位与修复建议；不替用户改写、不覆盖任何定稿文件、不改变产品判断。修复由主技能或用户在人工核验后执行。

## 关键判据（复用共享契约）

- **状态不升级**：`[待确认]` / `[待验证]` 不能写成事实；代拟不能伪装成用户原话。七态：`[用户明确判断]` `[确认采纳]` `[专业建议·代拟]` `[已被修正]` `[拒绝]` `[待确认]` `[待验证]`。
- **保真底线**：按主方法学逐段核对前提、条件/限定、反例/例外、证据等级、修正链与未决项；只最小改写、不压缩。不得把长论证改成一句结论、要点清单或摘要，不得删理由/例证/限定/反例/修正，或以报告概括替换记录中的长篇回应。
- **三态可回溯**：`03→02→原始底稿`，任意加工节点带原始定位，拒绝对底稿的自证与改写。
- **报告的证据源是记录，不是报告自身**。
- **代拟边界**：`[专业建议·代拟]` 必须在视觉和语义上与用户原话/判断分开；未获明确确认不得冒充用户观点。
- **机制与推断边界**：产品机制、猜想、推断、待验证不能自证为事实；报告必须保留对应证据等级与限定。

## 口径与集成检查点（报告集成前/后）

**集成前**（建骨架时）：报告是以 02 为唯一内容证据源；章节切块与记录问题单元对应；未擅自引底稿补内容。

**集成后**（定稿前）：长答案未压缩、状态未升级、待确认/待验证单列、每个问题单元都有原始定位、三态可回溯、未越权改用户已确认结论。

## 权限与边界（必须遵守）

- **只读与只建议**：默认只读；只输出"通过/阻塞/需人工复核 + 定位 + 修复建议"。
- **不越权改稿**：不得无授权直接覆盖 00/01/02/03 定稿文件。
- **不替用户做产品判断**：质检发现问题时提出并让主技能/用户决定是否调整；不自行改变产品决策。
- **如实陈述**：区分脚本已核实项与需人工语义复核项；未执行验证就说"未验证"。

## 配套结构导航（渐进披露）

- **scripts/**：`python3 scripts/qc_run.py <访谈目录>` 或 `python3 scripts/qc_run.py <02记录.md> <03报告.md>` —— 确定性启发式综合校验（结构/证据/状态/长论证信号/定位/权限）；有阻塞以非零退出。脚本只做启发式，不替代人工语义核验。
- **主方法学**：`../interview-workflow/references/reasoning-methodology.md` —— 质检依据；只读并引用，不复制。做长论证、摘要/报告、代拟边界核验前读取。
- **references/`qc-checklist.md`**：专业质检清单，按阻塞/严重/一般分级，覆盖结构完整性、证据链、状态一致、保真、定位、权限与人工复核；含报告集成前后检查点。**做逐项人工质检时读。**
- **assets/**：本技能不产生新内容工件，不放产物模板；当前为空是有意规划（见 `assets/README.md`），不读取。
- **examples/**：**不确定质检报告长什么样时对照** `qc-findings.example.md`——虚构示例，标明非产品结论，展示通过项/阻塞项/证据定位/严重度/修复建议/需人工复核项。

## 完成自检

- 是否对 00/01/02/03 的关系（结构/证据/状态/长论证保真/定位/权限）逐层核对？
- 是否按主方法学逐段核对前提、条件/限定、反例/例外、证据等级、修正链、未决项？
- 是否确认代拟未被冒充为用户原话/判断，且未把摘要当成长论证？
- 是否给出"通过/阻塞/需人工复核 + 证据定位 + 修复建议"，且未生产一份新产品报告？
- 是否只建议、未越权覆盖定稿文件、未改变产品判断？
- 状态是否未被升级、待确认/待验证是否单列、三态是否可回溯？
- 是否如实分开了"脚本已核实"与"需主技能/用户人工语义核验"？

**使用本技能时：拿到访谈目录或 02/03 路径，跑 `qc_run.py` 得启发式结果，再按 `qc-checklist.md` 逐项人工核验，输出含严重度与定位的质检结论，交回主技能；任何阻塞项即停止放行。**
