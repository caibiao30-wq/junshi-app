# Interview QC 专业质检清单

> 用途：在 `03_访谈报告.md` 集成前后，核对 `00/01/02/03` 的关系。清单是质检依据，不是产品判断；发现问题只记录定位与建议，不直接改稿。
>
> 依据：先读取 [`../interview-workflow/references/reasoning-methodology.md`](../../interview-workflow/references/reasoning-methodology.md)。本清单只抽取其质检边界，不复制方法学正文。

## 结论规则

- **阻塞**：必须停止定稿，修复并重新质检。
- **严重**：原则上修复后再定稿；若主技能决定保留，必须记录理由与人工确认。
- **一般**：不自动阻止定稿，但要给出建议。
- **需人工复核**：脚本无法判断的语义问题，必须交主技能/用户确认，不能标为脚本通过。

## 一、阻塞项

### A. 结构完整性

- [ ] 访谈目录存在 `00_访谈约定.md`、`01_调查取证.md`、`02_访谈记录.md`、`03_访谈报告.md`。
- [ ] 四个文件属于同一次访谈，未将其他访谈的记录或报告混入。
- [ ] `03` 仅在完整访谈完成后进入定稿；若尚未完成，停止放行。

### B. 证据链

- [ ] `03` 明确声明唯一内容证据源为 `02_访谈记录.md`。
- [ ] 报告中的每个问题单元能定位到 `02` 的对应问题单元。
- [ ] 报告没有以报告自身、外部未列来源或未经批准的底稿作为证据自证。
- [ ] `01` 的材料结论没有被直接当作访谈用户结论；如进入报告，必须能经 `02` 回溯并带状态。

### C. 保真

- [ ] 长篇回应的事实、观点、理由、例证、限定、反例、失败路径、犹豫和自我修正仍可逐段找到。
- [ ] 报告没有用一句结论、要点清单或摘要冒充 `02` 的长篇回应。
- [ ] 每段长论证的前提、条件/限定、反例/例外、证据等级、修正链、未决项仍可逐段找到；缺失任一项列阻塞或需人工复核。
- [ ] 报告没有静默截断长答案；脚本低保留率信号一律列入人工复核，明显压缩列阻塞。
- [ ] 没有补入模型隐藏推理；只保留访谈中可检查的外显内容。

## 二、严重项

### D. 状态一致

- [ ] 七态标记含义一致：`[用户明确判断]`、`[确认采纳]`、`[专业建议·代拟]`、`[已被修正]`、`[拒绝]`、`[待确认]`、`[待验证]`。
- [ ] `[待确认]` 没有在 `03` 变成 `[确认采纳]` 或无状态的确定事实。
- [ ] `[待验证]` 没有被写成已证明、已具备或已完成能力。
- [ ] `[专业建议·代拟]` 没有被改写为用户原话或用户结论；代拟在视觉和语义上清楚隔离。
- [ ] 产品机制、猜想、推断或待验证项没有被自证为事实。
- [ ] 早期观点被修正时，早期文本仍保留并标 `[已被修正]`，后续观点单独标状态。
- [ ] “确认”只覆盖明确指向的内容，没有把同段扩展自动升级。

### E. 定位与回溯

- [ ] `02` 的每个问题单元都有非空的 `原始定位`。
- [ ] `03` 的每个问题单元都有记录定位或回溯索引。
- [ ] 定位不是泛泛的“见上文/见记录”，而是消息编号、段落锚点或相对路径等可复核位置。
- [ ] 定位指向的是原始底稿或 `02` 的真实位置，未因集成改写而失效。

### F. 权限与未决项

- [ ] 报告未越权修改用户已确认的原意。
- [ ] 报告未自行补齐工程细节、服务边界或产品判断。
- [ ] `待确认` 与 `待验证` 均进入报告中的对应清单，未被摘要遮蔽。
- [ ] 质检人只提出修复建议，未直接覆盖定稿文件。

## 三、一般项

- [ ] `03` 为正式章/节结构：含总目录与结论总览；第一章←阶段0、第二章←阶段1、第三章←阶段2、第四章←阶段3、第五章←阶段4、第六章←阶段5。
- [ ] 章节名称、问题编号和阶段导航在 `02` 与 `03` 间一致或有明确映射；章=阶段、节=问题，节号为 `章号.问题序`，节标题保留原始问题编号（如 `3.1 问题 2-1：<主题>`）。
- [ ] `00` 的访谈边界与 `03` 的内容范围没有明显越界。
- [ ] `01` 的“材料状态”与 `03` 中引用的来源状态一致。
- [ ] 重复内容只在完全相同、无新信息且不改变顺序/状态时合并。
- [ ] 术语、状态标签和待办清单标题稳定，便于后续检索。

## 四、需人工复核项

脚本无法可靠判断以下事项，不能仅凭“脚本通过”放行：

- [ ] 报告是否改变了因果关系、论述顺序或语气限定。
- [ ] 代拟与用户原话是否在视觉和语义上清楚分开。
- [ ] 长答案虽保留字数，但理由、反例或自我修正是否被语义性删去。
- [ ] 同一问题多轮合并是否仍保留观点演进与状态变化。
- [ ] 记录定位是否真的指向受访者原始消息，而非后来补写的摘要。
- [ ] 报告是否把 `01` 的调查推断误当成访谈确认。
- [ ] 报告是否把摘要/结论段当成长论证，或遗漏前提、限定、反例、证据等级、修正链、未决项。
- [ ] 代拟是否被视觉或语义上冒充为用户原话/判断。

## 五、集成前检查点

1. 锁定 `02` 版本与问题单元范围，声明其为 `03` 唯一内容证据源。
2. 建立正式章/节骨架：章=阶段（第一章←阶段0至第六章←阶段5），节=问题；节号采用 `章号.问题序`，节标题保留原始问题编号。
3. 确认报告含**总目录**与**结论总览**（结论总览置于正文前），且总目录所列章节能在正文找到。
4. 将报告章节映射到记录问题单元，先标出无法映射的章节；不得编造空章正文。
5. 建立双层状态：每节保留具体确认状态，文末以结论边界、待确认清单、待验证清单汇总；禁止静默升级或抹除。
6. 对长答案保留原段与定位，不以摘要先行替代记录。
7. 运行：

   ```bash
   python3 scripts/qc_run.py <访谈目录>
   ```

8. 将脚本发现转成带定位的人工复核项；阻塞项不放行。

## 六、集成后/定稿前检查点

- [ ] `03` 的证据源仍是 `02`，没有新增自证来源。
- [ ] 报告保留总目录、结论总览，且目录章节均可在正文定位。
- [ ] 第一章至第六章分别对应阶段0至阶段5；每节对应问题，节号为 `章号.问题序`，标题保留原始问题编号。
- [ ] 正文没有编造空章；每个章/节均能回到 `02` 的问题单元。
- [ ] 每章、每个问题单元、每个状态表项均能回到 `02`。
- [ ] 双层状态一致：节内具体状态与文末结论边界、待确认清单、待验证清单一致，未升级、未抹除。
- [ ] 七态没有丢失或升级，待确认/待验证清单仍存在。
- [ ] 文末含结论边界、待确认清单、待验证清单、回溯索引及附录（状态与代拟说明）。
- [ ] 长答案通过逐段保真审查，而不只看启发式保留率；逐项核对前提、条件/限定、反例/例外、证据等级、修正链、未决项。
- [ ] 报告未将摘要或结论冒充长论证，代拟未被冒充为用户判断。
- [ ] 所有 `原始定位` 与记录定位非空且可复核。
- [ ] 没有未经授权的文件覆盖或产品判断改变。
- [ ] 结论写明：通过/阻塞/需人工复核、定稿是否放行、未验证边界。

## 七、重检触发条件

发生以下任一变化后，应重新运行脚本并重复人工清单：

- `02` 新增、删除、合并或修正问题单元；
- `03` 改动章节、状态表、长答案或待确认/待验证清单；
- 任何人补入外部来源、调查结论或新的代拟内容；
- 原始底稿路径、消息编号或段落锚点发生变化。
