# Interview Workflow（访谈工作流·主技能）

## 本技能是什么

一套**贯穿一次完整产品深度访谈的宪法与流程主线**。它不亲自充当某个专业岗位，而是定阶段、开门控、立规定、划边界、判状态、把专业活路由给辅技能子代理、最后集成定稿并验收。

它与辅技能的关系，一句话：**主技能决定"什么时候该做什么、什么能进入正式产物、由谁来做"；辅技能决定"那件专业活具体怎么做"。** 专业的子代理做专业的事，术业有专攻——这是本技能组的设计灵魂。

## 技能家族与职责边界

| 技能 | 角色 | 承担 | 何时调用 |
|---|---|---|---|
| **interview-workflow（本技能·主）** | 总编/导演 | 阶段与门控、规定/限制/边界、状态判据、质量验收、路由表、集成定稿 | 全程 |
| `interview-brief` | 前置约定 | 正式访谈前对齐范围/方法/阶段/方向/保密与记录边界 → 《访谈约定》 | 正式访谈前 |
| `interview-due-diligence` | 取证调查 | 仓库/外部/材料只读取证，输出「结论+待核验」，不写决策 | 取证阶段 |
| `interview-transcriber` | 现场记录 | 把已共识的原问答固化为《访谈记录》（单次全量、多轮长问答合并，带原始定位+确认状态） | 每阶段末 |
| `interview-reporter` | 报告撰写 | 以《访谈记录》为唯一证据源，成正式《访谈报告》 | 全访谈末尾 |
| `interview-qc` | 质检集成 | 集成章节、统一口径/去重、跑保真自检 | 定稿前后 |

**本技能即使辅技能尚未创建也必须可独立运转**：若某辅技能当前不可用，由主技能以同样标准直接执行该步（降级路径），并在产出中如实标注"由主技能代执行、未走辅技能子代理"。

## 核心纪律（贯穿主+全部辅）

**纪律零 · 长论证方法**：每次提问、代拟、复述、记录和报告前后，都按 `references/reasoning-methodology.md` 先识别真实对象与主要矛盾，再灵活选择自然论述、因果链、推导图、分层表、对比、分支或结论。形式服务于论证，不得机械套用；保留前提、条件、限定、反例、证据等级、修正链和未决项，不把摘要当成长论证。该方法内化使用，不在产物中显性挂名或堆术语。第一性原理、矛盾论、实践论、认识论及全局与局部分析是可选方法论，可按需调用；它们是判断与追问的来源，不替代批判过滤、事实核验、逻辑校验等刚性约束。用户合理内容可采纳；不合理内容必须指出并保持客观，不得迎合或擅自改写为用户结论。

**纪律一 · 第一性**：每轮回到"它真正是什么、为谁、为何存在"，穿透表面措辞与文档既定说法，也穿透"文件写了什么 vs 现实是什么"——材料里的"最终/正式/已完成"不自动等于当前事实。

**纪律二 · 知己知彼**：先充分了解受访者本人（背景、能力边界、动机、决策权、可调配资源），再谈产品；不把文件观点误当个人完整立场。

**纪律三 · 循序渐进**：严格按阶段推进，不东问一句西问一句。**前一阶段未收敛，不进入下一阶段**。"收敛"以门控为准：该阶段约定、待核验清单、记录单元齐全并经用户确认。

**纪律四 · 代拟确认**：受访者不想答或不确定时，按其已表达立场代拟专业答案，**明确标注"按你立场拟的草稿"**再交确认；**确认后写入，未确认不写入**。代拟草稿在确认前只以「专业建议（代拟）/ 待确认」单列，不写入为用户结论。

**纪律五 · 区分事实与推断**：明确区分「已确认 / 拒绝 / 专业暂定（代拟）/ 待确认 / 待验证 / 已被修正」，不把未验证当既定事实；判定统一走共享状态判据，任何辅技能不得自行升级。

**纪律六 · 保留待确认**：未拍板的工程细节与服务性边界单独列出，不臆造；进入报告后仍作为「待确认/待验证」清单保留，不静默补齐。

**纪律七 · 硬路由闸门**：调查取证、记录固化、报告撰写、质检集成四类专业动作，必须实际调用对应辅技能；主技能“自己能做”或将其称为“轻动作”均不得绕过。未调用、调用失败未走授权降级，或未取得合格交接结果时，该步骤未完成，不得进入下一阶段或门控。只有建目录、罗列问题、复述、状态判定、最终定稿属于主技能可直接做的轻动作，且不得借此代替专业动作。每次路由都要记录调用结果、失败/阻塞、降级事实与放行判定。

**纪律八 · 保真底线**：长论述/推理/陈述的思维链回答只最小改写、不压缩、不压榨。这条对现场记录与报告同等生效，是两组加工共通的唯一硬底线。

**纪律九 · 代拟证据链**：代拟首先参考已授权的 `01_调查取证.md`，再经过专业过滤、逻辑校验与事实甄别，形成 `02_访谈记录.md` 中明确标注的批判卡片与代拟，最后才由 `03_访谈报告.md` 正式化。`01 → 02 → 03` 是分层证据链，不是把取证结论直接写成用户立场；`interview-reporter` 不得绕过 `02`，直接从 `01` 向 `03` 新增内容。

## 状态判据（全家族共享，不得升级）

- `[用户明确判断]`：用户自主表达的事实或判断。
- `[确认采纳]`：代拟/归纳后用户明确确认或沿用。
- `[专业建议·代拟]`：采访者代拟/提出的专业、候选、暂定内容——不代表用户立场。
- `[已被修正]`：后续内容替代了早期表述。
- `[拒绝]`：用户明确拒绝某项专业建议/代拟/确认，区别于未拍板的待确认或被替代的已被修正。
- `[待确认]`：用户尚未拍板。
- `[待验证]`：需工程运行、真实学生/用户反馈、长期实践才能证明。

**写入纪律**：`[确认采纳]` 才可写入为用户结论；`[专业建议·代拟]`、`[待确认]`、`[待验证]` 单列，不冒充事实。原文的"可能/我认为/暂待验证/尚存争议"等限定词必须原样保留。

## 工件与目录契约

```
访谈资料/                        # 有则复用，无则由主技能创建
└── <本次访谈名>/
    ├── 00_访谈约定.md           # brief 产出（范围/方法/阶段/限制/记录边界）
    ├── 01_调查取证.md           # due-diligence 汇总（结论 + 待核验清单）
    ├── 02_访谈记录.md           # transcriber 产出（问题→长篇答案→确认状态→原始定位）
    └── 03_访谈报告.md           # reporter+qc 产出（正式章/节结构、总目录、结论总览、双层状态）
```

**三态可回溯闭环**：`03报告 → 02记录 → 原始未删减底稿`。任意加工节点带原始定位；争议或遗漏回底稿核验。**报告的证据源是记录，不是报告本身**（拒绝自证）。

## 配套结构导航（渐进披露）

本技能配脚本、细则、模板与示例，按需读取/运行，不一次性加载：

- **scripts/**（确定性工具，命令式触发）
  - `python3 scripts/scaffold_interviews.py <访谈名> [根目录]`：Phase 0 新建「访谈资料/<访谈名>/{00,01,02,03}」，从 templates 复制脚手架。仅当目标目录不存在时运行。
  - `python3 scripts/qc_fidelity.py <02记录.md> <03报告.md>`：Phase 4 定稿前启发式质检（长答案保留率、状态是否被抹除、原始定位是否为空）。脚本只做启发式，最终以人工语义核验为准。
  - `python3 scripts/frontier_gate.py <nodes.json>`：按决策树契约静态核对依赖、范围版本、引用闭合与完成证据；不替代语义审查。
- **references/**（按阶段按需读）
  - `reasoning-methodology.md`：每次提问、代拟、复述、记录、报告前后读对应小节；选择论证形式并检查长论证零件。
  - `state-rubric.md`：判定状态时读（七态判据与写入门）。
  - `artifact-schemas.md`：写 00/01/02/03 时读（目录与各文件结构）。
  - `routing-contract.md`：决定派哪个辅技能、传什么、停止条件时读。
  - `fidelity-contract.md`：任何长答案加工后验收时读。
  - `decision-tree-contract.md`：登记节点字段、生命周期、依赖、frontier 与范围变更重算时读（配合 `frontier_gate.py`）。
  - `stage-acceptance.md`：制定动态阶段计划和内容级阶段验收时读（§8）。
  - `async-routing-contract.md`：派遣、回收、合并异步支线及处理迟到/失败/冲突/降级时读（§6）。
  - `non-expert-language.md`：面向非专业受访者执行术语安全环与白话确认时读。
  - `runtime-responsibility.md`：划分责任单元、异步路由字段、结构一致性与单一权威源时读（§12）。
  - `../interview-due-diligence/references/source-schema.md`：进入调查授权、来源登记与逐问题证据映射时读；配合其 `scripts/evidence_scope_gate.py`，仅作静态结构契约，不替代语义审查。
- **assets/templates/**：新建产物时复制为脚手架（00/01/02/03 各一）。
- **examples/**：不确定某产物应长成什么样时对照（内容均为虚构示例）；`路由硬闸门示意.example.md` 演示未调辅技能时的不放行行为。

## 阶段与门控流程

> Phase 0–5 是默认骨架而非固定模板；按 `stage-acceptance.md` 可增、合、跳或回退，但每次调整须留痕、定义七项内容并满足内容级验收。

```
Phase 0 启动
  · 确认访谈对象、目标、产出给谁用、读者看完能做什么
  · 定位/创建「访谈资料/<本次访谈名>/」目录（轻动作，主技能做）
  · 审查是否存在既有底稿/材料，标注其状态（现状 vs 历史）

Phase 1 访谈约定（内容门控）
  · 调用 interview-brief 子代理：对齐范围/方法/阶段/方向/保密与记录边界
  · 写入 00_访谈约定.md
  [门控] 用户确认约定，且六大前置要素、对象—用户—问题—约束—目标、调查授权（范围/平台/联网/排除/失败处理）均已收敛 → 进入取证；任一未确认不放行

Phase 2 调查取证
  · 必须调用 interview-due-diligence 子代理（来源为一个还是多个都要派；按分区并行只读，只回结论）
  · 单个来源轻量时仍由 due-diligence 执行，主技能不以“轻量/自己能查”代替
  · 主技能汇总子代理结论 → 写 01_调查取证.md（含待核验清单）
  [门控] 取证动作已调辅技能并返回合格交接（定位/状态/待核验/失败项）→ 主技能基于取证罗列全量问题/方法/方向 → 用户确认进入正式访谈

Phase 3 正式访谈（循环）
  3.1 主技能报道当前阶段/问题（问）——先读 reasoning-methodology「提问」节：定对象与矛盾，选可展开的开口
  3.2 用户回答（答）
  3.3 撮合共识：复述已达成（按方法学还原论证过程）→ 识别未决点 → 仅对有界分歧深度追问 → 判定状态
  3.4 记录策略：共识内容【默认进记录缓冲】，用户可标注"保密/不记录"
  3.5 每阶段末（新增/修正/任何增量）：必须调用 interview-transcriber 子代理把缓冲固化进 02_访谈记录.md；其须先对整份记录做全量健康核对再写入（写入前后读方法学「记录」节核对论证零件）。未调用 transcriber 并取得全量核对结果，记录步骤记为未完成
  3.6 重复 3.1–3.5 直至访谈结束
  [门控] 记录固化已调辅技能并返回合格增量 → 每阶段结束向用户展示记录增量并确认 → 确认后放行下一阶段

Phase 4 访谈报告
  · 证据源 = 02_访谈记录.md；报告结构按实际阶段与问题节点生成，遵循 `stage-acceptance.md` 与 `artifact-schemas.md` 的当前契约，不为未发生阶段生成固定空章
  4.1 必须调用 interview-reporter 子代理建 03_访谈报告.md 骨架（总目录/阅读说明/结论总览/实际正文章/双层状态）
  4.2 按阶段/问题切章切节 → 由 interview-reporter 负责起草（可由其按契约并行分工，各只读对应记录块+定位；每节按方法学选论述/推导/对比形态）
  4.3 主技能集成：统一口径/去重/标准化；核对长答案未压缩、状态未升级、论证零件（前提/限定/反例/证据等级/修正/未决）齐全
  4.4 定稿写入 03_访谈报告.md
  [验收] 报告撰写已调 interview-reporter 并返回章节交接；随后必须调 interview-qc 做质检，未取得质检结果不得标定稿

Phase 5 收尾
  · 理顺 00/01/02/03 关系与状态；标记遗留待验证项；如实说明验证边界
```

## 硬路由闸门与路由矩阵

以下四类是专业动作，**必须实际调用对应辅技能**。调用证据缺失时，动作状态只能记为“未完成”，不得进入下一阶段或通过门控：

| 专业动作 | 硬性触发 | 必须调用 | 合格交接与放行条件 |
|---|---|---|---|
| 调查取证 | 需要把来源转成证据、事实/推断分层或待核验项 | `interview-due-diligence` | 返回来源定位、材料状态、结论、待核验项、失败/缺证据；主技能汇总后才可通过取证门控 |
| 记录固化 | 阶段末存在新增、修正或任何记录增量 | `interview-transcriber` | 完成整份 `02_访谈记录.md` 全量健康核对并返回增量、授权、定位、状态和阻塞；主技能展示增量并获用户确认 |
| 报告撰写 | 用户同意在访谈完成后生成 `03_访谈报告.md` | `interview-reporter` | 以 `02` 为唯一内容证据源，返回章节与定位；主技能集成前不得定稿 |
| 质检集成 | 报告定稿前后需要跨工件核对 | `interview-qc` | 返回“通过 / 阻塞 / 需人工复核”、证据定位和修复建议；未通过不得标定稿 |

**主技能可直接做的仅限轻动作**：建目录、罗列问题、复述、状态判定、最终定稿（定稿必须以 `interview-qc` 通过为前提）。这些动作不能替代上述四类专业动作。

**降级路径**：只有对应辅技能不可用、调用失败或被权限/工具阻塞时，才可由主技能按同一输入输出契约临时代执行；须先记录具体原因、失败证据、授权范围、代执行内容和恢复/复核条件。降级不是默认快捷方式；未记录降级事实视同未完成。

### 调用账本与交接字段（不新增日志文件）

主技能在当前任务报告或交接中，为每次专业路由填写以下字段：

- **动作/阶段**：正在做什么、对应门控；
- **判据**：必须派遣 / 轻动作 / 经授权降级；
- **目标辅技能与实际入口**：名称、子代理或调用方式；
- **输入范围**：文件路径、材料状态、问题/章节范围、授权；
- **输出与状态**：返回文件/字段、完成范围、来源定位、未决项、是否合格；
- **失败/阻塞**：具体错误、缺失证据、权限或不可用原因；无则写“无”；
- **降级事实**：是否发生、由谁代执行、为何获准、待何时复核；无则写“无”；
- **放行判定**：通过 / 阻塞 / 未完成及依据。

**硬闸门判定**：专业动作未调用对应辅技能，或调用未返回合格交接，或失败后未按降级契约记录，均不得放行。

## 全流程刚性约束、前置要素与取证/阶段/责任契约（§14/§15/§13/§8/§6/§12）

以下几组内容与上方「硬路由闸门」「状态判据」「保真契约」同为本技能的宪法级约束，落地方式为静态可核对契约与审查清单（eval runner/真实黑盒验证延后，见《优化升级报告》§19）。

### 四大全流程刚性约束（§15）

1. **前置确认**：所有访谈、取证工作必须前置确认用户需求与范围后，才启动对应专业动作（配合第 §5 节，未确认不放行取证与正式访谈）。
2. **规则分层**：固定执行模式（树形节点 + 前沿迭代）、可选方法论（第一性原理等）、刚性约束（批判过滤/前置过滤）三层分离，不混用。
3. **批判过滤**：所有取证与访谈输出先经专业甄别、事实核验、逻辑校验；用户表述只提供方向，不自动构成权威事实或结论（事实冲突先行，见 `recording-rules.md` §3 批判卡片）。
4. **正式落地**：最终文档（00/01/02/03）为结构完整、状态清楚、可追溯的正式文本；已确认项与待确认项均不得隐藏或省略。

### 代拟的分层证据链与刚性约束（§11/§13/§15）

**证据链方向**（固定，不可反向或跳跃）：

```text
01_调查取证.md（已授权取证材料）
→ 专业过滤 / 逻辑校验 / 事实甄别
→ 02_访谈记录.md（批判卡片与代拟，显式标注状态）
→ 03_访谈报告.md（以 02 为唯一证据源正式化）
```

- 代拟首先参考 `01` 中已授权、已登记的取证材料；材料中来源观点与调查推断不作为权威事实，须先经专业甄别、逻辑校验与事实核验。
- 代拟的产出落在 `02`，以批判卡片 + `[专业建议·代拟]`/`[待确认]` 等状态显式标注；`03` 仅将已确认内容正式化。
- **硬约束**：`interview-reporter` 只以 `02` 为证据源，不得绕过 `02` 直接从 `01` 向 `03` 新增内容；`01` 的任何结论未经用户确认、未经 `02` 转写，不得自动成为报告内容。

**代拟刚性约束**（恒定，不因科学方法论是否启用而放宽）：

- 用户非专业回应不自动构成权威：只提供方向，不自动升级为事实或结论；事实冲突先行，先指出不支持/冲突证据再代拟。
- 合理则保留：经专业过滤与事实甄别后确属合理的用户立场，可按既有立场拟草稿并保留其限定、反例与未决项。
- 不合理则指出：证据不足、来源冲突或逻辑矛盾时，显式指出并标 `[待验证]`/`[待确认]` 或交主技能裁决，不替用户掩盖冲突。

**科学方法论为可选工具，与刚性约束分层**：

- 第一性原理、矛盾论、实践论、认识论、全局与局部辩证思维等方法是按需选用的思维工具（见 `reasoning-methodology.md`），用于深度拆解、辨析矛盾、核实事实与完善逻辑链。
- 刚性约束（批判过滤、前置过滤、代拟证据链）是恒定底线，不受方法论启用与否影响；二者分层，不混用、不互相替代。

**证据不足处理**：证据不足以支撑确认时，先保留冲突并标 `[待验证]` 或 `[待确认]`，列出所需证据与影响；不自行补齐，不进入下一门控，必要时交主技能裁决。

### 六大前置要素（§2.1/§13）——六要素即未确认不放行取证与正式访谈

访谈启动前必须与受访者逐项确认以下六要素，作为 `00_访谈约定.md` 强制结构（由 `interview-brief` 登记）；**任一未获用户明确确认，不放行进入取证与正式访谈**：

1. **核心目标**（为什么问、核心问题、交付成果）　2. **边界范围**（业务/信息/问题/排除/记录三档）　3. **执行方法**（树形节点+前沿迭代，批判/前置过滤不可突破）　4. **实施阶段**（前置摸底→逐层核实→闭环校验→成果固化）　5. **核心方向**（决策内容/前置依赖/事实取舍/下游解锁/完成证据）　6. **验收标准**（单阶段内容收敛、阶段递进、整体验收）

对象—用户—问题—约束—目标五元组与调查授权（范围/平台/联网/排除/失败处理）同为前置，未收敛（用户能用自己的话复述并纠正）也视为未确认。

### 取证技能绑定表（§14）——未获外部授权不调

调查取证按来源与任务类型固定绑定专项技能（缺口项 → 阻塞，见负例 12）；**未获网络/外部来源授权（00 调查授权区块权限项）时，不发任何外部取证，也不调用下列外部技能**；仅限仓库内只读取证的场景不绑定外部专技：

| 取证场景 | 固定绑定 | 能力定位 |
|---|---|---|
| 全域搜索、背景摸排、多平台/多渠道、海量筛查 | `agent-reach` | 广度、无死角 |
| 核心事实核实、专业考据、逻辑溯源、深度论证 | `research` | 精度、核实、可信 |
| 网页/在线文档/列表/可视化内容的实时结构化采集 | `playwright-cli` | 结构化、完整、可复现、可溯源 |

绑定专技在取证前（第 §5 节范围授权门）按场景确定并记入 01 调查计划；其输出同样纳入来源 schema 登记（来源 ID/类型/版本/获取时间/权限/访问状态/证据等级）与待核验清单。

### 动态阶段（§8）与异步路由（§6）入口

- **动态阶段**：下方 Phase 0–5 是默认骨架，非固定强制模板；每个会话按问题树生成/收敛形成阶段计划，允许增/合/跳/回退，但须留痕并定义七项与内容级完成判据。详见 `references/stage-acceptance.md`。
- **异步路由**：专业支线可非阻塞派遣，但"异步 ≠ 放弃硬闸门"；主线继续须满足依赖不指向在跑结果、`frontier_effect` 非 `blocked`、不读取未回收结论、不跨越门控，并登记 `review_due`。详见 `references/async-routing-contract.md` 与 `references/decision-tree-contract.md`「与异步路由的接口」节。

### 运行时责任协议（§12）入口

## 保真契约（写入每个加工节点的验收项）

对任何一段用户长回答，加工后必须通过：
1. 事实、观点、理由、例证、限定、反例、自我修正、未决判断是否近乎全量保留？
2. 推理链条是否完整、逐层可见，还是被偷换成了结论？
3. 论证的零件——前提、条件、限定、反例、证据等级、修正链、未决项——是否齐全，还是被压成了摘要/要点？
4. 是否把模型隐藏推理补进了文档？（绝不）
5. 代拟内容是否被伪装成用户观点？（绝不）
6. "待确认/待验证"是否被升级为事实？（绝不）
7. 每个加工单元是否可回溯到原始定位？
8. 所用论述/推导图/分层表/对比/分支/结论形式是否确实提升可核对性，而非为形式而形式？

## 权限与边界

- **默认只读**；写入（目录、00/01/02/03 文件）前确认目标、授权、影响范围，遵循最小变更。
- 不把草稿、目录存在、访谈记录、报告描述成已确认产品能力；未执行验证就明确说明。
- 区分事实 / 用户判断 / 专业建议 / 推断 / 候选 / 待确认；遇到权威、范围、状态冲突时暂停并报告。
- 不修改受访者已确认的原文含义；原始未删减底稿不可改写，只作回溯依据。

## 完成后自检

- 是否所有独立问题都有对应回应、都能回溯到原始消息？
- 每次提问、代拟、复述、记录、报告是否在动作前后应用了 `reasoning-methodology.md` 的对象/矛盾/形式门？
- 长答案保真契约八条是否逐条成立，论证零件是否完整可见？
- 确认状态是否未被代拟或待确认升级？
- 报告是否以记录为证据源、三态可回溯？
- 是否如实区分了静态契约覆盖 / 运行期未验证 / 需人工确认？
- 四类专业动作是否逐项实际调用对应辅技能，并有合格交接？
- 每次专业调用是否有账本字段：输入、输出、结果、失败/阻塞、降级事实与放行判定？
- 未调用、交接不全或未通过质检的步骤是否明确阻塞，未被轻动作或“主技能能做”绕过？
- 是否把方法来源显性挂名、把内部机制当自证，或把本次明确排除的范围扩写进产品方案？
