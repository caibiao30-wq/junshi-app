# 状态判据

本文件定义访谈全流程共享的证据状态。状态贴在具体问题、回应或判断上，不给整篇文档套一个笼统状态。

## 七种状态

| 状态 | 含义 | 可否写成用户结论 |
|---|---|---|
| `[用户明确判断]` | 用户自主表达的事实、观点或决定 | 可以，仍须保留原有限定词 |
| `[确认采纳]` | 采访者归纳/代拟后，用户明确确认或明确沿用 | 可以，注明确认依据 |
| `[专业建议·代拟]` | 采访者按既有材料代拟的专业回答、候选或暂定方案 | 不可以冒充用户观点 |
| `[已被修正]` | 后续内容替代早期表述 | 早期内容保留，不能静默删除 |
| `[拒绝]` | 用户明确拒绝某项专业建议/代拟/确认 | 不可以写成采纳或确认 |
| `[待确认]` | 用户尚未拍板，或确认指向不清 | 不可以升级为事实 |
| `[待验证]` | 需要运行、样本、现实反馈或长期实践验证 | 不可以写成已证明能力 |

## 三种状态域的边界

本文件的七态只描述证据与确认，不代替决策树节点生命周期或取证状态。节点生命周期（`candidate / ready / active / blocked / done / stale / superseded`）、依赖、前沿与范围版本见 `decision-tree-contract.md`；取证状态（`unverified / partially_verified / verified / conflicting`）也须单独记录。

- 节点进入 `ready` 的前提是 `depends_on` 全部完成；`ready` 不等于用户已确认。
- `done` 只表示节点有合格完成证据；能否写成用户结论仍由本文件七态判定。
- 用户改变目标或范围时，递增 `scope_version`，旧下游节点标记 `stale`，不得继续沿用旧 frontier。
- 空的 `source_location`、`evidence_refs` 或 `completion_evidence` 不能作为合格证据；占位符也不能放行。

## 特殊判定

- “请为我作答”表示授权代拟，不表示确认。
- “确认”只确认当时明确指向的内容，不自动覆盖同段扩展。
- 用户沉默、空消息或 API 错误不能被推定为确认。
- 代拟回答即使专业、完整，也仍是 `[专业建议·代拟] / [待确认]`，直到用户确认。
- 用户明确拒绝某项建议/代拟/确认时标 `[拒绝]`，区别于未拍板的 `[待确认]` 与被后续替代的 `[已被修正]`。
- 早期观点被后续修正时，保留早期文本并标 `[已被修正]`，将后续内容单独标注其当前状态。

## 状态写入门

1. 主技能判定状态，辅技能只能按证据填写，不能自行升级。
2. `[确认采纳]` 才能作为用户已确定判断写入报告主体。
3. `[待确认]` 与 `[待验证]` 必须进入对应清单，不得被阶段摘要遮蔽。
4. 任何状态不确定时取较保守状态，并记录缺少的证据。
