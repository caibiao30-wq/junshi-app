# 工件契约

## 目录契约

```text
访谈资料/<本次访谈名>/
├── 00_访谈约定.md
├── 01_调查取证.md
├── 02_访谈记录.md
└── 03_访谈报告.md
```

原始未删减底稿不由本技能覆盖或改写；记录与报告通过原始消息编号、段落锚点或相对路径回溯。

## 00_访谈约定

必须说明：访谈对象与角色、访谈目标、读者与用途、阶段与方法、收敛门槛、记录边界、保密/不记录规则、是否允许代拟。未经用户确认，不进入正式访谈。

## 01_调查取证

每条来源按完整来源 schema 登记并展开（权威依据：`../../interview-due-diligence/references/source-schema.md`）：

```text
### 来源：<名称> [来源ID]
- 来源ID：SRC-xx
- 来源类型：<仓库文档 | 外部·平台 | 代码 | 访谈 | 用户反馈……>
- 定位：<路径/URL + 章节/行号/消息号>
- 获取时间：<日期>
- 版本：<分支/提交/tag/文档版本>
- 权限：<是否获主技能授权>
- 访问状态：<成功 | 失败·不可访问 | 部分>
- 材料状态：[现状材料 | 历史材料 | 候选/研究 | 待核验]
- 证据等级：[来源事实 | 来源观点 | 调查推断 | 待核验]
- 可直接观察的事实 / 来源作者的判断 / 调查推断（含依据）：
- 内在张力/缺口；
- 第一性问题候选：<供访谈确认，不写成事实>
```

来源登记表逐来源必填：来源ID、来源类型、定位、获取时间、版本、访问状态、材料状态、证据等级；权限在来源区块标注。文件须含 `question_id → evidence_ref[]` 映射，逐问题至少一个已登记且非静默跳过的来源引用。文件末尾必须有“待核验清单”，并区分事实、推断、用户待确认判断。

## 02_访谈记录

`02` 是代拟与批判卡片的承载层：代拟首先参考已授权的 `01_调查取证.md`，但须经过专业过滤、逻辑校验与事实甄别；用户非专业回应不自动成为权威，合理内容保留、不合理内容指出，证据不足标 `[待确认]`/`[待验证]`。

```markdown
### 问题 N-M：<主题>
**问题**：<原问题的最小必要整理>
**长篇回应**：<全量保留可见论述；代拟单独标注>
**确认状态**：[状态]
**原始定位**：<消息编号/路径/锚点>
```

一次完整无误的问答可整体转写；同一问题多轮展开时可合并成连贯单元，但不得删去推理、条件、反例、修正或状态变化。

## 03_访谈报告

报告为**正式章/节结构**的正式报告，证据源只能是 `02_访谈记录.md`（拒绝自证，不以报告自身取证）。

**章/节映射**：章=会话实际阶段，节=问题。
- 章按 `02_访谈记录.md` 中实际发生且有记录内容的阶段、最终顺序动态生成；章名使用记录中的实际阶段名，不预设阶段数量或固定六章。阶段可增加、合并、跳过或回退，报告按最终记录顺序映射。
- 节号格式 `章号.问题序号`，节标题保留原始问题编号，例 `3.1 问题 2-1：<主题>`；报告问题 ID 与记录问题节点一一对应。
- 每个动态章可在章标题后保留记录已有的阶段字段：目标、当前 frontier、问题集合、完成证据、用户确认方式、未决清单、下一阶段解锁条件；不得由报告侧补造。

**必含结构顺序**：标题与文档状态 → 总目录 → 阅读说明 → 结论总览（正文前） → 按记录实际阶段动态生成的正文（每章只含真实问题；每节含 标准化问题 / 回应与论证 / 节内确认状态 / 记录定位） → 文末：结论边界 → 待确认清单 → 待验证清单 → 回溯索引（报告章/节→记录→底稿） → 附录（状态与代拟说明）。

**双层状态**：每节内保留具体确认状态；文末以「结论边界 + 待确认清单 + 待验证清单」做全报告汇总。

**无空章（硬约束）**：仅当 `02_访谈记录.md` 中存在该阶段且至少有一个真实问题记录时生成章节；未发生、无问题内容或无记录内容的阶段不生成空章、空节或固定六章占位。

## 变更与门控

- `00` 用户确认后才放行取证。
- `01` 取证完成、问题/方法/方向经用户确认后才进入正式访谈。
- `02` 每阶段增量写入，用户确认记录增量后才放行下一阶段。
- `03` 全部访谈完成后生成，质检通过后才标记定稿。
