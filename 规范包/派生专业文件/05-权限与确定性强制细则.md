## 2. 确定性优先原则（承接 Q7-1，`[确认采纳]`）

确定性设施用于强制高影响、权限、证据与义务边界。理由：提示词只能引导模型行为，不能可靠保证边界不被突破；必须由代码、数据、权限与审计强制，不交给 Agent 自律。`[访谈/02] L3097`

六条通用性原则（`[确认采纳] [访谈/02] L3101-L3107`）：

| # | 原则 | 语义 | 落位 |
|---|---|---|---|
| 1 | 确定性优先 | 凡能用代码/数据/权限强制的，不依赖模型或提示词 | §3-§7 全部强制点 |
| 2 | 最小权限 | 每个 Agent/工具/责任域只获得完成任务的最少能力 | §3 对象范围、§6 最小必要 |
| 3 | 可拦截 | 违规/越界/高危操作能在执行前被下游设施阻断 | §4 强制点、§7 阻断 |
| 4 | 可追溯 | 重要操作留下与证据/状态/版本关联的审计记录 | §5 操作ID、§7 审计关系 |
| 5 | 可降级 | 设施异常时不扩大错误、能安全降级或停止 | §5 失败处理 |
| 6 | 可复用 | 通用能力复用成熟组件，语义与责任由产品自持 | §1.9 边界 |

**责任自持 ≠ 全自建**：通用机制（LangGraph/Temporal/OPA/Casbin/OTel 等，按能力评估可复用）可提供实现，但判断语义、状态含义、审计字段、责任边界、回滚语义、验收标准由学业军师定义。`[确认采纳] [访谈/02] L3109`

## 3. 四维权限模型（`[确认采纳] [访谈/02] L2761`）

> 权限按四个维度控制：**主体身份 × 角色 × 对象范围 × 操作类型**。同一对象的「可查看」≠「可修改」，「可建议」≠「可生效」。不能因某主体具较高系统权限，就自动拥有学业规划/判断/学业资产的产品责任。

### 3.1 四维定义

| 维度 | 定义 | 取值示例（`[候选/待验证]`，供落库） |
|---|---|---|
| 主体身份 | 是谁或哪个运行实例 | `student.<id>`、`agent.<id>`、`teacher.<id>`、`system.facility`、`guardian.<id>`、`institution.<id>` |
| 角色 | 在当前场景承担什么责任 | `student_owner`、`total_commander`（总军师）、`subject_commander`（学科军师）、`domain_agent`（责任域）、`subject_expert`（学科专项）、`teacher_support`、`audit`（监管）、`guardian_support` |
| 对象范围 | 对哪个对象、在什么范围内操作 | 对象实体（§6.1）+ 学段/学科/责任域/学生/阶段/时间窗 限定 |
| 操作类型 | 以何种动作操作（≥12 类） | 见 §3.2 |

### 3.2 操作类型（≥12 类，`[确认采纳] [访谈/02] L2761`）

查看、提交、分析、建议、写入候选、确认、修改、撤回、删除、发布/生效、暂停、回滚。

| 操作 | 语义 | 谁通常可执行（矩阵落地，`[确认采纳]`方向） | 生效去向 |
|---|---|---|---|
| 查看 | 读取对象 | 已授权角色按可见范围 | — |
| 提交 | 提供/登记材料或内容 | 学生（必要信息）、证据 Agent 登记 | 进入登记/候补 |
| 分析 | 形成认知输出 | 判断引擎、专项 Agent | 候选 |
| 建议 | 提出专业意见 | 专项 Agent、责任域 Agent | 候选 |
| 写入候选 | 写入未生效候选 | 判断引擎、规划协作 Agent | 候选区 |
| 确认 | 认可内容生效/必要确认 | 学生（对自身学业内容）、规划层裁决 | 生效 |
| 修改 | 改动既有内容 | 按对象/角色最小权限 | 需重校验 |
| 撤回 | 撤销已提交内容 | 学生（必要纠正/拒绝/退出） | 撤回态 |
| 删除 | 删除对象 | 按删除访问控制 | 见 04 生命周期 |
| 发布/生效 | 候选→生效 | **仅规划层**（唯一能把候选路径变生效规划） | 生效 |
| 暂停 | 挂起操作/规划变更 | 设施/规划层/监管请求 | 暂停态 |
| 回滚 | 回到稳定状态 | 设施按回滚语义（G1 待拍板） | 稳定态 |

### 3.3 权限与状态/证据联动（`[确认采纳] [访谈/02] L2765`）

- 未授权对象不能读取或使用。
- 待确认判断不能写入生效规划。
- 撤回或过期证据不能继续支持高影响判断。
- 学生无权修改系统根级权限规则，但有权对自身学业内容作必要纠正、拒绝和退出。
- Agent 无权替学生完成重大确认。
- 产品运行时无权改变根级权限模型。
- 监管可检查与阻断越权行为，但不因此获得任意业务读写权。

### 3.4 统一契约（专项 Agent 强制，`[确认采纳] [访谈/02] L568`）

没有契约的 Agent 不得接入生产协作。专项 Agent 统一契约至少声明：唯一主责对象；适用学段学科场景；输入类型和最小权限；可读取证据范围；可写入对象；输出结构和判断等级；不负责内容；与其他 Agent 输入输出接口；失败冲突不确定时处理；版本依赖模型配置；完成定义和验收标准；责任范围外的拒绝与降级行为。

## 4. 确定性强制点清单（「由代码强制、不靠 prompt」）

> 下列每项由确定性代码/数据/权限强制。标注 **⌘ 代码强制** 者不得降级为提示词约束。`[确认采纳] [访谈/02] L3099, L514`

### 4.1 由确定性设施强制的完整清单（承接 Q7-1，`[确认采纳]`）

| # | 强制点 | 归属 | 强制方式（落位） |
|---|---|---|---|
| 1 | 身份、角色和数据隔离 | 权限 | ⌘ 权限求值 + 对象范围过滤（§3、§6） |
| 2 | 输入来源与授权登记 | 证据 | ⌘ 证据字段完整性校验（04/03 联动） |
| 3 | 状态迁移合法性 | 状态 | ⌘ 状态机合法迁移校验（04 联动） |
| 4 | 证据状态、来源字段完整性 | 证据 | ⌘ schema 校验 + 字段必填强校验 |
| 5 | 高影响或不可逆操作拦截 | 权限/状态 | ⌘ 执行前拦截（§4.3） |
| 6 | 未确认内容不得升级为生效规划或长期资产 | 状态/权限 | ⌘ 候选/生效分离，发布权仅规划层 |
| 7 | Agent 不得改写根级规则 | 权限 | ⌘ 根级规则写权白名单，运行时只读 |
| 8 | 自生长/自进化不得绕过批准或突破边界 | 演进 | ⌘ 批准门 + 边界校验 |
| 9 | 审计记录完整性 | 审计 | ⌘ 审计写入（06 联动；防篡改实现 G2 待拍板） |
| 10 | 撤回、删除、过期的访问控制 | 权限 | ⌘ 生命周期态 × 可见性过滤 |
| 11 | 工具、插件、外部服务调用边界 | 边界 | ⌘ 工具白名单 + 入参/副作用校验 |
| 12 | 停止、暂停、回退、灾备条件 | 状态/回滚 | ⌘ 暂停/恢复状态机（§5）+ 回滚语义（G1 待拍板） |

### 4.2 判断引擎与确定性设施职责边界（`[确认采纳] [访谈/02] L514`）

- **判断引擎承担**：阅读理解材料、识别学习问题、分析位置差距、提出路径候选、比较任务顺序、解释建议理由、识别需补证据、提出暂停/降级/学生确认请求、对执行结果提出修正建议。
- **确定性设施强制**：身份角色权限、各主体数据隔离、输入来源授权登记、状态迁移合法性、证据字段完整性、高影响/不可逆拦截、未确认不得升级、Agent 不改根级规则、自生长候选不绕过批准版本回滚、审计完整、删除撤回过期访问控制、工具插件外部调用边界、停止暂停回退灾备条件。
- 判断引擎负责形成受约束的认知输出；确定性设施决定该输出**是否有资格生效、能否执行、能否写入长期状态**。

### 4.3 高影响/不可逆拦截（⌘ 代码强制，`[确认采纳]`）

- 执行前拦截，不靠事后提示。`[访谈/02] L3104`
- 触发场景：可能产生高影响或不可逆后果、所需权限未取得、判断超学业范围、证据不足/来源冲突/证据过期、学业对象身份或阶段不清、规划版本与输入版本不一致、判断引擎或底层规则版本不匹配、违反统一状态接口验收规则。`[确认采纳] [访谈/02] L522`
- 拦截/降级去向：请求补充材料、降低判断强度、只提供低风险建议、暂不形成规划候选、提交人工/学生确认、暂停当前动作、回退到上一稳定状态。`[确认采纳] [访谈/02] L522`

## 5. 幂等与暂停/恢复/重试（承接 Q7-3，`[确认采纳] [访谈/02] L3186-L3218`）

### 5.1 幂等设计（⌘ 确定性设施承载，不靠模型自觉）

外部副作用必须处理幂等性：同一操作重复执行不产生重复的不可逆副作用。`[访谈/02] L3197`

机制四要素（`[确认采纳]`）：**操作 ID**（唯一标识每次副作用操作）、**去重**（按操作 ID 检查已执行）、**状态标记**（操作状态机：进行中/已生效/已完成/已失败）、**事务语义**（副作用与状态写入同事务，回滚一致）。

| 副作用类型 | 幂等要求 | 实现载体 |
|---|---|---|
| 工具调用（发送/支付/提交/写库等） | 重复执行不产生重复不可逆后果 | ⌘ 操作 ID 去重 + 事务 |
| 判断/规划写入 | 同一版本不重复产生 | ⌘ 版本键幂等 |
| 检验/反馈 | 不因重试重复入账 | ⌘ 操作 ID + 状态标记 |
| 命令/指令 | 防重复执行 | ⌘ 状态机 + 去重 |

### 5.2 暂停与恢复（`[确认采纳] [访谈/02] L3193, L3199`）

- **需暂停情形**：需学生确认或提供信息；证据不足需补证；高影响/不可逆操作前确认；跨责任域或跨学科交接；人为介入或学业校准等待。
- **暂停时必须**：保留当前状态、规划版本、证据、待决事项；记录暂停原因、时间和恢复条件；**不把暂停当作完成或失败**；可恢复时从稳定状态继续。
- **恢复**：从稳定版本继续，不从头重放已生效副作用；恢复时检查期间新证据、状态、版本和权限变化。

### 5.3 重试（`[确认采纳] [访谈/02] L3195`）

- **可重试失败**：网络、临时性模型或无副作用失败；本地/云端服务瞬时不可用。
- 重试策略（间隔、次数、退避）应**确定性配置**。
- **不可重试或重试会重复副作用**：必须预先识别并停止或降级，不盲目重试。

### 5.4 失败处理与错误传播阻断（`[确认采纳] [访谈/02] L3224 起`）

- 失败可安全降级、停止或从稳定状态恢复。
- 底层设施异常时不扩大错误（六原则 #5）；阻断局部错误向下游传播，避免污染判断、规划、资产或学生状态（详见派生文件 `08-多代理编排细则.md` 与基础设施）。

## 6. 数据隔离边界（`[确认采纳] [访谈/02] L2763`）

> 在同一学生范围内，结合全局—局部，至少隔离以下维度；专项 Agent 和工具只能读取完成责任所需的最小范围。

| 隔离维度 | 边界 | 落位 |
|---|---|---|
| 责任域最小必要 | 不同责任域之间只共享完成任务所需最小数据 | ⌘ 对象范围过滤 |
| 学生可见 vs 内部运行/监管/审计 | 学生界面不展示内部 Agent 拓扑，只呈现必要下一步 | ⌘ 可见性字段 |
| 证据原件 vs 学生转述 vs 产品推断 | 三类证据不模糊（外部/内部证据根级分型） | 03 证据模型联动 |
| 当前会话 vs 长期记忆 vs 学业资产 | 生命周期/持久层分离 | 04/10 联动 |
| 生产运行 vs 工程调试 | 调试数据不混入生产 | ⌘ 运行环境隔离 |
| 个体适配 vs 跨学生策略 | 单个学生的适配与跨学生策略隔离 | ⌘ 数据域隔离 |

- 学生是现实材料唯一必要承接者；教师批注/评分/意见/评价及学生转述教师意见**不作产品输入或效果裁判**。`[确认采纳] [访谈/02] L4618-L4624, L90-L102`
- 证据资产反馈权限共享：通过统一接口读取最小必要证据；只能读取被授权学段/学科/阶段/学生范围；不能读取其他责任域全部内部数据；不能绕过底层设施写入长期资产或生效规划；跨域写入走统一提交/候选接口。`[确认采纳] [访谈/02] L574`

## 7. 越权/跨用户污染阻断与恢复（`[确认采纳] [访谈/02] L2767`）

**产品内立即阻断，不把后果交给学生自行诊断，也不要求构建者逐个用户手工修复。**

| 步骤 | 动作 |
|---|---|
| 1 阻断 | 发现越权、身份不一致、权限配置错误或跨用户污染时，产品内部立即阻断相关读取或写入 |
| 2 隔离 | 隔离受影响会话、状态和适配 |
| 3 停止传播 | 停止错误传播 |
| 4 保留审计 | 保留必要的内部审计关系 |
| 5 恢复 | 恢复到最近安全状态 |
| 6 重检 | 重新检查已产生的判断、规划、资产和适配 |
| 7 聚合信号 | 将重复或系统性问题聚合为产品级缺陷信号 |

验收补充：越权与跨用户污染能被阻断、隔离和恢复（Q6-4 验收 #9）；权限错误不形成逐用户人工升级任务（#10）；不同学生的数据、状态、记忆、资产和适配**完全隔离**（#6）。`[确认采纳] [访谈/02] L2779, L2782-L2783`
