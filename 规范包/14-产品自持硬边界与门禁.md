## 一、五类硬边界的具体字段与确定性承载边界

> 每类给「已定结构（可据此写校验代码）」+「待用户拍板」两栏（承接 `[CLAUDE 工程目录] 准入门清单` 步骤 2-4 的拆分表）。

### 硬边界 #1 · 客观证据模型（细则 `03-客观证据模型细则.md`）

**已定结构（[确认采纳]，确定性承载）**:
- 两大根级类型**不可模糊**：`external_evidence` / `internal_evidence`（[用户明确判断]）。`[访谈/02] L1541-1552`。
- 每条证据必含字段（据此写校验代码，缺少即拒绝使用）：`source`、`type`、`strength`、`authenticity`、`time`、`completeness`、`authorization`、`status`、`lifecycle`、`linked_ids`。`[访谈/02] L2566`。
- 外部证据限定学生带回可核验客观实体材料（排名/成绩/试卷/作业/答题过程）；教师批注/评分/转述不作输入。`[访谈/02] L4624`。
- 证据状态迁移：进入→登记→检查→可使用/待补证/冲突/受限/撤回→复核/过期/失效/停止。`[访谈/02] L2621`。
- 确定性强制：来源/类型/强度字段完整校验；证据不可静默升级为判断/资产/规则。`[访谈/02] L3099`。

**校验代码示例（伪/可落）**:
```ts
function assertEvidenceValid(ev: Evidence): AssertResult {
  if (!ev.source || !ev.type || !ev.strength || !ev.authenticity || !ev.time) {
    return { ok: false, code: 'EV_FIELD_MISSING' };            // 底层设施强制，不靠 prompt
  }
  if (ev.type !== 'external' && ev.type !== 'internal') {
    return { ok: false, code: 'EV_TYPE_AMBIGUOUS' };           // 两大类型不可模糊
  }
  return { ok: true };
}
```

**待用户拍板**: 字段与来源颗粒度、自动提取来源标记真实性。`[前置工作] §2.3`。

### 硬边界 #2 · 唯一状态源与生命周期（细则 `04-唯一状态源与生命周期细则.md`）

**已定结构（[确认采纳]）**:
- 每种对象的状态枚举与合法迁移表（证据/判断/规划/任务/资产/适配/权限）。`[访谈/02] L2676`。
- 迁移必经合法性检查（当前状态+触发事件+证据/权限条件 → 允许/降级/暂停/拒绝）。`[访谈/02] L2680-2692`。
- 候选与生效分离；模型/Agent 只能提迁移候选，不能直接改状态。`[访谈/02] L2692, L3144`。
- 状态冲突不静默覆盖，保留双方来源。`[访谈/02] L2698`。

**校验代码示例**:
```ts
const LEGAL_MIGRATIONS: Record<string, RegExp[]> = {
  'plan.draft': [/^-->candidate$/, /^-->discard$/],
  'plan.candidate': [/^-->active$/],   // 仅候选→生效，且需裁决记录
  'plan.active': [/^-->paused$/, /^-->rolled_back$/, /^-->ended$/],
};
function checkMigration(from: string, to: string): boolean {
  return LEGAL_MIGRATIONS[from]?.some(r => r.test(`-->${to}`)) ?? false; // 非法迁移由代码拦截
}
```

**待用户拍板**: 「允许的合法迁移集合」与触发阈值（`[访2] L937` 待确认）。

### 硬边界 #3 · 权限与确定性强制（细则 `05-权限与确定性强制细则.md`）

**已定结构（[确认采纳]）**:
- 确定性优先，不靠提示词：身份/隔离/来源登记/状态迁移/证据字段/高影响不可逆拦截/未确认不升级/Agent 不改规则/自生长边界/审计/撤回删除/工具边界/停止暂停回退 均代码强制。`[访谈/02] L3099`。
- 四维权限：主体身份×角色×对象范围×操作类型。`[访谈/02] L2762`。
- 不可逆/高影响操作执行前拦截，非事后回滚。`[访谈/02] L3370`。

**校验代码示例**:
```ts
// 四维权限求值（矩阵驱动，非字符串比较）
export function can(op: Operation, principalId: string, role: Role, scope: Scope): boolean {
  return MATRIX[role]?.allows(op, scope) ?? false;   // 最小权限
}
export function guardIrreversible(op: Operation): never | void {
  if (op.isIrreversible) throw new ProtectedActionError('IRREVERSIBLE_GATE'); // 执行前拦截
}
```

**待用户拍板**: 首版最小确定性强制集取舍、审计字段表与防篡改实现细节（G2）。`[前置工作] §2.3`。

### 硬边界 #4 · 证据审计链（细则 `06-证据审计链细则.md`）

**已定结构（[确认采纳] 原则）**:
- 每个判断/规划/行动/修正可回溯到客观证据或内部真实记录。`[访谈/02] L3280`。
- 审计记录自身完整、防篡改、可回溯。`[访谈/02] L3282`。
- 撤回/删除对象保留必要审计关系但不继续被禁用途。`[访谈/02] L3282, L2620`。

**校验代码示例**:
```ts
// 审计写入必须带不可变链式哈希（防篡改），缺失即拒绝后续操作
export function appendAudit(entry: AuditEntry, prevHash: string): AuditEntry {
  if (!entry.operator || !entry.object || !entry.action || !entry.time) {
    throw new AuditIncompleteError('AU_FIELD_MISSING');   // 底层强制
  }
  entry.hash = sha256(JSON.stringify(entry) + prevHash);   // 链式防篡改
  return entry;
}
```

**待用户拍板**: 审计字段表与防篡改实现细节（G2）、防篡改密钥管理。`[CLAUDE 工程目录] 硬停门·G2`。

### 硬停门定义（任一未达即停，不静默补齐）`[CLAUDE 工程目录] 硬停门`

- **架构符合性门**: 工程规范须与其所依赖上层约束（访谈/外部指导文件/根 CLAUDE）符合，不引入与之相悖的设计。判据在母文件成文（baseline_id 一致性核对）。**本项目当前已通过**（本规范包严格继承三份访谈权威锚）。
- **V-07 质量门**: 进入工程代码阶段的质量关卡。本次判据在母文件 S0-S8 成文；定义未核对即触发硬停。**状态**: 已按前置工作要求核对为本轮 S0-S8 验收；若后续无法核对定义即硬停。
- **G1 业务回滚语义**: 未成文不得进入工程代码实现。**状态**: 已成文（引用原则）但回滚单元/版本/错误补偿业务定义 `[待用户拍板]`；未拍板不得进入相关实现。
- **G2 证据审计防篡改**: 审计字段表/篡改防护实现细节未成文不得进入实现。**状态**: 防篡改原则+链式哈希校验已给出确定性承载；审计字段表细节 `[待用户拍板]`。
