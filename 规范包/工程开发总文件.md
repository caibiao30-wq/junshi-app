## 1. 全产品总览与范围

### 1.1 学业军师是什么（产品本体定义）

学业军师是以**学业规划为最高产品责任**、以**判断引擎和术业有专攻 Agent 体系**为规划认知结构、以**证据为事实基础**、以**学业资产为长期沉淀**、以**受控自生长/自进化为长期演进机制**，并由教与授、任务、反馈和底层确定性设施共同承接的**长期学业规划系统**。`[访谈/02] L387, L404-L405`。

分层关系（上层建筑 / 认知结构 / 经济基础，`[访谈/02] L409-L426`）：

```text
                    学业规划
          （产品最高责任 / 上层建筑）
                         │
       ┌─────────────────┼─────────────────┐
       │                 │                 │
    路径任务          教与授执行        反馈修正
                         │
          判断引擎 + 术业有专攻 Agent
                  （规划认知结构）
                         │
       证据 ── 学业资产 ── 自生长/自进化
             （事实基础与长期演进）
                         │
    状态 / 权限 / 会话 / 记忆 / 审计 / 回滚
       技术栈 / 运行 / 监管 / 外部反馈
                  （经济基础）
```

### 1.2 最核心不可缺少（按优先级，`[确认采纳]`）

1. 学业规划（上层建筑，最高责任）；2. 判断引擎专项化（认知结构）；3. 术业有专攻 Agent 体系（认知结构，服从统一规划）；4. 证据驱动（事实基础）；5. 学业资产（长期沉淀）；6. 受控自生长/自进化（演进机制）。`[访谈/02] L428-L434`。

### 1.3 第一性问题与产品判定句

学生最根本问题：在持续变化的学业处境中，依据真实信息判断「我在哪/到哪去/差什么/为何差/先做什么/下一步/为何行动/行动后如何调整」。`[访谈/02] L1005-L1006`。产品判定句：以学业规划为最高责任，基于可追溯学业证据形成并动态修正学生学业路径，将路径落实为可理解、可执行、可检验的任务与教与授，长期受控沉淀学业资产；判断引擎、Agent、自生长/自进化和底层设施均服务于此责任，不得替代/绕过/静默改写。`[访谈/02] L908`。

### 1.4 成立与不成立边界

成立需同时具备 10 项最低必要条件（规划最高责任、判断引擎专项化、Agent 服从统一规划、可追溯证据、规划进入真实行动、行动结果反向修正规划、学业资产受控沉积、自生长受控、学生低负担、确定性设施保护责任链）。`[访谈/02] L890-L909`。设计成立 ≠ 工程实现 ≠ 教育效果成立（四层分开）。`[访谈/02] L910`。

## 8. 总配置与凭证接入（以 iFlytek HMAC-SHA256 为示例）

> 示例仅说明凭据的**签名/注入机制**，不锁定供应商；最终云端模型机构/API 供应商属用户门（§9.5/§13.3），团队不得擅自选定。`[启动Prompt] §二.配置与凭证`。

- **注入**: 模型 API 密钥只存于云端后端（`cloud/`）服务端环境变量/密钥管理，**绝不明文入库**、不进入学生端安装包；接触面走网关统一鉴权。`[访谈/02] L3617`。
- **签名（示例机制）**: 对请求按规范做 HMAC-SHA256 签名，请求头携带 `Authorization: <algorithm> access_token="<keyId>", signed_headers="host;date;request-line", signature="<sig>"`。网关侧校验签名、时间戳防重放、HTTPS 传输。具体供应商密钥管理见派生文件《配置与凭证接入细则（云）》（不在学生端工程文件主范围内，学生端只依赖网关契约）。
- 凭证安全由确定性设施 + 运维承接（密钥/证书/补丁由产品方运维管理）。`[访谈/02] L3364`。

### 9.1 最小闭环路径（证据→判断→规划→任务→教与授→行动→检验→反馈→修正）

```text
1 学生提交一份学校材料（外部证据：成绩/试卷/作业/答题过程）
      ↓
2 来源登记 + 类型（外部证据）+ 强度（原始/可核验）+ 授权 + 完整性检查（底层设施强制）
      ↓
3 档案+材料摄入 → 判断引擎：基于证据识别位置/目标/差距（候选，区分事实/推断/候选/未知）
      ↓
4 学业规划层裁决 → 形成当前阶段规划（候选与生效分离，候选不经裁决不生效）
      ↓
5 任务分解 + 教与授承接（把规划转成讲解/练习/检验/纠错，触发可观察行动）
      ↓
6 学生执行任务 → 行动记录（内部证据）
      ↓
7 检验/结果反馈回流（区分外部证据/内部证据、原始结果/产品解释）
      ↓
8 反馈触发规划修正（继续/调整/暂停/回退）→ 学业资产候选（受控确认）→ 下一轮规划
```

## 11. 交叉一致性、版本与变更传播协议

1. **冻结基线**: 总编签发 `baseline_id`（本文件为 `JUNSHI-ENG-MASTER-001`）。
2. **继承声明**: 每派生文件头 `inherits_from: JUNSHI-ENG-MASTER-001`。
3. **变更传播**: 本文件根级变更 → 签新 baseline_id → 标记受影响派生 `STALE/PENDING` → 触发定向重验。
4. **单一写权**: 每派生文件独立责任人/写入者。
5. **冲突裁决**: 只回本文件或用户决策簇，禁总编静默择一。
6. **向上修订**: 派生发现缺口 → 变更请求 → 总编判定（重冻结+STALE / 待决挂用户门）。`[启动Prompt] §九`。
