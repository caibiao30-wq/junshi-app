## 一、产品本体：学业军师是什么

三个来源在"产品身份"上高度一致，且随阶段收敛而越发精确。

**当前阶段性确定定义（draft，D-001 最终确认）：**
> 学业军师以**学生为主体**，持续理解其学习处境，承担受约束的学业判断、规划建议、学习方法指导、行动指导和复盘引导。产品创造的是**理解与实践的条件**，不承诺替学生制造能力、成绩或人生结果。

**一句话身份（三源交叉）：** 面向中国初高中学生的 **1 对 1 专属学业军师**——是学生的"参谋长"而非"代理执行者"，是主动指挥官而非被动工具。

**产品不是什么（draft§1.3，最终确定的边界）：**
- 不是题库/答题器；
- 不是只生成计划的待办工具；
- 不是替学生行动、替学生完成全部复盘的自动化管家；
- 不是心理咨询/治疗/危机救援产品；
- 不以家长监管为中心；
- 不承诺提分，不对成绩作保证。

**范式反转（早期雏形 + 代码库均确认）：** Agent 不是被动响应工具，而是**主动指挥官**——军师定策，学生（君主）执行。这一"主导性"主张与项目目标里"用户主导 > 决定 > 参与"的排序一脉相承。

## 二、核心机制：义务环与学业闭环

**三条来源交叉证实"闭环"是学业军师的第一机制，而非单点功能。**

**当前形成的核心闭环（draft，D-004 最终确认）：**
```text
理解处境 → 军师定策 → 学生形成或调整规划 → 学生行动 → 提交行动信息或材料 → 共同复盘 → 进入下一轮
```
拒绝后：军师重新理解处境、解释依据与局限、提出减少/替换/延后/暂停/重组方案，由学生参与定下一步，**不得静默改变长期方向**。

**规划三层级（draft§2.2）：** 学业阶段周期 → 阶段性学业规划 → 近期行动规划。长期目标是共同讨论的趋近方向，须随真实处境与证据调整，非结果保证。

**义务环的早期形态（项目资料 + 代码库）：** 早期设想了"九步循环"（看清→裁决→规划→行动→调整→总结→复盘→回写→突破）与"五步最小循环"（看清→裁决→行动→复盘→回写），以及**套娃式循环**（全局慢/局部快）与**三层记忆**支撑"回写即生长"。代码库（Project-educate）确认最小义务环：学生可见五步（看清局面→裁决→行动→复盘→回写），内部九步"，对外只用五步名称"。**历史"三层记忆、五镜、了解度、回写即生长"等早期候选，在 draft 中因未过五门槛被列为**待重新确认/已阻断**，需数据验证后以新 D-ID 升级。**

**内外双循环（draft，D-011 最终确认）：** 外部产品循环（How/What）+ 内部判断引擎（Why/Whether），首尾调用衔接——进入时静态路由、输出时动态调用。双层架构：工作会话 + 持久记忆。

**完成判断（draft§6.6）：** 每轮闭环须能回答：理解了什么处境 / 做了什么判断 / 学生是否理解、同意或拒绝 / 产生了什么证据 / 复盘发现什么 / 下一轮入口在哪。任一环节无法回答则触发异常契约。

## 三、产品判断逻辑：判断引擎与可靠性

**这是学业军师区别于通用 Agent 产品的关键差异点，三源一致强调"证据驱动判断"。**

**判断引擎定位（draft，D-003 保留阶段性）：** 在大模型通用推理之上叠加**领域专用思考过滤器**，是内部认知引擎。设计哲学"化繁为简，20% 核心配置撬动 80% 业务价值"。
- **双模式触发：** 静态路由（按任务类型×风险）+ 动态调用（低置信度/事实冲突/新证据/连续失败/安全风险时主动重判）。
- **方法激活：** 高频先跑"实事求是" + "实践论"；低频哲学方法（矛盾论等）第一版不实现，待运行数据后激活。
- **输出维度：** task_type、facts、unknowns、evidence、learner_state、primary_issue、confidence、allowed_action、risk_level、next_evidence_needed、revision_trigger。
- **风险降级三层（D-011）：** L1 证据不足→待核实建议 / L2 证据冲突或过载→保留冲突补充核实 / L3 安全或不可逆→暂停进安全边界。
- **硬底线：** AI 不得在任何层级下自行修改规则、最高边界或不可逆长期状态。

**早期"了解度"与"五镜"（项目资料）：** 了解度=军师对该学生可裁决把握的显式百分比（首日≤60、探索态<15、保守带15–30）；了解度算法由目标澄清+成绩证据+试卷错题+行为时间+方法复盘计算。五镜=能力/目标/行为/方法/动机真相。**但这些在代码库（Project-educate）中权重标 `pending_calibration`，"不得假装已科学定论"；在 draft 中列为待重新确认候选。**

**判断纪律（draft§3.4）：** 区分有据判断/有限推断/工作假设/完全未知；不把证据、过程结果或入库量等同于学生成长、长期迁移或教育价值。

## 四、证据、资产、可靠性与追溯（最硬的核心差异）

**这是三源一致指向的学业军师独有内核，也是代码库中规格最完整的部分。**

**信息四分域（draft，D-008/D-013）：** 学业证据 / 学业资产 / AI-军师记忆 / 军师内部资源四者不得混合。证据四分类：原始输入(a)、过程记录(b)、判断依据(c)、外部验证(d)。

**学业资产（draft，D-007 修订/F1-14 闭合/保留阶段性）：** 面向单一学生的个人知识库，**内容只能面向且只能属于该学生**。四类一级模块（知识理解/错题认识与修正/学习方法/共同复盘沉淀）+ 学科分桶。**硬约束：原始材料永不直写资产，须 AI 整合提炼为候选草稿 + 学生显式确认才晋级，沉默≠确认**；仅共同复盘为晋级入口；三段式"收集→草稿→确认晋级+失效/归档" + 独立版本化。**三条价值假设（碎片化/缺乏认知/高复用）指标与对照已定，结论待试点。**

**可靠性三维正交（draft）：** 来源可信度 × AI 置信度 × 产品声明确定性；对外简化为三级标签"确定/可能/待确认"。

**代码库的证据规格（Project-educate，未实现）：** `EvidenceRecord` 字段含 id/type(score|weak_spot|blocker|understanding_delta|behavior|judge_note)/ts/content/source(subject)/ref_asset_ids/confidence/window/revocable。**证据≠认知硬规则**：用户侧能力层只放客观证据，军师认知进三层记忆，判断须可指向证据或显式"证据不足"。资源层五域：01 原始归档（**写入即锁、永久只读**）→02 缓冲加工（≤7天）→03 知识图谱→04 产出沉淀（强制回链）→05 系统规范。三级编译；原件"只增补/标注，写入即锁，不因炼化消失"。

**标注与追溯（draft，D-013）：** AI 输出时+复盘时标注、学生可见；ID 追溯 + 时间线追溯 + 会话级因果追溯；安全/法律场景例外留存需审计+声明。

## 五、状态、记忆与上下文运行

- **双层架构（draft，D-011）：** 工作会话（有边界）+ 持久记忆（跨会话），学生不感知技术边界。
- **10 项最小运行时状态（draft§6.3/7.2，D-011）：** 会话级 5 项 + 持久级 5 项；状态转移三原则：有触发、可追溯、不可逆需确认。
- **记忆蒸馏：** 切换时提取结构化事实（非摘要原文），每条标注来源/时间/置信度/验证状态，**未验证不写持久记忆**；"必须继承"+"应该继承"。
- **"军师的认识"入口（D-013）：** 学生可查看/纠正/删除持久化判断，三粒度，重置需二次确认。
- **上下文过载=L2 异常：** 检测过载→蒸馏归档→开新会话→继承→继续。
- **三层记忆（早期+代码库）：** 事件记忆（append-only、分窗加载）/ 认知记忆（证据加权、降权归档不硬删）/ 方法记忆（"何法对此人有效"）。**draft 中列为待重新确认候选，需数据后升级。**

## 六、角色、权限与安全边界（家长与学生权重极高）

**责任矩阵（draft，D-006/D-014 最终确认）：** 按决策类型分五类：(a)目的/价值取舍⇒治理者；(b)目标/偏好⇒学生；(c)同意/行动⇒学生+AI；(d)高风险判断⇒专业者；(e)规则执行⇒确定性规则。

**主动性 A-E（D-009/D-014）：** A理解/B建议 AI 自主可追溯；C 低风险可撤回行动 AI 自主+学生可撤；D 对外沟通/执行需有权主体确认；E 长期/不可逆/安全需专业/治理者确认。

**家长/监护人（D-015/F1-11 精简闭合）：** 家长通道仅推送学生学业特定内容，**经学生可见后**推送；家长角色分别判断（付费者/法定监护人/支持者/信息接收者）；日常仅支持，安全/法律场景才可代理；**普通处境表达不自动转为家长监控**。

**代码库的家长权限设计（Project-educate）：** **"禁止家长具备学生裁决写权"**——家长只可读规划，不可改证据/阶段目标/今日令；家长期待记 `FamilyExpectation`，"不得直接当 stage_target"。

**安全兜底（draft，最小）：** 产品不承担危机干预/救援/治疗；识别到明显超出学业辅导范围的表达，仅执行"暂停普通学业流程 + 突出能力限制 + 建议联系可信成人 + 留审计"，不诊断不转介。**安全判断与普通学业事实判断分域，安全表达不要求先有成绩证据。**

**退出/导出/删除/留存：** 学生可随时退出、导出、请求删除；最小必要留存并告知。

## 七、交互与体验：控制面与"负责任学长"

- **控制面最小集 8 项（D-009）：** 依据/不确定性可见、状态/记忆可见、纠正/反驳/删除、暂停主动性、撤回/回滚、重大变化确认、导出/退出、审计记录。
- **C1 学生确认协议：** 青少年认知适配（简化语言/可视化/分步）+ 家长代理边界 + 知情同意，按风险分级应用。
- **"负责任学长"边界：** 有温度、有判断、有方法，但不伪装真人、不以拟人化掩盖未知、不以拟人化制造过度信任。
- **人化证据（AI-Agent 研究草稿，状态：暂停）：** 外部证据仅支持"适度社会临场感提高感知/情感连接"弱命题；**不支持"越像人越优秀"。** 转化方向：不伪装前提下提供适度临场感、校准信任而非最大化信任、把学生主体性与可观察结果放在比拟人化更高位置。

## 八、验证、治理与阶段门槛

- **四轴验证契约（draft，D-010 最终确认）：** 产品能力/产品形态/工程实现/商业发布治理四轴，原则+可核验清单，**不设业务数值阈值**。**单轴否决即暂停**，回退上一可追溯版本，仅产品治理者重审后放行。
- **关键原则：** 功能数量、benchmark、喜欢、留存、成绩或"更像人"**不得替代四轴门槛**，否决优先于它们；仅工程可追溯性（审计完整性）可有 100% 硬要求。
- **三方交叉验证：** 产品治理者 + 学生视角 + 工程审计，**AI 不自证**。
- **历史候选升级五门槛（F1-15）：** 试点真实数据+对照 / 四轴通过且否决优先 / 不冲突现行决策 / 产品发起人显式确认新建 D-ID / 下游可继承未改写本体，**缺一不得升级**。
- **代码库立法层级（Project-educate）：** constitution > agent-runtime/safety/governance > engineering/quality > strategy > operations/observability > process > archive；规范状态机 `stub→draft→review→locked`，**未 locked 不得作唯一验收依据**。

- **技术栈选型（代码确证）：** Python 3.12、LangGraph + langchain-anthropic/openai、FastAPI、SQLite（Postgres 后期同层切换）、pydantic v2、mypy 严格模式、Vite+React19+TS。
- **A≠B 边界：** A（`.claude/` 创造侧）≠ B（`runtime/` 学生运行时），禁止互读。

### 上一版本结构（文档设想，全为空/ stub）

### DeepTutor 底座评估（官网证据支撑，已更新）
**证据来源：** DeepTutor 官方中文官网 + 官方文档站（https://deeptutor.info/zh-cn/）取证 + 本地代码库目录框架图（`工程代码库目录框架图/DeepTutor目录框架图.md`）。官网取证完成后，本节由"带证据缺口的推断"修订为"官网证据支撑的结论"。

**DeepTutor 是什么（官网）：** 官方定位"Agent-native 的开源个性化学习伴侣"，以智能体运行时为核心，将对话、资料、记忆、知识库、学习路径和多种学习工具整合进统一工作区。八个界面（Home/Partners/My Agents/Co-Writer/Book/Learning Space/Memory/Knowledge Center）共享同一运行时上下文。面向个人学习者为主，多用户模式有 Learner/Guardian/Standard/Custom 角色。

**DeepTutor 与学业军师硬内核的贴合度（官网证据）：**

| 学业军师硬内核 | DeepTutor 官网对应证据 | 贴合度 |
|---|---|---|
| 证据/来源追溯 | Research 生成带引用报告；Co-Writer 可背书；Immersive Watching 字幕绑定时间戳；Little Tutor 以选区来源为依据；知识库锚定答案 | **高** |
| 记忆可审计 | Memory=可审计三层管线（L1 工作区镜像/L2 界面摘要/L3 跨界面综合），非隐藏向量库，提供 Update/Audit/Dedup | **高** |
| 判断逻辑/可靠性 | 先规划工具调用→观测→继续；Solve 带验证；Mastery Path 知识点类型决定"什么算掌握" | **中高** |
| 掌握度而非时长 | Mastery Path 以"是否真正掌握"衡量，硬门槛解锁、间隔复习 | **中高** |
| 持久化学习资产 | 学习空间组织聊天/笔记/题库/人设/Skill/MCP 为可复用资产 | **高** |

**关键差异（须学业军师自行强化）：**
1. **判断引擎哲学深度**：DeepTutor 有"先规划后调用"的 agent loop，但**没有**学业军师"领域判断引擎 + 三层降级 + 8 类异常契约 + 硬底线（AI 不得自行改规则/最高边界/不可逆状态）"的显式架构——差异 A/B 的强化点。
2. **学生主体/边界/隐私**：DeepTutor 有 Guardian/Learner 授权模型，但**没有**学业军师"家长无学生裁决写权""拒绝/沉默不自动等于失败""不承诺提分"的产品伦理与最高边界——差异 C 的强化点。
3. **垂直深度**：DeepTutor 是广谱学习空间（8 界面多形态），学业军师是垂直学业闭环——「减法」的落点。

**底座资格结论（修订）：** DeepTutor **适合作学业军师工程代码库的底座镜像**——不仅"分层骨架"贴合，"证据/记忆/可靠性"机制也贴合（贴合度高中）。加减法应聚焦：**保留/强化** agent 原生运行时分层、learning/knowledge/evidence 域、记忆分层、Quiz/Solve 学习闭环；**砍减** co-writer/book/video（immersive watching）/多智能体 Research 等广谱内容域（首版不做或降级）；**新增/强化** 领域判断引擎、产品伦理与最高边界、家长权限、安全兜底、四轴验证治理。此结论为官网形态判断，不等同于对 DeepTutor 运行质量、学习效果或可靠性的独立验证。

## 十、核心特点总结（贯穿三源）

1. **学生主体性为第一原则：** 学生可理解、质疑、拒绝、纠正、暂停、退出；拒绝/沉默不自动等于同意或失败；军师无强制权、无最终决定权。
2. **主动指挥官而非被动工具：** 判断引擎主动监测学情、识别瓶颈与提分幻觉、调整规划、派发任务。
3. **证据驱动为硬内核：** 判断须可指向证据或显式"证据不足"；四层可靠性、可追溯、可纠正。
4. **学业资产属学生所有：** 内容只能面向且属于该学生；原始材料永不直写资产，须学生显式确认晋级。
5. **受约束的能力边界：** 不承诺提分/医学/心理；不伪装真人；安全判断与学业判断分域。
6. **家长有限介入：** 家长无学生裁决写权，日常仅支持、不自动转为监控。
7. **主导性产品意志：** 军师定策、学生执行、"主导 > 决定 > 参与"的价值排序在此产品上被实例化。
8. **治理是产品的组成部分：** 四轴验证、三方交叉、AI 不自证、历史候选须过五门槛才能升级。
