## 一、访谈概况

- **访谈主题：** 学业军师产品的深度剖析。
- **访谈方向：** 产品开发、设计、实现方式；受访者个人背景；Super Vibe Coding 系统（作为后续独立访谈专题）。
- **访谈方式：** 采访者（深度访谈者）提问，受访者（学业军师产品构想者）作答；受访者多次授权采访者按其立场代拟专业答案，再由受访者确认。
- **基本纪律：**
  1. 一切访谈皆服务于未来更高质量、更高水平、更高效率地完成学业军师项目。
  2. 第一性原理：从现象追溯到本质，不满足于文件既定的表面措辞。
  3. 知己知彼：先了解受访者本人，再谈产品与系统。
  4. 循序渐进、有序推进：不东问一句西问一句。
  5. 商业变现不作为独立主航道；仅在涉及产品边界、发布治理时作为背景约束。
  6. 区分事实、推断、候选方案与待验证事项，不把未验证内容写成既定事实。

## 二、受访者背景（阶段 0）

### 2.1 身份与经历

- 本科法学专业，2024 年毕业，毕业后持续创业。
- 曾进入研学旅行赛道，后退出；该段经历成为转向学业军师的重要背景。
- 无传统编程背景，但从 AGI 兴起时即系统探索 AI。
- 现决定深耕人工智能，以 AI 开发第一款产品——教育领域的学业军师。

### 2.2 核心定位

受访者自我定位为：

- 顶层设计者；
- 产品方向与呈现形式的决定者；
- AI 与子代理的驾驭者；
- 资源调配者（能力互补、价值互补，而非死磕 0-1）。

### 2.3 对"驾驭 AI"的立场

- 主张"驾驭 AI 高于使用 AI、高于学习基础工程语言（如 Python）"。
- 认为非编程背景更应保留想象力与创造力，反去学习工程语言是压缩自身优势。
- 倾向于把 AI Agent 调教成高度可靠的伙伴，通过驾驭 AI 达成目的。
- 倾向于打造专属的 Super Vibe Coding 系统，而不采用网络通用的"共享学习"或割韭菜式课程。

### 2.4 能力、约束与资源

- 最能独立完成：发现问题、提出产品构想、价值判断。
- 最不能独立完成：代码审查、系统架构、工程部署。
- 判断 AI 可靠性的方式：逻辑一致性、调查取证、多个 Agent 交叉、AI 查 AI。
- 当前可调配资源：时间、AI 工具与 Agent、资金。

### 2.5 教育哲学与价值观

- 将人的一生分为四个等份，一等份约 20 年；学业占第一等份，且对绝大多数人决定后三个等份的质量。
- 第一等份的学业是撬动人生后续效率最高、风险最低、收益最高的杠杆。
- 学业是持久战（至少十余年），坚持长期主义，反对短期畸形提分。
- 学生真正的收获：
  - 第一价值：把学习规划成一条可视化、可逐步抵达的成长路径；
  - 第二价值：将规划、执行、总结、复盘等人生方法论，以习惯方式沉淀进学生潜意识，惠及学业与未来职业。

### 2.6 认识论

- 主观判断须经客观实践反复检验、反馈、改造。
- "永远相信自己"与"不以主观强加客观"之间，靠实践循环调和：客观事实验证主观 → 主观方案投入实践 → 实践结果反馈改造认识 → 再实践，直至概念经实践逐步验证。
- 不把未验证的事当作事实，不把推测包装成证据。
- 不预先把产品任何具体部分设为"不可改"；可改与不可改由实践自然呈现。

### 2.7 背景画像结论（已确认）

1. 身份：法学本科、持续创业者、AI 时代投身教育产品。
2. 技术背景：无传统编程，主张驾驭 AI。
3. 核心模式：顶层设计 + AI/子代理执行 + 资源调配。
4. 能力短板：代码审查、系统架构、工程部署。
5. 可靠性判断：逻辑一致、调查取证、多 Agent 交叉、AI 查 AI。
6. 资源：时间、AI、资金。
7. 动机：以"被证明的价值"立足；学业军师与 Super Vibe Coding 是验证自身价值的实践对象。
8. 教育哲学：学业是撬动人生的长期杠杆，价值=可视化成长路径（第一）+ 方法习惯沉淀（第二）。
9. 产品一句话：为未来创造杠杆。
10. 认识论：实践反复检验主观，不把未验证当事实。
11. 可改与不可改由实践自然呈现，不预设禁区。

## 三、项目现状与最小验证对象（阶段 1）

### 3.1 项目真实状态

- **学业军师**：处于产品定义、产品设计、原型设计阶段。无完整工程实现，无真实用户验证。
- **Super Vibe Coding**：处于个人工作方法、正在整理的方法论阶段。非已验证系统，非可交付 skills。
- **当前仓库**：产品研究资料库、产品与系统设计资料库；工程代码库尚未形成。
- **正式方案性质**：产品原则与顶层说明，而非可直接指导工程开发的完整产品规格。

### 3.2 已拥有与缺少

- 已拥有：较具体的产品构想、候选底座、正在整理的开发方法论。
- 最缺少：Super Vibe Coding 系统、完整的学业军师产品方案、工程代码库。
- 当前最应该做：初步开展 Super Vibe Coding 系统的研发设计。
- 当前最不应该做：直接完成完整 Super Vibe Coding 系统（尚未验证）。

### 3.3 最关键的三个未知（构成连续因果链）

1. 核心闭环如何运行；
2. 规划如何转化为行动；
3. 学业资产是否有价值。

> 任何一环不成立，产品都可能退化为"理念完整但实际无效"的规划工具。

### 3.4 最小验证对象

- **场景**：学生提交一份作业、考试或错题材料。
- **理由**：这是基于客观学生证据形成规划、执行、总结、复盘等行为的起点，也是区别于传统教育产品的核心——以真实证据为据，不做违反事实、缺少证据的动作。
- **验证入口（已确认）**：以一份来源明确、经过适当授权的真实学生学业材料，验证产品能否完成证据归类、有限判断、边界拦截与来源追溯。

### 3.5 最小输入组合（五项，已确认）

1. 材料本体；
2. 材料类型；
3. 学科/课程归属；
4. 学生处理意图；
5. 学生确认材料归属与本次处理。

可由 AI 识别的内容（材料类型、学科）采用"AI 提候选 → 学生确认"，不直接写成确定事实。

### 3.6 最小处理边界

最小组合只允许：材料理解、证据归类、低确定性初步分析。
不允许：长期学情判断、长期规划、资产写入、无证据高确定性结论、替学生决定。

### 3.7 权限与工程边界（已确认）

- 学生资产、权限、不可逆操作等硬边界，由确定性代码规则强制，AI 无法绕过；
- 提示词负责引导，不能承担权限保护；
- 提示词不宜过度堆叠，避免模型判断混乱。

### 3.8 最上游源定义（专业暂定）

输入与来源定义 → 证据归属建模 → 判断/建议/输出契约 → 确定性权限边界 → 追溯机制。

### 3.9 访谈结构调整（已确认）

分为两条先后独立的访谈：
- 第一部分：学业军师独立访谈（本记录所覆盖）；
- 第二部分：Super Vibe Coding 独立访谈（学业军师完成后单独进行）。

### 3.10 Super Vibe Coding 的正确界定（已确认）

- Super Vibe Coding 是"链接系统"：把非技术用户的自然语言表达，通过特定桥梁由 LLM 处理，连接到工程代码库；
- 它解决的是：非编程背景人士通过自然语言指导、控制、参与整个产品开发；
- 它提升使用者开发的质量、效率与容错；
- 它**不是**学业军师的运行时判断引擎，**不负责**决定学业军师在每个场景下如何判断。

## 四、产品本质与价值（阶段 2）

### 4.1 产品第一性价值（已确认）

学业军师最终交付的不是"一条更好的路径"，而是**学生自己走路径的能力**。可视化路径、行动、反馈、复盘与资产是培育这种能力的支架，随学生能力成长逐步移除。

### 4.2 使用前缺失 → 使用后新增

- 使用前最根本缺失：方向感、位置感、从现状到目标的现实路径。
- 使用后最核心新增：理解处境、判断问题、决定行动、依据结果修正方向的能力。

### 4.3 学生应形成的三种能力（已确认）

1. 看清自己的问题；
2. 决定下一步行动；
3. 依据结果修正方法。

三者构成"看清 → 行动 → 检验 → 修正"的连续循环。

### 4.4 成长路径的"一步"（已确认）

由当前问题、本步目标、学生行动、可观察结果、证据判断、学生确认/调整、下一步入口组成的动态单元。最核心的是学生通过真实行动获得新认识，产品据此调整后续路径。

### 4.5 "杠杆"的定位（已确认）

- 对产品：长期方向与价值信念；
- 对学生：当下可感知的方向感、掌控感、前进感；
- 人生宏大叙事不持续压到学生面前，主要在家长/成人沟通语境、适当时机呈现；
- 学生即使不使用"杠杆"一词，只要在反复行动中形成自主能力，长期价值就在积累。

### 4.6 产品必要性（已确认）

- 现实教育帮助分散于教学、督促、答疑、训练等环节，缺少一个持续依据学生真实证据，把处境、判断、规划、行动、结果和复盘连接起来的主体；
- 学业军师要补的是这条长期连接的缺口，而非替代老师、家长、培训机构或题库；
- 其必要性目前是**基于现实观察形成的强假设**，须通过真实场景验证，不能由 AI 形式或产品理念本身证明。

### 4.7 教与授承接（新增，关键，已确认）

- 教与授是承接规划、行动实现的功能载体；
- 没有具体的教与授，规划与执行只停留于空谈；
- 判断规划不是"伪规划"的关键标准之一，在于是否具备真正承载教与授、使学习真实发生的载体；
- 已列为产品机制设计的独立专题【教与授承接】。

## 五、产品角色、关系与边界（阶段 3）

### 5.1 军师是参谋型主控角色（已确认）

- 主动观察、理解、判断和提出问题；
- 主动提出低风险、可撤回的行动候选；
- 主动提示证据不足、冲突和需要复盘的事项；
- 可在适当条件下主动发起对话；
- 但不得强迫、代替、操纵或静默改变学生的长期方向；
- 最终决定权、确认权和行动权属于学生；
- 军师主动性的衡量标准：是否帮助学生更好地理解处境、作出自己的决定，并逐步形成独立行动能力。

### 5.2 教与授是完整闭环（已确认）

- 教与授不是单向"讲—听"，而是由诊断、讲解、练习、检验、反馈构成的完整行为闭环；
- 可用"学—练—查—验"近似表达；
- 练习必须由学生真实完成；
- 检验必须产生可观察结果；
- 反馈必须回到规划、判断和下一步；
- 没有练习和检验，就不能把"讲过/听过"当作学习已发生。

### 5.3 一主多专、统一入口（已确认）

- 学业军师是"一主多专"架构：一个主控军师 + 多学科专家集群；
- 学生统一面对军师；军师负责判断、规划、调度与承担学生交互；
- 各学科专家 Agent 在后台只做自己最专业的一环；
- 产品出口统一，专业能力分散，责任归于一统。

### 5.4 每个学科独立专家集群、因地制宜（已确认）

- 学业军师面对多学科，每个学科应依据自身特性独立具备专家集群；
- 专家数量、职责组合、调用顺序、学科内部闭环依学科特性而定；
- 有的学科可能只需少数专家，有的需要更多；
- **具体问题具体分析，不能一刀切**；
- 统一的是治理原则与责任边界，变化的是学科专业组织方式。

### 5.5 统一基础闭环 + 学科加减法（已确认）

- 各学科共享同一"最基础闭环"：**理解 → 行动 → 检验 → 反馈**；
- 在基础闭环之上，针对学科特性做加减法；
- 允许调整环节内部深度、顺序、分工、工具；允许相邻环节在具体任务中合并执行；
- 不允许删除必要环节、不允许学生不参与真实行动、不允许取消检验反馈、不允许各学科另立完全独立的基础闭环。

### 5.6 主控军师与学科专家的责任边界（已确认）

- 主控军师：跨学科规划、优先级、学生关系、整体判断、调度学科单元、组织复盘与长期方向；
- 学科专家：本学科专业诊断、讲解、练习、检验、反馈，并提供证据与不确定性；
- 判断分歧裁决："专业内容听学科专家、跨学科与优先级听军师、最终决定听学生"。

### 5.7 多层战场指挥体系（已确认）

- **总军师**：负责全学科整体战略、优先级、资源分配、失衡调整、服务学生整体学业；
- **学科战场军师**：负责学科协调、监督、任务下达、战况汇总；
- **学科内专业 Agent**：负责具体教与授、诊断、练习、检验；
- 总军师无法独立掌控所有战场，通过分层授权与学科战场军师间接掌控；
- 每个 Agent 只负责一件专业的事，不做全能选手。

### 5.8 建立方式（已确认）

- 总军师：永久常设，是"持续理解学生"的稳定载体；
- 学科战场军师：学生实际学习的学科常设；非活跃学科动态成立；
- 学科内专业 Agent：按任务动态组织，完成任务后解散。

### 5.9 证据处理必须独立成责（已确认）

- 学业军师区别于其他教育产品的核心是证据驱动；
- 证据处理不能作为主控军师的附属能力，也不能由主控 Agent 自己兼任；
- 应设独立的证据治理责任（证据治理 Agent）。

### 5.10 证据是产品底层设施（已确认）

- 证据处理不是某个 Agent 的能力，而是产品底层的确定性基础设施；
- 证据底层设施：保存原始材料、登记来源归属、分类版本、证据—判断引用、生命周期、权限隔离、审计、纠正/撤回/删除/回滚、跨会话跨学科承接；
- 证据治理 Agent：管理和维护该设施，执行归类、事实提取、关联、冲突发现、生命周期处理；
- 只有 Agent 而无底层设施 = 伪证据处理；
- 只有设施而无管理 Agent = 形同虚设；
- "作出判断的主体"与"管理判断依据的主体"分离，使"AI 不自证"在结构上成立。

### 5.11 家长推送规则（已确认）

- 向家长推送的内容皆以学习内容为主，主动推送无需学生授权同意（产品底层规则）；
- 家长是监护人/学习支持者，不是学生学业的主控者；
- 家长反馈是外部输入，不自动覆盖学生判断、规划或资产。

### 5.12 范围收缩（已确认）

- 学业军师只深入学业领域；
- 过去文档中存在的心理、安全、法律等超出学业范畴的内容，全部废弃，不呈现于产品之中。

## 六、产品机制与设计（阶段 4）

### 6.1 双层（多层级）闭环：全局与局部

- 以学科空间为第一视角，重新定义层级：
  - **真正的全局**：站在全学科、学生整体学业处境的立场上的方向与协调；
  - **一级局部**：单个学科层面（数学、英语等）；
  - **二级局部**：学科内部的具体任务/知识点。
- 主控军师第一职责：保证多学科协调平衡，防止顾此失彼，而不只是推进某个学科进度。
- 全战场作用于独立战场，独立战场反作用全战场，独立战场之间又互有联系。

### 6.2 战场模型（已确认）

- 学业军师面对"全学科大战场"；
- 各学科为"独立战场"；
- 学科内任务为"战场内的战斗"；
- 全战场作用于独立战场，独立战场反作用全战场，独立战场之间互有联系；
- 主控军师作为总战场的指挥，决定各学科战略地位与资源分配。

### 6.3 学校现实反馈闭环（上位约束，已确认）

- **学校是学业军师作用于学生、学生反作用于学业军师的真正现实检验场**；
- 完整闭环：学校教学与评价 → 学生获得真实任务与结果 → 学生反馈学校证据 → 证据系统登记处理追溯 → 学业军师调整全局与学科规划 → 学科专家教与授 → 学生回到学校实践 → 学校再次检验；
- 学生上传的是持续增加的学校现实证据流，而非一次性材料；
- 产品内部练习与判断不能自行证明教育效果；
- 没有学校现实反馈，学业军师只能形成封闭的产品内循环，不能证明真实价值。

### 6.4 学校反馈的最小闭环（已确认）

- 反馈内容：学校真实任务、教师批改/评分、错题要点、是否应用训练方法、新题型暴露问题；
- 以结构化结果摘要为主，完整材料按需补充；
- 学校证据必须真实，不能由产品内部训练替代；
- 教师批改（外部验证）、标准答案（参考）、考试分数（结果性）、学生自述（处境线索/待核实）四类分层；
- 反馈节奏：关键节点、连续结果积累到可判断时反馈，不逐任务强制；
- 未上传结果：标记缺少学校证据、降低需现实证据支持的判断强度、温和提醒，不假装已验证；
- 影响分层：单次小幅变化记待观察→可能影响当前任务；连续同类结果→影响学科内部；学科趋势/重要考试→影响学科层；跨学科失衡/时间冲突/方向存疑→上升全学科总战场；
- 调整条件：连续、可解释、有来源的结果表明规划需修正时才调整，并保存证据、范围与原因。

### 6.5 证据调用权（已确认）

- 原始材料：保留在证据底层设施中，仅向相关任务提供最小必要访问；
- 已归类证据：按层级调用（学科专家→学科战场军师→总军师→家长）；
- 学生主观自述：谨慎处理，标为待核实，家长不读取；
- 跨学科、跨会话证据：不自动开放，经总军师显式组织或召回；
- 家长：只接收整理后学业摘要，不读取原始证据；
- 学生：可了解证据用途、纠正、撤回特定用途、删除，但必要审计记录保留；
- 原则：最小够用、分层授权、跨域受限、原始保留、学生主体。

### 6.6 学业资产（已确认）

- **本质**：学生在真实学习实践中形成，并经过证据支撑、整理提炼和学生确认后，能够持续用于理解、行动、复盘与自我修正的个人化学业认识。
- **与能力关系**：证据层（发生了什么）→ 资产层（沉淀了什么认识）→ 能力层（能否独立使用）。资产是从证据走向能力的中间承接层。
- **最小价值单元**：由证据支持、经复盘、被学生确认，并能够指导下一次行动的个人学习认识。
- **四类**：知识理解、错误认识与修正、学习方法、复盘经验沉淀。
- **价值证明**：不由数量/字数/入库率证明，而由"是否被学生理解、在新任务中复用、影响后续行动并接受新证据检验"证明。

### 6.7 证据、资产、会话、记忆四者关系（已确认）

| 对象 | 核心回答 | 生命周期 |
|---|---|---|
| 证据 | 发生了什么、依据是什么 | 可追溯、可复核、可失效 |
| 学业资产 | 学生沉淀了什么个人认识 | 有版本、可修订、可归档 |
| 会话 | 当前这一轮在做什么 | 有边界、可结束、可归档 |
| 记忆 | 军师跨会话保留的受控理解 | 跨会话、可见、可纠正、可删除 |

- 会话内容不自动成为证据（需有来源、时间、关联、可区分原话/提取/推断、可复查）；
- 证据不自动成为资产（需提炼、关联、学生确认、复验）；
- 资产不自动进入记忆（需确认、有持续价值、可见可纠正）；
- 会话结束执行受控蒸馏：临时上下文不持久化、过程证据入证据系统、待确认保留为候选、已确认按规则入资产/记忆、未决事项留作恢复线索。

### 6.8 完整运作模型（已确认）

三个相互嵌套的循环：
1. **现实反馈循环**：学校任务 → 学生实践 → 学校评价 → 学生反馈 → 学业军师调整；
2. **产品学习循环**：理解 → 教与授 → 学生行动 → 检验 → 反馈；
3. **全学科协调循环**：总军师理解整体 → 学科任务分配 → 各学科战场推进 → 学科结果上报 → 全局重新布局。

学校现实是上位边界，贯穿全程；监察贯穿各层关键交接；学业资产与跨会话记忆是条件性分支，非每轮必经；学生是最终主体。

### 6.9 上下文与会话治理（重点专题，已确认）

- 判断权重必须逆转：学业军师要确保 **证据 > 受控记忆 > 当前上下文**，防止上下文污染证据、产生伪记忆、伪证据；
- 上下文是受限工作区，不是记忆也不自动成为证据；用完收缩、切换或结束，不无限累积；
- 记忆是受控的：满足准入条件、可查看纠正删除重置、不能因"出现过就成立"；
- 证据是硬约束：需要证据支撑的判断必须有证据，上下文与证据冲突时以证据为准并标注；
- 会话按责任域分板块：全战场/学科战场/证据/资产独立对话，一会话只解决一件事，前端独立窗口由底层会话、上下文、权限、证据和 Agent 责任隔离支撑；
- 自动生命周期：即使学生一直开着窗口，底层也要在任务完成、上下文接近安全边界、主题变化、长时间暂停、证据异常或不可逆变化时自动治理，不依赖学生关闭窗口；
- 学生立场：面向完全不懂 Agent 的学生，做到简单、直白、清晰、响应快、出错立改；
- 产品质量标准：治理能力、操作与学习成本、速度响应，是产品核心验收方向。

### 6.10 监察底层设施（已确认）

- 学业军师内建监察底层设施，由专门监察 Agent 对重点 Agent 及关键交接进行独立核验，证明产品不是空有其表、外强中干；
- 三类监察：确定性规则校验、抽样监察（低风险稳定 Agent）、深度监察（总军师/学科战场军师/证据治理 Agent/关键教与授 Agent）；
- 监察结果可触发补证、复核、暂停、纠正、回滚、扩大监察；
- 证据设施证明"依据是什么"，监察设施证明"谁做了什么、是否合规、结果是否可靠"。

### 6.11 家长推送生命周期与方式（已确认）

- 节奏：以周期性学业概览为主，以关键状态变化推送为辅，普通学习事件不逐条打扰；
- 即时推送：仅用于影响阶段规划、需家长及时提供学习条件、影响学科协调的重大变化；
- 学生控制：学生不拥有逐次关闭或限制学习内容推送的权利，但推送范围由底层规则严格限定为学习内容，不扩展为私人信息或家长监控；
- 家长反馈：进入证据系统，经来源登记、归类、对照、影响范围判断、必要时重新检验后，才可能影响学科或全局规划；不能自动覆盖学生证据、判断或资产；
- 内容生命周期：产生 → 推送 → 更新 → 旧版标记失效 → 保留追溯。

## 七、实现方式与工程设计（阶段 5）

### 7.1 0.5→1 总原则（已确认）

> 复用优先 ＞ 改造 ＞ 受控整合 ＞ 必要重构 ＞ 最后自建。

- 0.5→1 不是某一个底座的改造路线，而是学业军师整个产品的开发总原则；
- 凡是已存在、可验证、与产品目标相容的开源项目、成熟模块、工具、协议或工程能力，都应优先纳入复用、改造、重构、整合的候选范围；
- 机械拼接、无治理缝合、目录照搬不属于合格的整合。

### 7.2 DeepTutor 底座候选（已确认，非唯一）

- DeepTutor 是优先评估的底座候选，不是唯一候选，也不是预先确定的最终答案；
- 可复用：Agent 运行时、知识库/引用/检索、学习/练习/测验、工程纪律等（均须逐项核验）；
- 必须自建/深度改造：证据底层设施、全局/学科战场分层、责任域会话、证据优先判断、学校现实反馈、学业资产、监察、家长学习推送、学科因地制宜专家集群；
- 须删除/降级：与学业军师核心闭环无关的广谱内容域（Co-Writer、沉浸式视频、无关多 Agent 研究等）；
- 底座与产品本体边界：DeepTutor 可替换，学业军师产品本体不能被底座决定。

### 7.3 产品能力地图（已确认）

**核心本体（必须自持）**：全学科总战场+多层 Agent 协作、证据底层设施与证据治理、学校现实反馈闭环、学业资产确认与生命周期、证据>记忆>上下文机制、责任域分域会话、监察设施与质量门槛。

**可优先复用/改造**：Agent 运行时、会话持久执行、工具编排、知识检索引用、多层 Agent 协作、前端工作台、测试评估观测部署、认证权限审计。

**学科知识/教与授/练习检验**：能力可复用，但闭环必自持。

**必须自行定义掌握**：学生主体与军师边界、全学科协调逻辑、证据本体、学业资产本质、会话责任域划分、证据优先机制、监察质量标准、家长推送边界、学科因地制宜教与授。

### 7.4 复用边界（已确认）

- 复用外部项目第一判断：能否承接一项明确产品责任，且不破坏已确立的产品边界；
- "相似、成熟、活跃"都不作为第一判断；
- 可试用：承接明确责任 + 边界兼容 + 输入输出清楚 + 状态权限可控 + 依赖可接受 + 可验证 + 可回退；
- 立即排除：职责不清/重叠、破坏本体边界、依赖或许可证不可控、无真实验证、无法回退、需大量 hack；
- 越靠近产品本体（证据、资产、会话、权限），对复用的宽容度越低；
- 外部项目与学业军师核心原则冲突时，优先守住学业军师本体；
- 决策由产品负责人最终拍板，不能由开源项目反向决定。

### 7.5 单学科最小教与授闭环（已确认）

- 第一学科选择：优先由"能否持续、真实、可获得其学校材料与反馈"决定，而非抽象学科难度；
- 首版必备：材料证据归类、学科战场承接、学科教与授（讲解/练习/检验）、学校结果回流、证据优先与责任域会话；
- 最优先验证："教与授能否真正承接规划、产生真实学习，并在学校现实中被检验"；
- 真实材料不足时：只处理确有真实材料的场景、建立最简证据入口、有限度使用少量真实学校结果、学生参与确认、证据不足时降低确定性、不用模拟数据冒充真实教育验证。

### 7.6 模拟评测（已确认）

- 模拟评测可以做，且必须做（客观资源不足条件下推进机制验证的最合理手段）；
- 只能验证机制与工程运行（证据、会话、监察、Agent 协作、记忆积累）；
- 不能冒充真实教育效果验证；
- 模拟评测通过 = 机制完整，不等于教育有效；
- 真实学生小样本验证（哪怕 3-5 个）后置，有真实学生时立即做。

### 7.7 自生长自进化（已确认）

- 必须纳入长期架构，是学业军师长期（至少六个月）价值所在；
- 只能生长"对学生的理解"（偏好、有效方法、错误模式、稳定水平、确认资产）；
- 绝不能改变产品规则、最高边界、学生主体、证据纪律、权限安全、不可逆状态、未经确认资产；
- 策略/方法自生长必须：候选 → 沙箱验证 → 确认 → 可回滚 → 标注来源时间 → 不自动成为决策 → 无效清理；
- 自生长的机制可用模拟评测验证，价值只能由真实长期使用验证。

### 7.8 自生长与学生主体（已确认）

- 对学生的长期认识以可见、可修正、可纠正、可删除为底线；
- 理解学生的目的是帮助学生，而不是利用学生；
- 凡利用深入理解诱导、施压、操控或隐瞒信息的行为，一律被证据纪律、监察和确定性边界拦截；
- 自生长让学生越用越懂学生，但越懂越应尊重学生自主。

### 7.9 前端呈现边界（已确认）

学生前端以五个第一性问题为设计骨架：
1. 我在哪里，该做什么；
2. 我为什么做；
3. 做了之后怎么办；
4. 我做的东西存在哪里；
5. 我怎么去看见这些东西。

对应呈现模块：全学科路线图+当前任务表、任务依据与目标关系、结果检验+下一步、学业资产仓库、清晰导航+学生控制入口。

**呈现总原则**：简单、清晰、直白、实用主义；不花里胡哨；呈现内容以能否帮助学生理解、行动、控制为唯一衡量标准。

**学业资产特殊地位**：必须独立、可视化呈现，作为学生"个人学习仓库"，是"我积累了什么"和"我怎么看见积累"的载体。

### 7.10 战场模型前端（已确认）

- 学业军师前端以"战场"为总呈现框架；
- **前线**（紧要工作）：可视化地图、学生理解程度、当前任务等；
- **后方**（物资囤积）：学业资产等长期积累；
- 战场是学生理解产品的呈现框架，底层仍是已确认的责任域、证据纪律、会话治理与监察系统；
- 战场语言用于让学生好懂，不是为了掩盖产品真实运行。

### 7.11 军师角色：参谋长兼指挥者（已确认）

- 学生一上来不会使用 Agent 产品、无指挥基础能力；绝大多数学生若自己指挥会陷入"当局者迷"；
- 因此军师必须担任"参谋长 + 指挥者"，明确布置当前任务与方向，带动学生行动；
- 但军师指挥的是执行层面（现在做什么、怎么做），学生保留的是主体层面（方向对不对、要不要走、是否停止）；
- 分层：日常执行（军师指挥）→ 方向确认（学生知情确认）→ 重大变化（学生决定是否接受）→ 拒绝/纠正（军师尊重并调整）→ 不可逆/长期（学生决定）。

### 7.12 主军师只做顶层调度编排（已确认）

- 主军师只负责最顶层的拍板、调控、编排；
- 分化出各专业 Agent/人格：战局研判（参谋部）、任务部署（作战部）、学科战场军师（各战线）、教与授 Agent（前线部队）、证据处理（情报部）、学业资产（后方仓库）、监察 Agent（督察机构）；
- 主军师是体系内唯一负责最高层整体决策的，其余专业工作分派给专业 Agent；
- 分化不等于碎片化、各自为政：必须建立在统一证据、责任、会话、监察体系之上；
- 每个 Agent 只负责一件事，不做全能选手，符合"术业有专攻"。

## 八、整体产品结构（汇总）

学业军师形成以下统一结构：

```text
学生（最终决定者，保重大方向决定权）
  ↕
主军师（总指挥部：顶层拍板、调控、编排）
  ├── 战局研判 Agent（参谋部）
  ├── 任务部署 Agent（作战部）
  ├── 学科战场军师（各战线指挥部）
  │   └── 学科专业 Agent（前线部队：教与授/练习/检验）
  ├── 证据处理 Agent（情报部）+ 证据底层设施
  ├── 学业资产 Agent（后方仓库）
  └── 监察 Agent（督察机构）+ 监察底层设施

统一底座：证据设施 · 会话治理 · 权限审计 · 学校现实反馈 · 学业资产 · 监察
```

**核心机制**：
- 证据 > 记忆 > 上下文；
- 一会话只解决一件事，按责任域分板块；
- 学校是现实检验场；
- 教与授承接规划，使学习真实发生；
- 自生长只长对学生的理解，不改变产品规则；
- 前端战场化：前线（紧要工作）+ 后方（学业资产仓库），简单直白实用。

## 十、关键矛盾与风险（记录）

访谈中识别出、需后续处理的核心张力：

1. **"驾驭 AI" vs "依赖 AI 无法识别错误"**：产品质量仍需可独立验证，需防止 AI 主导下的判断失真。
2. **学校现实反馈 vs 真实学生可得性**：模拟评测只能验证机制，真实教育效果须真实学生验证。
3. **自生长 vs 学生主体**：越懂学生越需尊重自主，防止操控。
4. **专业分化 vs 各自为政**：分化须建立在统一底座上，防止碎片化。
5. **军师指挥 vs 学生主体**：指挥执行层面，学生掌握方向与根本决定权。
6. **0.5→1 复用 vs 无原则拼接**：复用优先但不破坏产品本体。
