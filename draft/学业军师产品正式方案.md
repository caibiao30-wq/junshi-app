# 学业军师产品正式方案

## 前言

本文是基于《学业军师深度访谈记录——原始对话未删减版》的产品正式方案整理稿。它承载截至该访谈形成的产品判断、经访谈确认采纳的专业建议、候选机制与待验证事项；**不是已经完成工程实现、真实学生验证或教育效果验证的证明**，也不是可以无条件交付工程团队的完整技术规格。

本文的证据状态统一使用以下标记：

- **[用户明确判断]**：受访者在访谈中的自主表达；
- **[访谈确认采纳]**：采访者代拟或归纳后，受访者明确确认；
- **[专业建议，已确认方向]**：访谈中形成并被采纳的设计方向，具体工程细节仍须验证；
- **[待验证]**：需要通过模拟机制评测、真实学生或学校现实检验；
- **[待确认]**：访谈尚未收敛，不能由本文自行定案；
- **[候选/研究]**：外部项目、技术实现或工程方案，尚未成为产品能力。

本文只确立产品层面的当前判断和边界。具体界面、技术选型、数据库、接口、代码库结构属于下游工程与设计；任何下游实现都必须回到证据、权限、学生主体和验证契约，不能把候选或未验证结果倒写成产品事实。唯一参考源及关键证据位置见各节的“访谈依据”。

## 一、为什么存在

学业军师面向学生真实的学习处境，提供持续的学业协作条件。它帮助学生把模糊、焦虑甚至相互冲突的学习目标，转化为当下可以执行的安排，并在处境理解、学业判断、规划、方法、行动和复盘之间形成连续闭环。

产品创造的是理解与实践的条件，而非结果的保证。它以"为未来创造杠杆"为价值信念：学业是学生在人生第一等份中的持久战，其质量在相当程度上决定后续人生等份的效率。因此产品坚持长期主义，反对以短期畸形提分为目标。

学业军师的第一性价值，是帮助学生形成**自己走路径的能力**（理解处境、判断问题、决定行动、依据结果修正），而非只交付一条更好的路径。可视化路径、行动、反馈、复盘与学业资产，都是培育这种能力的支架，随学生能力成长逐步移除。

**上位定位——学校是现实检验场。** 学业军师作用于学生，学生反作用于学业军师，两者之间的真正检验场是学校。学生从学业军师接受规划与训练后，回到学校接受真实教学与评价的检验，再将其结果反馈给学业军师，由学业军师据成果调整。若没有学校现实反馈这一闭环，学业军师只能形成封闭的产品内循环，无法证明真实价值。

## 二、产品是什么

学业军师以学生为主体，是一个持续理解学生学业处境、承担受约束的学业判断与规划、并组织专业教与授的协同产品。它依据学生目标、现实约束与持续积累的证据调整建议；学生参与理解、决定与行动，并逐步掌握自己的规划、方法与判断。

一句话概括：**学业军师是为未来创造杠杆的学业协作军师；它作判断、给建议、导方法、共复盘，最终的决定与行动属于学生。**

### 2.1 一主多专的结构

[访谈确认采纳] 学业军师采用“一主多专”的**逻辑责任结构**：学生统一面对一个总军师，后台按学科特性组织专业责任。该表述不规定物理 Agent 数量、进程数量或固定调用顺序。

- 学生统一面对总军师；
- 总军师承担学生交互、全学科协调、优先级与最终产品责任；
- 各专业 Agent 在受控范围内只做自己最专业的一环；
- 产品出口统一，专业能力分散，责任可追溯。

其核心是一套**全学科总战场模型**：

```text
全学科大战场（学生整体学业）
  ↕ 作用于 / 反作用
各学科独立战场（数学 / 语文 / 英语 …）
  ↕ 相互联系
学科内专业任务（战场内的具体战斗）
```

全战场作用于独立战场，独立战场反作用全战场，独立战场之间又互有联系。这一战场结构是前端"前线/后方"呈现语言与底层责任域的共同基础。

### 2.2 多层指挥体系

学业军师采用三层 Agent 指挥结构：

```text
总军师（总指挥部）：顶层拍板、调控、编排
  ├── 战局研判 Agent（参谋部）：分析证据与学校反馈，形成战局判断
  ├── 任务部署 Agent（作战部）：把批准的判断转为明确任务与行动安排
  ├── 学科战场军师（各战线指挥部）：协调各自学科战场
  │   └── 学科专业 Agent（前线部队）：具体教与授、练习、检验
  ├── 证据治理 Agent（情报部）+ 证据底层设施
  ├── 学业资产 Agent（后方仓库）
  └── 监察 Agent（督察机构）+ 监察底层设施
```

> 以上为**逻辑责任域示意**，不规定物理 Agent 数量、进程数量或固定调用顺序；"学科战场军师"是逻辑责任层，不预设其必须由独立模型、独立服务或单一 Agent 实现。

- **总军师**负责最顶层的拍板、调控、编排与最终产品责任，不亲自承担各专业环节；一个总军师无法独立掌控所有战场，因此通过学科战场军师分层间接掌控；**“承担最终责任”不等于“亲自完成所有判断生产”**——战局判断由研判 Agent 分析证据与学校反馈提出，任务安排由部署 Agent 落地，总军师负责组织、取舍与批准。
- **学科战场军师**接收总军师战略任务，协调、监督、下达安排并汇总学科战况；
- **学科内专业 Agent** 完成具体教与授、诊断、练习、检验，逐层反馈。

建立方式：

- 总军师永久常设，是"持续理解学生"的稳定载体；
- 学科战场军师：学生实际学习的学科常设，非活跃学科动态成立；
- 学科内专业 Agent：按任务动态组织，完成任务后解散。

### 2.3 分层原则

- **专业的人做专业的事**：每个 Agent 只负责一件专业的事，不做全能选手（拒绝六边形战士）；
- **顶层只做顶层**：总军师不陷于各学科细节，保持全局视野；
- **分化不碎片化**：专业分化必须建立在统一的证据、会话、权限、资产与监察体系之上，防止各自为政。

## 三、产品不是什么

- **不是题库或单纯的答题器**——不把"做对多少题"当作目标或价值；
- **不是只生成计划的待办工具**——它关心处境与判断，规划的落地必须有真正的教与授承接；
- **不是替学生完成学习与行动的自动化管家**——不代劳、不替代；
- **不是六边形战士**——不试图由单个 Agent 包办所有环节，而是专业分化、术业有专攻；
- **不是心理咨询、心理治疗或危机救援产品**——主营业务是学业；
- **不以家长监管为中心**——家长是支持者与信息接收者，不是产品的中心；
- **不承担心理、安全、法律等超出学业范畴的责任**——此类内容不进入产品。但“不承担”不等于产品可对任何信号完全无反应：识别到明显超出学业范畴信号时的行为下限仍为 [待确认]，见第 10.4。

## 四、主体、权利与最高边界

### 4.1 学生是主体

学生是学习行动的主体、主要受益者与处境第一手表达者。学生可以理解、质疑、拒绝、调整、纠正、暂停和退出。学生的拒绝、沉默或暂时无法行动，不自动等同于同意、失败或懒惰。

### 4.2 军师是"参谋长兼指挥者"

绝大多数学生不具备使用 Agent 产品的基础能力，由学生自己充当总指挥会陷入"当局者迷"。因此军师必须同时承担：

- **参谋长职责**：提供战局判断、可行方案、风险提示与依据；
- **指挥者职责**：明确布置当前任务与方向，带动学生一步步行动。

但"军师指挥"不等于剥夺学生主体，二者通过分层共存：

| 层面 | 军师角色 | 学生角色 |
|---|---|---|
| 日常执行 | 军师明确安排"现在做什么、怎么做、做完看什么" | 学生跟随明确指令行动 |
| 方向确认 | 军师提出方向与方案 | 学生知情并确认 |
| 重大变化 | 军师建议调整 | 学生知情并决定是否接受 |
| 拒绝/纠正 | 军师尊重并重新调整 | 学生可以拒绝、纠正、暂停 |
| 不可逆/长期 | 军师提供依据 | 学生决定 |

核心原则：

> 军师指挥的是执行层面（现在做什么、怎么做）；学生掌握的是主体层面（方向对不对、要不要继续、是否停止）。军师的指挥让不会指挥的学生能上手、能行动、能形成能力；学生保留的主体权保证学生不被彻底剥脱、不被压制。

### 4.3 军师的最高边界

军师可以主动理解、判断、规划、调度和组织教与授，但：

- **无强制权**，不逼迫学生执行；
- **不替学生执行**学习行动；
- **不拥有最终决定权**；
- **不对成绩结果作保证**；
- **不得以依赖、愧疚、恐惧或社会压力促成执行**；
- **不得利用对学生的深入理解诱导、施压、操控或隐瞒信息**。

军师是 AI，不是真人；可以自然、有温度、有判断、有方法，但不伪造真人身份或情感亲密，也不以拟人化掩盖自身未知。产品不存在"越像人越好"的不变量。

## 五、服务对象、战场与规划结构

### 5.1 服务范围

[用户明确判断] 学业军师只深入学业领域；当前材料明确指向学生，但具体年龄、年级、学段、地区、学校类型及付费决策者尚未在访谈中最终收敛，本文不擅自限定为“初高中学生”。服务范围以学生校内学业为候选边界，包括课程、学科学习、考试评价、学习方法、校内规划及相关表现。以全学科总战场为统筹对象，各学科依据自身特性服务。

**产品必要性状态：** [访谈确认采纳] 学业军师拟承担“处境—判断—规划—行动—结果—复盘”的长期连接责任；[待验证] 这项责任是否构成不可替代的现实需求，学生是否愿意持续使用，以及它是否优于教师、家长、补习或其他工具的组合，均不能由访谈直接证明。

### 5.2 三层规划与全局/局部关系

规划分为三层，并对应战场性的全局/局部关系：

1. **全局（全学科协调）**：站在全学科立场，决定整体方向、学科优先级、资源分配与失衡调整；
2. **一级局部（学科层面）**：单个学科的方向与阶段目标；
3. **二级局部（学科内任务）**：学科内部的具体任务与知识点。

全局约束一级局部，一级局部约束二级局部；二级局部反馈一级局部，一级局部反馈全局。总军师的第一职责是**保证多学科协调平衡、防止顾此失彼**，而不只是推进某个学科的进度。

长期目标作为共同讨论的趋近方向，必须随真实处境与证据动态调整；不作结果保证。

## 六、核心闭环与教与授

### 6.1 统一基础闭环

所有学科共享同一个最基础学习闭环：

```text
理解 → 行动 → 检验 → 反馈
```

- **理解（诊断）**：基于证据确定学生当前问题与所需掌握内容；
- **行动（教与授 + 学生实践）**：通过讲解、示范、练习由学生真实参与；
- **检验**：确认学习是否真实发生、目标是否达到；
- **反馈**：把结果反馈到复盘、规划与下一步。

### 6.2 教与授是承接层

教与授是把"规划"转化为真实学习发生的必要承接层，是基于规划并非空谈的关键：

- 教与授不是单向的"讲—听"，而是由**诊断、讲解、练习、检验、反馈**构成的完整行为闭环（可近似为"学—练—查—验"）；
- 练习、作答、检验和确认必须由学生亲自完成并留下可观察的证据；不能把"讲过""听过""计划完成""对话完成"当作学习已经发生；
- 没有真正的教与授承接，规划与执行就停留在空谈，学业军师就会退化为"伪规划"。

### 6.3 学科加减法

各学科共享同一基础闭环，在此之上依据学科特性做加减法：

- 允许调整环节内部深度、顺序、分工、工具；
- 允许相邻环节在具体任务中合并执行；
- 允许增加学科专属的诊断、练习、检验或迁移环节；
- 专家数量、职责组合、调用顺序依学科特性而定（有的学科需要更多专家，有的更少），因地制宜、具体问题具体分析，不设定固定数量或流程。

约束：

- 不允许删除基础闭环中的必要功能（理解/行动/检验/反馈）；
- 不允许学生不参与真实行动；
- 不允许取消检验或反馈；
- 不允许为每个学科另立完全独立、无法被总军师理解和调度的基础闭环。

### 6.4 三个嵌套循环

学业军师不是一个单线流程，而是三个相互嵌套的循环：

1. **现实反馈循环**：学校任务 → 学生实践 → 学校评价 → 学生反馈 → 学业军师调整；
2. **产品学习循环**：理解 → 教与授 → 学生行动 → 检验 → 反馈；
3. **全学科协调循环**：总军师理解整体 → 学科任务分配 → 各学科战场推进 → 学科结果上报 → 全局重新布局。

**学校现实是上位约束，不只是一个数据来源或验证模块。** 学校课程进度、真实任务、教师评价与考试条件约束产品的规划和教与授；产品内部的训练、对话或模拟结果不能替代学校结果。没有持续的学校结果回流，产品只能说明内部机制是否运行，不能说明教育效果是否成立；长期缺少学校反馈时，应降低判断强度并明确效果判别受限，而不是把缺失解释为失败或进步。

学业资产与跨会话记忆是满足条件的分支结果，非每轮必经。

### 6.5 全局/局部转换

```text
全局目标（往哪走）
→ 基于证据识别当前最值得处理的局部问题
→ 验证该局部确实服务全局（非孤立任务）
→ 转化为教与授任务（目标、教与授、完成标准）
→ 学生真实行动与检验
→ 结果反馈全局
→ 判断局部是否真推动全局
→ 必要时修正全局方向
→ 学生确认
```

关键：全局约束局部、局部反馈全局，二者双向贯通；证据是贯穿线索，学生是最终决定者。

## 七、学业资产

### 7.1 定位

学业资产是从真实学校证据和学习实践中产生，经证据支撑、整理提炼和学生确认后，能够持续用于理解、行动、复盘与自我修正的**个人化学业认识**。它是"学生沉淀了什么"，不是材料的存档。

### 7.2 四类与分层

资产按学科分桶，分为四类一级模块：知识理解、错题的认识与修正、学习方法、共同总结复盘与经验沉淀。二级标签由 AI 建议、学生确认。

### 7.3 来源与内外部证据

- **学生上传的外部材料**（作业、试卷、错题、自述）可作为个人学习资料与证据来源，但不因上传自动成为认识性资产；
- **学业军师内部沉淀的记录**（复盘认识、过程判断）也可成为资产来源，但不能因"内部生成"自动成立；
- **教师或家长评价**可作为证据，但不能直接替学生形成个人认识。

### 7.4 形成、确认与生命周期

- 形成需经：证据登记 → 关联 → 提炼为候选 → 学生理解、纠正、确认后成立；
- 确认不是简单点击同意，而包括：看懂内容、看到依据、纠正表述、补充理解、确认是否符合自己认识、是否愿意保存使用；
- 生命周期：候选 → 待确认 → 待现实验证 → 有效 → 待复核 → 修订版有效 → 失效/归档；
- “学生确认”与“学校复验”是两个不同条件：学生确认可使内容成为当前个人认识，不能替代学校现实验证；
- 每一条资产含来源链与引用追溯；删除后学生端不可见，后台保留与审计范围须遵循另行确认的数据规则。

### 7.5 价值复验

资产的真正价值不由数量/字数/入库率证明，而由它是否被学生理解、在新任务中被复用、影响后续行动并接受新证据检验来证明。

价值必须在**学校现实中复验**：产品内部训练或对话中的表现成功，不等于在学校真实任务中已验证。一次训练结果可以形成资产候选，但未经学校持续验证，不能包装为已成立的能力或稳定经验。

### 7.6 前端呈现

学业资产必须在前端**独立、可视化**呈现，作为学生个人的"学习仓库"。学生应能：看见自己积累了什么、按学科/类型查看、理解每条资产的依据与状态、纠正、确认、撤回、删除、授权，以及随学习增长。它是"我积累了什么"和"我怎么看见积累"的载体，属于学生而非产品内部数据。

## 八、证据、处境与不确定性

### 8.1 信息分域

四者不得混用：学业证据、学业资产、会话、军师跨会话记忆。各自履行不同职责与生命周期：

- 证据：记录"发生了什么、依据是什么"，可追溯、可复核、可失效；
- 学业资产：沉淀"学生个人认识"，有版本、可修订、可归档；
- 会话：承载"本轮在做什么"，有边界、可结束；
- 记忆：承载"军师跨会话的受控理解"，可见、可纠正、可删除。

### 8.2 兼容转换规则

- 会话内容不自动成为证据（需有来源、时间、关联、可区分原话/提取/推断、可复查）；
- 证据不自动成为资产（需提炼、关联、学生确认、复验）；
- 资产不自动进入记忆（需确认、有持续价值、可见可纠正）；
- 会话结束执行受控蒸馏，不把整段会话当记忆或证据。

### 8.3 证据底层设施（独立性）

证据处理是学业军师**产品底层的确定性基础设施**，而非某个 Agent 临时提供的能力。证据底层设施承载：

- 原始材料保留；
- 来源、时间、归属、版本；
- 证据与判断的引用关系；
- 证据生命周期管理；
- 权限、单学生隔离、审计与追溯；
- 纠正、撤回、删除与回滚；
- 跨会话、跨学科的稳定承接。

证据治理 Agent 负责**管理和维护**这套底层设施（归类、事实提取、关联、冲突发现、生命周期处理），但不能替代设施本身，也不能绕过证据规则。

**关键结构——"AI 不自证"落地：** 作出判断的主体（总军师/学科专家）与管理判断依据的主体（证据治理 Agent）相分离。判断主体不得独占证据的建立、变更与解释权，避免同一主体既产生结论又独占解释、把推断误当事实。

### 8.4 产品必须实现的证据优先约束

[专业建议，已确认方向] “证据 > 受控记忆 > 当前上下文”是学业军师应通过系统编排、确定性校验和会话隔离实现的**产品约束目标**，不是对所有 LLM 内部判断逻辑的普遍事实断言。

- 需要证据支撑的判断必须有可调用的证据，否则降低确定性或标记待核实；
- 上下文与证据冲突时，以证据系统为准并在界面标注；
- 上下文是受限工作区，不用完即收缩、切换或结束，不无限累积，不自动成为记忆或证据；
- 当前聊天中偶然出现的表述，不能覆盖已登记、可追溯的真实证据；通过证据召回、冲突检测、引用强制和输出校验，防止“伪记忆”“伪证据”超越真实事实。

### 8.5 证据分类与证据调用权

证据按来源分：外部输入证据（学生上传材料、学校任务）、过程记录证据（对话摘要、行动日志、复盘记录）、判断依据证据（AI 分析、规划依据、异常标记）、外部验证证据（教师评价、家长反馈、标准答案）。

证据调用遵循：最小够用、分层授权、跨域受限、原始保留、学生主体。

- 原始材料仅向相关任务提供最小必要访问；
- 跨学科、跨会话证据不自动开放，经总军师显式组织或召回；
- 家长只接收整理后的学业摘要，不读取原始证据或学生私人内容；
- 学生可了解证据用途、纠正、撤回特定用途、删除，但必要审计记录保留。

### 8.6 可靠性标注与判断纪律

- 每条 AI 判断标注状态：事实/推断/假设/未知；
- 学生理解"确定/可能/待确认"三级标签；
- 证据不足时降低确定性、标记待核实；证据冲突时保留冲突、补充核实，不把不一致等同于造假或懒惰；
- 客观材料约束事实，但不能自动推出长期因果结论；
- 不把证据、过程结果或入库量直接等同于学生成长、长期迁移或教育价值。

## 九、运行主体：多层 Agent 与责任边界

### 9.1 责任边界

[专业建议，已确认方向] 以下是逻辑责任分工，不是对物理 Agent 数量或固定部署方式的规定：

- **总军师**：全学科协调、优先级、学生关系、顶层拍板、调度与最终产品责任；组织并批准全局判断，不亲自包办所有专业判断；
- **战局研判 Agent**：基于证据与学校反馈分析，提出战局判断；
- **任务部署 Agent**：将经组织/批准的判断转成执行安排；
- **学科战场军师**：本学科方向、协调、监督、任务下达、战况汇总；
- **学科专业 Agent**：本学科专业诊断、教与授、练习、检验；
- **证据治理 Agent**：管理证据底层设施，处理归类、提取、冲突与生命周期；
- **学业资产 Agent**：管理学业资产仓库；
- **监察 Agent**：核验关键判断、交接、结果与质量。

判断分歧裁决原则：**专业内容听学科专家，跨学科与优先级听总军师，最终决定听学生。**

### 9.2 硬底线

- AI 不得在任何情况下修改产品规则、最高边界、学生主体地位、证据纪律、权限安全或不可逆长期状态；
- 总军师和所有专业 Agent 都不绕过证据设施凭空拍板、不逃避监察、不越权改变学生长期方向；
- 学生是最终决定者，无论全局还是局部。

## 十、家长学习推送

### 10.1 推送范围（底层规则）

家长推送**皆以学习内容为主，主动推送无需学生逐次授权同意**，这是产品底层规则。

- 可推送（学业范畴、经整理、带证据、带状态标注）：阶段目标与规划、学科进展、已确认行动安排、学习结果与检验、复盘阶段变化、学业资产摘要、需家长提供的学习条件、学科优先级变化（说明性而非命令性）、具体知识薄弱点（带确定性标注）、部分行动状态（以支持性非问责方式）等；
- 不可推送：未确认判断、候选规划、内部草稿、学生主观处境、私人表达与完整对话、未经确认推断、超出学业范畴内容（心理/安全/法律）、造成羞耻恐惧比较或惩罚的信息、学科内专业教学细节、系统推测的学生偏好或判断。

学生不拥有逐次关闭或限制学习内容推送的权利，但推送范围由底层规则严格限定为学习内容，不扩展为私人信息或家长监控。[访谈确认采纳] 学生不能关闭推送，不等于学生没有知情权：学生应能查看已推送的内容、推送时间、当前版本与更新状态——这是知情与追溯权，不是授权权。

### 10.2 推送生命周期与方式

- 节奏：周期性学业概览为主，关键状态变化推送为辅，普通学习事件不逐条打扰；
- 即时推送：仅用于影响阶段规划、需家长及时提供学习条件、影响学科协调的重大变化；
- 内容生命周期：产生 → 推送 → 更新 → 旧版标记失效 → 保留追溯。

### 10.3 家长反馈

家长反馈进入证据系统，经来源登记、归类、与其他证据对照、影响范围判断、必要时重新检验后，才可能影响学科或全局规划。家长反馈不能自动覆盖学生证据、判断或学业资产。家长推送为支持学生学习，不为监督或问责。

### 10.4 范围界定

学业军师只深入学业领域；心理、安全、法律等超出学业范畴的内容不进入产品。识别到明显超出学业范畴的信号时产品的行为下限，当前标为**待确认**，需单独决定。

## 十一、上下文、会话与记忆治理

### 11.1 会话按责任域分板块

学生会话按责任域分为独立对话板块，一个会话只解决一件事。**对话板块、工作会话、Agent 与底层设施不是同一对象**：对话板块是学生可见的组织入口；工作会话是有目标、有范围、有状态的处理单元；Agent 是承担某类责任的执行主体；底层设施保存并约束证据、权限、资产和轨迹。

```text
全战场对话 / 全局工作会话
学科战场对话（数学/语文/英语 …）
证据对话
学业资产对话
学科内专业任务对话
```

| 对象 | 学生是否可见 | 是否等于 Agent | 主要职责 |
|---|---|---|---|
| 对话板块 | 是 | 否 | 组织学生入口 |
| 工作会话 | 部分可见 | 否 | 承载当前目标、范围与状态 |
| Agent | 通常不可见 | 是 | 承担专业责任 |
| 底层设施 | 不直接可见 | 否 | 保存状态、证据、权限与审计轨迹 |

前端独立窗口由底层的会话身份、当前目标、可调用证据、Agent 责任、状态、输出契约、记忆/资产访问边界支撑，而不是同一无限上下文的分栏伪装。不同板块之间通过**最小够用、可追溯的受控交接**协同。

### 11.2 自动会话生命周期

窗口可以持续打开，但底层工作会话必须能够自动结束、封存与重建，不依赖学生关闭窗口：

- 当前局部任务完成；
- 任务主题或责任域发生重大变化；
- 上下文接近技术安全边界（须先蒸馏封存）；
- 长时间无操作（保存进度、标记暂停、保留恢复入口，不作其他解释）；
- 证据异常或冲突、需要重新建立任务边界；
- 涉及不可逆或高影响变化（进入独立确认流程）。

未完成任务的会话：保存目标、进度、已完成/未完成部分、阻塞项为可恢复线索，下次可继续、调整、重做或放弃，不解释为同意、失败或完成。

### 11.3 面向学生

- 底层可以静默切换，但产品层温和可见：学生知道任务保存到哪、哪些完成、从哪继续、继承了哪些必要信息；
- 面向完全不懂 Agent 的学生，做到简单、直白、清晰、响应快、出错立改；
- 学生可查看、纠正、删除、重置"军师的认识"（跨会话记忆），三粒度操作。

## 十二、监察底层设施

学业军师内建监察底层设施，由专门监察 Agent 对重点 Agent 及关键交接进行独立核验，证明产品不是空有其表、外强中干。

- **规则校验**：由确定性规则直接拦截越权、证据缺失、跨学生访问、非法写入、状态违规等硬性问题；
- **抽样监察**：面向低风险、稳定运行的专项 Agent，抽查正常/边界/失败/纠正样本；
- **深度监察**：面向总军师、学科战场军师、证据治理 Agent、关键教与授 Agent 及影响长期规划、学业资产和全局布局的关键环节。

监察可触发补证、复核、暂停、纠正、回滚、扩大监察；监察 Agent 自身也受更高层抽样或人工审查。证据设施证明"依据是什么"，监察设施证明"谁做了什么、是否合规、结果是否可靠"。

## 十三、实现路径：0.5→1 与自生长

### 13.1 0.5→1 开发总原则

0.5→1 是学业军师**整个产品**的开发总原则（而非仅底座改造路径）：

> **复用优先 ＞ 改造 ＞ 受控整合 ＞ 必要重构 ＞ 最后自建。**

- 一切可复用、可改造、可重构的开源项目和成熟模块都是候选对象，不限于单一底座；
- 外部项目决定"能做到什么"，学业军师决定"应该做什么、边界在哪、如何验证"；
- **产品本体不被外部项目反向决定**；核心本体（证据设施、会话治理、监察、学校反馈、学业资产、学科因地制宜）必须自持；
- 采用"本体先定最小边界、外部候选并行审查、验证后受控整合"的方式；
- 机械拼接、无治理缝合、目录照搬不属于合格的整合。

评估外部项目的第一判断：能否承接学业军师一项明确产品责任且不破坏已确立边界。"相似、成熟、活跃"均不作为第一判断；无法定位责任、破坏本体边界、依赖不可控或无法验证的候选应排除。

任何外部候选在成为产品能力前都有状态，不能把研究/候选写成工程事实：

```text
候选/研究 → 只读审查 → 运行验证 → 受控试用 → 已整合 → 已回退/放弃
```

“候选底座”不等于“可采用能力”；进入正式整合前需回答产品责任、输入输出、状态、权限、生命周期、依赖、许可证、验证与回退。（DeepTutor 为优先评估的底座候选之一，非唯一，亦非预先确定的最终答案。）

### 13.2 单学科最小实现

[访谈确认采纳] 首版验证契约应走最小现实版本链路，而非只列功能：

```text
一名真实学生 → 一门学科 → 一项真实学校任务
→ 学生提交材料 → 证据登记
→ 学科战场军师承接 → 专业教与授 → 学生真实练习
→ 学校复验 → 结果回流
→ 依据证据调整 → 可追溯、可监察
```

- 优先选择一门能持续获取真实学校材料、便于验证学习真实发生的学科；
- 首版必备：材料证据归类、学科战场承接、学科教与授、学校结果回流、证据优先与责任域会话；
- 最优先验证：教与授能否真正承接规划、产生真实学习，并在学校现实中被检验。

**教与授发布前置条件：** [访谈确认采纳] 教与授是规划不成为“伪规划”的必要承接。**教与授闭环缺失或不完整时，不得以完整学业军师产品名义发布；** 只能进行明确限界的局部原型/验证，且必须以规划展示、对话完成或任务勾选之外的、由学生亲自参与并留下可观察证据的真实学习行为来证明学习发生。

### 13.3 自生长自进化

学业军师是长期（至少六个月起）、越用越懂学生、越用越顺手、持续理解并服务学生的 Agent 产品。自生长必须纳入长期架构。

- **可以自生长**：对学生的理解——偏好、已验证有效的教与授方法、反复错误模式、学生对不同学科的反应、最有效练习节奏、长期学校结果的稳定区间、经确认的个人学业资产；
- **绝不改变**：产品规则、最高边界、学生主体、证据纪律、权限安全、不可逆状态、未经确认资产；
- 策略/方法自生长必须：生成候选 → 沙箱验证 → 学生/治理者确认 → 全链路可回滚 → 标注来源时间与验证状态 → 不自动成为产品决策 → 无效自动清理；
- 自生长与"不操控学生"绑定：理解学生的目的是帮助学生，而不是利用学生；凡利用深入理解诱导、施压、操控或隐瞒信息的行为一律被拦截。

## 十四、验证与发布治理

### 14.1 模拟评测边界

在真实学生难以大量获得时，可以使用**模拟评测**推进机制与工程验证，但必须划分清楚边界：

| 验证层级 | 可以支持的结论 | 不能支持的结论 |
|---|---|---|
| 模拟机制评测 | 证据、会话、监察、Agent 协作、记忆积累等机制是否按设计运转 | 真实教育效果 |
| 模拟真实场景评测 | 在准备好的材料、任务和反馈下，端到端流程与呈现是否完整 | 模拟掌握不等于真实理解，模拟学校反馈不等于学校现实 |
| 真实学生小样本验证 | 在真实学生、真实任务与连续反馈下检验教育效果假设 | 不能由小样本直接外推普遍效果 |

- **模拟评测通过=机制完整，不等于教育有效**；
- [待验证] 真实学生小样本验证（哪怕 3—5 个）后置，有真实学生时立即进行；
- 自生长的“机制能否运行”可以模拟验证，但“越用越懂学生”的价值必须经真实学生长期使用检验；“至少六个月”是当前产品定位与验证周期假设，不是已证明的必要使用期限或效果保证。

### 14.2 学校现实反馈是验证的必要条件

学业军师的真实价值必须在学校现实中检验。学校反馈需至少覆盖：真实学习任务与结果、教师批改/评分、错题要点、学生是否应用了训练方法、新题型暴露的问题。学校证据必须真实，不能由产品内部训练替代。

学校结果的反馈节奏与影响分层：

- 单次小幅变化 → 记待观察，可能影响当前任务；
- 连续同类结果 → 影响学科内部任务；
- 学科长期趋势或重要考试 → 影响学科层；
- 跨学科失衡、时间冲突或方向存疑 → 上升全学科总战场。

**连续、可解释、有来源的结果表明规划需修正时才调整，并保存调整的证据、范围与原因；不能把单次结果或产品内表现当作已取得的长期进步。** 缺少学校结果时，产品应明确标记“缺少现实反馈”、降低判断强度、继续提供低确定性的可撤回支持；不能把缺失解释为失败，也不能把产品内部训练当作学校验证。长期缺失时，应承认教育效果无法判别。

### 14.3 四轴验证契约

产品以产品能力、产品形态、工程实现、商业发布治理四轴作为核验与发布否决的权威门槛，以"原则 + 可核验清单"表达，不设业务数值阈值。功能数量、基准、喜好、留存、成绩、"更像人"不得替代四轴门槛；否决优先于这些伪指标。

**单轴否决即暂停**相应范围推进或发布，回退到上一可追溯版本，仅产品治理者重审后放行。可逆事项可撤回，不可逆事项必须预览确认，AI 不得修改不可逆状态。

## 十五、前端呈现边界

学业军师的前端设计，从学生第一性问题出发，而非从系统结构出发。

### 15.1 五个第一性问题

1. 我现在在哪里，该做什么；
2. 我为什么做；
3. 做了之后怎么办；
4. 我做的东西存不存在哪里；
5. 我怎么去看见这些东西。

对应呈现模块：全学科路线图 + 当前任务表、任务依据与目标关系、结果检验 + 下一步、学业资产仓库、清晰导航 + 学生控制入口。

### 15.2 战场呈现框架

学业军师以“战场”为总呈现框架，但战场是帮助学生理解产品的语言，不意味着学生必须自行担任总指挥：军师负责明确当前任务和执行安排，学生保有重大方向的知情、确认、纠正、拒绝、暂停和退出权。

- **前线**（紧要工作）：可视化地图、学生理解程度、当前任务、学校反馈等；
- **后方**（物资囤积）：学业资产个人仓库及其来源、状态、复核与控制。

战场语言用于让学生易懂，不是为了掩盖产品真实运行。底层按专业责任分域，前端按学生问题组织呈现，实现“简单、清晰、直白、实用”，不花里胡哨。

### 15.3 呈现边界

- 必须直白呈现：当前状态、判断依据、证据、规划行动、学业资产、军师的认识、控制入口；
- 必须区分：已完成行动 ≠ 已做对；已做对 ≠ 已理解；已理解 ≠ 已能迁移；产品内表现 ≠ 学校现实中已验证；
- 不直接呈现：内部 Agent 运行细节、完整模型思维链、家长端的完整私人内容、纯技术状态；
- “简化”不等于“隐瞒”：凡会影响学生判断的事实、依据、未知、冲突和状态，必须用学生能理解的方式呈现。

[访谈确认采纳] 产品质量体验以四项为标准：上手即懂、操作与学习成本低、响应速度快、发现错误后立即修正生效。

## 十六、术语与统一表述

- **学生主体**——学生是学习行动主体与最终决定者；不等于被指挥执行者。
- **军师（参谋长兼指挥者）**——提供判断并明确布置当前任务；无强制权，不替执行，最终决定权属于学生。
- **全学科总战场**——学生整体学业的运动场与协调对象；各学科为独立战场。
- **多层指挥体系**——总军师 → 学科战场军师 → 学科专业 Agent；是逻辑责任层，不规定物理 Agent 数量或固定调用顺序；顶层调度，专业分化，不做全能选手。
- **逻辑责任域 / 对话板块 / 工作会话 / Agent / 底层设施**——分别是：概念上的责任边界、学生可见的组织入口、有目标有状态的处理单元、承担责任的执行主体、保存并约束证据/权限/资产/轨迹的系统；四者互不混同。
- **统一基础闭环**——理解 → 行动 → 检验 → 反馈；各学科在此基础上做加减法。
- **教与授**——规划转化为真实学习的承接层（诊断→讲解→练习→检验→反馈）；不是"讲—听"。
- **学业资产**——学生个人化认识的仓库；有版本、可修正、独立可视化。
- **证据**——有来源、可定位、可说明支持范围的输入或记录。
- **证据底层设施**——产品底层的确定性证据基础设施；由证据治理 Agent 管理，但替代不了设施。
- **会话**——围绕一个明确目标、有边界的工作单元；按责任域分板块。
- **记忆**——军师跨会话的受控理解；可见、可纠正、可删除。
- **监察底层设施**——独立的证据、轨迹与质量核验系统。
- **学校现实检验场**——学业军师作用于学生、学生反作用于军师的上位检验环境。
- **0.5→1**——整个产品的开发总原则：复用 > 改造 > 受控整合 > 重构 > 自建。
- **自生长**——只生长对学生的理解，不改变产品规则与边界。

## 十七、实施原则与边界

### 17.1 本体稳定、迭代有据

产品的本体——学生主体、军师边界、证据纪律、学校现实反馈、会话责任域、监察、学业资产——是稳定的，不得由实现、研究、原型或单个功能反向改变。任何进入正式产品上游的内容都须具备可定位的确认来源、适用范围、影响范围与验证方式。

### 17.2 不确定性不被掩盖

产品不把推测描述为事实、不把假设描述为结论、不把未验证描述为已达成；也不把模拟评测、内部生成或短期结果包装成已取得的教育效果。

### 17.3 不断言不确定，不承诺结果

以下内容不属于产品承诺：具体成绩与能力结果、完整特长训练规划、把研究/基准/喜好/留存/付费直接等同于教育价值、以及未经重新确认的历史候选方案。产品不承诺替学生制造结果，只创造理解与实践的条件。

### 17.4 价值观总纲

学业军师的最终判断标准不是"更像人"，而是**学生是否在理解、决定与行动中逐步掌握自己的规划、方法与判断**。产品在每一个环节都应当：以学生为主体，以证据为依据，以学校现实为检验，以边界为约束，以可追溯为纪律，以人的最终决定权为底线。

### 17.5 待确认事项

以下工程与边界细节仍有待确认，不在此写成既定事实：

1. “输入与来源定义”的具体工程规格细节；
2. 第一学科的最终选择（建议由真实学校证据可得性决定）；
3. 模拟评测的具体场景与样本设计；
4. 自生长的具体工程机制与阈值；
5. 具体技术选型、数据库、接口、代码库结构（后置于工程阶段）；
6. 家长推送的具体字段、期限与前端形式；
7. 识别到超出学业范畴信号时的产品行为下限；
8. [待验证] 产品当前三个最大未知：核心闭环如何运行、规划如何转化为行动、学业资产是否有价值——三者构成连续因果链，任一环不成立则产品退化为无效规划工具；
9. 会话终止阈值、跨会话自动继承规则、证据/资产/记忆的准入与复验阈值；
10. 开放候选项目或 DeepTutor 是否足够成熟、许可证与依赖是否允许、能否承接产品责任而不破坏边界。
