# 领域判断引擎调研报告

> **调研日期：** 2026-08-24
> **调研目的：** 为学业军师产品 F1-07（哲学总纲和七种方法映射）提供外部证据，验证"判断引擎与执行层分离"的可行性和最佳实践
> **调研范围：** 学术论文、GitHub 开源项目、商业产品中与"领域专用判断引擎"相关的方案
> **证据等级说明：** A=论文方法+实验/公开代码；B=可运行README明确模块；C=商业/官方仅公开行为；D=概念/提示工程

## 一、总判断

存在"通用LLM之上叠加领域判断层"的成熟近邻，但通常不叫 domain-specific reasoning engine。教育领域最接近的实现是：学生状态/知识追踪（判断当前状态）+ 教学策略/规则层（判断下一步）+ LLM生成层（表达）+ 反馈更新。

尚未找到一个同时满足"七种哲学方法命名、教育领域、LLM之上独立判断引擎、可静态路由+动态主动调用"的现成产品。**学业军师的判断引擎是创新组合，不是复制现有方案。**

## 二、最强学术证据

### 2.1 SLOW（A级）
- **全称：** Strategic Logical-inference Open Workspace for Cognitive Adaptation in AI Tutoring
- **来源：** arXiv:2603.28062，https://arxiv.org/html/2603.28062v1
- **核心架构：** 显式分离 learner-state inference 与 instructional action decision；四阶段：evidence parsing → cognitive validation → affective prediction → strategy integration
- **关键能力：** counterfactual simulation、多准则决策、可读的 Reasoning Workspace/System-2 pedagogical trace
- **评估：** 论文报告对9个模型做混合人机评价和消融；SLOW提升个性化、情感敏感性、清晰度、可操作性（注意：成本约6.4×，真实课堂效果仍待验证，均为论文报告数据）
- **契合度：** ⭐⭐⭐⭐⭐；几乎是"判断/执行分离"的教育版原型
- **差距：** 论文框架，未形成可嵌入产品的稳定规则协议；哲学七法未涉及

### 2.2 规则整合数学辅导（A级）
- **全称：** Taming the black box: Design principles for rule-integrated LLM tutoring systems in primary school mathematical problem solving
- **来源：** Computers & Education: AI 2026，DOI 10.1016/j.caeai.2026.100586，https://www.sciencedirect.com/science/article/pii/S2666920X26000482
- **核心架构：** diagnosis → intent selection → constrained response generation；另有 unit-rule locking、verification
- **评估：** 论文报告40名五年级学生课堂试点，规则引导减少提前给答案/提前结束、提高一致性和认知投入（注意：试点规模有限）
- **契合度：** ⭐⭐⭐⭐⭐；最像"判断过滤器"
- **差距：** 规则是数学脚手架，不是一般学业处境判断；未见动态主动调用独立判断服务

### 2.3 Pedagogical Inference Controller / PIC（A级）
- **全称：** Intelligent educational decision-making system driven by multimodal data fusion and knowledge graphs
- **来源：** Scientific Reports 2026，DOI 10.1038/s41598-025-33066-8，https://www.nature.com/articles/s41598-025-33066-8
- **核心架构：** CIFNet（神经+符号）表示学习者状态、教学意图、教学依赖；PIC 是 domain-embedded decision strategy layer，做 strategic utility、regret-aware adaptation、uncertainty exploration、curriculum alignment、counterfactual outcome simulation；用逻辑约束Γ过滤可行策略
- **契合度：** ⭐⭐⭐⭐☆；可借鉴数据结构和约束，不宜直接照搬模型复杂度
- **差距：** 教育决策支持近邻，页面没有把LLM放在PIC之上/之下，不应说成LLM判断引擎

### 2.4 FairTutor（A级）
- **全称：** FairTutor: Equity-Aware Pedagogical LLM Routing
- **来源：** arXiv:2606.20713，https://arxiv.org/html/2606.20713v1
- **核心架构：** AnalyzeQuery（学科、年级、难度、直接给答案风险、多步推理）→ MakePedagogicalPlan（苏格拉底提示/例题/错因诊断/类比/小测/写作反馈）→低成本Tutor→Evaluator；达标直接返回，接近阈值则 Critic-Rewriter 重写并复评，仍不达标才升级高级模型
- **关键价值：** 最强"静态分类触发+动态主动调用"证据——前置场景路由 + 执行后按质量主动重写/升级
- **评估：** 论文报告92%查询接近premium质量、升级率18%（注意：论文实验数据，非独立验证）
- **契合度：** ⭐⭐⭐⭐⭐；非常适合"判断Why/Whether，执行How/What"
- **差距：** 判断器仍是LLM/评分器，非稳定教育规则引擎；成本和公平阈值需本地验证

### 2.5 2503.06424（A级）
- **全称：** Training LLM-based Tutors to Improve Student Learning Outcomes in Dialogues
- **来源：** arXiv:2503.06424，https://arxiv.org/html/2503.06424v1
- **核心架构：** 用LLMKT学生模型预测某句导师话术后学生答对概率；GPT-4o按教学rubric评分；加权合成分数构造偏好对；DPO训练Llama-3.1-8B，并有蒸馏步骤
- **关键价值：** "把领域判断压缩进小模型"的直接证据
- **契合度：** ⭐⭐⭐⭐☆；适合后续压缩，0.5阶段不建议先做

### 2.6 ELA Tutor（A级）
- **全称：** An Adaptive Multi-Agent Architecture with Reinforcement Learning and Generative AI for ITS
- **来源：** Applied Sciences 2026，DOI 10.3390/app16031323，https://www.mdpi.com/2076-3417/16/3/1323
- **核心架构：** Moodle+n8n+LLM+数据库实现RL Meta-Agent；按用户状态/行为/历史选择专业Agent；混合切换策略：历史置信度足够→RL policy；置信度不足→确定性启发式或LLM推理
- **契合度：** ⭐⭐⭐⭐☆；具备静态路由+置信度触发fallback的雏形
- **差距：** 论文中的"router conceptual/implemented"表述混杂，需限制为"论文报告的实现"

## 三、开源项目（B级）

### 3.1 Business Rules Reasoning System
- **来源：** https://github.com/lwardzala/business_rules_reasoning
- **核心架构：** LLM主要做事实提取/缺失变量询问；Horn clauses/decision table/tree engine负责deduction或hypothesis testing；支持缺失事实、暂停/续推、日志、工作流动作
- **关键价值：** 最直接的"LLM接口 + 专用判断引擎 + 执行"工程先例
- **契合度：** ⭐⭐⭐⭐⭐；非教育但可迁移

### 3.2 MWPTutor
- **来源：** https://github.com/eth-lre/MWPTutor
- **核心架构：** LLM填充预定义finite-state transducer；保留传统ITS状态和教学策略
- **评估：** 论文做过两数据集人工评价，优于自由形式GPT-4
- **契合度：** ⭐⭐⭐⭐⭐；最小可用架构参考，LLM不是流程权威
- **注意：** README承认运行TODO但论文有评估

### 3.3 OATutor
- **来源：** https://github.com/CAHLR/OATutor
- **核心架构：** BKT-brain.js更新技能掌握；skillModel映射题目→知识组件；可配置/可A-B测试题目选择启发式；hint/scaffold pathway
- **关键价值：** 成熟学习状态判断后端
- **契合度：** ⭐⭐⭐⭐；但非LLM外置引擎

### 3.4 TutorAgent
- **来源：** https://github.com/pagand/tutoragent
- **核心架构：** BKT、Intervention Controller、epsilon-greedy提示策略、显式/隐式反馈混合闭环
- **契合度：** ⭐⭐⭐⭐
- **注意：** 已实现声明与营销声明混杂，评估数字不宜直接引用

### 3.5 SocraticMath
- **来源：** https://github.com/ecnu-icalk/SocraticMath
- **核心架构：** SocraticLLM LoRA；513知识点、6846多轮对话；4阶段苏格拉底策略
- **契合度：** ⭐⭐⭐⭐；是方法压缩/策略固化，不是外置判断引擎

### 3.6 agent-harness
- **来源：** https://github.com/ramannanda9/agent-harness
- **核心架构：** hybrid DAG planner/replanner、routed path、受控executor、观察截断、HITL、checkpoint
- **契合度：** ⭐⭐⭐⭐；双模式和可靠执行边界，通用框架

### 3.7 GenMentor
- **来源：** https://github.com/geminilight/gen-mentor
- **核心架构：** Skill Gap Identifier、Adaptive Learner Modeler、Learning Path Scheduler、Tailored Content Generator、AI Chatbot Tutor
- **契合度：** ⭐⭐⭐⭐；模块职责清晰，但README没有明确独立判断服务或场景路由

### 3.8 AI Learning Brain
- **来源：** https://github.com/princ3kr/notebook-lm-mini
- **核心架构：** Neo4j知识图谱、MSMS路径规划、诊断测评、失败后补救并重规划
- **契合度：** ⭐⭐⭐⭐；适合参考0.5→1流程

## 六、七种哲学方法的工程化映射

未发现公开项目把七个名称完整实现为教育引擎。可转译为工程机制：

| 哲学方法 | 工程机制 | 已有实践来源 |
|---|---|---|
| 实践论 | interaction/outcome evidence loop | OATutor BKT、TutorAgent、SLOW evidence parsing |
| 矛盾论 | principal contradiction/priority + 冲突检测 | SLOW cognitive validation、FairTutor query analysis |
| 唯物辩证法 | context/state transition/dependencies | CIFNet/PIC、知识图谱路径、BKT/KT |
| 实事求是 | fact/interpretation/inference/wish/unknown 分层 + 证据溯源 | Business Rules、VOR Truth Gate |
| 否定之否定 | belief revision / replan | Business Rules 暂停续推、agent-harness replan-on-failure |
| 认识论循环 | observe→judge→act→observe 闭环 | OATutor、TutorAgent、CtrKT |
| 对立统一 | competing objectives/constraint reconciliation | PIC utility/constraints、FairTutor quality-cost cascade |

## 八、0.5→1 最小落地建议

最小闭环：
```
observe（学生输入/作业/历史）
  → classify（场景/风险/是否需要判断）
    → judge（结构化判断）
      → execute（LLM 生成或工具）
        → verify/update（结果证据更新状态，必要时重入 judge）
```

判断输出固定为结构化字段：
- facts[] / unknowns[] / evidence[]
- learner_state
- primary_gap_or_contradiction
- confidence
- allowed_action
- next_evidence_needed
- revision_trigger

关键原则：LLM 只负责自然语言理解和表达；判断字段、阈值、证据、状态迁移和可执行动作由代码/规则控制。

## 九、重要负面结论

1. **"哲学七法完整工程实现"暂无直接匹配**；最接近是 Hegelion（可调用辩证流程）和 d-wwei/dialectical-thinking（矛盾论提示层），但都缺教育状态模型、证据闭环和产品验证
2. **"领域判断层"与"领域模型微调"不是一回事**：先外置判断层，积累数据后再考虑压缩进模型
3. **ReWOO 的静态规划不适用于教育闭环**：新证据会改变学生判断，必须支持动态 re-entry/replan
