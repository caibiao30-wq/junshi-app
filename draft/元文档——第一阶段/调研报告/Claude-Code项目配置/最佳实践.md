## 1. 配置目录结构

Claude Code 的项目配置集中在 `.claude/` 目录下：

```
.claude/
├── settings.json          # 团队共享配置（提交到 git）
├── settings.local.json    # 本地配置（不提交到 git）
├── CLAUDE.md              # 项目级智能体指令
├── commands/              # 自定义斜杠命令
│   └── *.md
├── hooks/                 # 生命周期钩子脚本
│   └── *.sh
├── rules/                 # 规则文件（可被 CLAUDE.md 引用）
│   └── *.md
├── agents/                # 子代理定义
│   └── *.md
├── skills/                # 技能定义
│   └── */
└── agent-memory/          # 智能体持久化记忆（可选）
```

## 2. settings.json vs settings.local.json

| 特性 | settings.json | settings.local.json |
|------|---------------|---------------------|
| **用途** | 团队共享配置 | 个人本地配置 |
| **是否提交 git** | 是 | 否（应加入 .gitignore） |
| **permissions** | 可设置 | 可设置（会覆盖 settings.json） |
| **hooks** | 可设置 | 可设置（会合并） |
| **enabledPlugins** | 可设置 | 可设置 |

**最佳实践：** Solo 开发者只需 `settings.local.json`，将团队和个人配置合并。

## 3. 权限配置（permissions）

```json
{
  "permissions": {
    "allow": [
      "Bash(git status:*):true",
      "Bash(git diff:*):true",
      "Bash(ls:*):true"
    ],
    "deny": [
      "Bash(rm -rf /:*):true",
      "Bash(sudo:*):true"
    ],
    "defaultMode": "acceptEdits"
  }
}
```

### defaultMode 选项

| 模式 | 行为 |
|------|------|
| `acceptEdits` | 默认接受 Edit/Write（需确认） |
| `disableAll` | 禁止所有工具调用（需逐次确认） |
| `allowEdits` | 自动放行 Edit/Write（无确认） |

### allow/deny 规则格式

```
ToolName(pattern):true
```

示例：
- `Bash(git status:*):true` — 允许 `git status`
- `Edit(src/**):true` — 允许编辑 src/ 下的文件
- `Write(*.log):false` — 禁止写 .log 文件

## 4. 钩子配置（hooks）

### 支持的钩子类型

| 钩子 | 触发时机 | 用途 |
|------|----------|------|
| `PreToolUse` | 工具调用前 | 权限检查、输入验证、日志记录 |
| `PostToolUse` | 工具调用后 | 结果处理、状态更新 |
| `Stop` | 智能体停止时 | 清理工作、保存状态 |

### 配置格式

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": ".claude/hooks/readonly-guard.sh"
          }
        ]
      }
    ]
  }
}
```

### 钩子脚本约定

- **输入：** JSON on stdin，包含 `tool_name`、`tool_input`、session info
- **退出码：**
  - `0` = 放行
  - `2` = 阻止（stderr → Claude 会看到错误信息）
  - 其他 = 非阻塞警告

### 只读守卫示例

```bash
#!/bin/bash
INPUT=$(cat)
TOOL_NAME=$(echo "$INPUT" | grep -o '"tool_name":"[^"]*"' | head -1 | cut -d'"' -f4)

if [[ "$TOOL_NAME" != "Edit" && "$TOOL_NAME" != "Write" ]]; then
  exit 0
fi

if [[ "$CLAUDE_READONLY" == "1" ]]; then
  echo "🚫 当前处于只读模式" >&2
  exit 2
fi

exit 0
```

## 5. 自定义命令（commands）

在 `.claude/commands/` 下创建 `.md` 文件，文件名即命令名：

```bash
# 使用方式
/audit    # 执行 audit.md 中的指令
/grill    # 执行 grill.md 中的指令
```

### 命令文件格式

```markdown
# 命令描述

执行步骤：
1. 第一步
2. 第二步
3. 第三步

输出格式：
- 结论
- 建议
```

### 推荐的命令集

| 命令 | 用途 | 触发场景 |
|------|------|----------|
| `/audit` | 审计配置一致性 | 定期检查 `.claude/` 目录健康状态 |
| `/grill` | 深度追问设计方案 | 设计评审、需求确认 |
| `/draft` | 进入草稿模式 | 探索性编辑，不提交到 git |

## 6. .claudeignore

类似 `.gitignore`，用于排除不需要 Claude 读取的文件，节省 token：

```
node_modules/
dist/
build/
*.log
.scratch/
.orca/
.git/
```

**最佳实践：** 排除所有构建产物、依赖目录、日志文件。

## 7. 规则文件（rules）

规则文件用于定义智能体行为约束，放在 `.claude/rules/` 下：

```markdown
# 规则名称

## 规则内容
描述具体的行为约束...

## 触发条件
在什么情况下应用此规则...
```

**注意：** 规则文件需要在 `CLAUDE.md` 中引用才能生效。

## 8. 子代理定义（agents）

子代理定义放在 `.claude/agents/` 下，用于定义可复用的智能体角色：

```markdown
# 代理名称

## 角色
描述此代理的职责...

## 能力
- 能力 1
- 能力 2

## 使用场景
在什么情况下使用此代理...
```

## 9. 技能定义（skills）

技能定义放在 `.claude/skills/` 下，用于定义可复用的工作流：

```
.claude/skills/
└── skill-name/
    ├── SKILL.md           # 技能定义
    └── references/        # 参考文档（可选）
```

## 10. 关键配置原则

1. **分层配置：** `settings.json`（团队）+ `settings.local.json`（个人）
2. **最小权限：** 只开放必要的 Bash 命令和文件操作
3. **钩子守卫：** 用 PreToolUse 钩子实现只读模式、权限检查
4. **忽略文件：** 用 `.claudeignore` 排除无关文件，节省 token
5. **模块化规则：** 将规则拆分为独立文件，便于维护和复用
6. **版本控制：** 敏感配置（settings.local.json）不提交 git
