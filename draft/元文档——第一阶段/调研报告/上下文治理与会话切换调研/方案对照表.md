# 方案对照表

> 按来源等级排列。A=官方文档/论文明确机制；B=垂直领域论文或公开实现中的机制；横向字段用于比较，不等于产品规格。

## 一、开源框架与官方机制（A级）

| 来源 | 领域 | session/working context | durable memory | 边界标识 | 读写/切换触发 | 压缩、召回与验证 | 用户控制/可见性 | 主要缺口 |
|---|---|---|---|---|---|---|---|---|
| LangChain/LangGraph | 通用 Agent | thread-scoped graph state；checkpoint 保存每步状态 | Store JSON 文档，可跨 thread | `thread_id`；长期记忆可用 user/org namespace | 新 thread 不自动带入 Store；需显式读取；hot path 或后台写入 | 删除、截断、摘要；profile/collection 各有损失；生产需持久化与保留策略 | 概念层可通知写入；非默认终端 UI | 没有现成的同意、查看、编辑、删除和隐私治理层 |
| Microsoft AutoGen | 通用 Agent | `model_context`；可用 Buffered 或 TokenLimited context | ListMemory、ChromaDB、Redis、Mem0 等 | Memory 协议和 Agent/Team state | 步骤前 query 并 `update_context`；`save_state/load_state` | 按时间或向量召回，支持 `k`、`score_threshold`；默认可发送完整历史 | `MemoryQueryEvent` 是事件/API 级可观测 | 不等于默认终端展示；完整历史默认存在上下文过长风险 |
| CrewAI | 通用 Agent | 任务前召回并注入 prompt | 统一 Memory；Crew/Agent/Flow 可用 | hierarchical scopes、agent scoped view、private source | 任务后抽取保存；任务前召回；后台线程写入并由 recall drain | semantic 0.5 + recency 0.3 + importance 0.2；half-life 30 天；相似度 0.85 consolidation、0.98 批内去重 | 主要是 API 级，不是默认 UI | 记忆内容会发送给配置的 LLM；需另建用户控制和审计层 |
| MetaGPT | 通用多 Agent | Role 的进程内 `list[Message]`，按 recency 取最近消息 | 论文有项目反馈总结，但当前主要改 constraint prompt | Role 与 `cause_by` 索引 | observe 写入；新项目开始前总结反馈 | 基础实现无向量召回和生产持久化 | 人可发起、观察、停止；屏幕/日志可见自然语言操作 | 重启/新 Role 不应假设可恢复；自改进不改结构化通信接口 |

## 二、垂直领域机制（B级）

| 来源 | 领域 | session/working context | durable memory | 边界标识 | 读写/切换触发 | 压缩、召回与验证 | 用户控制/可见性 | 主要缺口 |
|---|---|---|---|---|---|---|---|---|
| ChatLaw | 法律 | 会话内法律知识图谱，持续补齐事实 | 明确是跨会话长期记忆产品之外的形态 | 事实节点是否足够完整 | 缺失节点触发继续提问；Researcher 触发法规/案例 RAG | 结构化事实 + 外部 RAG；无成熟 retention 方案 | 未给出成熟查看、删除、导出、可见性控制 | 敏感记录留存诉求冲突；幻觉、恶意输入、并发压力 |
| Agent Hospital | 医疗模拟 | 经验与案例作为当前推理上下文 | experience base 可保留验证成功的原则 | 模拟经验与案例数量边界 | 错误答案反思后生成；验证成功写回，失败丢弃 | 语义 top-k；较优为 top-4 experiences + top-3 medical cases | 不是患者生产档案治理 | 不可直接外推为真实患者 session、持久化或隐私协议 |
| MedAgents | 医疗 | 会话内多专家协作 | 无跨会话用户记忆或持久化存储 | 专家协作会话边界 | zero-shot/training-free 的专家协作 | 以会话内多专家为主要治理手段 | 未形成生产级用户记忆控制 | 不能替代跨会话 persistence/privacy 协议 |
| FinMem | 金融 | working memory；按可调认知跨度保留信息 | layered long-term memory | working/long-term 分层 | 按金融数据和认知跨度处理 | 按重要性与新近度组织 | 无用户查看、编辑、删除、同意或审计接口 | 实验性能不能证明生产级安全与合规 |
| HabitatAgent | 地产/住房 | conversational memory 最近 5 轮，TTL 24 小时；可选 context-aware state | entity、bias、retrieval 三类中长期记忆 | entity、bias、推荐房源 ID 等四层边界 | 每轮摘要用 Add/Update/Relax；7 天房源 ID 滚动缓存 | 验证门：factual ≥0.85 且 entity ≥0.90；自适应 vector+graph/GraphRAG | 论文称 auditable、带证据引用；未说明终端用户控制 | 未说明查看、编辑、删除四层记忆或撤回偏好 |

## 三、用于会话切换的比较维度

| 维度 | 公开实践中的可复用观察 | 当前报告的边界结论 |
|---|---|---|
| 会话身份 | `thread_id`、Role、session 内知识图谱等决定工作上下文边界 | 会话切换应先改变 working/session context；不能把同一用户身份当作自动携带全部历史的授权 |
| 跨会话召回 | Store、向量记忆、分层长期记忆和验证后经验写回 | durable memory 的召回应有 namespace、权限和显式读取动作 |
| 中断恢复 | checkpoint、Agent/Team state、流程状态保存 | 状态恢复与跨会话记忆召回是两类动作，不应混为一个“记忆”接口 |
| 压缩与摘要 | 删除、截断、摘要、原子事实、consolidation、去重、认知跨度 | 所有压缩都是可能有损的写入；需保留来源、时间、验证状态、版本及原文回看路径 |
| 验证与写回 | HabitatAgent 验证门；Agent Hospital 成功保留、失败丢弃 | 长期写回不能只因模型生成或被检索就自动成立 |
| 用户控制 | 多数框架只有事件、scope、日志或 API 可观测性 | 查看、编辑、删除、撤回、同意和审计需独立治理，不能由底层 memory API 默认推定 |
| 成本与污染 | context window、TTL、数量阈值、recency decay 和重要性权重 | 需要同时治理上下文长度、召回数量、过期和无关信息；单一阈值不能保证正确性或合规 |
