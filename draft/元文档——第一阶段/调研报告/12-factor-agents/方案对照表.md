# 方案对照表——12-Factor Agents vs. 学业军师

> 调研日期：2026-08-24
> 说明：以学业军师仓库客观事实为锚点，对比 12-Factor Agents 各原则的适用性和覆盖度。

## 一、逐因子对照

| Factor | 12-Factor 原则 | 学业军师对应设计 | 对齐度 | 差距/行动 |
|---|---|---|---|---|
| F1 | 自然语言到结构化工具调用 | 判断引擎首尾调用（§6.1） | ✅ 高 | 需定义具体 intent 类型 |
| F2 | 拥有自己的 Prompt | 无对应设计 | ⚠️ 缺失 | 需建立 Prompt 管理策略 |
| F3 | 拥有上下文窗口 | 双层架构 + 上下文治理（D-011 §5） | ✅ 高 | 需定义序列化格式 |
| F4 | 工具就是结构化输出 | 无对应设计 | ⚠️ 缺失 | 需定义工具/意图类型体系 |
| F5 | 统一执行与业务状态 | 10 项运行时状态 + 状态生命周期（D-011 §3, §7.2） | ✅ 高 | 需定义数据结构 |
| F6 | 简单 API 暂停/恢复 | 状态转移三原则（D-011 §2） | ✅ 中 | 需设计具体 API |
| F7 | 用工具联系人工 | A-E 主动性 + 异常降级（D-009, D-011 §4） | ✅ 高 | 需为四类介入定义协议 |
| F8 | 拥有控制流 | 三层降级 + 状态转移（D-011 §4, §2） | ✅ 高 | 需细化分支逻辑 |
| F9 | 错误压缩到上下文 | error_chain 目录（已规划） | ⚠️ 中 | 需定义错误类型和升级路径 |
| F10 | 小型专注 Agent | runtime/engine/ 模块划分 | ✅ 高 | 需验证各模块的 Agent 化程度 |
| F11 | 从任意渠道触发 | 移动端 + 语音 + 推送（已规划） | ⚠️ 中 | 需独立设计触发机制 |
| F12 | 无状态归约器 | 双层架构（§7.1） | ⚠️ 部分 | 仅工作会话层适用 |
| +13 | 预取上下文 | 无对应设计 | ⚠️ 缺失 | 需定义预取清单 |

## 四、需注意的风险

| 风险 | 来源 | 建议 |
|---|---|---|
| 12-factor 是通用原则，非教育领域方案 | 仓库定位 | 所有设计必须从学业军师产品事实出发 |
| 代码模板质量有漂移（依赖不一致等） | 静态分析 | 不直接引用，只参考模式 |
| Factor 12 正文为空，仅有标题 | 源文件 | 不作为硬性要求 |
| 社区对 MCP/标准化仍有争议 | Issues #20, #25 | 学业军师内部标准化即可 |
| A2H 协议草案未完成（OpenAPI 为空） | drafts/ | 参考理念，不引用协议 |
