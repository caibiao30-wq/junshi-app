## 2. Grilling 工作法

### 2.1 先定位，不先写

本阶段的主要工作是产品设计、打磨和撰写，不是直接实现代码。每轮先从决策登记和设计参照表中定位主题，再以“第一阶段必做工作总表”的任务编号和前置依赖确定当前可启动工作；表格之外不得另行创建并行任务清单。

表格的前置依赖是唯一执行顺序。以下仅是主题阅读顺序，帮助 Agent 定位材料，不替代表格任务：

1. 产品本体与边界；
2. 工作机制、闭环和领域关系；
3. 学业资产等核心产品组成的内容边界；
4. 人、AI、确定性规则、家长和专业责任边界；
5. 证据、隐私、安全、控制和验证门槛；
6. 统一术语；
7. 第一阶段正文收束与下游派生准备。

当前工作重心仍是第一阶段元文档的设计、打磨与撰写。已登记内容不重复烘烤；只对表格中处于 ⏳ 或在条件满足后可转为 ⏳ 的任务继续提问。

### 2.2 逐轮烘烤

每轮遵循以下闭环：

1. 列出当前设计树的前沿，只问前置条件已经明确的问题。
2. 每个问题给出推荐答案、选择理由和不处理范围。
3. 等待产品发起人回答；不把沉默、模糊表达或拒答解释为确认。
4. 根据回答重新计算下一轮前沿；将确认、保留阶段性、暂定、工作假设和待解决分开。
5. 直到本轮主题形成共享理解，再进入写入。

共享理解确认前，不修改正文、决策登记或其他产品内容文件。产品发起人明确确认后，才可把内容按其状态写入相应输出；未确认内容保留为候选或待解决。

### 2.3 事实与判断分层

所有讨论和写入都区分：

- 仓库或材料可核验的事实；
- 产品发起人的明确决策；
- 设计参照中的候选；
- 开发者判断；
- Agent 推断；
- 愿景和价值假设；
- 尚未核验的内容。

历史文档写过某个方案，不等于方案已实现、已验证或当前有效。发现历史方案与当前决策冲突时，保留来源并暂停越级采纳。

## 3. 写入规则与输出责任

### 3.1 正文承载稿

只有满足以下条件的内容才能进入 `学业军师产品元文档-第一阶段正文.md`：

- 产品发起人已经明确确认，或决策登记已有对应 ID 和状态；
- 内容属于第一阶段产品本体、顶层机制、边界、验证方向或本阶段允许承载的粗粒度方向；
- 已明确适用范围、来源、状态和不确定性；
- 不越界写入 API、数据库字段、Prompt、页面线框、具体测试、部署或技术选型。

正文只写产品要表达的内容，不写本文件的执行过程。进入正文不等于永久锁定。

### 3.2 工作日志

每次实际工作都在 `学业军师产品元文档-第一阶段工作日志.md` 末尾追加记录，至少说明：日期、来源、参与者/模型（可核验时）、实际动作、结果、状态、影响范围、验证方式和下一步。日志只记录过程，不把 Agent 建议或研究结果写成产品决策，也不承担下一轮工作指引。

### 3.3 决策登记与设计参照表

决策登记和设计参照表是本文件的输入依据，不因本文件被读取而自动改变：

- 新的产品决定必须有产品发起人明确确认，并按决策登记规则登记唯一 ID、状态、来源、范围和下游约束；
- 新的候选、问题或验证参照进入设计参照表的流程，不能借工作安排直接升级；
- 正文写入必须能回指决策登记或明确的阶段性确认来源；
- 日志只能记录登记或参照表变更已经发生，不能代替变更本身。
