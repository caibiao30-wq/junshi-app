## 2. 设计哲学总纲（候选／待重新确认）

哲学先判断，工程再转换，AI 受约束执行。面对问题先问：目的是什么、本质是什么、结构和关系如何、条件有哪些、矛盾在哪里、如何由实践检验；再把判断落成可观察的约束、责任、证据和验证。哲学语言是非技术方与 AI 之间的转换语言，不是工程规格、教程或隐藏思维链。

任何哲学判断进入产品前，必须映射到四层、状态、决策 ID 和验证契约；不能凭哲学名词推出正确答案、自动化主权或产品决策。

## 3. 七种哲学方法及工程化检查入口（候选／待重新确认）

以下名称以第一版草稿 §9.2 为准。每项只规定问题入口、工程检查和不能推出的结论；不要求展示内部推理过程。

| 哲学方法 | 哲学问题 → 工程检查 | 不能推出 |
|---|---|---|
| **实践论** | 行动和客观结果带来什么新证据？→记录行动、结果、复盘和下一轮验证 | 不能只凭一次结果断定能力或人格 |
| **矛盾论** | 主要矛盾是什么，优先级依据是什么？→检查冲突目标、约束、降级和取舍记录 | 不能把复杂问题简化成单一原因 |
| **唯物辩证法** | 处境中的联系、发展和矛盾如何影响判断？→检查上下文、时间变化和关系，不孤立看单点材料 | 不能替代具体证据和专业判断 |
| **实事求是** | 哪些是材料、解释、推断、愿望和未知？→标注来源、真值域、不确定性并校验事实 | 不能以流畅表达制造事实 |
| **否定之否定** | 新证据是否要求修正旧判断？→保留版本、过期标记、纠正和回滚路径 | 不能保证每次更新都更正确 |
| **认识论循环** | 实践—认识—再实践如何逐步检验？→设置复核节点和执行后验证 | 不能用 benchmark 代替真实价值 |
| **对立统一** | 矛盾诉求能否共存，如何寻找兼容方案？→记录候选方案、边界、拒绝和人工升级 | 不能在未理解冲突前强行二选一 |

## 4. 四层模型与层间转换

| 层级 | 回答什么 | 当前状态 |
|---|---|---|
| **产品本体** | 为什么存在、是什么/不是什么、服务谁、价值、角色权利、最高边界和不变量 | 既有内容较强，仍需登记确认 |
| **工作机制** | 输入如何进入理解、判断、规划、行动、证据、复盘和下一轮；何时主动、询问、等待、停止、升级 | 候选，需形成领域契约 |
| **实现方式** | 人、AI、确定性规则如何分工，如何保持证据、权限、安全、验证和可替换性 | 候选，不能锁定技术栈 |
| **验证治理** | 如何证明没有做偏，如何设门槛、追踪、修改、回滚和处理冲突 | 候选，需形成验证契约 |

固定转换模板：**目的/本质→产品不变量；结构/关系→领域对象与循环；条件→触发、前置校验与权限；矛盾→优先级、降级、拒绝和人工升级；实践→证据、验证、回滚；发展→版本、过期和受控演进。** 转换只落在四层，不下沉 API、数据库字段或 Prompt 正文。

## 6. 产品价值、证据分域与人／AI／规则责任

| 价值域 | 评价对象 | 不可推出 |
|---|---|---|
| 能力证据 | AI 是否基于证据理解、规划、调整、验证并守权限 | 不能证明学生成长 |
| 感知价值 | 被理解感、连续性、温度、可控感、解释清晰度 | 不能证明学习效果 |
| 客观过程价值 | 理解建议、行动/调整、材料、复盘和错误识别是否闭环 | 不能直接证明长期迁移 |
| 长期价值 | 迁移、独立判断、减少依赖、可离开/毕业 | 不能由产品自认发生 |
| 商业/运营结果 | 激活、付费、留存、成本等 | 不能替代教育价值 |

责任优先序候选：产品发起人/治理者负责目的、价值取舍、最高边界和全局变化；学生负责目标偏好、同意、行动、纠正和主体控制；监护人提供必要支持；专业责任者/审核者处理高风险判断；AI 负责受约束理解、候选判断、生成和调度；确定性规则负责身份、权限、同意、数据、状态迁移、安全、审计、撤销和删除。AI 不得修改规则、最高边界或不可逆长期状态。

## 8. 学业资产与个人知识库的阶段性设计参照

### 8.1 已确认的上游方向（D-007）

学业资产是学业军师的核心组成部分之一，与规划和行动闭环并列。第一阶段暂将其理解为面向单一学生的个人知识库，内容必须面向一个特定学生，也只能面向该学生。它承载产品对学生材料以及军师与学生共同学习、规划、行动和复盘形成的学生特定价值内容进行处理、整合和沉淀后的结果。

当前候选内容范围：知识理解；问题/错题认识及修正理解；学习、练习、复习和考试方法；共同总结、复盘和经验沉淀。原始材料可保留为来源依据，但不作为学生端主要展示内容；AI 私有工作记忆、军师通用资源和未经确认的长期学生画像不自动进入学业资产。

本节是设计参照，不新增产品决策；正式状态、来源和适用范围见《学业军师产品元文档-第一阶段决策登记》D-007。

### 8.2 设计方向（F1-14 闭合，保留阶段性原则 2026-09-01）

- 学生端可进入独立的“学业资产”窗口（不叫知识库/资产库）；窗口层级：学科/课程 → 四类内容（知识理解/问题/错题认识及修正理解/学习方法/复盘沉淀）→ 条目列表 → 条目详情（含来源/版本/操作）。
- 第一层按学科/课程分桶，同条资产归属单一学科，跨学科通过引用不复制；设“通用”桶承载通用方法；二级标签由 AI 建议+学生确认生成。
- “学业资产”是产品责任和领域对象主术语；“个人知识库”是阶段性产品含义；“学业资产知识库”只作内部讨论组合称呼，不作学生端名称。
- 学生端展示处理、整合和沉淀后的价值性内容；原始材料仅作可追溯来源，不直接成为资产（硬约束：AI 整合提炼+学生确认才晋级，沉默≠确认）。
- 仅共同复盘是晋级入口，规划/定策仅产生候选草稿；三段式：收集→草稿→确认晋级+失效/归档（版本保留，可追溯）。

以下 8 项原为第二阶段待研究，现经 F1-14 grilling Q1-Q12 已闭合为保留阶段性原则（见 D-007 2026-09-01 修订），详细阈值/像素/技术选型仍留待下游：

## 10. 主动性、自生长与可观察控制权边界

主动性候选分级：A 主动理解/判断；B 主动建议；C 安排低风险可撤回行动；D 代表对外沟通或执行（预览和确认）；E 改变长期方向、不可逆状态或安全信息（不得由 AI 单独或静默完成）。

界面控制面是产品形态候选而非产品本体，最小可观察面包括：依据/不确定性、当前状态/记忆可见、纠正/反驳/删除、暂停主动性、撤回/回滚、重大变化确认、导出/退出和审计记录；具体页面下沉设计文档。

自生长仅允许在受控评估中形成候选策略或局部适配，不得自行改变产品规则、最高边界、角色权利、长期方向或不可逆状态。长期写入须有来源、时间、置信度、范围、可见性、有效期、冲突和撤销路径。学生共同复盘、AI 证据自检、系统策略评估三层分开。

## 11. 验证契约与四轴阶段门槛

每个运行环节定义：输入、输出、触发、结束、异常、责任者、证据和可逆性；每条下游验收绑定决策 ID、适用范围、状态和证据来源。四轴均有通过与否决条件：

- **产品能力：** 能基于证据理解、规划、调整、验证并守权限；
- **产品形态：** 承诺的关系、控制权和体验成立，未完成形态不被误读为完成；
- **工程实现：** 状态、权限、证据、错误、审计、撤回可追溯；
- **商业发布治理：** 安全、隐私、家长、运营责任和支持能力达标。

不通过可暂停、回退或重审，否决门槛优先于功能数量；benchmark、喜欢、留存、成绩或“更像人”不能替代四轴验证。

## 16. 12-Factor Agents 行业参照与工程设计前沿（候选／待研究）

### 16.1 行业对齐验证

12-Factor Agents（HumanLayer，25.4k stars）提出构建可靠 LLM 应用的 12 条原则，核心主张是：LLM 负责有限范围内的决策，确定性代码负责执行和控制流，Prompt 和上下文都是应用代码的一部分。

与学业军师已确认设计的对照：

| 12-Factor 原则 | 学业军师对应设计 | 对齐度 |
|---|---|---|
| F1：自然语言到结构化工具调用 | 判断引擎首尾调用（正文 §6.1） | ✅ 高 |
| F3：拥有上下文窗口 | 双层架构 + 上下文治理（D-011 §5） | ✅ 高 |
| F5：统一执行与业务状态 | 10 项运行时状态 + 状态生命周期（D-011 §3, §7.2） | ✅ 高 |
| F7：用工具联系人工 | A-E 主动性 + 异常降级（D-009, D-011 §4） | ✅ 高 |
| F8：拥有控制流 | 三层降级 + 状态转移原则（D-011 §4, §2） | ✅ 高 |
| F10：小型专注 Agent | runtime/engine/ 模块划分 | ✅ 高 |
| F2：拥有 Prompt | 无对应设计 | ⚠️ 缺失 |
| F4：工具就是结构化输出 | 无对应设计 | ⚠️ 缺失 |
| F13：预取上下文 | 无对应设计 | ⚠️ 缺失 |
