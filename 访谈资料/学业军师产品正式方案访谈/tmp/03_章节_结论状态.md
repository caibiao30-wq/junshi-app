### （一）已确认

已确认指用户在当前会话明确回复「确认/同意」予以采纳的方向与表述。以下均来自 [专业建议·代拟] 正文被 [确认采纳]，不视为用户自主原始论证（详见附录）。

- **[确认采纳] 产品责任边界**（1-1）：学业军师不是替学生完成学业，而是把可追溯的学业信息转化为受约束的判断、可执行行动与必要教与授，并通过现实反馈持续修正判断；产品责任的最低闭环与「不纳入责任」边界。
- **[确认采纳] 产品本体定位**（1-2）：面向中小学教育相关机构的 B 端学业支持产品，直接作用于学生真实阶段性学业过程，全学科整体协调，以证据与学校现实反馈为主要判断依据，通过统一产品结构承载并适配不同学段；机构为技术/服务赋能方、不参与实体教育经营。
- **[确认采纳] 本体与外部能力边界判定标准**（1-3）：以「移除后学业军师是否仍成立 / 是否定义核心责任 / 是否控制关键状态 / 是否直接影响学业路径 / 是否体现独特方法 / 是否决定产品能否自证有效」六项为判据；外部项目可提供实现能力但不得反向决定产品责任。
- **[确认采纳] 「自持」的定义**（1-4）：自持 = 掌握定义权与控制权，不等于从 0 构建；实现层可在已有 0.5 基础上复用、改造、重构。
- **[确认采纳] 产品本体能力清单**（1-5）：以「六个核心业务责任域 + 四项横向控制机制 + 两项产品结构能力」取代「十一项平行能力」，并给出开发优先级与延后策略。
- **[确认采纳] 底层基础设施与 Agent 管理职责边界**（1-6、1-7）：「底层确定性基础设施 + 受约束 Agent 管理层」分层结构；Agent 是管理者与执行者，不是底层规则制定者、事实最终确认者或高影响操作无条件执行者。
- **[确认采纳] 学业输入语义与证据边界**（1-8）：五类输入（材料本体、学生补充说明、实际行动、学校/教师反馈、Agent 分析）证据地位不同；输入必须先定义对象、来源、授权与用途边界。
- **[确认采纳] 判断/建议/状态输出契约**（1-9）：Agent 输出与正式状态分离；内容状态与现实验证状态双维模型；学生确认不等于现实复验。
- **[确认采纳] 状态迁移与确认机制**（1-10）：「候选申请—底层校验—必要确认—合法执行—审计追溯」闭环；无明确确认不得升级；学生确认、现实复验、系统状态三者为不同维度。
- **[确认采纳] 全学科学业协调**（2-1）：整体—学科—任务三层责任关系，局部升级层级，防止局部最优，学校反馈驱动整体修正。
- **[确认采纳] 阶段生命周期与统一产品结构**（2-2）：阶段化生命周期（升学为阶段结束一等事件），通用产品层—阶段适配层—学科内容层分层；统一产品机制、适配教育内容。
- **[确认采纳] 路径、任务与教与授承接**（2-3）：规划必须转化为具体、可执行、可检验的任务并经教与授支持学生行动；任务层面有效与能力层面有效相区分。
- **[确认采纳] 学校现实反馈进入机制**（2-4）：反馈须经来源登记、证据归属、完整性/时间/冲突处理后再决定影响层级；不能自动改写重大规划；学校现实检验成立条件。
- **[确认采纳] 学业资产与阶段内认识生命周期**（2-5）：学业资产 = 从真实证据提炼、经学生理解纠正确认、可复用可修订的阶段内个人认识；与证据/记忆/能力证据相区分。
- **[确认采纳] 底层设施与 Agent 接口契约**（3-1）：Agent 读写必须经底层接口，输入最小必要、输出结构化候选；最低可运行十二类契约。
- **[确认采纳] 会话、责任域与多 Agent 协作编排**（3-2）：前端统一入口、底层责任分域、主军师统一编排、专业 Agent 分工执行、统一约束与审计；责任域与会话分离。
- **[确认采纳] 教与授产品机制**（3-3）：教与授为核心承接机制而非内容附加；讲解/练习/检验分工；「看过讲解」不等于「掌握」；任务完成与能力形成三级区分。
- **[确认采纳] 证据、记忆与会话的持续治理**（3-4）：对象先有来源、范围、状态才能生效；记忆满足准入且学生可见可纠正可撤回可删除；会话结束只产生受控蒸馏候选。
- **[确认采纳] 模拟评测与真实验证边界**（3-5）：模拟评测证明机制、不冒充教育效果；区分机制/真实小样本/学校现实反馈/长期能力形成/教育归因五层验证。
- **[确认采纳] 监察、质量门槛与回滚**（3-6）：监察使可靠性可被证明而非自称可靠；质量门槛阻断伪证越权；回滚保留快照、处理下游、监察自身受监督。
- **[确认采纳] 前端呈现与学生控制**（3-7）：采用「战场总框架（前线—后方）+ 分级学科操作窗口」双层结构（其中前端结构为用户明确判断）；学生控制权由底层强制记录保证。
- **[确认采纳] 0.5→1 开发路径与首版边界**（3-8）：首版 = 底层设施四组 15 项全部闭合 + 一个核心闭环跑通；全量业务功能不在首版一次补齐（首版优先底层设施为用户明确判断）。

### 待验证（须经工程或真实使用，本次访谈不可证明）

以下均须验证，本次访谈（含模拟评测、抽象设计）不能证明其成立：

- 不同学业阶段能否在同一统一产品结构上稳定运行，学段差异能否靠配置/内容/专业能力承接；
- 机构能否有效部署并持续使用；
- 学生能否形成独立的学业判断与行动能力；
- 教与授能否真正促成学生行动、改善学校现实学习结果；
- 学校反馈能否真实获得、被正确登记解释、并触发可追溯的规划修正；
- 学业资产能否在后续任务中真正复用、学校反馈能否支撑复验；
- 证据治理、底层规则、接口契约、监察/回滚能否在不同学段与 B 端机构中稳定、可靠、不增负担地运行；
- 多 Agent 协作是否降低而非增加学生认知负担；
- 模拟评测能否证明机制可靠；学生是否愿意真实使用；真实长期使用能否形成能力。

### 本次访谈不可证明（超出证据边界，须明示）

- **教育效果**：产品是否改善学生学校结果、是否形成学生能力、教育效果是否由产品造成（归因），均不能由模拟评测或本次访谈证明（1-3、1-5、3-5、3-6）。
- **跨学段迁移**：同一统一产品结构能否跨小学/初中/高中稳定运行，是待验证结构属性而非已验证事实（1-2、2-2）。
