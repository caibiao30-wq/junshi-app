## 2.1　问题 2-1：全学科学业协调如何成立

**标准化问题**：

学业军师如何从各学科局部信息形成可解释、可追溯、可调整的整体学业判断，并转化为学科优先级、任务安排和资源取舍？回应语境与前提：全学科学业协调不是多学科并列、Agent 数量叠加或分数汇总，而是把各学科状态、任务、资源占用、现实反馈及相互影响纳入同一决策过程；三层责任组织、升级层级与最低成立条件仍属候选，尚待验证。

**回应与论证**：

以下内容为记录中本单元完整回应正文（`[专业建议·代拟]`，用户随后回复“确认”）。

### 一、定义与责任分层

全学科学业协调不是多学科并列、Agent 数量叠加或分数汇总，而是在特定学业阶段和整体目标约束下，将各学科状态、任务、资源占用、现实反馈及相互影响纳入同一决策过程，形成可解释、可追溯、可调整的整体安排。单科能力负责本学科问题、教与授、练习和检验；整体协调负责全局状态、优先级、取舍、失衡识别、跨学科冲突和是否上升处理。

建议的责任层次为：

```text
整体学业协调层
  → 学科协调层
    → 任务与教与授执行层
```

整体层形成整体状态、比较优先级、识别失衡、调整资源、处理跨学科冲突、决定升级并接收反馈；学科层转化学科计划、组织学科内教与授并报告限制；执行层落实任务、记录学生行动、收集结果。三层是责任关系，不是固定 Agent 数量。

### 二、整体协调的输入

整体目标应包括阶段目标、结束条件、学校课程/评价要求、需维持或改善的方向、剩余时间和现实约束；不能由单次成绩或单一 Agent 自动推导。各学科输入应包括当前任务、可观察表现、证据及强度、已采取行动、行动结果、学校/教师反馈、资源占用、影响、未知和冲突。整体协调还应考虑学生时间/精力、课程考试安排、任务耗时、学科依赖、实际执行能力以及机构/教师支持。

整体层默认读取受控的学科结构化状态摘要、证据强度和来源索引、当前任务与结果、资源占用、学校反馈摘要、升级请求及待确认/待验证项；只有确有必要时按最小必要范围请求原始材料、关键作业/考试、教师反馈或冲突相关跨学科材料，不默认读取无关私人信息、无授权历史、其他学生数据或完整会话。

### 三、局部问题的升级

不能仅凭分数或单次结果升级。应综合：证据强度、持续性、影响范围、资源影响、阶段影响、现实反馈、替代解释、可逆程度、建议冲突、学生意愿与执行能力。建议层级为：

```text
任务层问题 → 学科内问题 → 学科阶段规划问题 → 全学科协调问题 → 阶段目标/重大方向问题
```

单次、局部、可逆且不影响整体的事项留在任务层；同科重复模式进入学科层；持续影响该科阶段推进的事项进入学科规划层；跨学科冲突、整体资源失衡或多个学科共同指向整体障碍时上升整体层；可能改变阶段总体目标、长期优先级或核心取舍时进入重大方向确认。

### 四、防止局部最优

底层必须将整体安排绑定阶段目标、证据和影响范围，记录任务时间/资源占用，识别学科冲突，设置重大优先级变更门槛，禁止低强度证据触发高影响调整，禁止单次结果自动改写整体规划，并保留变更、旧版和修正原因。Agent 可汇总状态、比较资源、识别失衡、生成含收益/代价/未知/风险的方案、请求补证/复核并提交学生确认，但不能把“认为整体最优”直接写成生效规划。

### 五、学校反馈与整体修正

学校反馈应经过：学校任务/结果/反馈 → 来源登记与证据归属 → 学科层解释 → 识别跨学科影响 → 整体比较协调 → 规划变更候选 → 底层校验与必要确认 → 执行并持续检验。

单次单任务结果通常先影响任务层；同类连续结果可能影响学科规划；持续重要反馈可能影响学科阶段安排；跨学科失衡可能上升整体；阶段目标受实质影响可能触发重大方向确认。缺少学校反馈时可整理材料、标记未知、提供低确定性解释、设计可逆观察任务，但不得将内部练习升级为稳定能力、学校结果或教育效果，也不得据此大幅改写整体优先级。

### 六、底层与 Agent 分工

| 范围 | 底层确定性基础设施 | Agent 管理与执行 |
|---|---|---|
| 学科状态 | 来源、时间、证据、版本、权限 | 分析、汇总 |
| 优先级 | 影响范围、变更规则、确认门槛 | 提出方案 |
| 资源安排 | 时间/资源约束、冲突检测、状态记录 | 比较、协调 |
| 跨学科调用 | 最小必要范围和授权 | 提交申请 |
| 规划变更 | 合法迁移、审计、回滚 | 提出候选 |
| 任务部署 | 接受/完成区分、真实行动记录 | 生成、调整任务 |
| 学校反馈 | 来源、完整性、冲突、影响层级 | 解释、提出修正 |
| 学生决定 | 确认、拒绝、暂停、退出记录 | 引导、请求确认 |
| 结果检验 | 真实行动与结果记录 | 分析和提出下一步 |

### 七、最低成立条件

只有当产品拥有阶段性整体目标；各学科状态带来源、时间、证据和适用范围；能识别学科相互影响和资源冲突；能形成整体优先级并转成学科任务；能接收执行结果和学校反馈并修正整体安排；重大调整有学生确认；证据不足时能降级或暂停；整体判断、规划变更和交接可追溯；单科 Agent 不能绕过底层改写整体规划；且不以单科局部最优替代阶段整体目标时，才能称为全学科学业协调，而非多个单科工具的集合。

### 八、专业结论

> **全学科学业协调是以阶段性整体目标为约束、以各学科受控证据为输入、以资源与相互影响为比较基础、以任务和教与授为执行出口、以学校现实反馈为修正依据的整体决策责任。学科 Agent 负责本学科判断和执行支持，整体协调 Agent 负责比较、取舍、冲突处理和整体安排，底层负责对象、证据、权限、状态、确认、审计和回滚，学生参与真实行动并对重大方向和重要取舍保有相应权利。其成立取决于“学科状态→整体取舍→学科任务→学生行动→现实反馈→整体修正”的可追溯闭环，而非学科或 Agent 数量。**

## 2.2　问题 2-2：学业阶段生命周期与统一产品结构

**标准化问题**：

如何在一套统一产品结构中承载小学、初中、高中等不同学段在学习目标、知识内容、任务形式、学生能力、评价方式、参与角色和结束边界上的差异，同时保持学业军师的核心责任与运行边界稳定；如何定义学段生命周期、结束交接与跨阶段处理；如何证明统一产品结构成立而非三个互不相容产品或一条超长时间线；统一层、阶段适配层与学科内容层如何划分；底层固定哪些硬规则，Agent 可依学段调整什么。前提：不能为每个学段开发三套互不相容产品，也不能把三个学段压成一条无边界的超长时间线，或仅凭同一登录页面声称结构统一。

**回应与论证**：

以下内容为 `[专业建议·代拟]`，原始底稿仅作参考、不覆盖当前代拟，用户随后回复“确认”。

### 一、统一产品结构要回答的问题

学业军师要覆盖小学、初中、高中等不同学段，但不能为每个学段重新开发三套互不相容的产品，也不能把三个学段强行压成一条无边界的超长时间线，或用同一个登录页面就声称结构统一。真正要解决的是：如何用一套产品机制，承接不同学段在学习目标、知识内容、任务形式、学生能力、评价方式、参与角色和结束边界上的差异，同时保持学业军师的核心责任与运行边界稳定。因此，“统一”统一的是产品机制，“适配”适配的是教育内容与阶段差异，二者必须分开。

### 二、跨学段必须保持稳定的产品机制

以下内容原则上不受学段内容影响，由通用产品机制承载：学业处境理解与判断；全学科整体协调关系；证据的来源、状态和权限；路径、任务、教与授、行动、检验和反馈之间的连接；学生确认、拒绝、暂停和退出机制；学业资产与阶段内记忆的生命周期；底层确定性设施与 Agent 管理边界；学生、Agent、机构、教师的角色权限；状态迁移、审计、追溯和回滚规则；B 端机构接入和角色隔离；质量门槛与监察基础。这些内容不因学段不同而改变，描述的是“学业军师如何工作”而非“某个学段教什么”。但它们是候选机制，不是已证明跨学段都能运行的事实，须通过阶段迁移验证。

### 三、跨学段稳定、阶段配置与学科内容要区分

即使某项机制跨学段稳定，在具体学段中仍可有配置差异，须区分三层：一是产品硬规则，跨学段不可改变，例如证据上限不超过支持范围、学生不能替 Action 于确认、沉默不等于同意、Agent 不能绕过底层权限、缺少来源不能给高确定性结论、内部练习不能替代学校现实反馈；二是阶段配置参数，可在不同学段配置，例如阶段时间长度和结束条件、年级和课程结构、任务时长和难度基准、评价指标和反馈频率、内容包和学科范围、学生可操作界面复杂度、机构/教师/家长的参与范围；三是学科与内容模块，承载具体教育内容，例如知识与技能范围、教材和课程内容、学科方法和练习材料、教与授学科流程、学科证据与评价规则。配置和内容模块只是装入内容，不能改变产品硬规则。Agent 可依阶段配置调整组织方式，但不能用“配置”绕过学生主体、证据边界或监察规则。

### 四、哪些差异可能不只是“换内容”

不同学段差异不能简单归为“换知识库”，至少以下方面可能需要阶段适配机制额外处理：学生认知与操作能力（小学/初中学生对复杂路径、任务理由、确认流程的理解不同）；任务复杂度与节奏（任务规模、时间长度、完成方式不同）；教与授交互方式（讲解、练习、检验的呈现和引导不同）；学校反馈形式（作业、考试、教师反馈、课程安排不同）；机构与教师参与度；评价标准（阶段目标和升学要求不同）；家长信息边界（不同学段支持范围可能不同）；阶段交接复杂度（小升初、初升高对资产、记忆、规划的交接要求不同）。应区分内容差异（主要靠配置和内容模块承载）与机制差异（须重写责任链、状态规则或权限模型时需适配机制调整）。不能把所有差异预先归于配置，也不能把全部差异当作须重写。

### 五、学业阶段的生命周期

每个学业阶段应有明确边界：阶段从何时开始、到何时结束；升学或其他明确事件是否构成硬性结束；阶段中断、暂停或特殊情形如何处理；阶段配置和内容何时更新。升学通常是明确的阶段结束事件，而不是简单数据累积，是产品生命周期管理中的一等事件。阶段结束时，应区分当前会话、阶段内过程证据、阶段内学业资产、阶段内记忆、阶段规划、当前任务、未确认判断、学生主动选择交接的内容、需封存或归档的内容。

### 六、候选的阶段交接规则

建议采用以下候选原则：阶段内状态默认随阶段结束而封存；未经确认的推断不跨阶段延续；已确认、来源清楚且具有跨阶段复用价值的认识，只有在学生主动选择或满足明确交接条件后才进入下一阶段；所有交接均保留来源、版本、适用范围和撤回路径。可延续但需重新确认或说明范围的内容包括：学生主动选择保留的学业资产、学生希望在下一阶段继续引入的已知稳定认识、满足规则的跨阶段信息。不应静默延续的内容包括：未经确认的推断、已失效的规划、陈旧的长周期记忆、需重新按新阶段目标判断的内容、旧阶段中可能已不适用的方法或对象。底层应保证旧阶段对象和新阶段对象可区分、未确认内容不能自动作为新阶段初始上下文、阶段切换触发确定性封存流程、交接必须经明确学生选择或规则检查、Agent 不能自行把旧阶段状态当作新阶段事实继续使用、历史记录可回溯且可排除在即时语境外。

### 七、对象、状态、权限、反馈的跨学段适配

不同学段的材料、学科、任务、资产、记忆、反馈应各自绑定所在阶段标识，便于确定适用范围。阶段状态与学段内状态分开：某学科当前在该阶段的优先级、当前阶段的任务状态、该阶段内资产和记忆、阶段结束状态、跨阶段交接状态，不以“同一名学生”的名义自动合并不同阶段状态。不同阶段角色权限可以不同（教师/机构参与方式和查看范围、家长可见范围、学生可执行控制能力可以不同），但权限变化不能越出产品硬边界。不同学段学校任务、作业、考试、教师反馈形式不同：反馈来源和类型、频率、影响层级规则可以不同，但现实反馈不能自动拥有任意决定权。

### 八、如何证明统一产品结构成立

不能只用同名功能或相同界面证明统一结构。至少需验证：更换学段内容后底层责任链仍成立；阶段配置不需重写底层硬规则；Agent 在不同阶段使用同一套接口和权限契约；阶段适配能处理不同学生认知和操作复杂度；一个学段的修改不会意外破坏其他学段；各学段状态、权限、反馈相互隔离；阶段交接、封存和重新确认流程可用；多学段差异能通过配置、适配和内容模块覆盖，而非必须重写核心机制。出现以下情况不能继续当作统一产品结构：为共用同一逻辑把实质差异抹平；为统一牺牲学生可理解性；为复用代码让一个学段迁就另一个学段限制；用一个学段的最复杂逻辑限制所有学段；为统一而忽略机构、教师、家长和阶段目标差异。真实结构应在合理抽象层保持统一，在适配层承载差异，而不应在所有层强行统一或强行分开。

### 九、屏障结构：通用产品层—阶段适配层—学科内容层

合理的产品结构可分层：通用产品层（跨学段）负责责任链、证据/状态/权限/审计、底层/Agent 契约、阶段生命周期、B 端角色；阶段适配层负责阶段目标、课程、评价、学生复杂度适配、任务模型、机构/教师/家长配置、反馈类型；学科与内容层负责知识、方法、练习材料、教与授学科流程、学科证据规则、内容包版本。只有当适配层调整后，通用机制仍保持稳定，才能称其为统一产品结构。

### 十、底层与 Agent 的职责边界

底层负责：定义阶段边界；强制阶段结束的封存流程；保证学段间状态和权限隔离；记录升级、切换和交接；验证配置修改不破坏硬规则；阻止旧阶段内容静默进入新阶段；保证清单、审计和回滚；让 Agent 只能访问当前阶段受控对象。Agent 负责：依当前阶段配置调整任务、教与授和表达；生成符合该学段的解释和任务候选；根据阶段适配处理不同学生复杂度；在授权范围内读取当前阶段信息；组织阶段内学科和任务；提出阶段交接和重新确认建议；报告该阶段结果。Agent 不能：自行延长或终结阶段；自行改写阶段边界；把配置当规则绕过学生主体、证据或监察边界；在没有底层和确认机制的情况下让跨阶段状态直接生效。

### 十一、专业结论

> **学业军师采用阶段性生命周期，以升学或明确的阶段事实作为当前生命周期结束事件，不设定无边界的超长时间线。阶段内状态默认封存，未经确认的推断不跨阶段延续，已确认且具有复用价值的认识只有在学生选择或规则允许下才进入下一阶段。**
>
> **要证明统一产品结构成立，必须区分通用产品层、阶段适配层和学科内容层；必须验证在更换学段配置和内容后，底层责任链、证据规则、权限状态和运行契约仍保持稳定，且一个学段的修改不会破坏其他学段。**
>
> **不能在所有层强行统一现实，也不能为统一而抹平必需的特殊处理；统一层保持结构一致性，适配层承载各学段的任务组织、目标、任务复杂度、机构和家长的参与方式等差异。**

## 2.3　问题 2-3：学业路径、任务与教与授的承接

**标准化问题**：

学业军师如何把“整体判断 → 阶段内规划”转化为学生能够理解、接受并实际完成的任务，并通过教与授支持学生真实行动、取得可检验结果；任务应包含哪些要素；学生如何接受并行动（是否逐项确认、拒绝/暂停/未完成/无法完成处理、区分真实行动）；教与授是否必须由任务触发、讲解/练习/检验各解决什么、“看过讲解”为何不等于“掌握”；任务完成判据、任务层面有效与能力层面有效的区别、反馈如何进入下一轮规划、内部检验与学校现实反馈如何配合；底层固定哪些硬规则、Agent 负责什么。前提：规划要真正作用于学生，不能停留在“建议列表”或“对话里的计划”；这条链不能由 Agent 通过提示词自行保证，需底层对任务状态、行动真实性、教与授结果和检验依据做确定性记录。

**回应与论证**：

以下内容为 `[专业建议·代拟]`，原始底稿仅作参考、不覆盖当前代拟，用户随后回复“确认”。

### 一、核心原则

> **规划要真正作用于学生，不能停留在“建议列表”或“对话里的计划”。它必须被转化为学生能够理解、接受并实际完成的任务；任务必须通过教与授支持学生行动；行动必须产生可检验结果；结果必须回到任务状态、证据系统和下一轮规划。**

这条链不能由 Agent 通过提示词自行保证“我布置了任务”“学生明白了”。它需要底层设施对任务状态、行动真实性、教与授结果和检验依据进行确定性记录。

### 二、从规划到任务

任务是阶段内规划的具体、可执行单元。一个任务至少应包含：目标（这一步要达成什么）；理由（为什么现在做、承接了什么）；范围（属于哪个学科、知识点、阶段）；步骤（具体怎么做、分几步）；完成条件（做到什么程度算完成）；检验方式（如何确认真正掌握或解决）；预估时间；所需资源；所需证据（完成时会产生什么可观察结果）；适用范围（影响任务层、学科层还是整体规划层）；可逆程度（失败或调整会有什么影响）。任务不能只是“今天学数学”“多做几道题”，需足够具体让 Agent、学生和底层能就同一件事协作。

任务可由整体规划或学科安排派生：阶段目标 → 学科优先级 → 学科内计划 → 当前最应做的事 → 具体任务 → 教与授支持 → 学生行动 → 检验 → 反馈。Agent 负责拆解和生成任务候选；底层负责确认任务状态、权限及与当前规划的一致性。Agent 生成的任务默认属于任务候选，它进入当前规划、进入学生待办或改变任务状态，需经过与当前阶段目标和学科安排一致、证据支持其优先级、权限允许、必要时学生知情或确认、底层状态迁移。不能因 Agent 生成了任务，就自动认为学生应该完成或已接受。

如果只有建议列表，将无法回答：学生是否知道先做哪个、是否接受、是否真的开始做、做到哪一步、是否完成、结果如何、是否有效、是否需要调整。建议列表适合信息展示，不构成学习行动闭环。学业军师需要的是有状态、有行动、有结果、可反馈的任务。

### 三、学生如何接受并行动

不建议对所有任务逐次确认，否则会给学生造成过大负担，尤其对不擅长复杂操作的学生。建议分层：低影响、可逆、当前执行任务可默认进入待执行状态，学生可随时调整、拒绝或暂停；改变学科内安排或明显影响当前规划的任务，学生知情、必要时确认；改变全学科优先级、阶段目标或重大方向的任务，必须学生知情并确认；涉及资产、记忆、传播或跨阶段交接，必须明确确认。“默认进入待执行”不等于“学生已同意或已完成”，底层必须区分“待执行”“已接受”“已完成”等状态。

学生接受时记录进入执行阶段。学生拒绝时：若拒绝目标本身则停止该方向、回到目标澄清；若拒绝当前任务但接受目标则换方法、拆小任务、调整顺序；若拒绝提供材料则降低判断强度并明确无法继续判断的部分；若拒绝教与授则不伪造学习完成、保留未完成状态；若拒绝记录或传播用途则停止该用途并评估下游影响；若反复拒绝且原因不明则暂停扩展、提出有限澄清而非无限施压。Agent 不能把拒绝改写成“暂时没空”或“默认接受”。学生暂停时保留任务状态、明确暂停原因，不视为完成或放弃，恢复时从安全断点继续并说明是否仍有效。学生未完成时区分时间不足、任务过难、学生不理解目标、学生不认同任务、资源缺失、遗忘或中断，根据原因调整任务而非简单标记失败或继续加量。学生无法完成时（能力、时间或资源确实不足）降低任务规模和复杂度、拆分为更小步骤、调整完成条件和时间、请求补证、由教与授提供更充分支撑、必要时暂停相关高影响判断；不能因学生无法完成就伪造结果或降低质量标准。

必须区分：系统布置任务、学生接受任务、学生声称完成、存在可检查结果。“存在可检查结果”和“学生声称完成”必须分开。底层至少记录：学生提交的作答、练习或材料；提交时间；内容是否真实存在；是否来自学生本人；是否经过系统生成包装。不能因学生点击“我完成了”就自动把任务升级为“已验证完成”。完成检验取决于结果是否可观察、可检查，并可能需现实复验。

### 四、教与授如何承接任务

教与授不应成为与任务无关的独立内容消费，它应服务于当前任务或当前问题。但这不等于只有任务触发才能提供帮助，可能出现：学生遇到障碍需先讲解再继续任务；学生在练习后需要反馈；学生请求对某内容作更深入讲解；学生在复盘时需要回顾。因此更准确的表述是：教与授服务于当前任务或问题，但可以根据任务进度、学生反馈和实际需要动态触发，而不只是线性地“先讲—再做—再检验”。

讲解解决“理解和为什么”（为什么重要、怎么理解、与已有内容的关系、常见误区和边界），讲解不自动等于掌握，学生看过讲解后需要练习和检验来验证理解。练习解决“会不会做、做得对不对”（应用和熟练、暴露真实能力、巩固理解、发现未掌握之处），应由学生亲自完成，不能由系统代写或生成结果冒充学生作答。检验解决“是否真正掌握、能否迁移”（检验即时理解、迁移能力、暴露记忆和方法缺口、为下一轮任务提供依据），检验结果需来源、对象和时间才能成为可靠证据。

“看过讲解”不等于“掌握”，因为：看过可能只是阅读或播放；理解是内部过程需行为证明；记忆会随时间衰减；知识需迁移到不同任务才算掌握；系统无法仅凭“已查看”证明能力形成。因此：讲解结果作为“已提供支持”记录；练习和检验结果作为“学生行为与表现”记录；只有学生完成的、可检查的行为结果才能作为能力相关证据；不能把“已查看”“已生成”“对话中表示明白”当作能力已形成。底层应区分“系统生成内容”和“学生真实行为”。教与授过程至少应产生：提供了什么支持；学生完成或未完成什么；练习和检验结果；结果对应来源和对象；学生理解和应用的缺口；下一步建议；是否进入下一轮任务或需补证。这些结果应进入任务状态和证据系统，供整体协调和后续规划使用。

### 五、检验与反馈闭环

任务完成不等于任务被提交或学生声称完成。较合理的判据应包括：有明确完成条件；产生可检查的结果；结果与任务目标相关；结果来自学生真实行动；有来源、对象和时间；必要时经过现实复验或 Agent 复核；通过底层状态迁移。对学习性任务，“完成”还可能不等于“已掌握”，需区分任务层面完成和能力层面形成。

任务层面有效指这次任务完成、结果满足该任务条件；能力层面有效指学生在相似或不同任务中持续表现稳定、能够迁移。单次任务完成不能推出能力形成，需多次任务、不同情境、时间持续性、迁移表现、学校现实反馈。因此：任务完成记录为“该任务已完成且结果可查”；能力层面只能作为“待观察”或“有限支持”，未经迁移和现实反馈不能宣称为稳定能力。

任务结果和检验结果应回到：该学科任务状态；学科内规划；整体协调层；证据系统；资产或记忆候选；下一步任务建议。反馈进入下一轮规划时仍需经过来源和对象确认、影响范围判断、权限和状态检查、必要时学生确认、底层合法迁移。内部检验可以验证机制和局部理解，学校现实反馈提供更真实的学习过程验证。建议顺序：内部练习 → 内部检验 → 学校任务 → 学校现实反馈 → 修正内部判断。内部检验不能替代学校现实反馈，学校反馈也不能跳过内部教与授和练习直接构成完整闭环。

### 六、底层与 Agent 的分工

底层负责：任务状态机（候选、待执行、已接受、执行中、已完成、已检验、已撤销、已暂停）；区分学生真实行动和系统生成内容；保存学生提交的原始作答和结果；记录教与授内容和版本；记录练习、作答和检验结果；检验结果必须有来源、对象和时间；防止伪造、代写和静默修改；权限和跨责任域调用；审计、版本、回滚和恢复；结果能否进入下一步的证据判断。

Agent 负责：从规划拆解任务；生成任务候选；组织教与授编排；解释讲解和反馈；分析练习和检验结果；识别学生困难和原因；提出下一步和替代方案；请求学生确认、拒绝或补证；汇总结果供整体协调使用。Agent 不能：把生成任务等同于学生接受或完成；代写作答；把“已查看”当“已掌握”；伪造检验结果；自行升级状态；绕过底层证据记录。

学生：理解任务、接受或拒绝、完成行动、参与练习和检验、提供复盘和反馈、确认重大方向。教师/机构：在授权范围内提供学校反馈、专业意见、课程进度和任务支持，不取代学生行动和产品底层规则。

### 七、专业结论

> **规划只有转化为具体、可执行、可检验的任务，并通过教与授支持学生行动，才真正成为学业军师的责任链，而不是停留在建议层面。任务必须有明确的状态和完成条件；学生行动必须真实、可观察、有来源；教与授服务任务但不自动等于掌握；检验区分任务层面有效和能力层面有效；结果必须回到证据、任务和规划，并经过底层状态迁移和必要确认。**
>
> **底层保证任务状态、行动真实性、检验来源和结果证据不可伪造；Agent 负责从规划到任务的转化、教与授编排、结果解释和下一步建议。二者通过状态、权限和审计契约协同，而不是靠提示词约束。**

## 2.4　问题 2-4：学校现实反馈如何进入产品并改变判断

**标准化问题**：

学校中的真实学习过程、作业、考试、教师反馈和评价结果，如何进入学业军师的证据系统，并在不被过度解释的前提下，改变任务、学科安排、全学科规划和学业资产？前提：学校现实反馈是重要外部检验来源，但既不是可任意使用的“高权重分数”，也不是自动改写规划的依据；反馈必须先登记来源、评估完整性、归属到对应学科和任务，在不受过度解释的前提下决定其影响层级与状态变化。

**回应与论证**：

以下内容为记录中本单元完整回应正文（`[专业建议·代拟]`，用户要求“专业代拟”，随后回复“确认”）。

### 一、核心原则

> **学校现实反馈是学业军师的重要外部检验来源，但它不是可以任意使用的“高权重分数”，也不是自动改写规划的依据。反馈必须先被登记来源、评估完整性、归属到对应学科和任务，并在不被过度解释的前提下，决定它能够影响哪些层级、触发何种状态变化。**

学校反馈的处理应遵循一条受控路径，而不是“收到即改变规划”：

```text
接收反馈
  → 来源登记与证据归属
  → 完整性、时间和冲突检查
  → 确定它属于哪个任务/学科/阶段
  → 判断证据强度和适用范围
  → Agent 分析并提出影响建议
  → 底层校验影响层级和权限
  → 必要时学生/教师/机构确认
  → 执行合法状态迁移
  → 记录审计与回滚路径
```

Agent 可以解释反馈并提出调整；底层决定反馈能否真正改变产品状态。

### 二、学校反馈的来源与类型

产品应能承接多类学校相关输入，但它们的证据性质不同。

#### 1. 原始学校材料

例如：作业、试卷、错题、教师批注、评分结果、课堂任务、课程进度。这些是可直接查看的原始对象，可用于提取可观察事实和定位问题。

#### 2. 成绩与评价结果

例如考试成绩、单元评价、阶段评定。属于结果性信息，能提供特定任务的表现，但不能单独证明长期能力或完全归因于产品。

#### 3. 教师批注与专业意见

反映教师对作业、过程或学习状态的观察和解释。属于外部专业观察，但教师意见也带有解释性，不能自动视为最终事实。

#### 4. 学生转述的学校反馈

例如学生转述教师说“字写得不工整”“这次进步了”。这是二手信息，证据强度通常低于原始材料和直接教师意见，需保留“转述”属性并考虑是否补证。

#### 5. 机构/教师/教研补充判断

机构或教研人员基于整体教学、课程要求给出的补充意见，可以协助理解学校现实，但不应绕过学生主体或底层规则。

#### 6. 家长对学校学习情况的反馈

家长反馈可以补充学习处境信息，但家长反馈一般不自动拥有直接改写规划或资产状态的能力，需先进入证据和处境信息处理。

### 三、来源可靠性与证据强度

#### 1. 不同来源如何分级

不能简单按“学校 > 教师 > 学生”一刀切。更合理的做法是区分：

- **原始可查材料**：如试卷、作业、评分单，可直接查看，证据强度相对高；
- **专业解释**：如教师对错因的解释，具有专业价值，但属于解释；
- **结果信息**：如分数，反映特定任务表现；
- **二手转述**：如学生转述教师意见，需保留转述属性并可能补证；
- **内部生成**：如产品对材料的分析、Agent 判断，属于分析而非原始事实；
- **待核实信息**：来源不明、无法验证或由一方单独提供，需降低确定性。

证据强度应结合来源直接性、材料完整性、时间新鲜度、是否存在独立印证、是否存在冲突、能否回溯到原始对象判断。

#### 2. 来源冲突的处理

当不同来源冲突时：保存所有来源；标记冲突；不单方面覆盖；识别冲突是事实冲突还是解释冲突；提出补证或复核；在冲突解决前限制高影响状态升级；必要时要学生、教师或机构确认。

例如，学生自述“我都会了”与考试结果冲突时，保留两者：考试结果提供结果性信息，学生自述提供主观处境；教师批注与评分结果冲突时，核对是否针对不同方面；单次考试与长期趋势冲突时，区分短期与长期。

#### 3. 学生只能提供摘要或照片

仍可登记为有限信息，但须标注完整性和可验证程度，降低由该材料支持的判断强度；不能把低分辨率或残缺材料当作完整结果；必要时请求更完整材料或注明限制。

#### 4. 反馈不完整、延迟或无法验证

应标记为待补或待核实，不影响已经建立的可靠判断，不作为高影响调整的主要依据，记录时间和延迟，避免把过时反馈当作最新状态。
### 四、反馈如何进入不同层级

学校反馈可以影响不同层级，但每一层的升级条件不同。

#### 1. 当前任务

单次任务或单次反馈可以影响当前任务的完成判断，影响当前教与授的调整，触发补充练习或检验，更新该任务的结果证据。

#### 2. 学科内判断

当反馈与既有材料结合，显示同一学科内的问题重复或改善时，可以影响该学科的教与授安排、学科内任务优先级和学科层工作判断，并提出补证或复核。

#### 3. 学科阶段规划

当反馈持续、重要且与学科阶段目标相关时，可以调整学科阶段内计划、任务安排和节奏，修订学科阶段目标描述；通常仍需学生知情，重大调整需确认。

#### 4. 全学科优先级

只有反馈显示跨学科失衡、资源冲突或整体目标受影响时，才可能上升到全学科协调层。需要来自多个学科的反馈或影响、明确影响范围、跨学科资源或优先级冲突，并经过整体协调层比较；重大优先级调整需学生确认。

#### 5. 阶段性总体目标

只有当反馈实质影响阶段目标或阶段结束条件时，才可能改变阶段性目标。这属于重大调整，应明确影响和依据，由学生知情并确认，保留版本和回滚。

#### 6. 学业资产状态

学校反馈可以支持或否定已确认资产的适用范围，将资产转为待复核、修订或失效，为形成新资产候选提供现实依据。但反馈不自动把内容升级为“已现实验证的学生能力”；资产是否成立仍需学生确认，是否有效仍需持续复验。

#### 7. 阶段内记忆

只有满足记忆准入规则（持续价值、范围清楚、来源可追溯、学生可见可纠正）时，学校反馈才可作为阶段内记忆的一部分，且不自动静默延续到下一阶段。

### 五、反馈缺失与冲突

#### 1. 没有学校反馈时

产品可以整理材料、标记问题和未知、提供低确定性解释、设计可逆练习和观察任务、记录学生行动和内部结果、明确需要何种外部反馈。应限制或暂停把内部练习升级为稳定能力、把一次表现升级为长期判断、形成未经复验的高影响资产、据此大幅调整全学科优先级、宣称产品已产生教育效果。

#### 2. 反馈缺失是否降低判断强度

一般应降低高影响判断的确定性，或在缺少关键学校结果时将相关判断标记为“待现实反馈支持”，避免把机制运行或内部结果当现实验证。

#### 3. 学生自述与教师反馈冲突

保留双方，标注冲突类型，不默认学生或教师一方正确，提出补证或复核，必要时要相关角色确认；冲突解决前限制高影响状态升级。

#### 4. 单次高低分与长期趋势冲突

区分单次波动和长期趋势；单次结果作为该任务的表现证据，不因单次结果自动改写长期规划，需要更多时间和结果判断趋势，并标识继续观察。

#### 5. 反馈无法归因于产品

学校结果改善也不自动归因于产品造成的全部变化。需考虑教师、课程、家长、学生自身变化等其他因素，不能因为“使用产品后成绩变化”就直接断言产品造成该变化。

#### 6. 何时暂停高影响判断或补证

当反馈与既有判断严重冲突、来源不足、无法验证，或影响阶段性重大决定时，应暂停相关高影响迁移，请求补证或复核，标记待确认，在获得足够证据前不改变重大状态。

### 六、底层与 Agent 的分工

**底层负责**：登记反馈来源、时间、完整性和归属；区分原始学校材料、转述、教师意见和内部分析；记录冲突和缺失；防止内部练习被当作学校结果；控制反馈可以影响哪个层级；阻止未经确认的重大规划迁移；记录影响对象、审计和回滚路径；保证单次反馈不能静默改写整体规划；保留反馈修正链。

**Agent 负责**：分析反馈；解释反馈对任务、学科和整体安排的意义；比较连续结果；识别可能趋势和冲突；提出任务、学科或规划调整候选；请求学生、教师或机构确认；汇总供整体协调使用。

Agent 不能把单次反馈直接升级为长期结论，不能隐藏反馈与既有证据的冲突，不能自行决定反馈足以改变全学科规划，不能绕过底层证据和状态规则，也不能把学校结果自动归因于产品效果。

**学生、教师、机构**：学生提供真实行动和学校材料、确认重大方向、纠正个人事实；教师/机构在授权范围提供学校反馈、专业意见、课程进度和补证，不代替学生行动，不绕过产品底层规则。

### 七、“学校现实检验”成立的条件

只有当以下条件同时满足时，才能说产品真正接入了学校现实，而不是只收集了学生上传的材料：

1. 反馈具有可追溯的学校来源；
2. 学生在学校中有真实行动；
3. 存在结果性反馈（作业、考试、评价等）；
4. 反馈经过来源登记、完整性和归属处理；
5. 反馈进入对应任务、学科或整体层；
6. 反馈引起可追溯的任务、规划或资产调整；
7. 反馈与内部判断、证据和既往安排一致或明确冲突；
8. 不能把内部模拟、局部练习或单次结果当作学校现实验证；
9. 反馈变化能被追溯和回滚。

如果没有这些条件，产品只是在收集材料或模拟练习，不能宣称已经完成学校现实检验。

### 八、专业结论

> **学校现实反馈进入产品，必须先经过来源登记、证据归属、完整性、时间和冲突处理，再确定它能影响哪个层级。反馈不能自动、静默地改变重大规划或资产状态，也不能把单次结果、内部练习或转述信息当作完整现实验证。**
>
> **底层负责反馈来源、层级控制、冲突、归因边界、审计和回滚；Agent 负责分析、解释和提出调整候选。产品只有满足可追溯学校来源、真实行动、结果反馈、持续观察和反馈回流到规划等条件，才可称为接入了学校现实检验。**

## 2.5　问题 2-5：学业资产与阶段内持续认识的生命周期

**标准化问题**：

学业资产与阶段内持续认识的生命周期。前提：学业资产不应被定义为资料、记录、标签或 AI 总结，而应定义为从学生真实学业过程中的证据中提炼、经学生理解纠正与确认、能在明确范围内参与后续学习、并可在新证据出现时被复核修订或失效的个人化学业认识；原始底稿仅作参考以提升“学业资产—证据—记忆—现实复验”的概念稳定性，不覆盖本次代拟，也不把历史“已确认”直接升级为当前决定。

**回应与论证**：

以下内容为记录中本单元完整回应正文（`[专业建议·代拟]`，用户随后回复“确认”）。

### 一、学业资产的产品定义

学业资产不应被定义为资料、记录、标签或 AI 总结，而应定义为：

> **从学生真实学业过程中的证据中提炼，经学生理解、纠正与确认，能够在明确范围内参与后续学习，并可在新证据出现时被复核、修订或失效的个人化学业认识。**

这个定义包含六个必要条件：

1. **有来源**：能够回溯到作业、试卷、练习、学校反馈、行动记录等证据；
2. **有提炼过程**：能够说明从哪些材料、行动和结果中形成；
3. **有适用范围**：明确适用于哪个学科、任务类型、学习阶段或条件；
4. **有学生理解与确认**：学生能够理解其含义、依据和限制，并确认愿意作为自己的认识保存；
5. **可参与后续学习**：能够对后续任务、教与授或复盘提供实际帮助；
6. **可被复核和修订**：不是永久事实，后续证据可以扩大、缩小、修正或否定其适用范围。

缺少这些条件的内容，可以是材料、证据、分析结果、规划建议或资产候选，但不能直接称为正式学业资产。

### 二、学业资产与相邻对象的区别

| 对象 | 它是什么 | 能否直接称为学业资产 |
|---|---|---|
| 原始材料 | 学生或机构提交的作业、试卷、教材等内容 | 不能 |
| 证据 | 能够支持特定判断的、有来源和范围的材料或记录 | 不能自动成为资产 |
| Agent 分析 | 对材料、行动或反馈的解释 | 不能 |
| 规划 | 对未来学习方向和行动的安排 | 不是资产 |
| 资产候选 | Agent 根据证据提出的可复用认识 | 尚不能 |
| 学生确认的认识 | 学生理解、纠正并愿意保留的个人认识 | 可以成为阶段内有效资产 |
| 阶段内记忆 | 为持续协作而受控保留的信息或认识 | 不等同于资产 |
| 能力证据 | 学生在任务或现实环境中的可观察表现 | 可支持资产复验，但不等同于资产 |

还必须区分三个问题：

1. **资产是否按产品流程成立**；
2. **资产能否在后续学习中复用**；
3. **资产所反映的能力是否经现实过程验证**。

学生确认主要解决第一项；后续复用观察解决第二项；学校任务、考试和持续反馈主要参与第三项。三者不能压缩成一个“已掌握”状态。

### 三、学业资产的形成流程

建议采用以下生命周期：

```text
原始材料
  → 证据登记
  → 证据关联与处理
  → 资产候选
  → 学生理解与纠正
  → 学生确认
  → 阶段内有效资产
  → 后续任务调用
  → 现实复验
  → 保持、修订、降级、失效或归档
```

#### 1. 原始材料

底层保存材料原件、来源、时间、归属、完整性和授权范围。Agent 不得覆盖原始材料。

#### 2. 证据登记

底层将材料登记为证据对象或其他明确对象，并记录来源、类型、学科、阶段、任务、时间、完整性、允许用途、当前状态。

#### 3. 关联与处理

Agent 可以对证据进行内容提取、问题识别、重复模式分析、行动结果比较、反馈关联、冲突发现。这些过程结果仍然是分析或处理证据，不能自动成为资产。

#### 4. 资产候选

Agent 可以提出一个资产候选，并说明候选认识是什么、来源于哪些证据、经过了什么分析、适用范围是什么、当前有哪些限制和未知、需要如何复验、为什么可能对后续学习有用。底层将其标记为“资产候选”，不能直接写成有效资产。

#### 5. 学生理解与纠正

学生应能够看到这项认识的内容、依据和来源、形成时间、适用范围、当前确定程度、仍存在的限制，以及可以如何纠正、补充或拒绝。学生可以指出事实错误、补充条件、缩小范围或拒绝将其保存为自己的认识。

#### 6. 学生确认

只有学生明确确认，并且底层检查来源、范围和状态条件后，候选才可进入“阶段内有效资产”或相应的正式状态。

学生确认的含义是：

> **我理解这项认识及其限制，并愿意在当前学业阶段内将其作为可复用的个人认识保存。**

这不等于该认识永远正确、学生已经形成稳定能力、学校已经验证其有效、产品可以将其无限传播、或它可以自动跨阶段延续。

### 四、学业资产的复用边界

#### 1. 当前任务

已确认但尚未充分现实复验的资产，可以作为当前任务的参考、教与授方式选择的依据、复验任务的设计依据、低或中确定性的判断输入。必须保留资产来源、适用范围、当前验证状态和可能的限制与冲突。

#### 2. 学科内规划

在资产适用于特定学科和任务范围时，可以参与学科内任务排序、教与授安排、学科内规划候选和后续复验设计。不能因为一项资产在某类任务中有效，就默认它适用于该学科所有任务。

#### 3. 全学科协调

只有当资产明确涉及多学科共同能力、时间和资源分配、学科之间的相互影响、阶段目标，并且证据和适用范围足够清楚时，才可以作为全学科协调的参考。单一学科资产不能自动改变整体学业优先级。

#### 4. 教与授

资产可以帮助 Agent 选择解释方式、识别学生可能需要的支架、设计复验练习、避免重复无效的教学方式。但资产不是教学结论，教与授仍需依据当前任务和新证据调整。

#### 5. 跨会话调用

阶段内资产可以跨相关会话调用，但必须在授权范围内、与当前任务相关、保留来源和适用范围、不把资产全文无差别注入所有会话、并在资产被撤回、修订或失效时停止旧版本调用。

#### 6. 跨学科调用

跨学科调用必须满足：明确说明为什么需要、只读取最小必要范围、经过跨域权限控制、保留调用记录、不把学科内认识直接当成全局事实、出现冲突时回到整体协调和证据治理。

#### 7. 跨阶段交接

跨阶段不能静默调用。只有在来源清楚、学生已经确认、具有明确的跨阶段复用理由、适用范围可以解释、新阶段重新确认或满足明确交接条件时，才可进入新阶段的受控交接内容。否则应封存、降级为待确认或留作历史记录。
### 五、资产失效、修订和归档

#### 1. 新证据支持

如果后续任务和学校反馈持续支持原认识，可以保持有效、扩大适用范围、提高现实验证状态；但不能因此自动提升为永久事实。

#### 2. 新证据冲突

如果新证据与资产冲突，应保留原资产版本、标记冲突、暂停无条件调用、进入待复核、由 Agent 提出修订或失效建议，必要时请求学生理解和确认新版本。不能静默覆盖旧资产。

#### 3. 仅在有限范围有效

如果资产只在某一学科、任务类型或条件下有效，应缩小适用范围、保留限制、禁止跨范围推广，不必因此将其整体判为失效。

#### 4. 学生撤回

学生撤回可以针对保存、当前调用、跨会话调用、跨学科调用、机构/教师可见、家长传播、跨阶段交接分别处理。撤回某一用途不必然等于删除全部历史审计，但撤回后的内容不得继续在被禁止的用途下使用。

#### 5. 长期未使用

长期未使用本身不能证明资产错误，但可以触发降低调用优先级、标记需要重新确认、进入待复核、在新任务中重新检查适用性。不能仅因未使用就自动删除或继续当作当前有效认识。

#### 6. 阶段结束

阶段结束时，阶段内资产默认封存；未确认候选不得交接；已确认资产不自动进入新阶段；适合跨阶段使用的内容应按交接规则重新确认；失效或过时内容不得作为新阶段默认输入；历史版本和来源链继续可回溯。

建议状态链如下：

```text
资产候选
→ 待学生确认
→ 阶段内有效
→ 待复核
→ 修订版有效
→ 降级
→ 失效
→ 归档
```

### 六、学业资产与阶段内记忆的关系

#### 1. 资产不自动进入记忆

资产是学生可以理解、查看和复用的个人认识；记忆是为跨会话持续协作而保留的信息。二者目的不同。因此已确认资产不自动写入记忆；只有符合持续使用价值、范围清楚、权限明确和阶段内用途的内容，才可成为记忆候选；阶段内记忆也不自动成为学业资产。

#### 2. 记忆可以没有资产

某些运行信息可能需要在阶段内保留，但不适合称为学业资产，例如当前任务进度、学生偏好的讲解方式、已经说明过的操作约定、阶段内的工作上下文、仍待确认的事项。这些内容可以是受控运行记忆，但不能被包装成学生的正式学业认识。

#### 3. 记忆的准入和退出

底层应控制进入记忆的条件、记忆适用范围、使用期限、可读取角色、可纠正撤回和删除、失效和阶段封存、下游调用阻断。Agent 可以提出“建议记忆”，但不能自行写入、扩大范围或延长生命周期。

### 七、底层与 Agent 的分工

**底层必须设计和强制执行**：资产、证据、记忆和规划的对象区分；原始材料保护；资产状态机；来源和版本链；学生确认流程；现实复验状态；适用范围；调用权限；跨会话、跨学科和跨阶段限制；撤回、删除、失效、归档和回滚；资产与记忆的下游影响追踪；Agent 不得静默改写或升级状态。

**Agent 可以执行**：从证据中提炼资产候选；解释资产来源、范围和限制；组织学生理解、纠正和确认；根据资产提出任务和教与授方案；分析新反馈；提出修订、降级、暂停或失效建议；生成阶段总结和交接候选；向学生呈现资产和复验状态。

**学生负责**：判断是否理解；纠正事实和范围；确认是否保存为个人认识；决定是否接受当前用途；撤回、拒绝、暂停和删除可控内容；参与后续行动和现实复验。

**学校、教师和机构负责**：提供或补充现实学习反馈；在授权范围内提供专业意见；协助核对事实和结果；不替学生确认个人学业资产；不绕过底层规则修改资产含义。

### 八、学业资产成立的最低判据

一项内容至少同时满足以下条件，才可以进入“阶段内有效资产”：

1. 有明确、可回溯的来源；
2. 形成过程可解释；
3. 适用范围和限制清楚；
4. 与学生真实学习过程有关；
5. 学生能够理解并纠正；
6. 学生明确确认保存；
7. 底层完成合法状态迁移；
8. 后续调用可以被审计；
9. 仍允许新证据触发复核、修订或失效。

即使满足这些条件，也只能说明它是**阶段内有效的个人学业认识**，不能直接说明学生已经形成稳定能力、该认识跨学科跨阶段普遍有效、该认识已经被学校现实充分验证、或产品已经产生教育效果。

### 九、专业结论

> **学业资产是从真实学习证据中提炼、经学生理解和确认、能够在明确范围内复用并可被现实反馈修订的阶段内个人学业认识。它既不是原始资料，也不是 AI 总结，更不是学生能力本身。**
>
> **资产的形成必须经过证据登记、关联处理、候选提炼、学生理解纠正、明确确认和底层状态迁移；资产的有效性还必须通过后续学习任务和学校现实反馈持续检验。**
>
> **底层基础设施负责资产对象、状态机、来源链、确认、权限、生命周期、撤回、失效和回滚；Agent 负责提炼候选、解释、组织确认、提出复用和修订建议；学生负责理解、纠正、确认、拒绝和撤回。**
>
> **资产不自动进入阶段内记忆，也不自动跨阶段延续。阶段结束时，资产默认封存；未经确认的内容不得交接，已确认内容只有在满足明确适用条件并经过必要重新确认后，才能作为新阶段的受控输入。**
