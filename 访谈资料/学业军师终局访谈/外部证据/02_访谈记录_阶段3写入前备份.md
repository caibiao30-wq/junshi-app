### 问题 0-2：元文件与专业领域文件之间的派生、继承、覆盖、冲突、回溯、版本关系如何定义

**问题**：
元文件与专业领域文件之间的派生、继承、覆盖、冲突、回溯、版本关系如何定义？（主持人先代拟，受访者澄清后确认。）

**回应**：

*主持人代拟初稿（[专业建议·代拟]，初稿曾把"元文件主导一切"与"带受控反馈通道的权威"两种框架混写）*：
初稿含 A/B 两种表述混写：A 为元文件主导一切；B 为元文件是当前最高权威但保留受控反馈通道。

*受访者追问（原话，关键）*：
"你的意思是……还是说元文件主导一切？"

*主持人澄清（[已被修正]）*：
主持人承认初稿把两种逻辑混写是表述失误，予以修正；明确不是元文件主导一切，而是元文件是当前最高权威、但保留受控反馈通道。

两种逻辑的对比：
- A. 元文件主导一切（单向权威）：派生文件只能服从元文件，冲突时永远元文件胜，派生文件无权质疑。
- B. 元文件为主导，但允许"冲突上报 → 由人裁决 → 可能修改元文件"（带反馈的权威）：派生文件不得自行改元文件，但有权指出"元文件某条与工程现实/学生现实冲突"，停下上报，由受访者裁决。

主持人明确选择 B，并指出 A 的问题：若元文件主导一切，元文件会变成不可修正的教条；学业军师处于真实教育环境，工程现实、学生现实一定会挑战元文件某些根级判断，若挑战被永远压回，元文件就和现实脱节。

三件事的权限区分：
| 动作 | 谁有权 | 说明 |
|---|---|---|
| 上报冲突 | Agent（派生文件）有 | 指出元文件某条与工程/学生现实冲突，附理由 |
| 裁决冲突 | 受访者（人）有 | 决定修改元文件/驳回/降级为派生层处理 |
| 改元文件 | 只有受访者 | Agent 不得自行新增/修改/删除元文件根级决策 |

*受访者确认后的最终判断（[确认采纳]）*：
采纳"元文件为主导 + 冲突可上报 + 由受访者裁决 + 仅受访者可改元文件"的框架，并采纳"上报须有实质证据且给出不改的后果"的门槛。受访者明确表示：不是元文件主导一切，而是元文件是当前最高权威，但保留受控反馈通道。

*最终判断内容*：
1. 元文件是当前最高权威，专业领域文件受它约束、不得越权修改它。
2. 当派生文件发现元文件某条根级决策与现实（工程/学生/学校）冲突时，它有权停止并上报，附理由与证据。
3. 冲突裁决权始终在受访者（人）手里：由受访者决定修改元文件、驳回上报，或把问题留在派生层处理。
4. Agent/派生文件只有上报权，没有改元文件的权力；修改元文件根级决策是人的专属权力。
5. 上报门槛：必须提供实质证据（工程失败、学生伤害、明确无法满足的验收），并给出"若不修改的后果"；不得以"我觉得这样更好"为由随意上报，以防稀释元文件权威。
6. 派生关系五规则：派生→受约束→冲突上报→回溯核验→版本衔接。专业领域文件从元文件继承根级责任、角色责任、统一状态/接口/权限/验收原则、完成定义与回溯链；只能缩小或细化根级边界，不能扩大、回避或改写根级责任；元文件根级变更须版本化、可追溯、可回退，并触发下游重新核验与验收；专业领域文件可替换/弃用/迭代但不能脱离元文件版本约束，须标注所依据的元文件版本。

**确认状态**：[确认采纳]

**原始定位**：第三轮终局访谈·方向0·Q0-2；主持提问"代拟"轮 → 主持人代拟（初稿曾把 A/B 混写）→ 受访者追问"是元文件主导一切还是可上报修改"轮 → 主持人澄清 A/B 并建议 B → 受访者"确认以上两点、可交付 fork"轮。修正链：初稿 A/B 混写 [已被修正] → 最终采用 B 带受控反馈 + 上报门槛。覆盖范围：Q0-2 最终判断六条、上报门槛框架、B 受控反馈通道框架，及 A/B 两种逻辑对比与三权（上报/裁决/改元文件）区分。

### 问题 0-3：一个专业领域文件从元文件派生时，最低必须继承哪些内容

**问题**：
一个专业领域文件从元文件派生时，最低必须继承哪些内容？（主持人代拟，受访者确认采纳。）

**回应**：

*主持人代拟稿（[专业建议·代拟]，供受访者确认）*：
每个派生文件必须携带"元文件锚点头"，含以下字段：
1. 根级责任锚：对应哪项根级/产品责任、主责任；
2. 适用范围：产品、学段/学科、角色；
3. 排除范围；
4. 继承的根级边界：证据纪律、学生控制、权限、判断引擎原则、自生长边界、不可逆操作、审计可追溯；
5. 统一规则：状态、接口、权限、验收，不另造平行体系；
6. 完成定义与验收判据；
7. 上游引用：元文件版本、决策节点、证据与访谈定位；
8. 新增内容清单；
9. 未定项；
10. 派生执行者：coding agent（Claude Code 主 / pi / Codex 辅）；
11. 回溯与控制：元文件变更触发重新核验；
12. 版本状态：自身版本、依赖的元文件版本、替换/弃用/演进。

锚点头是派生文件与元文件的强制契约，缺任一字段即未完成派生，不得进入实现；锚点头不能被派生文件静默扩大：只能缩小或细化根级边界，不能扩大责任、降低证据门槛或突破权限。派生文件正文 = 锚点头 + 元文件边界内的具体展开。

### 问题 0-4：多个专业领域文件重叠、边界、责任归属与协调

**问题**：
多个专业领域文件发生重叠时，边界、责任归属与协调关系如何定义？（主持人代拟，受访者确认采纳。）

**回应**：

*主持人代拟稿（[专业建议·代拟]，供受访者确认）*：
专业领域文件之间不形成平行权威体系。每个文件有明确主责、边界和依赖；共同依赖的根级内容归元文件，领域内部具体内容由主责文件负责，跨域事项通过上游根规则、明确接口和冲突上报协调。

1. 专业领域文件不形成平行权威。
2. 每个可验收对象只有一个唯一主责文件，可有协作文件。
3. 共同依赖的根级内容归元文件。
4. 跨域内容指定主责，并以稳定接口/版本引用，避免重复定义。
5. 允许横向引用，但不得绕过或改写元文件/主责；循环依赖必须上报。
6. 冲突对象处理：先冻结，核对锚点与主责；越界则撤回/改写；接口不清则修订接口；触及根级则按 Q0-2 上报由受访者裁决；之后更新并触发受影响文件重新验证。
7. 责任登记表为强制检查项，包含：责任对象、唯一主责、协作、输入输出、根级来源、冲突状态、验收责任、受影响文件。

应放入元文件的内容（满足任一条件）：被三个或以上领域共同依赖；涉及产品根级责任或最高边界；涉及跨域状态、权限、证据等级或验收原则；任何领域改变它都会影响多个下游；必须保持全产品唯一口径。

应留在专业领域文件的内容：只影响一个领域、不会改变根级责任的具体内容（学科内容、教与授具体流程、某前端页面交互细节、某技术组件配置、某学段适配规则）。

推荐结构：

```text
元文件
├── 判断引擎文件 ──提供判断结果接口──→ 教与授文件
├── 证据治理文件 ──提供证据状态接口──→ 判断引擎文件
├── 学业资产文件 ──提供资产生命周期接口──→ 判断引擎/教与授
└── 前端文件 ──呈现各领域已授权结果──→ 学生界面
```

箭头表示接口依赖，不表示下游文件可以修改上游文件的主责。

*受访者确认*：回复"确认采纳"。

### 问题 0-5：元文件变更后的影响传播与重新核验

**问题**：
元文件发生根级变更后，如何识别受影响的专业领域文件、触发重新核验、处理新旧版本与暂停工程实现？（主持人代拟，受访者确认采纳，并新增阶段写入要求。）

**回应**：

*主持人代拟稿（[专业建议·代拟]，供受访者确认）*：
元文件变更采用"影响分析 → 定向重验 → 冲突冻结 → 人工裁决 → 重新放行"的机制。所有派生文件必须依据明确的元文件版本工作；未完成受影响范围核验的派生文件，不得继续进入受影响部分的工程实现。

（一）会触发重新核验的变更：产品本体/核心责任/非责任变更；判断引擎专项范围、判断原则或证据要求变更；自生长/自进化允许范围、停止条件或控制边界变更；角色责任或权限变更；证据/状态/接口/权限/审计/验收原则变更；首版边界、专业领域派生规则或技术自持边界变更；任何可能影响多个专业领域文件的根级事实、约束或完成定义变更。仅错别字、排版或不改变语义的格式修改可不触发语义重验，但仍须记录。

（二）只重验受影响文件，但不得漏掉间接依赖：直接引用被修改决策/接口/状态/权限/验收标准的文件必须重验；依赖直接受影响文件输出的下游文件也必须检查间接影响；无法判断是否受影响时按受影响处理；重大根级变更可由受访者决定扩大为全量重验；影响范围必须形成清单，不能只凭 Agent 主观判断。

（三）识别受影响文件的依据：元文件锚点头中的根级责任引用；决策 ID、问题节点 ID 和版本引用；责任对象登记表；输入/输出接口引用；状态、权限和验收标准引用；文件间横向依赖；共享领域对象与共同数据模型；代码、测试或配置的反向引用。每个派生文件必须能回答：依赖哪个元文件版本、引用了哪些决策/责任/接口/状态/权限/验收、这些引用中哪些变化、变化是否影响本文件或其下游。

（四）重验期间新旧版本共存：旧版本保留不覆盖不删除；新版本作为待核验版本建立；新旧版本必须标明版本号、变更原因、生效状态和影响范围；受影响文件完成重验并获得放行前，旧版本可作为当前有效依据继续维持，但不得把新版本内容提前混入实现；新版本未放行前不得宣称其已生效；新版本放行后旧版本转历史版本但仍保留回溯与回退能力。

（五）未完成重验时的工程限制：不受影响的工作可继续；受影响文件及其下游依赖不得继续新增实现；涉及共享接口/状态/权限/判断引擎/自生长/根级责任的工作按受影响处理；影响范围无法判定时相关工作暂停，不得以"应该没影响"放行；已完成但依赖旧版本的实现须标记为待复核，不能直接视为符合新版本。

### 问题 0-7：元文件自身的完成定义与验收标准

### 问题 1-2：学业规划不可再下放的最终责任

**问题**：
哪些责任属于规划本身，不能完全下放给判断引擎、专项 Agent、教与授或其他领域文件？

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
学业规划是唯一拥有全局学业责任、并能对该责任负最终权威的上层建筑。判断引擎提供认知能力，专项 Agent 提供专业意见，教与授/任务/反馈提供执行，但它们都只是规划的支撑；学业规划不可把以下最终责任下放给任何单一或分散组件。

必须由学业规划直接承担、不可下放的最终责任：
1. 全局学业位置：学生当前真正处于什么学业状态。不能被某个学科 Agent 单独定义，必须由规划在全局学段、学科和阶段内综合判断。
2. 阶段目标：当前阶段要达到什么目标、目标顺序和优先级。决定一切任务方向，不能被教与授或单个专项 Agent 决定。
3. 差距分析：位置与目标之间缺少什么，是知识、技能、方法、习惯还是资源。决定"该教什么、该做什么"的前提。
4. 路径设计：通过什么阶段、顺序和步骤弥合差距。这是规划最核心的不可下放责任——它定义"路线"而非"某一步"。
5. 路径最终权威：当不同专项 Agent 意见冲突时，最终采用哪条路径。谁规划谁负责，不能把路线决定权交给任一专项。
6. 任务与资源全局安排：各任务之间的总体顺序、轻重缓急、资源分配，而非单个任务内容。
7. 执行与检验统一监测：判断规划是否在整体上被执行、推进、检验，而非只看单点结果。
8. 动态修正裁决权：何时调整路径、是否回退、是否暂停。这是对"现实反馈"的最终解释和决策权。
9. 阶段衔接职责：把本阶段形成的可靠认识和学业资产交接到下一阶段，保证连续性。
10. 对学生的最终承诺：整个学业进程对"学生这个人"负责，而不是对某个任务、某个学科或某次评价负责。

判断引擎可以替规划完成什么：理解处境、处理证据、识别问题、评估差距、生成路径候选、评测候选利弊、提出"可能更适合"的方案、判断证据是否支持某结论。判断引擎不能：最终定夺"采用哪条路径"、在没有足够证据时替路径背书、从证据直接生成并自动执行完整规划而不经路径裁决、在冲突时自行选定而不上报路径层。

专项 Agent 能做什么：提供学科专业判断、指出专业约束和风险、提出教与授/任务/复盘建议、报告证据和缺口。专项 Agent 不能：各自生成一套互冲突的完整规划、决定全局路径/阶段目标/优先级、在未经规划层整合前把专业建议当成已定计划、因局部优化而破坏整体路径、把"某个学科 Agent 认为对"当成"规划成立"。

教与授/任务/反馈如何服务规划：教与授服务"应掌握什么、为何掌握、如何掌握"，以是否承接规划并产生可观察行动为判据；任务可回溯到路径环节，不能脱离路径自成体系；反馈是规划调整依据，须判断影响的是局部任务还是整体规划，不让一次反馈自动重写整条路径；复盘服务"本轮规划是否成立、下轮如何更好"，不反向取代规划对路径的裁决。

"规划完成" vs "计划生成"：规划完成至少须同时满足：基于真实位置目标和证据非凭空假设；有明确路径阶段顺序；能分解为可执行可检验任务；有可核验完成定义和验收标准；冲突意见处理完毕或有明确裁决；预留执行监测与动态修正机制；在学生可理解可执行可反馈的限制内；已明确哪些判断仍是待确认/待验证不做虚假完整；学生能据此行动而非只看到一张承诺。单单输出计划文本不是规划完成。

### 问题 1-3：判断引擎与相邻对象的边界

**问题**：
判断引擎与 LLM、底层设施、专项 Agent 和学业规划的边界，以及输入输出、可解释和降级规则。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
判断引擎是学业军师的专项认知增强层：以 LLM 的通用理解、推理、归纳和生成能力为基础，通过学业对象限定、证据约束、判断流程、输出契约、降级规则和范围边界，将通用 LLM 收敛为服务学业规划的专项判断能力。判断引擎不是：另一个独立大模型；单纯提示词集合；普通 Agent 路由器；底层权限系统；学业规划本身；多个专项 Agent 的简单总称；可以自行修改产品规则的自治主体。其核心作用是让 LLM 能够在学业规划责任范围内判断，但不能让模型的自由生成直接成为生效的学业规划。

LLM 提供的能力：自然语言理解、材料阅读和归纳、多步推理、方案比较、解释和表达、从复杂信息中生成候选判断、根据反馈调整表达和候选方案。判断引擎叠加的限定：判断对象只围绕学生学业过程；问题范围限位置目标差距路径任务教与授检验反馈修正阶段衔接；证据要求登记使用了哪些证据、来源和强度；判断流程按规定步骤；输出等级区分事实分析推断候选待确认未知；不确定性处理证据不足冲突过期时降低强度补证或停止；范围边界超学业责任请求不被自由扩展；规划衔接说明判断如何服务规划；反馈修正能接受真实行动检验结果外部反馈修正；版本追溯可回溯到规则证据模型配置引擎版本。判断引擎不能自行改变：产品责任和服务范围、根级判断原则、证据有效性标准、权限和角色责任、学生控制边界、不可逆操作规则、元文件根级决策、已生效的学业规划、未经确认的长期学业资产。

判断引擎与底层设施分层：

```text
LLM
  ↓
判断引擎
  ├── 学业范围限定
  ├── 证据组织与判断流程
  ├── 候选分析与不确定性表达
  └── 结构化判断输出
  ↓
学业规划层裁决
  ↓
确定性底层设施校验与执行
```

可由判断引擎承担：阅读理解材料、识别学习问题、分析位置差距、提出路径候选、比较任务顺序、解释建议理由、识别需补充证据、提出暂停降级或人工/学生确认请求、对执行结果提出修正建议。必须由确定性设施强制：身份角色权限、学生教师机构家长数据隔离、输入来源和授权登记、状态迁移合法性、证据状态和来源字段完整性、高影响或不可逆操作拦截、未确认内容不得升级为生效规划或长期资产、Agent 不得改写根级规则、自生长候选不得绕过批准版本回滚、审计记录完整性、删除撤回过期访问控制、工具插件外部服务调用边界、停止暂停回退灾备条件。判断引擎负责形成受约束的认知输出；确定性设施负责决定该输出是否有资格生效、能否执行以及能否写入长期状态。

判断引擎与专项 Agent：判断引擎规定专项判断如何进行；专项 Agent 在各自领域内执行具体判断；学业规划层整合结果并承担最终规划责任；确定性设施校验状态权限执行资格。专项 Agent 输出必须经过统一判断引擎契约，至少带：专项 Agent 身份和版本、输入材料与证据引用、判断内容、判断等级、不确定项、建议影响范围、建议的规划对象、需要的确认或复核、可追溯定位。

判断引擎与学业规划：判断引擎可以提供判断，学业规划承担最终责任。判断引擎形成规划候选、分析差距风险、识别路径选择、提出任务资源建议、解释判断依据、根据反馈提出修正方案、标记无法判断和需补证处。学业规划层负责确定全局目标和优先级、统合不同专项 Agent 结果、处理冲突专业意见、决定哪条路径成为当前生效规划、决定何时调整暂停回退或结束阶段、保证规划与学生当前整体处境一致、对规划连续性可执行性和结果负责。判断引擎是"会判断的认知层"，学业规划是"承担全局责任的决定层"，判断引擎不能绕过规划层直接把候选分析变成生效规划。

结构化判断对象至少含字段：判断对象、相关规划、判断结论、判断类型（事实/分析/推断/候选/未知/冲突）、证据引用、证据强度、适用范围、影响范围、不确定项、建议动作、所需确认、版本信息、生命周期状态、回溯信息。

可解释与降级：可解释性不是要求输出隐藏推理，而是要求提供可核对的依据和决策结构：使用哪些证据、哪些事实哪些推断、哪些条件影响判断、哪些替代方案被排除、哪些仍未知、判断影响什么、需要谁确认、何时重新核验。必须降级或停止的情形：没有足够证据、证据来源冲突、证据过期、学业对象身份或阶段不清、判断超学业范围、专项 Agent 输出冲突、规划版本与输入版本不一致、判断引擎或底层规则版本不匹配、所需权限未取得、可能产生高影响或不可逆后果、违反统一状态接口验收规则。降级结果可以是：请求补充材料、降低判断强度、只提供低风险建议、暂不形成规划候选、提交人工/用户确认、暂停当前动作、回退到上一稳定状态。

### 问题 1-4：术业有专攻的 Agent 体系

**问题**：
如何构成区别于多个普通 Agent 拼接的专项体系。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
术业有专攻不是把多个通用 Agent 并排拼接，而是以学业规划为唯一全局责任，以判断引擎为统一认知与约束，以责任域和学科为两个正交维度组织专项 Agent。每个专项 Agent 只对授权的专业工作负责，通过统一证据、状态、权限和接口协作；它可以提供专业判断，但不能自行形成全局规划。

按责任/工作性质划分的责任域 Agent 可能包括：证据 Agent（材料登记、来源核验、证据关联、冲突标记）；学业位置/诊断 Agent（分析学生当前学业状态）；规划协作 Agent（提出路径阶段任务候选，不拥有最终规划权）；教与授 Agent（把规划目标转化为讲解练习检验纠错）；反馈/复盘 Agent（分析任务测验现实反馈提出修正建议）；学业资产 Agent（从证据提炼资产候选处理复核修订生命周期）；监管/监察 Agent（发现越权证据缺失冲突风险异常提出暂停复核回滚请求但监察结果必须接受上级治理）；交互承接 Agent（将内部复杂判断转化为学生能理解低负担界面内容）。

按学科划分：每个学科应拥有自己的最小专家集群，而不是所有学科共享一个泛化"学科 Agent"。学科集群可根据学科特性因地制宜：数学可能需要概念、证明、计算、解题策略和错误诊断；语文可能需要阅读、写作、语言表达、文本分析和知识积累；外语可能需要词汇、语法、阅读、听力、口语和写作；物理化学等可按概念、实验、计算、模型和错因分析组合；某些学科可能只需少数单元，某些需更多；专家数量不是固定常数，必须根据学科责任和验收结果决定。共同原则：数量可以不同，但每个集群必须有明确主责、输入、输出、协作边界和验收标准。

层级与调用关系：

```text
学生
  ↑↓（简单直白的统一界面）
学业军师主控层
  ├── 全局学业规划责任
  ├── 学生交互承接
  ├── 专项 Agent 编排
  └── 对外统一表达
          │
判断引擎（贯穿调用与输出约束）
          │
  ┌───────┴────────┐
责任域 Agent       学科专家集群
（跨学科工作）     （按学科特性组合）
          │
证据/状态/权限/会话/资产等底层设施
```

学业军师主控层承担全局规划和统一对外承接；判断引擎规定如何在学业范围内判断并约束所有专项 Agent 输出；责任域 Agent 按工作性质执行跨学科任务；学科专家集群按学科特性执行专业任务；底层设施决定哪些输出可以生效负责权限状态证据审计；学生界面不展示内部 Agent 拓扑只呈现必要下一步。

专项 Agent 统一契约（每个必须声明）：唯一主责对象；适用学段学科场景；输入类型和最小权限；可读取证据范围；可写入对象；输出结构和判断等级；不负责内容；与其他 Agent 输入输出接口；失败冲突不确定时处理；版本依赖模型配置；完成定义和验收标准；责任范围外的拒绝与降级行为。没有契约的 Agent 不得接入生产协作。

专项 Agent 是否直接面对学生：默认不成为学生多个平行入口；学生只面对学业军师统一入口。理由：学生不应学习多个 Agent 使用方法；多入口暴露内部复杂性；不同 Agent 可能给出矛盾表达；统一入口便于承接规划证据权限低负担交互；学生反馈可统一记录关联到正确责任域。少数明确低风险场景专项 Agent 可通过统一界面以学科/任务窗口呈现，但不绕过学业军师规划判断权限审计层。

避免冲突与局部最优：所有 Agent 读取同一套有效证据和状态；所有输出带责任域版本证据引用影响范围；规划相关建议先进入候选状态；学业军师主控层统一整合；判断引擎检查证据边界冲突；冲突意见不得静默择一；重大冲突暂停相关规划变更并请求裁决；局部优化不得突破全局规划目标；只有规划层能把候选路径变成生效规划；所有冲突和裁决可回溯。

证据资产反馈权限共享：通过统一接口读取最小必要证据；只能读取被授权学段学科阶段学生范围；学业资产以状态和权限控制访问；不能直接读取其他责任域全部内部数据；不能绕过底层设施写入长期资产或生效规划；跨域写入必须走统一提交/候选接口；学生教师机构等角色可见性由权限矩阵决定；所有读取写入建议拒绝都记录审计信息。

专项 Agent 专业有效性：不能因"能回答问题"就算专业有效，至少须：输入范围和适用边界明确；能使用授权学业材料和证据；输出符合统一判断和接口契约；在已知样本与边界样本上达到预设质量标准；能识别无法判断证据不足超范围请求；不越权读写或改变规划；错误冲突失败可记录处理；结果可由专业负责人或规定评测流程复核；版本依赖变更可追溯；替换或停用不破坏整体规划链路。专业有效性应分别进行机制测试、学科内容测试、边界与越权测试、冲突测试、真实任务测试、长期效果验证；通过其中一层不得声称全部有效。

缺少合格专项 Agent 时降级：明确标记"该领域能力未配置/待验证"；不生成伪装成专业结论的输出；不把通用 LLM 回答包装成专项能力；仅提供低风险明确有限的通用支持（若规则允许）；请求补充材料或人工/教师介入；暂停需要该专业能力的规划变更；记录缺口影响和恢复条件；不能因追求首版完整而静默放宽专业门槛。

### 问题 1-5：学生定位与低负担使用

**问题**：
学生是服务对象、保护主体还是主动操作者；产品如何承接复杂性并逐步培养主体能力。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
学生是学业军师服务的主体、被保护的对象和长期能力发展的受益者，但不是系统管理员，也不是必须先学会使用 Agent 才能获得服务的专业操作者。学业军师应主动承担专业理解、规划组织、任务调度和复杂操作，同时通过低负担交互让学生参与真实学习、理解关键安排、提供反馈并逐步形成自己走路径的能力。

学生在产品中的三种角色（权重不同）：
1. 服务主体：一切规划判断任务教与授都围绕学生真实学业过程展开，不围绕模型表现、Agent 数量或系统自身增长。
2. 被保护主体：学生可能无 Agent 经验、不理解复杂术语和系统状态、因年龄压力情绪疲劳无法充分判断、误操作沉默拒绝或暂时不配合、无法识别系统专业错误。产品不能把复杂确认记忆治理证据判断权限管理全部转嫁学生；学生未操作或误确认不能成为产品逃避责任依据。
3. 逐步形成能力的学习主体：产品应让学生逐步理解当前位置、为什么安排当前任务、行动结果如何影响下一步、如何认识学习问题、如何逐渐参与规划执行复盘修正。但"学生最终形成自主规划能力"是长期目标与待验证结果，不应写成首版已实现事实。

产品替学生做什么 vs 教学生做什么：产品主动承担收集整理必要学业信息、理解学生当前处境、组织证据判断、形成规划候选、安排任务顺序和资源、选择合适教与授方式、监测执行检验结果、处理普通低风险调整、将复杂机制转化为简单直白交互、在学生不理解沉默不会操作时解释降级引导。产品逐步教给学生：如何理解当前学业位置、如何理解目标和差距、如何根据证据判断学习问题、如何执行检验复盘、如何参与重要规划确认修正、如何逐步形成自己走路径的能力。

学生控制权按风险分层：

| 事项 | 默认处理 |
|---|---|
| 低风险可逆日常任务调度 | 产品主动承接，向学生说明即可 |
| 普通教与授安排 | 产品承接，学生可随时反馈暂停纠正 |

### 问题 1-6：产品责任与非责任

**问题**：
学业军师必须承担和明确不承担哪些责任，超范围如何处理，何时产品责任成立。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
学业军师对学生的长期学业规划及其可执行、可检验、可修正的承接负责；不替学生、教师、学校、机构或家长承担其各自不能转移的现实责任，也不把超出学业范围的能力包装成产品能力。

必须承担的产品责任：
1. 学业规划责任（最高责任）：了解当前位置、确认阶段目标与约束、识别差距、形成可理解可执行可检验路径、分解任务并安排顺序、根据行动检验现实反馈持续修正、负责阶段衔接和长期连续性。不能只生成一次性计划后把执行结果交给学生自行承担。
2. 专项判断责任：将通用 LLM 限定在学业规划范围内，通过判断引擎和术业有专攻 Agent 体系完成学业材料理解、学科问题识别、位置差距路径分析、规划候选比较、教与授及任务资源安排、证据不足冲突超范围时降级停止。专项 Agent 可提供专业意见，学业规划对最终整合和路径责任负责。
3. 证据责任：明确判断使用哪些材料、材料来自谁何时产生是否完整、哪些客观材料哪些学生陈述模型推断工作假设、证据不足冲突时能否继续、某证据能影响任务局部路径还是整体规划。证据责任不是保证所有证据真实，而是不能把没有依据内容伪装成证据并必须暴露证据缺口。
4. 规划执行与教与授责任：将规划转换为学生能理解任务、提供与任务匹配教与授、组织讲解示范练习检验纠错再练复测、观察任务是否完成能力是否表现结果是否变化、根据结果决定继续调整补教暂停回退。教与授是服务规划手段不取代规划最高责任。
5. 学业资产与长期连续性责任：从真实证据提炼资产候选、区分资产/普通记忆/临时上下文/模型推断、记录资产来源状态适用范围版本、防止错误认识静默进入长期规划、支持复核修订撤回删除阶段交接。
6. 学生低负担使用责任：复杂专业判断内部处理、统一入口统一表达、简单直白低学习成本交互、对学生不会操作沉默误操作或暂不能执行处理、必要时降低复杂度或请求其他责任主体介入。"学生可以纠正"不等于"学生必须管理系统"。
7. 可靠性与保护责任：身份角色权限边界、状态迁移合法性、未确认内容不得静默升级、越权不可逆高影响动作拦截、证据判断任务资产可追溯、异常冲突失败暂停恢复回滚停止、自生长/自进化不得绕过规则和治理。

明确不承担的责任：心理诊断心理治疗或精神疾病判断；医疗诊断治疗和用药建议；人身安全危机处置或紧急救援；法律判断法律代理和监护责任裁决；家庭关系裁决；对学生人格价值或人生价值作最终评价；替代教师学校或机构承担实体教育责任；替代家长承担监护责任；替学生承担实际学习行动；保证考试成绩升学结果或人生结果；在证据不足时保证规划一定正确；将学业规划扩展为商业就业或人生全领域规划。

各责任主体分工：

| 主体 | 主要责任 | 不能由谁自动替代 |
|---|---|---|
| 学业军师 | 学业规划、判断组织、任务承接、教与授协调、反馈修正 | 不替学生行动，不替学校承担教育责任 |
| 判断引擎 | 在学业范围内形成受约束判断候选 | 不拥有产品根级决定权 |
| 专项 Agent | 学科或责任域专业意见 | 不各自决定全局规划 |
| 学生 | 提供必要信息、参与学习、执行任务、反馈和必要确认 | 不应被当作系统管理员 |

| 学校/机构 | 教育场景、制度、资源、现实结果和组织责任 | 不由产品自动代表学校 |
| 家长 | 在授权边界内提供支持和接收必要学习信息 | 不应通过产品静默改写学生规划 |
| coding agent/外部底座 | 工程实现、组件运行或技术支持 | 不决定学业产品责任 |

超出范围或高风险交叉问题分流：1 纯粹超范围说明产品边界不生成专业结论；2 学业中混入非学业内容只处理明确低风险属学业部分；3 涉及心理医疗安全法律高风险信号停止相关自动判断白话说明限制按预定义人工/教师/机构/监护或专业求助路径转交；4 无法判断归属标记未知暂停相关规划不由模型自行扩大责任；5 学生要求继续但证据权限不足不能因催促降低门槛；6 紧急情况产品不能冒充救援系统具体转交路径和责任人须由监管治理领域文件定义。

产品责任最低成立条件（至少须同时满足）：有明确学业规划责任和非责任边界；能从输入证据形成可追溯规划判断；能将规划转化为任务与教与授；能获得行动检验反馈并据此修正；能处理证据缺失冲突拒绝沉默失败；能管理长期记忆与学业资产而不静默制造长期结论；判断引擎和专项 Agent 不越过规划责任；学生无需学习复杂 Agent 操作即可完成核心使用路径；权限状态审计停止回滚等责任层保护已实现；每个责任单元有完成定义和验收标准；尚未验证的真实教育效果长期能力形成跨学段适配被明确标为[待验证]。

### 问题 1-8：产品本体与外部能力边界

**问题**：
外部项目可提供什么实现能力、学业军师必须自持什么，如何判定复用后仍是学业军师。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
外部项目可以提供实现能力，但不能定义学业军师的产品责任。学业军师必须先确定自身本体，再按"复用 → 改造 → 受控整合 → 必要重构 → 最后自建"的顺序选择实现方式。只要外部能力改变了学业规划、判断引擎、证据纪律、学业资产或学生责任边界，技术上可用也不能直接纳入。

必须由学业军师自持的内容（自持 = 定义权、控制权、最终责任和替换权掌握在学业军师一方，不等于所有代码从零编写）：学业规划责任、判断引擎专项边界、证据纪律、学业资产定义与生命周期、学生及其他角色责任边界、产品根级边界与不可静默改变的责任。

可复用的外部实现能力（不改变上述定义权条件下）：LLM 和模型供应商；Agent loop 和工具调用运行时；工作流、状态持久化、暂停恢复；记忆检索存储组件；RAG、向量检索全文检索；权限策略引擎；遥测 trace 日志工具；评测回归测试工具；前端框架通用组件；容器部署备份基础设施；私立学校等特殊场景接入模块。但每项复用都要检查：输入能否接入学业对象和证据模型；输出是否符合判断状态权限契约；是否允许产品控制生命周期；是否能隔离学生角色数据；是否能追溯测试升级回退；许可证依赖维护状态是否可接受；组件失效或替换时产品本体是否仍能运行。

外部底座不能反向决定的内容：学业军师是否以规划为最高责任；教与授是规划服务手段；判断引擎如何专项化 LLM；哪些证据有效；学业资产是什么；自生长/自进化可改什么；学生承担多少操作确认责任；学校是否需要直接接入；哪些事项必须停止升级；首版"全部构建"定义；最终用户体验；是否已取得教育效果。这构成"产品本体先定、外部能力后接"的硬顺序。

没有特定外部项目学业军师必须仍然成立：即使移除 DeepTutor、OpenClaw、Hermes 或任何单一组件，学业军师的产品责任、规划逻辑、判断引擎定义、证据纪律、学业资产定义和用户体验仍然成立。DeepTutor 可以是候选底座，但不能成为"没有 DeepTutor 就没有学业军师"。

外部默认机制冲突优先顺序：学业军师根级产品责任；责任层硬边界和确定性规则；学业规划及判断引擎契约；学业证据资产状态权限要求；学生低负担现实使用约束；外部组件默认实现方式。组件必须适配产品责任而不是让产品迁就组件。

如何判定"复用后仍然是学业军师"（至少同时满足）：学业规划仍是最高责任；判断引擎仍按学业范围限定 LLM；专项 Agent 仍服从统一规划；证据仍有独立来源状态；学业资产仍由产品定义控制；自生长/自进化仍受产品边界约束；学生仍面对简单直白统一体验；学校反馈仍以学生间接承接为普遍关系；组件替换不会改变产品本体；所有关键动作仍可追溯审计处理失败；产品能说明每个外部能力承担什么没承担什么；外部项目宣传语没有被误当作学业军师能力证明。反事实测试：如果把外部项目名称默认界面宣传语全部删除，只保留学业军师责任规划判断证据资产用户体验验收标准，它是否仍是同一个产品？若否则说明外部项目反向定义产品。

### 问题 1-9：规划目标、位置与差距

**问题**：
规划对象链、当前位置、目标、差距、约束、输出和验收如何定义。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
学业规划不是从成绩直接生成计划，而是对学生在特定阶段、特定目标和现实约束下的学业位置进行对象化判断，识别可证据支持的差距及其成因，形成可执行、可检验、可修正的路径，并持续把行动结果反馈到规划。

学生"当前位置"的构成：知识与内容掌握（已掌握/部分掌握/未掌握/易混淆的概念知识）；学科能力表现（理解推理表达计算迁移解题应用等可观察表现）；任务表现（具体作业练习考试项目中的表现）；学习方法（已尝试有效无效尚未验证的方法）；执行状态（任务是否理解开始完成延迟中断反复失败）；时间和资源条件（课程进度考试日期可用时间材料帮助设备）；学生说明的处境（困难目标限制主观感受但必须与客观材料区分）；阶段成果与学业资产（已形成可复用阶段性认识）。不应直接纳入为学业判断事实的内容：未经授权的心理诊断或人格结论；对学生价值品格人生价值评价；没有证据的能力标签；单次表现直接推导的稳定结论；学业军师责任范围外的医疗法律危机判断。"当前位置"必须标注对象时间来源证据状态适用范围不确定性是否经学生理解确认。

目标来源与优先级：目标可能来自学生自己的阶段目标、学校课程作业考试要求、阶段性学业标准、家长期望、学业军师基于证据的建议、教师或机构提供的合法要求。学业军师帮助澄清拆分比较调整目标但不能把来源不同目标混成未经说明结论。处理顺序：登记目标来源原始表述→区分外部要求学生愿望家长期待产品建议→判断目标是否明确可理解可行动可检验→识别目标间时间资源优先级冲突→形成目标候选及影响→由规划层在责任证据范围内提出整合方案→对重大跨阶段冲突目标保留必要确认→目标仍不明确先进入目标澄清不伪造确定目标。家长期待或产品建议不能静默覆盖学生目标；学校要求不能自动变成完整人生目标。

差距类型表：

| 差距类型 | 可能表现 | 需要的证据 |
|---|---|---|
| 知识差距 | 概念事实规则基础内容缺失 | 作业测验错题口头/书面表现 |
| 能力差距 | 能记忆但不能理解推理迁移应用 | 变式任务综合题迁移任务 |
| 方法差距 | 不知道如何分析练习复盘检验 | 行动过程和多次任务表现 |
| 执行差距 | 目标理解但无法开始持续完成 | 任务记录时间和过程反馈 |
| 反馈/修正差距 | 不能根据结果调整方法或路径 | 多轮行动检验复盘 |
| 资源差距 | 时间材料教师支持设备环境不足 | 学生说明课程安排现实约束 |
| 目标差距 | 目标模糊冲突不现实未被理解 | 目标来源与确认记录 |
| 评估差距 | 当前测量不能准确反映真实状态 | 多来源结果交叉检验 |

这些类别是分析工具，不应在证据不足时给学生贴固定标签。一个结果可能同时涉及多个差距，也可能只是测量误差或偶发波动。

现实约束如何进入规划：至少登记当前课程与学校节奏、作业考试阶段节点、学生可投入时间和精力、已有基础与任务依赖、可用教材题目教师同伴支持、学生设备网络产品使用条件、其他已确认学业约束、尚不确定限制。约束不是由模型自行猜测，缺失时规划请求补充、给出多个条件化候选、降低规划确定性、暂不确定唯一顺序、记录该约束对路径影响。

规划最小输出（一次可成立规划至少包含）：规划对象和适用学生/阶段；当前基于证据的位置描述；目标及来源；差距及证据；现实约束；路径和阶段顺序；当前最小任务；所需教与授资源支持；完成定义和检验方式；反馈如何影响下一步；未确认待验证风险项；规划版本有效范围和回溯信息。没有目标差距路径任务检验条件的内容只能称分析或建议，不能称完整规划。

候选与裁决：可自动形成候选——位置分析、差距分类、目标澄清问题、路径候选、任务顺序候选、教与授方式候选、资源匹配建议、风险和证据缺口提示。必须由规划层承担裁决——当前生效目标、全局路径、重大优先级、跨学科资源分配、阶段开始结束、规划暂停回退重大修正、规划如何处理冲突专项意见。高影响事项还要根据权限要求取得必要人类确认。

避免被单次证据带偏：采用来源登记、时间标记、多次表现对照、不同任务类型交叉核对、学生说明与客观材料分离、学校材料与学生转述分离、规划假设与已验证认识分离、异常值和测量误差标记、形成判断后的后续检验、被新证据修正时保留历史版本。如果只有单次证据，可以形成有限范围低确定性工作判断或候选任务，不得形成不受限长期资产或重大规划结论。

逐项完成定义与最低验收标准：

| 对象 | 完成定义 | 最低验收标准 |
|---|---|---|
| 当前位置 | 在适用范围内对当前学业状态形成有来源有限定描述 | 至少来源/时间/对象/状态；事实与推断分开；未知显式保留 |
| 目标 | 目标来源明确含义可理解边界优先级清楚 | 学生/外部/家长/产品建议区分；冲突显式处理；有检验条件 |
| 差距 | 将目标与当前位置不足拆成可行动一个或多个问题 | 每项差距有证据或标待验证；不把成绩直接等同成因；可关联任务 |
| 路径 | 有顺序有依赖有阶段边界候选或生效路线 | 能说明为何这样排序；约束可满足；冲突有裁决；可检验可回退 |
| 任务 | 可被学生理解执行、服务某个路径节点的行动 | 有目标输入步骤完成标准预计结果反馈入口 |
| 教与授 | 为任务提供必要理解练习检验纠错承接 | 不以展示内容为完成；能观察行动或表现变化 |
| 反馈 | 对行动/检验结果形成有来源有限定结果信息 | 能关联原任务/规划；区分原始结果与解释；说明影响范围 |
| 修正 | 新证据导致规划继续调整补教暂停回退 | 有触发证据版本变化影响范围验收/复核条件 |

规划对象因果链：

```text
当前位置
  ↓ 与目标比较
差距及成因
  ↓ 在现实约束下形成候选
路径与阶段顺序
  ↓ 分解
任务与教与授
  ↓ 学生执行
检验与结果
  ↓ 反馈
规划继续、调整、暂停或回退
  ↓ 经确认/受控提炼
学业资产
  ↓
下一轮规划
```

这不是自动流水线，任何节点都可能因证据不足冲突权限学生拒绝而降级暂停回退。

### 问题 1-10：动态规划的生成、执行与修正

**问题**：
规划如何持续生成，如何分级修正、暂停、恢复、回退、结束并保持学生界面简单。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
学业规划不是一次性生成的计划文本，而是以阶段为单位、在真实行动和证据反馈中持续运行的受控对象。规划可以动态修正，但每次修正都必须有触发证据、明确影响范围、版本记录和可回溯的处理结果；不能因为模型想换一种说法或单次波动就静默改写路径。

规划生成方式：初始规划必须基于学生当前学业输入、目标来源、当前阶段、已登记证据、现实约束、可用资源、未知和待补信息；形成当前阶段总体方向、可解释路径候选、当前最重要任务、下一次检验反馈节点、可能导致调整的条件。持续规划不等于每轮对话都改规划，应区分稳定规划层（阶段目标主要路径关键约束）、执行安排层（当前任务顺序教与授方式时间安排）、临时交互层（当前对话解释练习反馈短期调整）。低层变化不能未经判断向上层传播：临时交互变化不自动改写执行安排不自动改写稳定规划；只有达到规定触发条件才可升级影响范围。

规划有效周期：不宜用一个对所有学生学科都相同固定天数，而应由当前阶段和目标、任务规模、检验反馈频率、学科特性、学生行动节奏、课程考试节点、证据稳定程度、现实约束变化共同决定。每条规划至少标记生效时间、预计复核时间、触发提前复核条件、适用范围、当前版本、失效或结束条件。"有效"不等于"永远正确"，复核时间到达而没有足够新证据应标记待复核，不自动延长有效期。

修正影响分级：
- 任务级修正（难度略高略低、任务说明不清、教与授方式不合适、学生需拆小步骤、时间安排微调、发现局部错误不影响路径方向）：调整任务解释练习顺序，不改变阶段目标和主要路径，记录修正原因，保留原任务状态。
- 局部路径修正（某知识点或能力差距判断被新证据明显改变、某学科子路径需补充回退换方法、多次任务结果当前子路径无效、某项资源时间约束变化）：调整该学科责任域路径，重新检查与其他学科任务资源接口，不自动改变整体阶段目标，由规划层确认影响范围。
- 阶段规划修正（阶段目标无法实现或不再适用、多个局部路径同方向证据、重要考试课程现实约束改变、学生提出重大明确新目标、学校要求或经学生承接外部材料改变阶段条件）：重新评估位置差距资源路径，保存旧版本，说明修正理由影响，取得必要学生/其他责任方确认，重新设定阶段检验条件。
- 全局规划修正（关键事实被证伪、目标或阶段方向根本改变、多学科结果共同表明原规划失效、重大现实约束改变、产品发现原规划违反根级责任证据纪律）：冻结受影响重大执行，形成新规划候选，由学业规划层承担最终裁决，需要时上报人工/受访者或其他授权责任方，不能由单一专项 Agent 或一次模型调用直接改写。

未完成任务原因诊断（不能直接解释为"学生不努力"或"规划失败"）：任务难度超过当前位置、任务说明目标不清、教与授没有提供必要支持、任务与学生当前路径不匹配、时间课程设备材料资源不足、学生暂时不愿执行优先级变化、学生不理解为什么要做、规划顺序或任务设计本身不合理、证据或执行记录不完整、其他超出产品责任因素。诊断结果只能先作为候选或待确认，不得把一次未完成直接写为稳定学生属性或长期学业资产。

学生提出新目标改变方向流程：学生表达→记录原始表达来源→澄清目标含义时间约束→与当前目标和规划比较→形成影响分析候选调整→判断任务级局部阶段全局变更→取得必要确认→版本化更新或保留待确认。产品不应因一句临时表达立即重写长期规划，也不能因旧规划存在忽略学生新明确目标。

局部变化何时升级全局调整：影响几个学科或责任域；触及阶段目标；改变资源和时间分配；改变关键考试课程节点；多次一致独立来源证据；可能造成下游任务大面积失效；涉及学生重大意愿变化；触及产品责任或权限边界。单一学科一次异常通常先留局部；多个独立信号指向同一根本问题才进入全局规划评估。

版本修正原因影响范围：每次规划变更必须保留旧规划版本、新规划版本、变更时间、变更触发事件、使用证据、变更前后差异、影响任务路径学科阶段、谁/什么责任层裁决、学生或其他角色确认状态、是否需要重新验证、回退条件。不能只更新当前计划文本删除历史版本，不能只改变版本号没有实质差异验证记录。

暂停恢复回退结束：暂停=暂时不推进相关规划或任务但保留当前状态原因恢复条件，不等于完成也不等于失败；恢复=恢复条件满足后从有效版本明确状态继续，必须检查期间新证据目标约束变化；回退=将执行或规划恢复到上一稳定版本或生成基于旧状态新版本，不能假装抹除已发生行动影响；结束=达到阶段目标、目标被取消、阶段转移、产品责任无法继续或学生明确退出，必须写明结束原因、达成/未达成状态、形成学业资产候选、未解决问题、下一阶段是否承接、数据和权限如何处理。

规划失效判定：目标已取消改变、关键前提被证伪、现实约束重大改变、多次检验显示路径无法产生预期推进、关键证据过期撤回纠正、学生长期无法理解执行接受当前路径、规划违反新根级责任权限证据要求、阶段已结束或外部课程节点改变。失效不是删除，系统标记失效原因、保留历史版本、停止沿用、形成新规划候选或等待人工/学生确认、处理下游任务和资产。

简单界面承接动态变化：学生不需要看到复杂版本图 Agent 决策树状态机。界面只需白话说明当前仍在做什么、发生了什么变化、为什么调整、现在下一步是什么、学生需要做什么或选择什么、如果不同意做不到暂停该怎么办。复杂审计版本依据保留内部，需要时提供可展开简明说明。

### 问题 1-11：学业军师成立与不成立的最终边界

**问题**：
何时学业军师成立，何时即使有许多功能仍不是学业军师。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：
成立需同时具备：规划最高责任；判断引擎专项化；专项 Agent 服从统一规划；规划基于可追溯证据；规划进入任务/教与授、行动、检验；结果反馈修正规划；学业资产受控沉淀；长期自生长/自进化受控；学生低负担；确定性设施保护权限/状态/证据/资产；能处理失败、冲突、拒绝、沉默和超范围。

产品成立的最低必要条件详细展开：
1. 最高责任明确：学业规划负责学生当前位置、阶段目标、差距及成因、路径与顺序、任务和资源安排、执行监测、检验与反馈、动态修正、阶段衔接。其他能力都必须服务于这项责任。
2. 判断引擎能够形成学业专项能力：将 LLM 通用理解与推理限定到学业对象、学业问题、证据要求、规划流程、不确定性处理、输出契约、降级停止边界。不能只是提示词集合，不能脱离规划层自行决定生效路径。
3. 专项 Agent 体系服从统一规划：学科证据教与授反馈资产 Agent 等有明确责任域、遵循统一判断证据状态权限契约、通过学业军师主控层协作、提供专业意见而不各自形成全局规划、能处理冲突缺证失败、无合格能力诚实降级。Agent 数量本身不构成产品成立条件，统一规划责任下的专业分工才构成。
4. 规划以可追溯证据为基础：区分原始学业材料、学生说明、学生转述学校反馈、实际行动记录、检验结果、专项 Agent 分析、判断推断工作假设。证据不足冲突过期时必须补证降级暂停停止不能静默补齐。
5. 规划能够进入真实行动：能转化为学生能理解任务、适配任务的教与授、明确完成条件、可观察学生行动、独立于计划文本的检验或结果。只有生成路径或计划文字不能证明规划成立。
6. 行动结果能反过来修正规划：根据任务完成情况、练习作业考试复测、学生反馈、学生带回学校材料、其他授权现实证据，判断规划应继续局部调整阶段修正暂停回退结束。
7. 学业资产受控沉淀：资产来自真实证据、与普通记忆临时上下文模型推断区分、可标记来源适用范围确认状态、可被理解纠正修订撤回删除跨阶段复核、能服务后续规划而不制造未经确认学生标签。
8. 长期自生长/自进化受控：提高对学生和学业任务适配、有证据版本评测批准发布撤回回滚、不降低证据门槛、不突破角色权限、不静默扩大产品责任、不擅自改变元文件根级决策、不把错误经验自动升级为长期事实。
9. 学生可低负担使用：界面简单直白、统一入口、内部复杂性由产品吸收、学生能理解当前情况下一步必要理由、学生不会操作沉默误操作拒绝时能安全处理、不被要求承担系统管理员或专业治理者责任。
10. 确定性设施保护责任链：身份与权限、证据来源与状态、合法状态迁移、学生和角色数据隔离、未确认内容不得生效、高影响不可逆动作、审计撤回删除暂停回滚、Agent 插件外部组件调用边界。不能把责任交给 Prompt 自律。

功能存在但产品不成立的情形：能聊天但没有学业规划；能生成计划但没有行动检验修正；多个学科 Agent 各自为政；有记忆但没有证据来源学业资产边界；有自生长但只是自动积累错误经验；有判断引擎但不能服务影响规划；有题库讲解测验但没有统一规划责任；有学校材料却无法区分原始材料学生转述模型推断；界面简单但内部无法追溯保护纠错；内部机制完整但学生无法理解使用；依赖某个外部底座移除后产品本体消失；只能证明模块存在不能证明一条真实或可复现规划闭环贯通；把模型流畅短期满意度日志增长资产数量当成教育效果；把未验证长期能力提分升学结果写成产品承诺。

最低判定句（[专业建议·代拟]）：

### 问题 2-2：学生真正需要解决的第一性问题

**问题**：学业军师首先要解决学生什么根本问题；最高优先级是位置/方向/路径/执行还是完整因果链；学生最难自行完成的判断；各产品能力解决哪一段；如何证明解决真实问题。

```text
不知道自己真实位置
        ↓
不知道当前阶段应去往哪里
        ↓
不知道当前位置与目标之间差在哪里
        ↓
不知道差距由什么造成
        ↓
不知道应该先处理哪个问题
        ↓
不知道下一步具体做什么
        ↓
不知道需要怎样的教与授、练习和资源
        ↓
不知道行动之后如何检验是否有效
        ↓
不知道结果如何改变下一步
        ↓
下一阶段重新陷入迷茫
```

最高优先级：完整因果链而非单点能力。学业军师最高优先级不是孤立选择位置/方向/路径/执行，而是使这些要素形成可回流因果链：

```text
真实位置
  ↓
阶段目标
  ↓
差距及成因
  ↓
路径与优先级
  ↓
当前任务
  ↓
教与授及资源
  ↓
学生行动
  ↓
检验与反馈
  ↓
规划修正
  ↓
下一轮位置判断
```

位置回答"我现在在哪里"，目标回答"我要到哪里"，差距及成因回答"还缺什么为什么缺"，路径回答"通过什么顺序抵达"，任务回答"现在先做什么"，教与授回答"如何获得完成任务所需理解能力"，检验与反馈回答"行动是否产生结果"，修正回答"接下来是否继续调整补教暂停回退"。没有回流修正只是计划；没有真实行动只是分析；没有位置目标差距的行动只是零散任务。

学生最难自行完成的综合判断：当前表现是否真实反映位置；当前最重要问题；多个问题应先处理什么；某问题属知识/能力/方法/执行/资源障碍；当前目标是否清楚可行值得优先；哪条路径适合自己阶段基础现实约束；一次失败说明任务太难/教与授不足/执行不足/规划不合理；一次成功是否足以形成稳定认识；新反馈只调整任务还是改变路径或整体规划；哪些认识留给下阶段哪些仍只是假设。学业军师价值在于承接这些高认知负担综合判断，而不是要求学生先成为能管理 Agent 的专业用户。

### 问题 2-3：学生为什么需要学业军师，而不是普通学习工具

**问题**：学业军师相对普通工具要替学生承接哪种最关键最难持续的工作；主动性问题与最小主动性边界。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：普通学习工具解决的是学生"想学的时候怎么学"的局部问题；学业军师解决的是学生"长期不知道该怎么组织自己整个学业过程"的整体判断与持续引导问题。学业军师不是更聪明的题库，而是替学生持续承接"跨学科、跨任务、跨时间"的规划责任，并主动发现问题、提出下一步、在合适时机介入。

各类工具分别解决什么：

| 工具 | 解决什么 | 不解决什么 |
|---|---|---|
| 题库 | 给定知识点题目练习 | 不知道练哪个练多久练完怎么纳入整体 |
| 搜索 | 检索信息答案概念解释 | 不判断该搜什么搜到后怎么规划下一步 |
| 问答/答疑 | 回答具体问题 | 不知道问什么为什么这个问题重要 |
| 课程/讲解 | 学某段内容听某节知识 | 不知道现在该学哪节和整体目标差距 |
| 错题本 | 记录错题按题复习 | 不知道错题代表的知识/能力/方法问题如何进入路径 |
| 计划工具/日程 | 把已定任务排进时间 | 不知道任务是否合理完成得如何要不要改路径 |
| 长期记忆 Agent | 记住历史对话或偏好 | 不判断哪些是可靠认识如何服务学业规划 |
| 学习管理软件 | 记录课程成绩时间 | 不判断位置差距成因路径 |

学业军师要解决的是跨学科、跨任务、跨时间的整体规划与持续判断：多个学科如何放进同一阶段目标；多个任务先后优先级切换；一个学科问题如何进入整体路径；新反馈如何影响当前任务局部路径还是整体规划；阶段结束时哪些认识进入下一阶段；长期使用中如何让学生逐步从"被引导"走向"能自己组织"。

跨学科跨任务跨时间时由学业军师判断：先做什么、为什么先做、做到什么程度、何时切换、如何把一个学科问题放进整体规划、何时整体路径需要调整、何时暂停回退结束阶段。这些判断全局且负责任，不能由任一局部 Agent 自行决定。

与相似对象区别：更聪明的老师仍是被动答疑或按教材讲通常围绕单学科单节课；学业军师主动承接跨学科跨阶段整体规划责任并把学校现实通过学生间接纳入持续修正路径，不替代老师教学而是替学生组织学什么为什么学按什么顺序做得好不好下一步怎么走。更强的题库/答疑回答这一题怎么做；学业军师决定为什么现在做这一题做完如何改变整体路径。长期记忆 Agent 记住历史偏好用于下次聊天；学业军师区分可靠学业资产与普通记忆从证据提炼受控确认服务后续规划避免错误认识自动累积。学习管理软件记录课程成绩时间偏信息登记；学业军师基于这些信息持续判断位置差距路径修正偏决策与引导。

主动性：不能只等学生提问，因为学生往往不知道自己不知道什么、不知道自己处于什么位置、不知道下一个问题应该是什么、无法自己组织多学科多任务整体路径。产品应主动在授权范围内观察当前处境任务状态、识别位置目标差距、提出当前最值得处理下一步、需要时给出原因行动建议、长期使用中逐步帮助学生理解参与路径。不能擅自打扰：学生明确休息暂停时强行推送、不了解任务时频繁催促、证据不足时伪造当前问题或下一步、没有授权干预规划、用频繁提醒替代真实判断、把学生推向自己都无法证明路径。主动性必须满足有依据、有边界、低负担、可纠正、不冒充确定。

最小主动性边界：在授权范围内能识别当前位置；能基于证据判断当前最重要下一步；能向学生白话说明现在做什么为什么做完如何检验；能主动提出可执行可检验可修正任务和教与授安排；能把行动结果送回规划触发继续调整补教暂停回退；在学生未提问不确定或无法自行组织时仍能提供持续引导；在证据不足或超出责任时降级补证暂停转介不擅自打扰。不能变成未经授权自动干预、强制推送、伪造问题、替学生作无法证明决定。

证明承接普通工具无法承接工作：产品能在真实学生一个阶段一个学科/责任领域一个真实任务上跑通"输入—证据—位置—目标—差距—路径—任务—教与授—行动—检验—反馈—修正"完整链路；跨学科跨任务优先级切换确实由学业军师统一承担而非各 Agent 各自为政；学校现实通过学生间接进入并与产品推断明确区分；反馈确实回流并触发可追溯规划处理；学业资产受控沉淀并服务后续规划；学生能理解当前位置当前任务下一步；长期使用后系统对位置差距路径判断稳定性得到改善；学生逐步从"被引导"走向"能参与甚至自己组织"；若只是把多个工具并排包装、没有统一规划责任和现实回流则不能称为承接了普通工具无法承接的工作。

完成定义与验收标准：学业军师能够以学业规划为最高责任，在一个明确学生阶段学科/责任领域和真实任务上，主动识别位置目标差距、提出下一步与教与授、把行动结果反馈回规划、受控沉淀学业资产、让学校现实通过学生间接进入，同时保持学生低负担可纠正可拒绝可请求人工介入。验收：跨学科跨任务全局判断由学业军师统一承担；主动性有依据有边界低负担可纠正不冒充确定；学生不知道自己有问题时产品仍能在授权范围内持续引导；反馈能回流并触发可追溯继续/调整/补教/暂停/回退；学生无需成为 Agent 或系统管理员即可完成核心路径；学校现实与学生转述产品推断没有混淆；未验证长期能力形成标为[待验证]；仅把工具包装在一起没有统一规划责任和现实回流不构成学业军师。

### 问题 2-4：学生低负担界面与内部复杂性的承接

**问题**：学生端如何呈现学业军师，做到简单直白而不失专业能力；复杂信息默认隐藏或按需展开；学生困难承接；简单与可追溯冲突优先级。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：学业军师的内部系统可以高度复杂，但学生端必须简单直白低学习成本。界面不是把内部机制全部展示，而是把复杂判断转译成学生当前能理解能执行能反馈的最小信息和操作。

首次进入不应先看到 Agent 列表、技术架构、判断引擎说明、复杂状态标签、记忆管理界面、大量表单、空洞产品宣传语、未经证据支撑的宏大人生路线图。首次进入应帮助学生快速回答：现在大概处于什么学习阶段；当前正在处理什么问题；产品还缺哪些必要信息；现在最重要的下一步；为什么要做这一步；如果不理解做不到不同意怎样处理。推荐首屏信息顺序：

```text
当前位置/当前情况
        ↓
当前最重要的问题
        ↓
现在先做什么
        ↓
为什么做
        ↓
做完如何判断
        ↓
不理解/做不到/不同意时怎么办
```

默认展示最小信息：当前处境白话描述、当前阶段目标、当前最重要问题、一项或少量明确下一步行动、行动基本原因、完成标准、完成后如何检验或进入下一步、暂停纠正拒绝求助入口。不应把所有任务、所有 Agent 分析、全部证据同时倾倒。

复杂信息默认隐藏：Agent 调用关系、判断引擎内部流程、数据库状态机接口名称、技术组件模型名称、全部候选路径、全部历史记忆、审计日志、复杂证据图谱、内部风险评分、细粒度权限版本信息。必须可按需查看：当前规划基本依据、相关关键材料或结果、当前判断是事实/分析/推断/待确认、哪些内容仍不确定、为什么当前任务与目标有关、当前规划由什么变化触发、哪些信息可纠正撤回删除、何时使用学生带回学校材料或学生转述。"可查看"不等于"默认展开全部技术细节"，通过白话说明分层展开和必要证据入口实现可理解性。

解释最低程度：学生不需看到模型隐藏推理，不需阅读专业审计报告，但至少应以白话说明"我根据什么知道？我现在判断什么？我还不知道什么？这会影响什么？你现在可以做什么？如果你不同意或做不到怎么办？"例如："你最近两次练习中基础题完成较好，但遇到需组合多步骤题目反复停住，所以先练习拆解步骤而不是继续增加题量。这个判断目前只根据这两次练习，完成下一次后会再检查。"含依据、当前判断、限定、下一步、后续检验。不应使用"系统置信度0.83""状态迁移S3→S4"作为默认解释。

一次交互主要行动：一个当前问题+一个主要下一步+一个完成标准+一个反馈入口。可提供辅助选项，但不能让学生同时面对多个同等优先级任务、多个 Agent 入口、多个冲突规划、大量审批按钮、复杂配置表单。确实有多个选择时先解释差异给出建议，不把未整理选项列表交给学生承担专业判断。

学生困难承接：我不理解→更白话重新说明、给具体例子、拆小任务、允许换解释、不把不理解记录成能力缺陷。我不会做→判断知识/方法/任务难度缺口、提供必要教与授、给示范提示第一步、允许请求更多帮助、不把求助等同失败。我不想做→了解是目标不认同/任务负担/疲劳/优先级变化/其他、允许暂缓或替代方案、评估对规划影响、不把拒绝自动记录成消极人格或稳定标签。我做不到→区分时间/资源/难度/理解/意愿、提供降低难度拆分调整顺序重新教与授、必要时触发规划复核、不要求学生解释内部系统。我不同意→允许说明原因、保留原判断和学生异议、判断需否补证或重新规划、低风险允许暂停替换、高影响保持未生效、不以学生不同意为由强行执行。

低负担纠正机制：学生纠正系统不应理解数据库状态机或 Agent，纠正入口用白话操作如"这不是我的情况""你理解错了""这项信息已过时""我没有做过这件事""请不要再依据这条信息""删除这条关于我的记录""换一种方法""暂时不要安排这个任务"。系统内部负责映射到证据纠正、判断异议、规划复核、资产撤回、记忆删除、任务暂停、重新教与授、人工/教师介入请求。学生不需知道内部分类，但系统必须保留明确状态审计记录。

不能把点击确认当理解：区分看到了、点击了、能用自己的话复述、实际执行了、执行结果支持判断。对低风险日常任务可用低负担确认或直接承接；对重大路径长期资产高影响事项通过更白话复述、选择、异议入口或其他可观察行为判断理解程度。不得把沉默、超时、随手点击、没有反驳解释成充分知情同意。

简单与可追溯冲突优先级（分层而非二选一）：

```text
默认交互：简单直白、低负担
        ↓
按需解释：白话依据、当前状态、下一步
        ↓
```

### 问题 2-5：学生低负担界面的首版核心路径

**问题**：学生第一次使用的最小核心路径；首次建档与任务起点；最低信息；首次输出优先级；完成标准与成功判定。

**回应**：

*主持人代拟初稿（[专业建议·代拟]，后经受访者修正）*：首次使用不应从建立完整档案或学习复杂操作开始，而应从学生眼前一项真实学业问题或任务开始。产品先用最少必要信息理解当前处境，再给一个明确重点和一个可执行下一步；随真实使用持续发生再逐步补齐规划证据资产长期理解。

*受访者修正（[用户明确判断]）*：完整个人档案、全部学科信息、长篇目标问卷、复杂学习偏好配置这些可以有也必须有。这些内容都没有，以证据驱动的学业军师就是伪军师。不能有的只包括关于 Agent 复杂操作的内容部分；关于学业的一切内容不算是复杂性转嫁。

*主持人修正（[已被修正]）*：学业信息的完整不等于 Agent 操作复杂，不能为了界面简单而削弱证据基础。以下内容不是可省略负担，而是证据驱动学业军师必须具备的产品内容：完整个人档案；全部学科信息；长期目标及形成过程；学习经历与阶段背景；复杂学习偏好配置；时间课程资源现实约束；作业考试错题成绩及其他学业材料；学生对自身处境补充说明；学校通过学生承接的课程要求教师反馈结果材料。这些内容可分阶段采集允许逐步补全，但不能因首次使用追求简单而从产品设计删除。没有完整学业背景全学科信息目标约束，产品无法承担整体学业规划，只能一题一事给出局部回答，那会退化为伪军师。

正确区分必须复杂的学业内容和不能转嫁的 Agent 复杂操作：

| 内容 | 是否必须具备 | 低负担原则 |
|---|---:|---|
| 完整个人档案 | 必须 | 产品用分阶段自动提取白话引导完成 |
| 全部学科信息 | 必须 | 学生不必一次手工填写，允许从材料逐步建立 |
| 长期目标 | 必须 | 通过对话材料和阶段确认逐步形成，不压缩成单一选项 |
| 学习偏好与限制 | 必须 | 允许自然语言表达，不要求理解内部配置 |
| 全部学业材料 | 必须持续接入 | 产品负责整理归类和去重 |
| Agent 编排方式 | 不应要求学生操作 | 由产品内部承接 |
| 判断引擎参数 | 不应要求学生配置 | 由产品按元文件和产品规则执行 |
| 记忆数据库管理 | 不应要求学生理解 | 学生只需用白话查看纠正撤回删除 |
| 权限状态机接口配置 | 不应要求学生操作 | 由系统和责任方按规则处理 |
| 专项 Agent 选择 | 不应要求学生自行选择 | 学业军师根据规划统一调度 |

"简单直白"修订为：学生不需要学习 Agent 使用方法和内部工程机制，但必须能以适合自己方式提供补充理解和修正与学业有关的完整信息。学业信息不能以简化交互为理由删减；应降低的是表达和操作门槛，而不是学业内容完整度。

首次路径修订：进入产品→建立或导入完整学业档案→登记全部学科与阶段背景→确认长期目标现实约束学习偏好→接收当前真实任务或材料→形成初步全局位置与当前问题判断→提出当前规划重点→安排任务与教与授→学生行动检验反馈→补充和修正档案规划学业资产。首次使用可采用渐进式完成：必须建立完整档案和完整信息模型；不要求学生一次性手工完成所有录入；系统可从上传材料自然语言回答后续任务提取候选信息；自动提取内容必须标明来源状态；缺失信息不能被伪装成已知；档案未完整时可先提供有限局部帮助但必须明确这不是完整规划；在形成整体学业规划前必须补齐影响规划的关键学业信息。

低负担正确含义：低负担不是少问学业问题、少收集学业材料、不建立全局档案、不了解全部学科、不询问长期目标、不记录学习偏好现实约束。低负担是不让学生学习 Agent 术语、不让学生配置判断引擎、不让学生选择管理多个内部 Agent、不让学生维护数据库状态机权限、不让学生把同一信息重复填写、允许自然语言上传材料分阶段补充、由系统主动整理识别缺口提出简单问题、每次只要求学生完成当前必要的一个信息或行动。

首次任务完成标准：不能以"学生打开页面"或"看过讲解"算完成。至少明确学生理解任务解决什么；学生完成规定最小行动；学生提交结果或明确说明无法完成及原因；产品能判断结果是否足以支持下一步；证据不足系统标记不足不把任务伪装成完成；任务结果可回溯到当前问题和规划候选。首次任务可以很小但必须真实有结果可检验。

没有材料材料不完整不会提交：没有材料产品不能因缺材料结束交互，可询问白话描述问题、提供低负担材料提交示例、让学生从当前正在做任务开始、先提供材料收集任务、明确说明目前能判断不能判断范围。材料不完整产品指出缺哪部分、说明缺失对判断影响、允许先处理不依赖缺失部分低风险事项、暂不形成超出证据范围结论、保存待补证状态。学生不会提交支持拍照上传或自然语言描述低负担入口、示例白话提示、分步提交、先提交一小部分、允许学生说"我不知道怎么提供"，不得要求学生先理解产品数据模型。

第一次使用留下什么：当前学生与任务关系、已提交材料和来源、当前问题原始表达、当前有限度位置/问题判断、当前规划或任务候选、任务执行状态、学生实际结果或困难反馈、下一步及其依据、尚未确认待补证待验证项、可能形成学业资产候选。第一次通常只能形成真实证据、临时任务状态、有限度判断候选、学业资产候选（如有充分依据）；不能因一次交互形成稳定学生画像或长期能力结论。

第一次使用成功判定三层：操作成功（无需培训进入核心路径、提交或说明真实问题、理解界面要求、没有因复杂操作中断）；机制成功（完成材料登记基本证据关联、形成有限定当前判断、给有理由重点和任务、学生完成行动或明确反馈困难、结果进入下一步处理、所有状态来源可回溯）；产品价值初步信号（学生知道当前要解决什么、知道为什么先做、知道下一步做什么、行动后获得更清晰下一步、产品没有把一次局部问答冒充完整学业规划）。这些只能说明首次路径成立，不能证明长期教育效果或学生已形成自主规划能力。

首次路径与普通工具区别：普通问答是"提问→回答→交互结束"；普通题库是"选题→给题/给答案→记录结果"；学业军师首次路径是"真实学业问题/材料→理解当前处境→判断当前重点→安排有理由下一步→教与授承接→学生真实行动→结果检验→说明下一步或修正规划"。差异不在首次回答字数更多，而在第一次交互就开始承接规划责任，并把学生带入可持续行动—检验—修正链。

完成定义与验收标准：完成定义——学生能从真实学业问题或材料出发，在无需学习复杂 Agent 操作情况下，获得对当前问题有限度白话理解、有依据当前重点、可执行任务和必要教与授；学生完成行动或反馈困难后系统能基于结果说明下一步或进入规划复核，并保留完整证据状态未决边界。验收标准——新学生无需阅读专业文档即可开始；首次启动不要求完整建档但需建立完整信息模型；所需信息不超过当前判断必需最小范围（缺关键必填时先补证不生成完整规划）；产品区分已知未知学生陈述系统推断；首次输出含当前重点下一步理由检验；主要交互不同时要求学生处理多个同等优先级事项；学生可提交不完整材料获明确补充路径；无法提交材料不困于复杂流程；学生能完成真实可观察可检验最小行动；产品不把看过内容点击确认生成计划当学习完成；任务结果能影响下一步；证据不足学生拒绝任务无法执行时降级补证调整暂停；学生无需管理 Agent 证据记忆权限状态机；首次路径不冒充完整教育效果或长期能力形成；首次路径可回溯到材料判断任务行动结果。

### 问题 2-6：学生的学业信息与认知状态

**问题**：学业军师对学生学业相关信息应掌握到什么程度、如何采集、如何登记来源/真实性/时效/授权、学生何时补充纠正撤回、证据在判断链中的地位。

**回应**：

*主持人代拟稿（[专业建议·代拟]，后经受访者两处修正）*：学业军师必须掌握足够学业信息才能承担整体规划。信息按来源时效真实性和授权登记，区分必需可补长期形成与临时上下文；不得因为只看到近期成绩或单次反馈就对学生的整体能力或学习状态作出过度判断。

学业档案字段：身份学段（学段学校年级、课程体系、当前阶段升学节点）；学业结构（各主要学科开设和进度、已完成进行中待学习模块、学校课程作业考试阶段要求）；成绩与表现（各科最近成绩排名教师评价、作业测验考试错题记录、学习表现趋势）；学习材料（提交过正在使用教材讲义题目、学生带回学校练习卷子反馈、材料对应学科用途）；方法与习惯（尝试过正在使用学习方法、习惯偏好有效无效方法经验、自我报告困难）；时间与精力（可投入时间节奏、日常负担精力约束、现实约束）；目标与动机（长期目标阶段目标优先顺序、学生对目标理解期望、考试升学现实要求来源）；已形成阶段认识（经确认学业资产、已验证有效无效方法、稳定学习问题/模式标来源不贴稳定人格标签、可复用可修订阶段内认识）。这些是学习内容不是复杂 Agent 操作，因此都应有且必须纳入；只是采集和管理由产品系统承接，学生用低负担方式提供纠正。

信息如何进入产品：

| 途径 | 说明 | 角色 |
|---|---|---|
| 学生主动提交 | 学生上传材料填写档案说明情况 | 学生 |
| 系统从材料提取 | 从作业试卷错题记录中自动识别候选信息 | 产品/判断引擎 |
| 学生反馈补充 | 学生对系统理解的纠正确认补充 | 学生+产品 |
| 学校通过学生承接 | 学生带回批注评分评语课程要求 | 学生承接/学校来源 |
| 历史会话与行动 | 过往规划任务验证反馈过程 | 产品积累 |
| 系统推断/假设 | 从证据推断模型分析候选 | 产品/判断引擎 |
| 特别授权接入 | 私立学校或合规机构授权下直接接入 | 特殊第三方 |

系统自动提取候选信息不等于已知事实，必须标来源和待确认，不能直接升级为长期资产。

每条信息登记：来源（材料/学生陈述/学校/推断/历史）；获取时间；真实性等级（原始材料/学生陈述/推断/待验证）；时效性（反映当前状态或已过时）；完整性（某学科某阶段全面）；授权范围（谁授权可访问哪些角色）；状态（已知/候选/待确认/待补证/已撤回）；生命周期（临时上下文/短期/长期资产）。来源不明真实性存疑过期或未经授权信息不能用于形成高影响规划结论，必须补证降级或标待核验。

*受访者修正一（[用户明确判断]）*：系统必须最大可能保持其稳定性专业性，避免学生进行实际补充纠正撤回等动作。基于客观事实这些动作只有长时间使用学业军师才能真正具备感知、存在意识；不要说学生连成年人都需要长时间使用 agent 才能慢慢注入这些动作，绝大多数前中期都是以 agent 产出的内容为主，很少去补充纠正撤回等动作。

*主持人修正一（[已被修正]）*：补充/纠正/撤回不是学生前中期的主要职责，而是低频必要低门槛的例外动作。产品前中期以系统产出的专业内容为主导，主动承担判断规划和呈现稳定性；学生默认不应被反复要求"纠正系统"；产品最大可能保持专业稳定，减少让学生介入机会；只有当系统确实明显误判、关键信息过时、或重大决定需学生确认时才触发补充/纠正/撤回；这些动作设计为最低门槛白话操作，一旦需要学生能不假思索完成；但产品不应因学生通常不纠正就放弃纠错通道——它必须存在稳定可及，只是默认不频繁触发。强制要求学生参与会转嫁专业治理负担；系统应把准确稳定专业作为首要目标而不是依赖学生纠错保证质量；学生感知存在意识是长期使用后逐渐形成，不是产品一开始就要求前提。何时真正需要学生参与（低频触发）：重大路径目标阶段变更且证据不足系统独立决定；系统发现原始材料与学生陈述明显冲突；关键信息可能过时或来源存疑影响高影响判断；学生明确表达异议或要求改变；涉及撤回删除长期信息或退出产品；系统判断进入能力边界之外需人工/教师介入。即使在此情形产品也用白话说明并默认给出建议，不把决策责任推给学生。

```text
        ↓

服务下一轮判断与规划
```

关系要点：证据是判断主要参考源，学业军师不凭模型印象或经验作判断，而以真实可核验与学生处境相关学业证据为依据；实事求是——判断尊重客观事实不把未发生未确认模型臆测当证据；因地制宜——同一问题不同学生学段学科目标现实约束下采用不同处理路径而不套用统一模板；具体问题具体分析——针对具体材料差距任务作判断不把一般经验直接套用个体。学业信息各层关系：证据是学业信息经过来源登记真实性时效授权筛选后可核验可追溯部分；判断引擎读取证据识别问题评估差距形成候选不凭空判断；规划层基于证据与判断形成位置目标差距路径任务修正；学业资产从真实证据提炼经确认可复用可修订长期认识；记忆更广历史上下文其中只有经筛选确认符合证据纪律部分能进入学业资产或判断。证据要经过筛选等级判断，不是所有信息都能作为判断依据；学生陈述模型推断临时上下文都不是可靠证据须降级；学业资产必须可回溯到证据；记忆不能静默成为证据也不能代替证据；判断引擎规划层都必须以证据为参考源而非模型自信为参考。

*剩余代拟内容*：不确定信息标记——确认（学生明确确认或高可信直接材料）；推断（有证据支持未达确认用于有限候选）；待验证（需工程或真实使用验证）；待补证（关键缺口禁止进入高影响判断）；用户临时提供（学生陈述可作线索不可冒充事实）；已撤回（学生明确要求删除撤销）；已失效（时间情况证据不支持继续使用）。系统使用这些信息必须保留原状态标识，把推断待验证或学生临时陈述写成事实属状态升级必须避免。

```text
        ↓
判断引擎：识别、关联、判断候选
        ↓
规划层：位置、目标、差距、路径、任务、修正
        ↓
反馈与行动：结果回流
        ↓

        ↓
服务下一轮规划与判断
```

关系要点：判断引擎读取并使用经登记学业信息；规划层基于信息形成位置差距路径；学业资产从真实证据提炼经确认可复用可修订长期认识；记忆含更广历史只有经筛选确认部分能成为学业资产；临时上下文只服务当前任务不静默进入长期资产。

避免过度判断：来源时间标记区分何时何物何时稳定事实；多次表现对照；不同任务类型交叉核对；学生说明与客观材料分离（错题 vs 学生转述）；学校材料与学生转述分离；异常值和波动识别；暂不贴"学生整体不行""某科完全不会"稳定标签；用"当前有限判断""证据不足""待验证"限定范围；重大判断多次证据支持后才升级；新证据可修正旧判断。例如一次测验不好只能说明该次测验反映知识/能力/熟练度可能不足，不能说明学生学不会某科；是否形成稳定认识须靠更多独立证据和长期验证。

```text
内部：完整、可追溯、责任清晰
外部：按当前需要提供、可逐步补充、白话可纠正
```

### 问题 2-7：低负担使用的完整性与边界

**问题**：学业军师如何在"不转嫁 Agent 复杂度"与"完整收集学业信息/证据"之间取得完整信息且不增负担；阶段2收束定位。

**回应**：

*主持人代拟稿（[专业建议·代拟]）*：学业军师在"不转嫁 Agent 复杂度"与"完整收集学业信息与证据"之间建立明确边界：Agent 编排、判断引擎、证据—状态—权限—记忆—资产管理等技术复杂性一律由产品自我承接绝不转为学生操作；学业档案、全部学科信息、长期目标、学习偏好、材料、证据与现实约束等学业内容绝不以简化交互为由删减，而是用低负担白话渐进自动提取方式完整采集。产品始终以系统专业输出为主保持稳定，不要求学生频繁补充纠正撤回；当需要学生介入时以最低门槛低频例外形式出现。

两类内容明确分界：第一类产品必须自我承接绝不转给学生——Agent 编排（多专项 Agent 如何协作谁调用谁如何交接由产品统一调度学生不选择不配置不管理）；判断引擎运行（如何限定 LLM 如何处理证据如何降级输出由产品按元文件规则执行学生不设置参数）；证据—状态—权限—记忆—资产管理（来源登记状态迁移权限矩阵记忆分类资产准入由底层设施完成学生不用理解数据库状态机接口）；自动化流程（规划任务教与授检验反馈回流自动推进由产品承接学生只按需参与真实学习）；内部技术术语（Agent 状态机证据等级权限审计接口默认不出现在学生主界面）。学生不需要学会使用 Agent 也不需要成为系统管理员。第二类学业信息必须完整但用低负担方式采集——完整个人档案；全部学科信息与阶段背景；长期目标及形成过程；学习偏好习惯方法与约束；学业材料（作业考试错题成绩讲义）；现实约束（时间课程资源家庭环境）；证据（可核验可追溯与学生处境相关事实材料）；学生带回学校课程要求教师反馈和结果材料。这些学业内容必须有且逐步补全；采集通过自然语言上传自动提取白话引导渐进确认完成，不让学生逐项手工填复杂表单。

证据在低负担中的核心地位：学业军师不能因界面简单而削弱证据基础。证据是实事求是（判断尊重客观事实不把未发生未确认模型臆测当证据）、因地制宜（同一问题不同学生学段学科目标约束下采用不同路径）、具体问题具体分析（针对具体材料差距任务作判断不套用统一模板）。证据地位示意：

```text
学业材料与档案
        ↓
【证据：实事求是、因地制宜、具体问题具体分析的主要参考源】
        ↓
判断引擎：基于证据识别、关联、形成判断候选
        ↓
规划层：位置、目标、差距、路径、任务、修正
        ↓
反馈与行动：真实结果回流为新证据
        ↓
受控提炼为学业资产
        ↓
服务下一轮判断与规划
```

学生不需理解证据内部管理，但产品必须用可追溯方式维护证据；学生提交材料和系统可核验事实是证据来源；学生陈述模型推断临时上下文都不是可靠证据须降级；学业资产必须可回溯到证据。

不依赖学生频繁纠正的准确性保障：证据驱动（判断基于真实可核验与学生处境相关证据）；多来源交叉（多份材料多次表现不同任务交叉核对）；状态与来源登记（区分事实推断待验证临时陈述不静默升级）；降级与补证（证据不足降低判断强度或请求补证不冒充确定）；回溯（判断规划任务可回溯到材料和证据）；专业承接（判断引擎专项 Agent 承担专业工作减少依赖学生审视）；长期积累（学业资产从真实证据受控沉淀服务后续判断）；低门槛纠错通道（虽默认低频但通道存在稳定白话可及，一旦需要学生能毫不费力完成）。补充纠正撤回应是低频例外不是学生前中期主要职责；成年人尚且需要长时间使用 Agent 才逐渐学会这些动作，绝大多数前中期以 Agent/系统产出为主很少主动补充纠正撤回；产品应最大可能保持稳定性专业性避免学生频繁介入；同时不放弃纠错通道它必须存在且可及只是默认不频繁触发。

阶段2一句话定位（收束判定句）：学业军师始终以系统专业输出为主保持稳定，不要求学生成为 Agent 或系统管理员；学生提供的学业信息与系统可核验证据，是产品实事求是因地制宜具体问题具体分析的主要参考源；Agent 复杂操作绝不由学生承担，但完整学业内容绝不以简化交互为由删减。

低负担完成定义：学生无需学习 Agent 操作、无需管理判断引擎证据状态权限记忆资产，即可在低负担白话渐进方式下提供和补充完整学业信息，理解当前重点与下一步，参与真实学习，并在需要时以最低门槛完成低频必要补充纠正撤回；同时证据作为实事求是主要参考源，其采集维护追溯过滤由产品自我承接，不因界面简单而缺失。

阶段2低负担验收标准：学生不需学习 Agent 判断引擎证据管理状态机权限配置；学生默认不必频繁补充纠正撤回，纠错是低频例外且通道可及；完整档案学科信息目标偏好材料和证据逐步补全不以简化删减；采集用自然语言上传自动提取白话引导完成；系统以证据为参考源区分事实推断待验证临时陈述；学业资产可回溯到证据；学生沉默误操作不理解拒绝时系统能降级简化暂停转介；学生能理解当前重点下一步和必要理由；高影响事项不因界面简单绕过确认保护；内部证据状态权限记忆审计仍可追溯；未验证长期能力形成标为待验证；只把工具拼装没有统一规划责任和证据回流不构成学业军师。
