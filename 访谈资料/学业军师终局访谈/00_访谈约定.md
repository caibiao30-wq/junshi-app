# 学业军师终局访谈约定

> 状态：已确认
> 访谈性质：终局产品工程开发访谈
> 当前阶段：约定已收敛，进入外部候选取证与正式访谈准备

## 访谈对象与权限

- 受访者：产品开发者、决策者、把控者（用户本人）。
- 受访者权限：确认、修正或否决学业军师产品的目标、用户、问题、责任边界、设计机制、工程约束、开发范围、验收方式和优先级。
- 采访者：访谈工作流主技能主持；负责提问、复述、识别矛盾、区分事实与判断、组织记录和报告；不替受访者作最终产品决策。
- 本次为一场新的终局访谈。既有仓库资料和既有结论不作为本次权威，仅可作为调查参考和核验线索。

## 唯一核心目标

将本次正在进行的终局访谈资料（主要为访谈部分资料）升级为一份**完整、详细、专业、可直接复用为后续代码工程输入的学业军师产品工程开发方案**。

该方案只讨论学业军师产品设计开发方面的具体问题，不能重复生成只有摘要、缺乏论证和工程细节的伪方案。凡属工程开发必要的关键点，都必须展开其前提、理由、边界、例外、依赖、失败处理、完成定义和验收标准。

“有验收标准”表示定义如何判定一个点成立或完成；不表示访谈已经证明该点已实现。尚未经过工程运行、真实用户使用或长期验证的内容，必须标记为 `[待验证]`，不得伪装成已实现能力。

## 对象—用户—问题—约束—目标

- **对象**：学业军师产品。
- **用户（本次访谈受访者角色）**：产品开发者、决策者、把控者。
- **产品最终用户及其他角色**：直接使用者、受影响者、协作方和决策方须在正式访谈中逐一确认，不由历史材料自动填充。
- **问题**：访谈问题必须针对学业军师产品工程开发的全量必要问题进行询问；凡属于产品设计、开发、实现前置条件、责任边界和验收的问题，均须进入问题树逐项排查。
- **约束**：只讨论学业军师产品设计开发及进入工程所必需的内容；不直接写代码；不把未验证内容写成事实；保留完整论证、限定、反例、修正、争议和验收判据。
- **目标**：在上述范围内逐一确认工程开发方案必须确认的全量问题，挨个排查、不遗漏关键细节，形成全量详细正式工程开发方案。

## 范围与排除

### 纳入范围

- 产品本体、责任和非责任；
- 产品最终用户、受影响者、协作角色、决策角色及真实场景；
- 学业问题、输入、证据、判断、规划、任务、教与授、反馈、复盘和学业资产；
- 判断引擎、Agent/非 Agent 责任边界、确定性规则和用户/人工控制；
- 自生长、自进化、记忆、会话、资产和其生命周期；
- 权限、确认、状态、审计、评测、异常、冲突、停止、回滚和错误传播；
- 候选工程底座、可复用能力、必须自持的产品责任及替换边界；
- 首版范围、后续演进、工程前置依赖、完成定义和逐点验收标准；
- 为上述产品工程内容不可回避的学校、教师、家长或机构关系边界。

### 排除范围

**明确不谈**以下内容，仅在实际构成产品工程不可回避的前置条件时讨论其必要边界：

- 商业模式、融资、定价和营销；
- 与产品工程无关的泛化教育哲学；
- Super Vibe Coding 系统本身的设计与实现；
- 本次访谈中的代码编写、部署和运行验证；
- 与学业军师产品责任无关的外部项目扩展。

如被排除领域构成产品工程不可回避的前置条件，只讨论其必要边界，不扩展为该领域方案。

## 执行方法

- 采用“树形问题节点 + 前沿迭代”推进；
- 先确认产品对象、用户、真实问题和约束，再进入产品机制、工程边界和技术候选；
- 每个问题依次经过：提问 → 受访者回答 → 复述 → 矛盾/缺口识别 → 必要追问 → 状态判定 → 记录确认；
- 既有资料只用于调查取证、提出核验问题和定位历史冲突，不代替本次回答；
- 可使用专业代拟帮助受访者思考，但代拟必须单列，只有受访者明确确认后才可标记为 `[确认采纳]`；
- 共享状态：`[用户明确判断]`、`[确认采纳]`、`[专业建议·代拟]`、`[已被修正]`、`[拒绝]`、`[待确认]`、`[待验证]`；
- 不把访谈确认等同于工程实现、真实用户效果或教育价值验证。

## 实施阶段与门控

1. **前置摸底**：收敛受访者角色、产品对象、用户、真实问题、目标和约束；
2. **逐层核实**：逐项核实产品责任、核心机制、角色关系、判断引擎、自生长/自进化、底座和边界；
3. **闭环校验**：核对输入—证据—判断—行动—教与授—现实反馈—修正—资产/能力，以及异常、拒绝、冲突、停止和回滚；
4. **成果固化**：逐项确认访谈记录，生成全量正式报告，完成结构、证据、状态、保真和可回溯质检。

发现重大矛盾时可以回退到上游节点；回退原因、受影响节点和重新确认结果必须留痕。

阶段放行条件：前一阶段的必答问题均已回应，或明确标记为 `[拒绝]`、`[待确认]`、`[待验证]`；空白不得被静默跳过。

## 核心方向与逐点验收

每一个工程开发必要问题至少登记：

1. 产品判断；
2. 前提与依赖；
3. 事实、历史材料、用户判断和调查推断的区分；
4. 取舍、风险、反例和被修正表述；
5. 边界、例外和失败路径；
6. 对下游产品与工程工作的影响；
7. 完成定义；
8. 验收标准与所需证据；
9. 当前状态；
10. 本次访谈记录定位及相关外部证据定位。

## 调查授权与来源范围

### 调查目标与核心问题

- **调查目标**：为终局访谈准备工程开发问题，重新核验候选底座、判断引擎、自生长/自进化及相关工程机制的外部事实和风险。

- **产出给谁**：给受访者审查，并作为终局访谈问题树和后续正式工程开发方案的参考证据。
- **时间窗口**：以实际访问日为准；每条来源登记获取时间，不以历史仓库报告的时间替代。
- **仓库分支/提交点**：当前工作区实际可访问内容；外部项目正式取证时登记具体 tag、release、commit 或论文版本。
- **文档版本**：外部项目以正式取证时读取的版本、提交点或发布日期为准；当前候选盘点不构成版本取证。
- **来源类型与平台**：GitHub 公开仓库、项目官方文档、论文；平台范围为公开可访问的 GitHub、官方站点和学术出版/预印本页面。

- **排除范围**：社交平台、营销软文、未署名转载、私有仓库、需登录或付费内容，以及与产品工程问题无关的材料。
- **失败来源处理**：记录访问失败、缺失版本、许可证不明、无法定位或证据不足；不以搜索摘要、记忆或其他来源静默补齐，并列入待核验清单。
- **调查验收条件**：每条纳入证据具备来源 ID、官方 URL、版本/提交点、获取时间、类型、访问状态、许可证、具体定位、原文摘录、支持/不支持范围、对应工程问题、风险和待核验项；调查报告交受访者审查后才进入正式访谈。

## 记录、保密与代拟边界

- 默认记录本次访谈的问题、受访者完整回答、必要追问、复述、状态和定位；
- 受访者可随时标注“不记录”“仅记录不进报告”“保密”“更正上一条”；

- 访谈报告不删除争议、缺口、待确认或待验证项。

## 第三轮正式访谈前对齐汇总（已确认）

### 唯一目标

将第三轮终局访谈资料升级为一份完整、详细、专业、可追溯、可逐点验收、可直接复用为代码工程输入的《学业军师产品工程开发元文件/方案》。每个工程开发必要问题必须展开产品判断、前提依赖、事实与推断、理由、取舍、风险、边界、例外、失败处理、下游影响、完成定义、验收标准、状态和定位。验收标准是未来判定成立/完成的条件，不等于本次访谈已证明实现或效果成立。

### 轮次与证据地位

- 第一轮：`draft/学业军师深度访谈记录——原始对话未删减版.md`。
- 第二轮：`访谈资料/学业军师产品正式方案访谈/03_访谈报告.md`。
- 第三轮：本次终局访谈。
- 第一、二轮材料及外部取证仅用于提出核验问题、定位历史表述、识别冲突和缺口；第三轮报告的内容证据源为第三轮访谈记录。

### 对齐后的统一原则

- 判断引擎是将具备广域推理能力的 LLM 通过学业对象、问题、证据、方法、输出和边界限定，改造成只适配学业军师的专项能力增强层；不是替代 LLM 的独立模型，也不只是提示词集合或权限拦截器。
- 自生长/自进化是长周期学业产品不可缺少的机制；允许产品在既定责任范围内持续提高对学生和学业任务的适配，但不得未经受控程序扩大责任、降低证据门槛或突破权限与安全边界。规则是否允许受控升级，作为正式访谈问题确认。
- 学生通常不是长期 Agent 用户，不能承担系统管理员或专业治理者责任；内部复杂性由产品吸收，学生端必须简单、直白、低学习成本。学生参与学习、提供反馈并保有必要的知情、纠正、拒绝和重大事项确认权，但不因“可纠正”而被要求频繁维护系统。
- 首版采用 0.5→1，目标是完成产品本体的完整可运行构建；除学业阶段的可替换部件外，不预设先做学生小样。产品构建完成、机制验证、真实使用验证和教育效果验证必须分层表达。
- 技术栈纳入本次访谈；产品责任先于技术选型，候选底座与组件可复用、改造、隔离、替换或自建，但不得反向决定产品本体。

### 方向 0–13（正式访谈问题树，完整版）

### 节点统一流程与验收

每个节点按“提问 → 受访者完整回答 → 复述/专业转译 → 矛盾与缺口识别 → 必要追问 → 状态判定 → 记录增量 → 受访者确认”推进。每个关键点必须登记完成定义、验收标准、责任方、所需证据、未验证边界和原始定位。状态使用七态：`[用户明确判断]`、`[确认采纳]`、`[专业建议·代拟]`、`[已被修正]`、`[拒绝]`、`[待确认]`、`[待验证]`。
