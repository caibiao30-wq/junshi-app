## T1 学生端产品本体职责与边界

- **[事实] P5「What is an agent?」**：「In its most fundamental form, a Generative AI agent can be defined as an application that attempts to achieve a goal by observing the world and acting upon it using the tools that it has at its disposal. Agents are autonomous and can act independently of human intervention...」
  → 给出 agent 通用定义：**应用 + 观察世界 + 使用工具达成目标**；自主、可独立于人工干预行动。为学业军师「学生端产品本体 = 一个达成学习目标的 agent 应用」提供通用边界词汇，但白皮书不定义学业军师本体，映射仅作外部参考。

- **[事实] P6「The model」**：「a model refers to the language model (LM) that will be utilized as the centralized decision maker for agent processes.」
  → 模型是 agent 流程的**中央决策者**；职责边界落在模型-工具-编排层三者，学生端职责需在此基础上另定，白皮书未给产品级职责清单。

- **[事实] P7「The orchestration layer」**：「The orchestration layer describes a cyclical process that governs how the agent takes in information, performs some internal reasoning, and uses that reasoning to inform its next action or decision. In general, this loop will continue until an agent has reached its goal or a stopping point.」
  → 编排层是「取信息→内部推理→据此行动」的循环，直到达成目标或到达停止点。提供 agent 行为边界（有明确停止语义），但无学业军师学生端职责切分。

## T2 客观证据模型(外部/内部证据)

- **[事实] P11**：「While the model could have guessed at an answer (hallucinated) based on its prior knowledge, it instead used a tool (Flights) to search for real-time external information. This additional information was provided to the model, allowing it to make a more informed decision based on real factual data and to summarize this information back to the user.」
  → 白皮书明确把「外部实时工具取证」与「凭先验知识臆测(hallucinate)」对立：外部工具数据 = 真实事实依据(real factual data)。可借鉴为客观证据模型「外部证据 > 模型臆测」的通用原则。

- **[事实] P27「Data stores」**：「Data Stores address this limitation by providing access to more dynamic and up-to-date information, and ensuring a model's responses remain grounded in factuality and relevance.」
  → 数据源用于让模型响应**扎根于事实性与相关性**(grounded in factuality and relevance)。

- **[事实] P29**：RAG 流程「1. A user query is sent to an embedding model... 2. The query embeddings are then matched against the contents of the vector database... 3. The matched content is retrieved from the vector database in text format and sent back to the agent 4. The agent receives both the user query and retrieved content, then formulates a response or action」
  → 给出「外部证据注入 → 模型据此作答」的可复现步骤；学业军师若引入 RAG，此为候选外部证据管线模板（见 T9）。

- **[推断]** 白皮书证据观为「外部工具/数据源 = 事实来源、模型内部知识 = 易臆测」；学业军师需要的「客观证据模型的具体实体/表单/证明结构」在原文本未取到，须由产品自持，不能由本文得出。

## T3 状态与生命周期(候选/生效/暂停/回退/失效/撤回/删除)

- **[事实] P8「Agents vs. models」**：agent 列「Managed session history (i.e. chat history) to allow for multi turn inference / prediction based on user queries and decisions made in the orchestration layer.」；「a 'turn' is defined as an interaction between the interacting system and the agent. (i.e. 1 incoming event/query and 1 agent response)」
  → 白皮书把「会话历史/多轮」作为 agent 相对纯模型的区分；"turn"= 一次入事件/查询 + 一次 agent 响应。是状态粒度的一种定义，但**非学业军师所需的状态机**（候选/生效/暂停/回退/失效/撤回/删除均未出现）。

- **[事实] P9**：「At the core of agent cognitive architectures lies the orchestration layer, responsible for maintaining memory, state, reasoning and planning.」
  → 编排层**负责维护 memory、state、推理与规划**。state 在此为编排层概念，白皮书未给状态迁移合法集合。

- **[事实] P40「Summary」**：「agents can leverage one or more language models to decide when and how to transition through states and use external tools to complete any number of complex tasks...」
  → 仅一句「模型决定何时及如何状态迁移」；无状态机定义、无合法迁移表。

- **[未取到]** 白皮书不含「候选/生效/暂停/回退/失效/撤回/删除」任一业务生命周期语义；T3 所需状态机须由学业军师产品自持，本证据稿不把白皮书「state」概念等同于学业军师状态模型。

## T4 权限与确定性强制(确定性代码强制，不靠提示词)

- **[事实] P19「Functions」**：使用 Functions 的常见理由含「Security or Authentication restrictions that prevent the agent from calling an API directly (e.g API is not exposed to the internet, or non-accessible by agent infrastructure)」「Timing or order-of-operations constraints that prevent the agent from making API calls in real-time. (i.e. batch operations, human-in-the-loop review, etc.)」
  → 白皮书确认存在「安全/鉴权限制 → 由 agent 侧改为客户端侧执行」的架构手段，可作为权限边界落地的工具选型依据（客户端执行把 API 调用移出 agent 直接路径）。

- **[事实] P18「Functions」**：「1. A model outputs a Function and its arguments, but doesn't make a live API call. 2. Functions are executed on the client-side, while Extensions are executed on the agent-side.」
  → 明确函数执行在客户端、扩展在 agent 侧；此分工可承载权限约束，但**不等于**「确定性代码强制」。

- **[待验证/未取到]** 白皮书通篇以「模型 + 推理框架(ReAct/CoT/ToT) + 提示词工程」为决策核心，未主张「确定性代码强制、不靠提示词」；「确定性与权限强制由确定性代码保证」在本文为 [未取到]，须由学业军师产品硬边界自持。

## T5 多代理编排(调度/优先级/交接/冲突裁决)

- **[事实] P38「Production applications with Vertex AI agents」**：「developers can rapidly define crucial elements of their agents - goals, task instructions, tools, sub-agents for task delegation, and examples - to easily construct the desired system behavior.」
  → Vertex AI 支持「sub-agents for task delegation（用于任务委派的子代理）」。为多代理「委派/交接」提供命名与概念，但白皮书未给调度/优先级/冲突裁决规则。

- **[事实] P40-41「Summary」**：「the strategic approach of 'agent chaining' will continue to gain momentum. By combining specialized agents - each excelling in a particular domain or task - we can create a 'mixture of agent experts' approach...」
  → 提出「agent chaining（代理链）」与「mixture of agent experts（专家混合）」，即把专精单域的子代理组合。可作为学业军师多代理划分的候选组织方式。

- **[事实] P32「Tools recap」**：Extensions 使用场景含「Multi-hop planning and API calling (i.e. the next agent action depends on the outputs of the previous action / API call)」
  → 多跳规划=下一步依赖上一步输出，是多代理/多步依赖链的通用描述。

- **[事实] P35「Agent quick start with LangChain」**：示例用 `langgraph.prebuilt.create_react_agent` 与 LangChain 工具，展示「chaining」together sequences of logic, reasoning, and tool calls（见 T9 代码引用）。
  → 提供开源多代理编排的具体组件候选（LangGraph `create_react_agent`）。

- **[未取到]** 白皮书无「调度优先级 / 冲突裁决 / 结果仲裁」的具体机制；T5 所需裁决规则须由学业军师自持。

## T8 0.5→1 路径与候选(复用改造＞重构＞自建；开源组件候选与准入)

- **[事实] P35**：「we'll build a quick prototype with the LangChain and LangGraph libraries. These popular open source libraries allow users to build customer agents by 'chaining' together sequences of logic, reasoning, and tool calls...」
  → 白皮书将 **LangChain + LangGraph 明示为「popular open source libraries」**，并给出可运行示例（Snippet 8）。是学业军师 0.5→1「开源组件候选」的直接外部证据（对应外部组件准入门禁的候选对象）。

- **[事实] P8「Agents vs. models」**：「Native cognitive architecture that uses reasoning frameworks like CoT, ReAct, or other pre-built agent frameworks like LangChain.」
  → 把 LangChain 列为「pre-built agent frameworks（预建代理框架）」，佐证其作为「复用现成开源组件」的候选地位。

- **[事实] P36「Snippet 8」**（代码）：
  ```python
  from langgraph.prebuilt import create_react_agent
  from langchain_core.tools import tool
  model = ChatVertexAI(model="gemini-2.0-flash-001")
  tools = [search, places]
  agent = create_react_agent(model, tools)
  input = {"messages": [("human", query)]}
  for s in agent.stream(input, stream_mode="values"):
      ...
  ```
  → 最小可运行的 LangGraph ReAct 代理骨架；0.5→1 若选该组件，此为骨架参考。

- **[待验证]** 白皮书未主张「复用改造＞重构＞自建」的优先级排序（此为学业军师访谈既定的 0.5→1 原则）；也未给组件准入评审标准。该优先级与准入规则须以学业军师既定决策为准，白皮书只提供「LangChain/LangGraph 是现成开源、可快速原型」的支撑事实。

## T9 技术栈/组件候选(状态持久化/编排/结构化输出等)

- **编排 / 状态：**
  - **[事实] P7**：编排层循环定义（见 T1 引用）。
  - **[事实] P9**：编排层「responsible for maintaining memory, state, reasoning and planning」（见 T3 引用）。
  - **[事实] P8**：agent「Managed session history」用于多轮推理（见 T3 引用）→ 会话历史为状态持久化的最简形态。

- **结构化输出：**
  - **[事实] P21-22「Use cases」**：「With Function Calling, we can teach a model to format this output in a structured style (like JSON) that's more convenient for another system to parse.」并给出 `function_call { name: "display_cities"; args: {...} }` 负载示例（Snippet 5，P22）。
    → Function Calling 作为「把模型输出结构化(JSON)供系统解析」的候选组件；学业军师若需结构化输出（如客观证据/表单化数据），此为直接候选。

- **外部知识注入 / 数据存储：**
  - **[事实] P28-29**：Data Stores 以**向量数据库**实现（「Data Stores are typically implemented as a vector database... store data in the form of vector embeddings」）；RAG 检索用 SCaNN 匹配算法。
  - **[事实] P35**：LangChain / LangGraph 作为开源编排候选（见 T8 引用）。

- **生产托管平台：**
  - **[事实] P38**：Vertex AI agents 全托管环境，「defines crucial elements of their agents - goals, task instructions, tools, sub-agents for task delegation, and examples」。

- **[推断]** 白皮书技术栈组合倾向为「模型 + 编排层(LangGraph/ReAct) + 工具(Function Calling/Extension/Data Store)」；学业军师技术选型可在该组合内做候选核对，但白皮书不给定「确定性/状态持久化/证据链」类专用组件（均[未取到]，见 T3/T4/T6）。
