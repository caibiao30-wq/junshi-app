## 一、目的

- 界定教与授在学生端产品本体中的**定位、判断对象、完成判据、承接流程、内容来源**，使其可直接落地为工程代码（schema + 判断动作）。`[确认采纳]`
- 明确教与授**不是学业军师的最高目的**，而是**服务学业规划、使规划能被执行和检验的手段**。任务、证据、判断、专项 Agent、自生长与学业资产最终都必须回答「它如何服务学业规划」。`[用户明确判断]` `[访谈/02] L404-L405`

## 二、范围

- 本文件只落实教与授的**学生端产品本体**语义：判断对象、动作产出、完成判据、困难承接、内容来源登记。`[确认采纳]`
- 不决定具体学科知识点、题库、教材、具体教学方法、具体提示词或界面像素（不替学段/学科文件填空）。`[确认采纳]` `[总文件] 0.1`
- 教师主观意见、批注、评分**不作产品输入或效果裁判**；产品只处理学生能带回的可核验客观实体材料（排名/成绩/试卷/作业/答题过程）。`[用户明确判断]` `[访谈/02] L4075, L4618-L4624`

## 三、输入 / 输出（教与授判断对象）

> 教与授是「应掌握什么、为何掌握、如何掌握」的承接，**输入**来自规划目标/任务 + 证据 + 学生位置，**输出**为可执行动作。`[确认采纳]` `[访谈/02] L474`

### 3.1 输入字段（可落 schema `TeachingJudgmentInput`）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `plan_goal` | 引用 | 当前规划目标（含来源、检验条件） | 规划层 `[访谈/02] L801` |
| `task` | 引用 | 教与授所承接的路径任务（须可回溯到路径环节） | 规划层 `[访谈/02] L804` |
| `evidence` | 引用集 | 支撑该判断的证据（外部/内部，区分原始结果与解释） | 证据模型 `[访谈/02] L806` |
| `student_position` | 结构化 | 当前学业位置描述（来源/时间/对象/状态，事实与推断分开） | 判断引擎 `[访谈/02] L800` |
| `constraint` | 引用集 | 现实约束（时间/资源/难度/意愿） | 档案+证据 |

### 3.2 输出动作（可落 schema `TeachingAction`，枚举）

| 动作类型 | 定义 | 完成信号（可观察行动） |
|---|---|---|
| `讲解` | 为「应掌握什么/为何掌握」提供理解承接 | 学生可复述/提出后续问题，而非仅已展示 |
| `练习` | 为「如何掌握」提供操练承接 | 产出练习记录/答题过程（内部证据） |
| `检验` | 校验是否掌握（任务完成≠掌握） | 检验结果回流，可关联原任务/规划 |
| `纠错` | 对错误/差距提供修正承接 | 学生按纠错产生新的行动或表现变化 |

`[确认采纳]` `[访谈/02] L805, L474`

### 3.3 判断约束

- 教与授判断**纳入首版验收**（`[确认采纳]`），不得出现无判断盲区；检验/反馈判断首版可简化纳入、不强验完整检验设计能力（只需能关联回原任务/规划、区分原始结果与解释）。`[确认采纳]` `[访谈/02] L3850-L3851`
- 教与授承接的内容**可回溯到任务与路径环节**，不能脱离路径自成体系。`[确认采纳]` `[访谈/02] L474`

## 四、完成定义与验收标准（逐项）

| 对象 | 完成定义 | 最低验收标准 |
|---|---|---|
| 教与授 | 为任务提供必要理解/练习/检验/纠错承接 | **不以展示内容为完成**；能观察行动或表现变化 `[访谈/02] L805` |
| 教与授判断 | 输入（目标/任务+证据+位置）→ 输出（讲解/练习/检验/纠错动作） | 动作可落 schema、可回溯证据与任务 |
| 教与授纳入首版 | 最小闭环含教与授，暂缓则「规划落地」断环 | 教与授判断纳入验收；任务完成≠掌握 `[访谈/02] L3808, L3859` |
| 困难承接 | 五类困难各有处理路径，不把拒绝记为消极标签 | 路径可执行、不记录成稳定标签 `[访谈/02] L1159` |
| 内容来源登记 | 三方来源登记清楚，教师材料限于授权 | 来源可追溯；版权合规 `[访谈/02] L4078-L4079` |

`[确认采纳]`

## 五、责任

- **教与授**：承接规划目标/任务，产出讲解/练习/检验/纠错动作，产生可观察行动；**不能**替学生承担实际学习行动。`[确认采纳]` `[总文件] 2`
- **专项 Agent**：提供教与授/任务/复盘建议、指出专业约束与风险；**不能**未经规划层整合把专业建议当已定计划。`[确认采纳]` `[访谈/02] L472`
- **规划层**：裁决生效目标/路径/重大优先级；教与授服从统一规划，不反向取代规划对路径的裁决。`[确认采纳]` `[访谈/02] L474, L792`
- **学生**：参与学习、执行任务、反馈必要确认；不把学生当系统管理员。`[确认采纳]` `[总文件] 2`

## 六、关键机制：看过讲解 ≠ 掌握

- **完成判据 = 可观察行动/表现变化，非展示内容**。不能以「系统已输出讲解」「学生点击了看过」作为掌握判据。`[确认采纳]` `[访谈/02] L805`
- 区分「看到了 / 点击了 / 能用自己的话复述 / 实际执行了 / 执行结果支持判断」五级；对重大路径、长期资产、高影响事项，通过白话复述、选择、异议入口或其他可观察行为判断理解程度。`[确认采纳]` `[访谈/02] L1163`
- 不得把沉默、超时、随手点击、没有反驳解释成充分知情同意或掌握。`[确认采纳]` `[访谈/02] L1163`

## 七、学生困难承接流程

> 五类困难各自处理路径，**不把拒绝记录成消极标签**。`[确认采纳]` `[访谈/02] L1159`

| 学生表达 | 处理路径 | 禁止 |
|---|---|---|
| 我不理解 | 更白话重新说明、给具体例子、拆小任务、允许换解释 | 不把不理解记录成能力缺陷 |
| 我不会做 | 判断知识/方法/任务难度缺口、提供必要教与授、示范提示第一步、允许请求更多帮助 | 不把求助等同失败 |
| 我不想做 | 了解是目标不认同/任务负担/疲劳/优先级变化/其他、允许暂缓或替代方案、评估对规划影响 | 不把拒绝自动记录成消极人格或稳定标签 |
| 我做不到 | 区分时间/资源/难度/理解/意愿、降低难度/拆分/调整顺序/重新教与授、必要时触发规划复核 | 不要求学生解释内部系统 |
| 我不同意 | 允许说明原因、保留原判断和学生异议、判断需否补证或重新规划、低风险允许暂停替换、高影响保持未生效 | 不因学生不同意为由强行执行 |

- **低负担纠正**：学生用白话纠正入口（「这不是我的情况」「你理解错了」「这项信息已过时」「请不要再依据这条信息」等），系统内部映射到证据纠正/判断异议/规划复核/记忆删除/任务暂停/重新教与授；系统保留明确状态审计记录。`[确认采纳]` `[访谈/02] L1161`
- 纠错动作改变后，教与授须基于新证据/新位置重新承接，不得沿用旧讲解。

## 八、教与授内容三方来源登记与版权边界

> `[确认采纳]` `[访谈/02] L4074-L4079`

### 8.1 三方来源（必须登记）

| 来源 | 定义 | 登记要求 |
|---|---|---|
| 产品内部生成 | 产品依据规划/证据生成的讲解/练习/检验/纠错内容 | 标记为内部生成，关联证据与任务 |
| 学校/教师材料（经学生承接） | 学生带回的可核验客观实体材料（排名/成绩/试卷/作业/答题过程） | 来源登记；经学生承接；教师主观意见不作输入 |
| 机构授权材料 | 经授权的机构材料 | 授权边界清楚，限授权范围使用 |

### 8.2 版权边界

- 产品**不未经授权复制、分发第三方教材**；引用的外部内容按来源登记；教育内容版权合规 `[待验证]`。`[确认采纳]` `[访谈/02] L4075`
- 验收：来源可追溯；教师材料授权边界清楚；版权合规 `[待验证]`。

## 九、与任务回流的关系（并行）

- 教与授与任务回流**高度耦合，建议并行**：无教与授则任务无可执行内容，二者互相支撑。`[用户明确判断]` `[访谈/02] L3914`
- 最小闭环主链顺序：规划层 → 教与授 → 任务/行动/检验/反馈回流（第 3 层·规划与执行）。`[确认采纳]` `[访谈/02] L3910`

### 10.1 实际证据

- 全部定位、判断对象、完成判据、承接流程、来源登记均出自第三轮终局访谈，覆盖 `[访谈/02]` L404-L474、L790-L807、L1155-L1165、L3798-L3863、L3908-L3918、L4067-L4084，确认状态以各段「确认状态」为准。`[确认采纳]`

### 10.2 未验证边界（`[待验证]`，不得写成已定）

- **真实掌握 / 教育效果**：教与授是否导致真实掌握与学习效果，属 L3/L4，一律 `[待验证]`，不冒充。`[访谈/02] L3859`
- **动态修正阈值**、**长期多学科稳定性**（教与授跨学科/长期稳定）`[待验证]`。
- **教育内容版权合规** `[待验证]`。
- 讲解的具体教学方法、界面表达、学段/学科内容不属本文件决定（后续由学科文件/前端文件承接）。

### 10.3 L1 / L2 验证入口

- **L1 机制验证**：教与授判断对象走完「证据→候选→校验→裁决→生效」；承接动作可回溯证据与任务；看过讲解≠掌握（无行动不标记完成）；五类困难承接路径各跑通一遍。`[访谈/02] L3859`
- **L2 故障注入**：缺失输入/证据冲突/学生拒绝承接/内容来源缺失时，教与授不产生无来源动作、不把拒绝记为消极标签、不绕过规划层裁决。`[访谈/02] L3862`
- 以 `helper` 目录的 L1/L2 验证工具为入口，机制正确性达标后再进入工程代码。
