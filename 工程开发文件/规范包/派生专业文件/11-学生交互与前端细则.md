### 1.5 责任
- **前端**: 把复杂判断转译成学生当前能理解、能执行、能反馈的**最小信息与操作**，承担理解组织；负责呈现状态与真实状态一致、控制生效记录、不隐瞒影响判断的事实与限制。`[确认采纳] [访谈/02] L1133, [03_访谈报告] L3897-3902`
- **学科军师/主军师（编排层）**: 统一入口背后统一编排，将复杂工作分派给专业 Agent，学生不必学习编排与底层接口。`[确认采纳] [03_访谈报告] L2423-2426`
- **底层确定性设施**: 真正保证学生控制权——确认/拒绝/撤回/暂停/退出的**强制状态**，不靠界面提示；前端点击后底层校验并记录对象/范围/时间/后果。`[确认采纳] [03_访谈报告] L3871-3882`
- **学生**: 服务主体、被保护主体、逐步形成能力的学习主体；**参与真实学习、理解必要安排、提供反馈、纠正**；**不是系统管理员，不是必须先学会使用 Agent 的专业操作者**。`[确认采纳] [访谈/02] L596-601`

### 1.6 完成定义
目标学生能够在不学习 Agent、状态机、记忆或权限系统的前提下，用简单直白界面理解当前重点、采取下一步行动、反馈困难或异议，并在需要时查看足够依据和控制自己相关信息；学生无需管理证据/记忆/权限/审计，即可低负担补充完整学业信息。`[确认采纳] [访谈/02] L1177, L1363`

### 1.7 验收标准（低负担承接层）
1. 新用户不需阅读专业文档即可完成首个核心任务。`[确认采纳] [访谈/02] L1179`
2. 首屏能说明当前处境、当前重点、下一步。`[确认采纳]`
3. 每个主要交互只突出一个核心行动；不同时要求学生处理多个同等优先级任务、多个 Agent 入口、多个冲突规划、大量审批按钮。`[确认采纳] L1157, L1179`
4. 默认不暴露 Agent 拓扑和技术术语；复杂依据可按需展开。`[确认采纳] L1179`
5. 学生能用白话纠正错误判断或过时信息；能暂停、拒绝、请求帮助或重新解释。`[确认采纳] L1179`
6. 不把沉默、超时、随手点击、没有反驳当充分知情同意。`[确认采纳] L1163, L1179`
7. 高影响事项不因简单界面绕过确认保护；内部判断/证据/状态/修正仍可追溯。`[确认采纳] L1179`
8. 学生遇异常看到明确白话下一步；不因无法管理记忆/证据/权限而无法使用。`[确认采纳] L1179`
9. 完整学业档案/证据/目标不以界面简单删减；Agent 复杂操作不以任何形式成为学生负担。`[确认采纳] L1214, L1335-1337`
10. 真实目标学生能完成核心路径，而非仅在演示环境成功（`[待验证]`）。`[确认采纳] L1179`

## 2. 战场总框架（前线—后方）+ 分级学科窗口（`[用户明确判断]` + `[确认采纳]`）

前端呈现为**前线与后方的战场总框架**；在此基础上按不同学科设立**分级操作窗口**。第一级窗口展示全学科内容，下设多个窗口，点击进入查看对应专业学科内容。`[用户明确判断] [03_访谈报告] L3814`

| 栏目 | 作用 | 回答 | 核心内容 |
|---|---|---|---|
| **前线** | 当前学业战况、趋势与紧要行动 | 「我现在整体在哪、当前最重要战况、接下来推进什么」 | 当前整体战况、阶段最重要方向、各学科状态、当前优先级、最应推进任务、学科冲突/失衡、近期趋势、需确认/补证/调整事项。**不是简单待办列表**，而是将全学科协调结果转化为可理解的当前行动视图。 `[确认采纳] L3835` |
| **后方** | 阶段内资产、认识与长期积累 | 「过去积累了什么、哪些仍有效、如何支持现在和后续」 | 学业资产、已确认阶段内认识、学习过程与历史结果、可复用方法、已验证/待复核认识、证据与反馈形成的长期趋势、阶段性总结、可供调用的历史资源。**不是静态档案库**，而受证据、状态、确认与复验约束的阶段内资源区。 `[确认采纳] L3837` |

```text
战场总框架
├── 前线：当前学业战况、趋势与紧要行动
│   ├── 第一级：全学科总览窗口
│   └── 第二级：各学科专业窗口
└── 后方：阶段内资产、认识与长期积累
    ├── 第一级：全局资产与趋势总览窗口
    └── 第二级：各学科资产专业窗口
```

`[专业建议·代拟]`（用户确认前端结构，此为结构细化）`L3820-3828`。

**两层解决不同问题**: 战场总框架负责整体理解和战况/趋势呈现（哪里、整体如何）；分级学科窗口负责具体操作和进入专业学科（这门学科现在做什么、如何推进）。战场视图理解全局，学科窗口进入行动。`[确认采纳] L3830-3833`

**前线与后方闭环**: 后方积累的证据/资产/趋势 → 支持前线当前判断与任务 → 学生完成前线行动并取得结果 → 结果回流后方形成新证据、修订认识和趋势。没有前线，后方退化为静态资料仓库；没有后方，前线退化为无历史依据的临时待办。`[确认采纳] L3839`

**第一级·全学科总览窗口**: 展示各学科当前状态、学科间优先级、整体战况与趋势、最应推进方向、各学科待处理事项概览、需进入具体学科处理的问题、整体层面冲突/风险/待确认。不承担全部学科细节，提供「从整体战况进入具体学科行动的导航与决策入口」。`[确认采纳] L3841`

**第二级·学科专业窗口**: 展示学科当前状态、学科内任务、任务理由与完成标准、讲解/练习/检验、学科证据与反馈、学科资产与阶段内认识、学科趋势、返回全学科总览入口。把全学科协调方向转化为该学科内可理解、可执行、可检验的操作。各学科窗口可专业内容不同，但**共享底层证据、权限、状态、会话与监察约束**。`[确认采纳] L3843`

**战况 / 趋势 / 资产 / 规划需区分**（不能混为一张图或一个分数）: `[专业建议·代拟] L3849-3856`

| 内容 | 时间尺度 | 作用 |
|---|---|---|
| 战况 | 当前/近期 | 决定眼下做什么 |
| 趋势 | 一段时间 | 判断是否持续变化 |
| 资产 | 阶段内可复用 | 支持后续学习 |
| 规划 | 未来安排 | 组织任务和资源 |

前端可关联展示，但**底层必须保留不同对象、来源与状态**。

## 3. 学生统一入口，不暴露内部 Agent 拓扑（`[确认采纳]`）

- 学生默认面对一个统一入口，即**主军师（总军师）**；主军师将复杂工作分派给专业 Agent；学生不必学习 Agent 编排和底层接口；学生仍可以看到足以理解当前安排的依据、状态、未知和控制选项。`[确认采纳] [03_访谈报告] L2423-2426`
- **统一入口 ≠ 把所有责任混在一个会话**: 统一入口不是把所有责任混在一句「最终答案」里。前端统一体验，底层责任分域；前端呈现清楚的结果与依据，不伪装成一次没有责任归属的聊天。`[确认采纳] L2428-2430, L3884-3893`
- **学生不必直接操作所有责任域，但应能**: 看到当前任务由哪类专业能力支持、查看影响当前安排的依据、看到未决和冲突、纠正事实、确认/拒绝/暂停/退出、查看资产和阶段内认识、知道信息如何被使用。`[确认采纳] L2434-2442`
- **不应展示**增加无意义负担的内部技术细节（Agent 调用关系、判断引擎流程等）；**也不能以隐藏全部过程为由**遮蔽会影响学生判断的事实和限制。`[确认采纳] L2444`
- **前端不能代替底层隔离**: 分栏、标签、多窗口只能帮助学生理解操作，**不能代替**权限隔离、强制确认、审计记录、状态机合法迁移。前端呈现与底层保持一致，不能只改界面。`[确认采纳] L2446-2448, L3878`

## 4. 低负担原则：内部复杂、外部简单 + 两类内容分界

### 4.1 低负担正确含义
低负担**不是**少问学业问题、少收材料、不建全局档案、不了解全部学科、不询问长期目标、不记录偏好约束。低负担**是**不让学生学 Agent 术语、不配置判断引擎、不选择管理多个内部 Agent、不维护数据库状态机权限、把同一信息重复填写；**允许**自然语言上传材料分阶段补充、由系统主动整理识别缺口提出简单问题、每次只要求学生完成当前必要的一个信息或行动。`[确认采纳] [访谈/02] L1218`

### 4.2 两类内容分界（Q2-7，`[确认采纳]`）
在「不转嫁 Agent 复杂度」与「完整收集学业信息与证据」之间建立明确边界：`[访谈/02] L1335`

**第一类·产品必须自我承接、绝不转给学生** `[确认采纳] L1337`
| 内容 | 低负担原则 |
|---|---|
| Agent 编排（多专项 Agent 谁调用谁、如何交接） | 产品统一调度，学生不选择、不配置、不管理 |
| 判断引擎运行（如何限定 LLM、处理证据、降级输出） | 产品按元文件和规则执行，学生不设参数 |
| 证据—状态—权限—记忆—资产管理 | 底层设施完成，学生不用理解数据库状态机接口 |
| 自动化流程（规划→任务→教与授→检验→反馈→回流） | 产品自动推进，学生只按需参与真实学习 |
| 内部技术术语（Agent 状态机/证据等级/权限/审计/接口） | 默认不出现在学生主界面 |

**第二类·学业信息必须完整、用低负担方式采集** `[确认采纳] L1337`
| 内容 | 低负担原则 |
|---|---|
| 完整个人档案 | 分阶段自动提取 + 白话引导完成 |
| 全部学科信息与阶段背景 | 不允许一次手工填写，允许从材料逐步建立 |
| 长期目标及形成过程 | 通过对话材料和阶段确认逐步形成，不压缩成单一选项 |
| 学习偏好习惯方法约束 | 允许自然语言表达，不要求理解内部配置 |
| 学业材料（作业考试错题成绩讲义） | 默认持续接入，产品负责整理归类和去重 |
| 现实约束（时间课程资源家庭环境） | 白话采集，可逐步补全 |
| 证据（可核验可追溯与学生处境相关事实材料） | 产品负责维护，学生用可追溯方式受益 |
| 学生带回学校课程要求/教师反馈/结果材料 | 经学生承接（教师主观内容不直接作输入） |

**边界一句话**: Agent 复杂操作绝不由学生承担；**完整学业内容绝不以简化交互为由删减**。学业信息不能以简化交互为理由删减；应降低的是表达和操作门槛，而不是学业内容完整度。`[确认采纳] [访谈/02] L1214, L1361`

**`[已被修正]` 记录**: 原「首次使用不建档」表述被受访者修正——完整个人档案、全部学科信息、长篇目标问卷、复杂学习偏好配置「**可以有也必须有**」，缺失则证据驱动学业军师即「伪军师」。不能有的只包括关于 Agent 复杂操作的内容。`[用户明确判断] [访谈/02] L1195`

## 5. 首屏信息顺序（`[确认采纳]`）

首次进入**不应**先看到: Agent 列表、技术架构、判断引擎说明、复杂状态标签、记忆管理界面、大量表单、空洞宣传语、未经证据支撑的宏大人生路线图。首次进入**应**帮助学生快速回答以下问题，推荐首屏信息顺序：`[访谈/02] L1135`

```text
当前位置 / 当前情况
        ↓
当前最重要的问题
        ↓
现在先做什么
        ↓
为什么做
        ↓
做完如何判断
        ↓
不理解 / 做不到 / 不同意时怎么办
```

默认展示**最小信息**: 当前处境白话描述、当前阶段目标、当前最重要问题、一项或少量明确下一步行动、行动基本原因、完成标准、完成后如何检验或进入下一步、暂停/纠正/拒绝/求助入口。**不应**把所有任务、所有 Agent 分析、全部证据同时倾倒。`[确认采纳] L1151`

**解释最低程度**: 学生不需看到模型隐藏推理、不需阅读专业审计报告，但至少应以白话说明「我根据什么知道？我现在判断什么？我还不知道什么？这会影响什么？你现在可以做什么？如果你不同意或做不到怎么办？」不应使用「系统置信度0.83」「状态迁移S3→S4」作为默认解释。`[确认采纳] L1155`

**一次交互主要行动**: 一个当前问题 + 一个主要下一步 + 一个完成标准 + 一个反馈入口。可提供辅助选项，但**不能**让学生同时面对多个同等优先级任务、多个 Agent 入口、多个冲突规划、大量审批按钮、复杂配置表单。确实有多个选择时先解释差异给出建议，不把未整理选项列表交给学生承担专业判断。`[确认采纳] L1157`

## 6. 首次核心路径（Q2-5，`[确认采纳]`）

首次使用**不应**从建立完整档案或学习复杂操作开始，而应从学生眼前一项真实学业问题或任务开始；产品先用最少必要信息理解当前处境，再给一个明确重点和一个可执行下一步；随真实使用持续发生再逐步补齐规划证据资产长期理解。`[访谈/02] L1193`

**`[已被修正]`**: 完整档案/全部学科/长期目标/偏好配置「可以有也必须有」（见 §4.2）——首版核心路径的实施方式是「**必须建立完整信息模型**，但不要求学生一次性手工录入」，分阶段渐进完成。`[确认采纳] L1216`

**首次路径（修订后）**: `[确认采纳] L1216, L1228`

```text
进入产品 → 建立或导入完整学业档案 → 登记全部学科与阶段背景
  → 确认长期目标/现实约束/学习偏好 → 接收当前真实任务或材料
  → 形成初步全局位置与当前问题判断 → 提出当前规划重点
  → 安排任务与教与授 → 学生行动检验反馈 → 补充和修正档案/规划/学业资产
```

与普通工具区别: 普通问答是「提问→回答→结束」，普通题库是「选题→给题/答案→记结果」；学业军师首次路径是「真实学业问题→理解处境→判断重点→有理由下一步→教与授承接→真实行动→结果检验→说明下一步或修正规划」，**第一次交互就开始承接规划责任**。`[确认采纳] L1228`

**渐进式完成**: 必须建立完整档案和完整信息模型；不要求学生一次性手工完成所有录入；系统可从上传材料、自然语言回答、后续任务提取候选信息；自动提取内容必须标明来源状态；缺失信息不能被伪装成已知；档案未完整时可先提供有限局部帮助但必须明确这不是完整规划；形成整体规划前必须补齐影响规划的关键学业信息。`[确认采纳] L1216`

**首次任务完成标准**: 不能以「打开页面」或「看过讲解」算完成。至少: 明确学生理解任务解决什么、完成规定最小行动、提交结果或明确说明无法完成及原因、产品判断结果是否足以支持下一步、证据不足标记不足不把任务伪装成完成、结果可回溯到当前问题和规划候选。首次任务可以很小但**必须真实、有结果、可检验**。`[确认采纳] L1220`

**没有材料/材料不完整/不会提交**: 没有材料不能因缺材料结束交互，可询问白话描述问题、提供低负担提交示例、从当前正在做任务开始、先提供材料收集任务、明确说明当前能/不能判断范围。材料不完整指出缺哪部分、说明缺失影响、允许先处理不依赖缺失部分的事项、暂不形成超出证据范围结论、保存待补证状态。学生不会提交支持拍照上传或自然语言描述低负担入口，允许学生说「我不知道怎么提供」。`[确认采纳] L1222`

**第一次成功判定三层**: `[确认采纳] L1226`
1. **操作成功**: 无需培训进入核心路径、提交或说明真实问题、理解界面要求、没有因复杂操作中断。
2. **机制成功**: 完成材料登记/基本证据关联、形成有限定当前判断、给有理由重点和任务、学生完成行动或明确反馈困难、结果进入下一步处理、所有状态来源可回溯。
3. **产品价值初步信号**: 学生知道当前要解决什么、知道为什么先做、知道下一步做什么、行动后获得更清晰下一步、产品没有把一次局部问答冒充完整学业规划。

三层只说明首次路径成立，**不能证明长期教育效果或学生已形成自主规划能力**（`[待验证]`）。`[确认采纳] L1226`

## 7. 简单与可追溯冲突优先级：三层分层（`[确认采纳]`）

简单与可追溯**不是二选一，而是分层**。`[访谈/02] L1165-1175`

```text
默认交互：简单直白、低负担
        ↓
按需解释：白话依据、当前状态、下一步
        ↓
专业展开：证据明细、版本、审计、完整回溯
```

**优先级（从高到低）**: 学生安全责任边界 + 不可逆保护 > 学生能理解能行动 > 证据与状态可追溯 > 内部机制完整 > 展示更多细节。`[确认采纳] L1175`

**双向约束**: 简单不能成为隐藏错误、取消学生控制、省略证据的理由；可追溯也不能成为把内部复杂性全部压给学生、强迫学生阅读审计报告的理由。`[确认采纳] L1175`

三层落位: 默认交互只给最小信息（§5）；学生在需理解依据/当前状态/下一步时进入按需解释（白话，§8 可查看清单）；证据明细/版本/审计/完整回溯仅在需要时专业展开（不默认展示技术术语）。学生默认面对三层中最顶层，随需要逐层下潜。`[确认采纳]`

## 9. 学生困难承接五态（`[确认采纳]`）

学生沉默、不会操作或误操作时: 系统不能把沉默当成同意，也不能把一次点击当成充分理解。对学生五种困难的白话处理：`[访谈/02] L1159`

| 学生状态 | 白话处理 | 禁止 |
|---|---|---|
| **不理解** | 更白话重新说明、给具体例子、拆小任务、允许换解释 | 不把不理解记录成能力缺陷 |
| **不会做** | 判断知识/方法/任务难度缺口、提供必要教与授、给示范提示第一步、允许请求更多帮助 | 不把求助等同失败 |
| **不想做** | 了解是目标不认同/任务负担/疲劳/优先级变化/其他、允许暂缓或替代方案、评估对规划影响 | 不把拒绝自动记录成消极人格或稳定标签 |
| **做不到** | 区分时间/资源/难度/理解/意愿、提供降低难度/拆分/调整顺序/重新教与授、必要时触发规划复核 | 不要求学生解释内部系统 |
| **不同意** | 允许说明原因、保留原判断和学生异议、判断需否补证或重新规划、低风险允许暂停替换、高影响保持未生效 | 不以学生不同意为由强行执行 |

**补充原则（Q2-6，`[已被修正]`）**: 补充/纠正/撤回**不是学生前中期的主要职责**，而是低频必要低门槛的例外动作。产品前中期以系统产出的专业内容为主导，主动承担判断规划和呈现稳定性；学生默认不应被反复要求「纠正系统」；只在明显误判、关键信息过时、重大决定需确认等低频场景触发。但纠错通道**必须存在且稳定可及**，只是默认不频繁触发；强制要求学生参与会转嫁专业治理负担。`[确认采纳] [访谈/02] L1266-1268`

**「不能把点击确认当理解」**: 区分看到了、点击了、能用自己的话复述、实际执行了、执行结果支持判断。低风险日常任务可用低负担确认或直接承接；重大路径/长期资产/高影响事项通过更白话复述、选择、异议入口或其他可观察行为判断理解程度。不得把沉默、超时、随手点击、没有反驳解释成充分知情同意。`[确认采纳] L1163`

## 10. 低负担纠正机制：白话入口 → 内部动作映射（`[确认采纳]`）

学生纠正系统**不需理解数据库状态机或 Agent**；纠正入口用白话操作完成，系统内部负责映射到对应确定性强制动作。`[访谈/02] L1161`

| 学生白话入口 | 内部映射动作 |
|---|---|
| 「这不是我的情况」 | 证据纠正 / 判断异议 |
| 「你理解错了」 | 判断异议 → 判断复核 |
| 「这项信息已过时」 | 证据时效修正 / 失效 |
| 「我没有做过这件事」 | 内部证据溯正 / 撤回用途 |
| 「请不要再依据这条信息」 | 撤回用途，阻断下游使用 |
| 「删除这条关于我的记录」 | 证据撤回 / 记忆删除（可删除项） |
| 「换一种方法」 | 重新教与授 |
| 「暂时不要安排这个任务」 | 任务暂停 / 调整 |

学生不需知道内部分类，但**系统必须保留明确状态审计记录**。`[确认采纳] L1161`

**控制入口完整清单（Q3-7，`[专业建议·代拟]`）**: 学生端至少应具备并可使用的 8 类入口（`[03_访谈报告] L3860-3869`，按母文件继承边界，代拟标签不上提）——
1. 确认/拒绝/暂停/退出；
2. 纠正事实（纠正后生效并受审计）；
3. 撤回用途（撤回后底层阻断下游）；
4. 查看和管理资产（来源/范围/验证状态）；
5. 查看和控制记忆（纠正、拒绝保留、撤回删除可删除内容）；
6. 向教师/机构/家长反馈边界；
7. 求助与人工介入（解释、帮助、反馈困难、复核、申诉）；
8. 无障碍与首次使用（三步上手、降低术语输入负担、支持跨能力访问）。

## 11. 学生控制权与底层相对保证（`[专业建议·代拟]`，底层为 `[确认采纳]`）

前端提供控制入口，**但真正保证学生控制权的是底层**：`[03_访谈报告] L3871-3882, L3897-3906`

| 事项 | 底层基础设施 | Agent/前端 |
|---|---|---|
| 内容一致性 | 保证呈现状态与真实状态一致 | 生成可理解表达 |
| 权限边界 | 决定谁能看到什么、控制什么 | 呈现必需且允许的内容 |
| 控制生效 | 确认/拒绝/撤回/暂停强制记录 | 提供操作入口和反馈 |
| 不隐瞒关键事实 | 保证不隐藏影响判断的依据与限制 | 用易理解语言说明依据 |
| 责任域隔离 | 防止前端伪装成单一对话 | 组织并解释结果 |
| 学生认识 | 保证可见、可纠正、可撤回 | 呈现对学生的认识 |
| 遗漏/冲突 | 保留未知、冲突和待确认 | 说明并请求确认 |
| 无障碍 | 支持跨能力访问 | 首次引导和简化表达 |

关键保证: 底层确认/拒绝/撤回/暂停/退出记录是**强制状态**，不是界面提示；前端点击「确认」后，底层必须校验并记录对象、范围、时间和后果；前端点击「纠正」后，底层必须让纠正生效并阻断下游错误使用；前端隐藏或显示内容必须与底层权限和状态一致；学生沉默不能被界面解释为「已同意」；学生拒绝不能被界面记录为「已完成」。`[确认采纳] L3875-3880`。**前端是让学生能发起和控制；底层记录是让学生控制真正生效。** `[确认采纳] L3882`

## 12. L1 / L2 验证入口与 L3 待验证（`[确认采纳]`）

- **L1 机制模拟**: 用模拟数据验证机制可用——首屏信息顺序是否成立、默认隐藏项是否确实不暴露、白话纠正入口是否映射到正确内部动作、三类学生（不理解/不会做/不同意）模拟困难能否被承接且不落负面标签。方法: 走通首次核心路径的状态/动作/道具全链路，核对每步可回溯。`[确认采纳] [访谈/02] L3952`
- **L2 故障注入**: 验证在场中健壮——学生沉默（无响应）不被当成同意；学生拒绝不被记录为已完成；无材料/材料不齐全不结束交互而是降级补证；模型/API 不可用时界面显示明确白话下一步而非伪装可用；高影响确认保护不被简单界面绕过。`[确认采纳]`
- **L3 真实使用可用性（`[待验证]`）**: 小样本真实目标学生使用，验证「战场总框架与分级窗口是否被学生理解」「分级窗口是否降低操作负担」「是否造成额外认知成本」「首屏信息顺序是否让真实学生无师自通」，及「学生能否完成真实核心路径而非仅在演示环境成功」。一律 `[待验证]`，不得冒充。`[03_访谈报告] L3914, L4149`, `[访谈/02] L3952`
- **完成界定**: L1 + L2 达标视为首版交互机制构建验收通过；L3 真实使用 / L4 教育效果 `[待验证]`，不冒充。
