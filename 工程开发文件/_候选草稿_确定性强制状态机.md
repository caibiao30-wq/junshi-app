## 4. 事实 / 推断 / 本仓库候选建议 分层

**已核验事实（外部证据，可复现；来源=GitHub MCP 一手核证）**
- 许可证：OPA/Casbin/Cerbos/OpenTelemetry/OpenLineage=Apache-2.0（源码 SPDX / Apache 项目已核）；XState/Temporal/LangGraph/Ajv/Zod/transitions=MIT（各 LICENSE 文件已核）；EventStoreDB=**Kurrent License v1**（根 LICENSE.md 已核，自定义受限）。
- 版本（均 GitHub list_tags/list_releases 实取）：OPA v1.20.2、Cerbos v0.55.0、OTel v2.11.0、OpenLineage client/go/v1.53.0、Temporal v1.32.0、XState 稳定 v5.33.0（最新 tag 为 alpha.54）、Ajv v8.20.0、Zod v4.6.5、casbin-node v5.51.1、casbin-dart v1.9.0、transitions v0.9.3、LangGraph 根 v0.0.8、EventStoreDB container tag。
- Spring Statemachine 已归档（archived:true，spring-attic）；EventStoreDB 官方已更名 Kurrent（根含 KurrentLogo/KurrentDB.slnx）。

**来源自身结论 vs Claude 推断**
- 「能承载权限/状态机/审计机制」= **推断**（基于各项目官方定位的合理外推），非这些项目的承诺；它们对「学业军师证据字段完整性/合法状态机/业务回滚语义」均无产品级实现——此点与证据包 T4/G2/G3 结论一致（外部信源对产品硬边界均[未取到]）。
- 对学业军师技术栈的贴合（如 casbin-dart 对 Flutter、Zod/Ajv 对 TS 云端、XState 对 TS、Temporal 的本地模式）均为**推断**，需 0.5-2 运行验证。

**本仓库候选建议（非决定，待主 Agent 与用户）**
- 组1 权限强制：OPA / Casbin / Cerbos 三者并列候选，机制取向（外部策略引擎 vs 进程内授权库）需结合本地权威架构选。
- 组1 字段完整性：Ajv(JSON Schema) 与 Zod(TS-native) 为两类取向候选。
- 组2 状态机：XState（TS 显式状态机）与 transitions（Python）为轻量显式迁移候选；Temporal（持久化编排+回滚）为重量级候选；LangGraph 状态/记忆为 Agent 运行时候选。
- 组2 审计/回滚：OpenLineage（血缘链）与 EventStoreDB（事件账本）为机制参照候选；EventStoreDB 许可证需先核清。

**风险提示（事实层面，初评存疑待核验）**
- EventStoreDB 许可证为 **Kurrent License v1**（自定义受限，明确禁止作为托管/受管服务向第三方提供、禁止移除许可机制）——私域/本地方案下能否用、如何合规，须在门禁环节专门核验。
- spring-statemachine 已归档（archived:true）且为 Java 栈，与暂定技术栈（TS 云端 / Dart 客户端）不符。
- XState 最新 tag 为 alpha（6.0.0-alpha.54）；若选用须锁定稳定主线 v5.33.0，避免追踪 alpha。
- 以上为「初评存疑待核验」记录，**未对任何候选做安全评级/产品责任判断/是否纳入首版**，该判定留待门禁环节与用户。
