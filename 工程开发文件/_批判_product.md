## 第一部分 · 产品层不足/必改点

### P-1 产品定位「B 端产品」与「学生端本体」只在证据包内做了语义区分，未形成可落进产物的统一表述

**① 问题陈述**：证据包 ③C1 已裁决「B 端客户关系」与「学生端产品本体」是不同范畴、不可混同（商务关系 vs 产品/工程边界）。但从产品/语义视角看，这个裁决是**证据包做的分析区分**，尚未落到「统一的产品定位一句话」：`[访2] L280` 仍写着「面向中小学教育相关机构的 **B 端**学业支持产品」（这是产品**定位/市场**层），而 `[访3] L2990`「一个 Agent 产品只能服务一个人」是产品**本体/部署**层。两层在证据包里并列，但「谁购买（机构）、谁被服务（学生）、谁持有（学生设备）」三元在产品定位层面**没有一句话同时成立**。若起草团队只在工程边界取了「学生端本体」，而未在产物层把「面向机构、作用于学生、工程首版=学生端本体」钉成统一表述，则「机构」这个实体在学生端首版里是否出现（账号/角色/授权来源）仍是悬空的，会直接落到工程前置的角色模型。

**② 证据依据**：`[证据包 T10/③C1]`（消解线索）；`[访2] L280`（B 端产品定位）；`[访3] 6-8 L2990`（单实例服务单学生）；`[上下] 工开CLAUDE L37-39`（工程只取学生端）。

**③ 状态标签**：`[确认采纳]`（访2 L280）对 `[用户明确判断]`（访3 L2990）——两处均为已采纳/已判断，属**跨层表述张力**，非事实冲突。

**④ 分类**：**应改**（统一产品定位表述，防起草在角色/授权模型上越界或漏机构）。

**⑤ 不改的后果**：学生端首版的「使用者=机构委托场景下的学生」与「独立个人学生」未定义，机构授权/账号/角色模型无从写起；起草团队要么漏机构、要么误把机构拉进学生端本体，两端都错。

### P-2（含原 P-12）云端模型 API 网关是「学生端系统前提」，却落在「云端不纳入」护栏内——接口边界必须为学生端刻出可写范围

**① 问题陈述**：证据包把「云端模型 API 网关」列为学生端本体**系统前提**（`[访3] 9-1 带三 L3801-3814`：因「Agent 依赖云端模型、无模型即不可用」），同时护栏又「云端/B端/后端仅提及、不纳入」。产品语义上这是**范围护栏内部的自洽断点**：学生端首版「无模型即不可用」，但工程文件对「学生端如何持有并调用云端模型 API」没有可写边界。**「云端模型 API 网关」是学生端的一个调用出口/接口契约（应可写），还是云端后端本身（不纳入）？** 证据包未成文区分这两者。

**② 证据依据**：`[证据包 T10 层次二]`（工开CLAUDE L37-39，云端仅提及）；`[证据包 T10/访3 9-1 带三 L3801-3814]`（云端模型 API 网关=学生端本体系统前提）；`[证据包 T9/访3 8-5 L3606]`（LLM 由云端统一代理，客户端不持 API Key）。

**③ 状态标签**：`[确认采纳]` 且两结论并存，护栏未给本条划界 → 属**范围护栏内的待澄清项**。

**④ 分类**：**必改**（不刻出接口边界，学生端首版无法按规范写「调用云端模型的契约」，起草会犹豫或直接越界写云端后端）。

**⑤ 不改的后果**：学生端首版「模型调用」无规范落点；或起草团队以「系统前提」为名把云端后端纳入工程文件，突破范围护栏；或反之完全不写模型调用，首版「无模型即不可用」无法交付。

### P-3「单实例服务单学生」与「面向机构的 B 端」在**多学生分发/机构角色**上语义悬空

**① 问题陈述**：`[访3] L2990`「一个 Agent 产品只能服务一个人」确立了**单实例语义**，`[访2] L280` 又确立**机构是 B 端客户**。但「机构购买后如何向多学生分发、每学生单实例由谁初始化、机构授权如何进入学生端」在产品语义上未成文。学生端首版是「单学生」没问题，但**「机构」这个实体在学生端首版是否出现、以什么角色出现**是未定项。

**② 证据依据**：`[证据包 T10/访3 6-8 L2990]`；`[证据包 T10/访3 8-3 L3529]`（三端部署结构，学生端本地实例）；`[证据包 T10/访2 1-2 L282-287]`（B 端是客户与赋能关系）；`[证据包 ④G4]`（数据本地化合规、机构委托框架待成文）。

**③ 状态标签**：`[确认采纳]`（两端结论都成立）+ `[待你拍板]`（机构在首版学生端的具体角色属产品范围决策）。

**④ 分类**：**待你拍板**（涉及机构在多学生分发中的角色，超出我单视角裁决范围）。

**⑤ 不改的后果**：学生端角色/授权模型写不出「机构→学生」的委托关系；后接三端闭环时（第3步 B 端）缺机构接入位，需返工。

### P-4「证据两大类型不可模糊」与「外部/内部/学业资产三层」表述张力——学业资产是否第三类证据必须澄清

**① 问题陈述**：证据包 T2 标题用「外部/内部/学业资产三层」，但证据正文 `[访3] L1538` 是**用户明确判断**「证据两大类型不可模糊」（只分外部/内部），而 `[访1] L8067-8081` 把**学业资产**定义为「由外部证据和内部证据**共同支撑、达确认条件后形成**的个人化学业认识」。产品语义上，**学业资产不是第三类证据，而是由两类证据衍生的「认识性对象」**——但证据包用「三层」并列表述，极易让工程数据模型把资产误建模成第三类证据类型，触发 `[上下] 门禁2 L118-121`「外部/内部证据混淆」红线。

**② 证据依据**：`[证据包 T2]`（标题三层 vs `[访3] 3-3 L1538` 两大类型）；`[访1] L8067-8081`（资产定义）；`[访3] 3-3 L1559-1573`（证据>记忆>上下文，资产须可回溯到证据）；`[上下] 门禁2 L118-121`（外部/内部证据不得混淆）。

**③ 状态标签**：`[用户明确判断]`（两大类型）+ `[确认采纳]`（资产定义）——语义关系（资产⊆证据衍生物，非第三类证据）未成文。

**④ 分类**：**应改**（成文一句「学业资产≠第三类证据，是两类证据衍生的认识对象」）。

**⑤ 不改的后果**：数据模型把资产当证据类型建模，破坏「证据是驱动性事实基础」定位；外部/内部证据与资产的转换语义（访1 L8067-8129）无法落成字段契约。

### P-5 C2 修正后「取消教师主观输入」与三端闭环「教师售后校准回流」语义矛盾——证据模型死结

**① 问题陈述**：`[已被修正]` 终局确立**取消教师批注/评分/评语/意见/评价作为产品输入、可信度分级对象或效果裁判**（`[访3] 13·Q13-2 L4618-4624`）。但三端闭环又明确 B 端教师工作台做「授权范围内周期性人工校准」，回流采用「结构化记录回流 + 本地校验、本地保留最终权」（`[访3] 6-9 L3037`），且 T6 可追溯操作清单把「售后校准查看/意见/回流/合并」列为可追溯操作（`[访3] 7-5 L3280-3298`）。**教师售后校准的「回流」会进入学生端并可能影响判断——这与 C2「取消教师主观输入/不作效果裁判」在产品语义上是什么关系？** 若教师校准回流会影响判断/资产，它算不算已被取消的「教师主观输入」？证据包只在 T10 分层（教师工作台=后置第3步）规避，但**学生端证据模型必须预留「外部校验回流」的语义位**，否则后接不上，且现在已隐含矛盾。

**② 证据依据**：`[证据包 T2/③C2]`（`[访3] 13·Q13-2 L4618-4624`，取消教师主观输入）；`[证据包 T10/访3 6-9 L3037]`（售后校准回流、本地保留最终权）；`[证据包 T6/访3 7-5 L3280-3298]`（售后校准回流列为可追溯操作）；`[证据包 T10/访3 8-7 L3676-3683]`（最小端到端验证含一次教师周期校准+一次校准回流）。

**③ 状态标签**：`[已被修正][用户明确判断]`（C2）与 `[确认采纳]`（三端闭环教师校准）——**两者并存但关系未裁决**。

**④ 分类**：**必改**（先裁决「教师售后校准回流 ≠ 已取消的教师主观输入」的边界，再写学生端证据语义；该边界直接影响学生端首版证据模型是否预留回流位）。

**⑤ 不改的后果**：学生端证据模型对「教师校准回流」无语义定义；起草要么违反 C2 把教师意见当输入，要么漏掉回流位导致三端闭环第3步接不上；审核时会判定为「与已确认门禁冲突」。

### P-6「三步 vs 五步」非步骤数问题，而是「拼接缝合」→「受控整合」的**语义演化是否被逐字接受**

**① 问题陈述**：③C3 已裁决以五步（复用＞改造＞受控整合＞必要重构＞最后自建）为确认细化版。产品语义上关键在：用户口语「拼接缝合改造优先」（`[访1] L11769`）被访谈2/3 规范化为「受控整合」，而「受控整合」正是 `[访1] L11817` 所防的「机械拼接缝合怪」红线的**限定词**——即五步把用户的「拼接缝合」**规范为「受控整合」**。证据包只标 `[确认采纳]`（非逐字用户原话）。引用时必须注明这是对用户原意的**规范化细化**，避免把「受控整合」当用户逐字判断。

**② 证据依据**：`[证据包 ③C3]`（处置=五步为确认细化版）；`[访1] L11769`（三步用户原话）；`[访3] 4-4 L2053`（五步）；`[访1] L11817-11826`（受控整合红线=缝合怪）。

**③ 状态标签**：`[用户明确判断]`（三步原话）+ `[确认采纳]`（五步代拟确认）。

**④ 分类**：**应改**（引用纪律：五步标注为「对用户'拼接缝合'的规范化细化」）。

**⑤ 不改的后果**：起草把五步当用户逐字原话引用，丢失「受控」是对用户口语「缝合」的规范性约束这一语义，0.5→1 整合纪律被弱化。

### P-7「第一交付=最小闭环+L1/L2」在工程文件语境=**规格样例**，非运行系统——须钉死防起草越界生成代码

**① 问题陈述**：`[上下] 门禁9` 第一交付=单学科/单任务最小闭环+L1/L2 验证包（`[证据包 T8]`），而 `[访3] 8-4` 产品链第1步也是「单学生/单学科/单任务最小闭环」。**这两个「最小闭环」同词但层级不同**：门禁9 的「第一交付」是**进入工程代码前的交付**（`[前置清单 §8.4 L227]` 明确「进入代码前须交付样例」，工程文件只写规格样例、不下层设计、不生成可运行代码——工开CLAUDE），而访3 第1步是**产品链要构建的首版系统**。产品语义上，「第一交付」若被起草理解为「要交付运行系统」，会直接突破 CLAUDE.md「不下层设计、不直接生成可运行代码」边界。

**② 证据依据**：`[证据包 T8/上下 门禁9 L153-156]`（第一交付）；`[证据包 T10/访3 8-4 L3568]`（产品链第1步=学生端本体最小闭环）；`[证据包 T10/前置清单 §8.4 L227]`（进入代码前交付样例）；`[工开CLAUDE]`（不生成可运行代码）。

**③ 状态标签**：`[确认采纳]` 且两处结论成立，但「第一交付」在本工作流语境=规格样例未成文。

**④ 分类**：**应改**（澄清「第一交付」在工程文件=最小闭环**规格/样例**，非运行系统）。

**⑤ 不改的后果**：起草团队以为要产出可运行最小闭环代码，越界生成实现；或反之把「第一交付」理解为纯文档而无最小闭环样例规格，无法通过 `[前置清单 §8.4]` 代码前门。

### P-8「L1/L2」双义——证据链层级标记 vs 验证包层级，同词不同义易混

**① 问题陈述**：证据包内「L1/L2」出现两种含义：(a) `[访3] 9-4 L3954` 的「层标记（L1/L2/L3/L4）」=证据链**闭环验收层级**；(b) `[上下] 门禁9` 与 `[前置清单 §8.5]` 的「L1 机制测试 + L2 故障注入」=验证包**测试层级**。产品语义上这是**术语冲突**，起草若混用，验收语义会混乱（L1/L2 既被理解为证据链层级、又被理解为测试层级）。

**② 证据依据**：`[证据包 T6/访3 9-4 L3954]`（L1-L4 证据链层标记）；`[证据包 T8/上下 门禁9 L153-156]`（L1/L2 验证包）；`[证据包 T10/前置清单 §8.5]`（L1机制测试+L2故障注入）。

**③ 状态标签**：`[确认采纳]` 两处均成立，属术语重名冲突（`[推断]` 我为两者语义不同）。

**④ 分类**：**应改**（术语统一，如证据链层级改称「证据层 E1-E4」，验证包保留 L1/L2）。

**⑤ 不改的后果**：验证包层级与证据链层级混用，L1/L2 验收标准与证据链闭合验收互相覆盖，质检判据（`_共识.md` §二.19 量化指标）失效。

### P-9「学生唯一承接者」的**承接范围**含糊——现实材料 vs 行动/确认 vs 他主体带入材料的边界

**① 问题陈述**：`[访3] L4632` 把学生界定为「现实材料唯一必要承接者」（承接=把客观学业材料带回产品），`[访1] L5025` 又泛称「学生是唯一亲身参与行动与确认的主体」（承接=行动与确认）。两者承接对象不同。更关键：`[访1] L8025` 外部证据定义含「由学生**或其他主体**带入系统的材料」（含家长材料）——与「学生唯一必要承接者」存在张力：**家长带入的材料是否算非学生承接的外部证据？** 产品语义上「唯一承接者」到底承接什么、他主体带入材料如何处理，未成文。

**② 证据依据**：`[证据包 T10/访3 L4632]`（现实材料唯一必要承接者）；`[证据包 T1/访1 L5025]`（唯一亲身参与行动与确认）；`[证据包 T2/访1 L8025]`（外部证据含其他主体带入，含家长材料）；`[证据包 ③C5]`（唯一承接者溯源差异）。

**③ 状态标签**：`[确认采纳]` 两处表述并存，承接范围未裁决 → `[待你拍板]`/`[待验证]`（家长材料与「唯一承接者」关系）。

**④ 分类**：**应改**（成文「唯一承接者=现实材料承接」并明确他主体（家长）带入材料的证据地位与登记边界）。

**⑤ 不改的后果**：学生端证据输入边界模糊——家长/其他主体带入的材料在证据模型里地位不明，违反「学生唯一承接者」边界或错拒合法材料。

### P-10 教师人设在学生端「责任缺席」、但在三端闭环「售后出现」——人设一致性需成文
