## T1 学生端产品本体职责与边界（学业军师是学生端；产品责任）

- **L3871-3875 [确认采纳]**：军师作为唯一对外的责任主体。「学生可以拒绝、质疑、纠正和决定，但它们必须作用于一个明确的对象。军师作为唯一对外的责任主体」；「对外承受学生判断和质疑的，始终是军师」。专业问题可由后台专项 Agent 思考。
- **L3877-3888 [确认采纳]**：「术业有专攻」是对后台能力组织的要求，不是对学生界面的要求；专项 Agent 做专业事不等于学生看到多个主体；「六边形战士」与「主控+专家团队」本质区别。对应 T5。
- **L5025 [确认采纳]**：「学生是唯一亲身参与行动与确认的主体。」
- **L11692-11704 [确认采纳]**：产品本体至少包括「学生是学习主体」「学业军师服务全学科总体战场」「学校是现实检验场」「证据是判断的硬约束」「学生拥有最终决定、纠正和退出权」等 13 项（见 T8/T9 段详列）。
- **L11686 [确认采纳]**：「DeepTutor 可以替换、改造或放弃；学业军师的产品本体不能被底座决定。」
- **L790/809-810 [确认采纳]**（T1×T2）：产品行为「必须基于学生的真实客观证据」，「不做违反事实的行为、不做缺少证据的动作」，是区别于传统教育产品的最大差异。
- **L3107-3117 [确认采纳]**（教与授承接层）：「教与授承接的是实现规划、行动所需要承接的功能与行动……判断一个规划不是'伪规划'，极大程度上取决于是否存在真正承担教学与讲授功能的实现载体」；教与授是把「规划」转化为「真实学习发生」的承接层，不是可选的附加功能。

## T2 客观证据模型（外部=排名/成绩/试卷/作业；内部=行动/检验）

- **L8025-8042 [确认采纳]**：外部证据定义。「'外部'不是指互联网外部，而是指由学业军师系统之外、由学生或其他主体带入系统的材料」，如学生上传的作业、试卷、错题、练习答案、文字/口述说明、教材、教师批注、标准答案、家长材料。「学生上传的内容当然可以成为学业资产的来源，但上传本身不等于资产成立。」
- **L8044-8065 [确认采纳]**：内部证据定义。是「系统在处理真实学习活动后形成的可追溯过程记录或判断依据」，必须能回溯到原始材料、学生实际行动、具体对话/交互事件、处理过程、确认/修正动作；否则「只是 Agent 自己生成的叙述，不能获得比外部材料更高的可信度」。
- **L8067-8081 [确认采纳]**：学业资产定义。「由外部证据和内部证据共同支撑，经整理、提炼、复核，并达到相应确认条件后，形成的面向特定学生、可被该学生理解和后续使用的个人化学业认识。」
- **L8084-8120 [确认采纳]**：学生上传内容是否为资产——区分「原始学习资料」与「经处理的学业资产」；「原始资料与认识性资产可以同时存在，但二者不能混为一谈」。
- **L8122-8129 [确认采纳]**：内外证据协调——「外部证据更接近'发生了什么'」；二者分别承担不同功能，非简单比可靠性。
- **L899-910 [确认采纳]**：最小场景第一优先判断是「证据归类」，所需证据四类（提交材料本身、学生补充信息、过往系统记录、需标记待核实部分）。
- **L5153-5184 [确认采纳]**：证据治理 Agent 职责含登记、归类（结果带候选状态）、事实提取、证据分级与关联、冲突发现、来源追溯、证据质量审查、证据生命周期治理（有效/待复核/失效/归档/删除；记录纠正、撤回、删除动作）。

## T3 状态与生命周期（候选/生效/暂停/回退/失效/撤回/删除，候选与生效分离）

- **L5181-5184 [确认采纳]**：证据生命周期治理「处理有效、待复核、失效、归档和删除状态；记录学生纠正、撤回和删除动作；确保错误证据不会静默继续影响后续判断。」
- **L5375-5382 [确认采纳]**：证据系统事实层面的状态流转——学生提交→系统登记→归类/提取（生成候选，学生或规则可确认）→判断引用→学生纠正（产生新版本并保留原版）→删除（留痕）。「独立于任何单次对话、任何单个模型而存在的、可持续、可版本、可追溯、可纠正、可删除、可审计的确定性数据基础设施。」
- **L1949 [确认采纳]**（候选与生效分离）：「可由 AI 识别的内容（材料类型、学科）采用'AI 提候选 → 学生确认'，不直接写成确定事实。」
- **L5153 [确认采纳]**（候选与生效分离）：归类结果应带候选状态，无法确定时标记未知或请求确认。
- **L11583-11595 [确认采纳]**（资产生命周期）：须自行建设「资产候选、学生确认、学科归属、来源链、版本、有效/待复核/失效/归档、新学校证据的复验和修正、学生查看/纠正/撤回/删除和授权。」
- **L1994-1997 [确认采纳]**（上下文治理）：长期对话不结束会导致上下文膨胀、证据混杂、错误传播、权限边界模糊；已提升为阶段4独立专题 4.6，核心判断尚未收敛（**该点状态为[部分确认]/[待验证]**）。

## T4 权限与确定性强制（由确定性代码强制，不靠提示词；不可逆拦截）

- **L1969-1971 [确认采纳]**：「学生资产、权限、不可逆操作等硬边界，由确定性代码规则强制，AI 无法绕过；提示词负责引导，不能承担权限保护；提示词不宜过度堆叠，避免模型判断混乱。」
- **L938-944 [确认采纳]**（硬边界落点）：对「不允许未经学生确认就改写学生资产」的强制方式，采访者以「你强调'AI 不自证、确定性规则守底线'的产品原则」判断应为「规则强制 + AI 合理行为」两者结合；**此为采访者转述的用户产品原则，[用户明确判断]**。
- **L1248 [确认采纳]**：工程规格序「以'输入与来源定义'为源头，以'证据归属建模'为核心，以确定性权限规则为硬边界，以输出契约和追溯机制完成闭环。」
- **L919-924 [确认采纳]**：军师在最小场景的权限边界——允许：材料诊断、建议学习重点、提出确认问题；不允许：未经确认改写学生资产、证据不足给高确定性结论、替学生做决定。
- **L6962-6987 [确认采纳]**（监察边界）：监察设施可读证据设施受控信息，但不能任意修改原始证据、判断结果或学生资产；监察发现问题通过纠正、复核、暂停、回滚等正式流程处理，不能静默改写历史。
- **L5395-5401 [确认采纳]**（AI 不自证结构成立）：「证据治理 Agent 负责管理证据，主控军师负责判断」，「作出判断的主体」与「管理判断依据的主体」分离，避免同一主体既产生结论又独占解释权；「只有底层证据设施+独立管理 Agent，才能让'AI 不自证'在结构上成立。」

## T5 多代理编排（总军师/学科军师/专项Agent/横向责任域；调度/优先级/交接/冲突裁决）

- **L3760-3786 [用户明确判断]**：「学业军师不应是试图包办所有环节的单一 Agent（六边形战士），而应是主控 Agent」；专项 Agent 各司其职；「术业有专攻，专业 Agent 做专业的事。」
- **L6538 [用户明确判断]**（战场分层）：「一个总军师是无法独立掌控这么多战场的，我建议每个战场应该设立独立的战场军师」；「专业的人做专业的事，每个 agent 只负责一件专业的事情，术业有专攻，只精通一个点不做全能选手。」
- **L6548-6590 [确认采纳]**（多层级战场指挥体系确立）：总军师（总战场指挥）→学科战场军师（独立战场指挥）→学科内专业专家（最基础 agent）→学生真实行动→逐层反馈→总军师调整全局布局。采访者：「你给的是决定产品底层的正确结构。我确认并确立它。」（**结构确立为[确认采纳]**；调度细节见下条[待确认]）
- **L6521-6525 [确认采纳]**：三层职责——总军师统筹全学科战略/优先级/资源/失衡调整；学科战场指挥负责学科内主控；学科内专家为执行者。
- **L3796-3810 [待确认]**（主控与专项边界）：「主控 Agent（军师）与专项 Agent 之间的分工边界、调用规则、判断权和责任归属如何划分」——军师调用 Agent 程度、专项 Agent 判断权、学生面对谁、输出如何回军师统一判断、证据/状态/记忆如何共享隔离、最终责任主体，均为「一个需要后续确认的边界」。
- **L7047 [确认采纳]**（横向检查）：监察链应能「横向检查不同层级之间的交接」，不是单向层层上报。对应 T6。
- **L5138 [确认采纳]**（冲突裁决权不独占）：「主控军师可以请求、使用和解释证据处理结果，但不应独占证据的建立、变更、确认和审计权。」
- **L5190-5207 [确认采纳]**（边界表）：证据治理 Agent 与主控军师职责划分表；「证据治理 Agent 判断'材料能支持什么'；主控军师判断'在这些证据和限制下，下一步应该讨论什么'」；主控不能把「可能」改写成「已经确定」。

## T6 证据/审计链（每判断/规划/行动可回溯；审计字段防篡改）

- **L5146-5174 [确认采纳]**（来源追溯职责）：证据治理 Agent「让任何重要判断都能回到具体证据；保留时间线、版本、处理过程和引用关系；支持后续复盘和错误回溯。」
- **L5200-5201 [确认采纳]**：来源与审计记录由证据治理 Agent 负责维护，主控军师必须引用和遵守。
- **L5384-5393 [确认采纳]**（防篡改/可回滚）：证据治理 Agent 自身操作「要被日志记录和审计」「它的行为要可回滚、可复查」「它不能隐藏冲突、删除记录或越过权限」。
- **L5358-5362 [确认采纳]**：证据处理系统是「底层确定性设施」，类比「数据库、权限系统、审计日志」；证据治理 Agent 是管理/执行主体。
- **L6966-6969 [确认采纳]**（证据设施 vs 监察设施职责分离）：证据底层设施「保存和治理'发生了什么、依据是什么'」；监察底层设施「保存和核验'谁做了什么、是否按要求做、结果是否可靠'」。
- **L5157-5159 [确认采纳]**（事实提取防篡改）：区分直接可观察内容与模型推断，不擅自补全缺失信息。

## T7 业务回滚语义（回滚单元/版本/错误补偿）

- **L6946 [确认采纳]**（回滚触发）：监察结果动作含「回滚并重新处理」。
- **L6973 [确认采纳]**（回滚流程）：监察发现问题后「应通过纠正、复核、暂停、回滚等正式流程处理，而不能静默改写历史。」
- **L5392 [确认采纳]**（可回滚）：证据治理 Agent「行为要可回滚、可复查」。
- **L5377 [确认采纳]**（版本/回滚单元）：学生纠正后「底层设施产生新版本并保留原版」；删除由学生或合法操作触发、底层设施执行并留痕。
- **L5450 [确认采纳]**：证据底层设施字段含「纠正、撤回、删除与回滚」。
- **L11604-11609 [确认采纳]**（监察回滚）：监察结论可触发补证、暂停、复核、回滚和扩大检查。

## T8 0.5→1 路径与候选（拼接缝合改造＞重构＞自建；DeepTutor 底座；开源组件准入）

- **L2013/2019 [用户明确判断]**（底座设想提出）：「我想以 deeptutor 为我的底座，根据我产品的特点在其已存在成熟基础上进行改造，综合下来这是与我项目最为近似匹配的项目……我不希望 0-1 开发一个乱七八糟、参差不齐的产品，不然借助 github 上成熟的可商业改造协议的开源项目进行拼接缝合形成自己的产品。」
- **L2027-2076 [确认采纳]**（专题确立与三层次）：采访者确立「阶段5. x DeepTutor 底座改造与 0.5→1 开发路径」专题；区分复用/改造/缝合三个层次——「复用（直接使用边界清楚、可独立验证的能力）；改造（保留底座结构但改变行为或领域适配）；缝合（多个项目未经统一架构和责任设计地拼接）」；前两者可能是合理 0.5→1 路径，第三种易形成「乱七八糟、参差不齐」的系统。
- **L2058 [确认采纳]**（用户立场记录）：「不从零重复建设已经存在且经过实践的 Agent 基础能力；优先选择与学业军师最接近的成熟开源底座，在明确边界、保留有效能力、删除冲突能力的基础上进行受控改造。」
- **L2060-2068 [待验证]**：DeepTutor「是否真的足够成熟、代码层/运行层/仅结构相似、是否适合个人长期改造、许可证依赖是否允许、架构能否承载证据/判断/资产/权限边界、改造成本是否更低、哪些成熟能力是与产品目标冲突的历史包袱」均未最终确认。
- **L11769 [用户明确判断]**（0.5→1 总原则扩大）：「0.5-1 指的不仅仅是底座，一切可复用可改造可重构的开源项目都是进入 0.5-1 的候选名单的内容。我遵循的是以拼接缝合改造优先＞重构＞自建。」
- **L11785 [确认采纳]**（0.5→1 正确含义）：「0.5→1 不是某一个底座的改造路线，而是学业军师整个产品的开发总原则：凡是已经存在、能够被验证、与产品目标相容的开源项目、成熟模块、工具、协议或工程能力，都应优先纳入复用、改造、重构和整合的候选范围；只有在复用、改造和重构都不适合时，才考虑自建。」
- **L11799-11815 [确认采纳]**（开发优先级）：已有成熟结构复用 ＞ 在已有结构上改造 ＞ 多个可验证结构受控整合 ＞ 必要范围内重构 ＞ 从零自建；「以复用和改造优先，以受控整合为主要手段，以重构和自建作为必要补充。」
- **L11817-11826 [确认采纳]**（受控整合红线）：机械拼接会产生重复状态/记忆系统、多套权限边界、不一致事件和数据模型、冲突 Agent 生命周期、证据/资产/会话断裂、「难以追责和维护的'缝合怪'」；复用优先不等于无原则拼接，每个候选须经产品责任、边界、依赖和验证审查。
